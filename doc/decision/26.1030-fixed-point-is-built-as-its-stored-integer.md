# 26.1030: fixed point is built as its stored integer

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**The RTC's calibration could not be built**: "is fixed point, whose value
is scaled". The refusal came with the first builder (6d5c014c) as a
conservative default, with no decision behind it, and it disagreed with
the rest of the tree: every reader's getter and setter take a fixed-point
field's stored integer -- `int16_t` for a Q8.8 in C, `int` in Python, `i16`
in Rust -- and a packed fixed-point member was already being built as its
bits.

**So a plain fixed-point member is built as its stored integer**, the
value the reader's own setter takes, in all four. A writer that took a real
number and converted it would be a second copy of a conversion, which the
`_scalar_refusal` docstring warns against.

**Measured**: a trim of -1.5 ppm (Q8.8, -384) and a 32768 Hz reference
(UQ16.16, 0x80000000) are `FE 80 80 00 00 00` from C, and the agreement
test builds `calibration` alike in all four.
