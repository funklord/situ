# 26.922: a number can start inside a byte

Status: recorded
Date: 2026-11-07
Source: 26.921's "not here", against the holder's "anything theoretically a need"

**CBOR, HPACK, QPACK and a BER tag number could not be described.** Each begins in
the low bits of a byte whose top bits are something else: a major type, a pattern
that says which representation this is, a Huffman flag, a class. They carry COSE,
WebAuthn, HTTP/2 and HTTP/3.

    encoding = cbor;              five bits; 24 to 27 say one, two, four, eight follow
    encoding = hpack; prefix = N; N bits; all ones says leb128 groups follow, added
    encoding = bertag;            five bits; all ones says be128 groups hold it

**The bits above are ordinary bit fields, stated before it.**

    struct string { u1 huffman; prefix7 length; u8 data[length]; }

A reader asks for `huffman` by name, a writer sets it, and `must_eq` and `peek` work
on it. The number starts at the byte the fields opened and counts that byte, so the
cursor goes back and each field before it spans nothing, as a `peek` does.

**Rejected: a mask and no fields.** A number that ignores its top bits needs no
layout rule, and `peek u8 first` would read them. But a flag that varies has then
no way to be written: HPACK's `H` bit is the caller's, per string.

**Rejected: a constant in the declaration.** `flags = 0x80` serves a pattern and not
`H`, and needs a type for each pattern.

**It has to be stated.** The number must land exactly as many bits into a byte as it
leaves, and nothing else is accepted: left out, a writer has no value for those bits.
Behind something of no fixed size the phase is not known, so it goes in a struct of
its own, as `string` is.

**One table row and one reader.** `cbor` is a row of `ast.MARKED` with a mask, and
`hpack` and `bertag` are one reader with two readings of the groups. The image says
203, 204 and 210 + N where a last group's bits would be, so a walker holds them as it
holds the others.

**Each `_put` keeps the bits above it**, and a builder's packed group stays open for
the number: it zeroes the byte, sets the fields, and does not spend it.

The witnesses are the RFCs': 8949's appendix A, read as the value it prints, and 7541's
C.1 to C.4, whose strings come out as the text it prints. EMV's 5F20 and 9F02 and
ICAO's 7F49 for the tag. No library for either is on this machine, so no second
implementation has read these bytes.

**`example/cbor` found four faults that are not this feature's**, being the corpus's
first counted runs of recursive structs and first sub-byte `peek`:

- `peek u3` raised the struct's minimum to three bits, and a struct of no whole size
  is measured by nothing: the C generator died on an assertion.
- Python's depth walk read `_extent` on a recursive element, which has `_extent_at`.
- C++ named a local `value`, so a varint member called `value` did not compile.
- `gen-checks` broke a pin the peek selects by, which makes another arm and no
  refusal. Such a pin is declined here, and checked in the struct that holds it.

`required` now stops at a peek and asks for its bytes, which also settles 26.753's
closing note. That record called the default arm's size over an absent discriminant
an allowed over-ask; the section on framing promises a lower bound, and `edges.kinded`
has a two-byte arm its answer of 3 stood above. Over no bytes all four answer 1.

**Not here.** CBOR's indefinite lengths, which a break byte ends: additional value 31
is no number. The Huffman coding and HPACK's tables are the decoder's. A builder's
pinned bit field is still the caller's argument.
