# 26.937: the dissector walks a tlv region's items

Status: recorded
Date: 2026-11-08
Source: the largest group the dissector still declined after 26.936

**A tlv region is walked as `walk._tlv_walk` walks it**, each item a row: read the tag,
decode its parts, take the rule the selector names, and the rule says how far the value
reaches -- fixed, computed, self-delimiting or prefixed. Where the walker stops, at a
tag or length the frame cuts, a value past the frame, or a selector no rule answers, so
does this, and nothing of that item is shown. It fell to "a length this dissector
cannot render" and stopped the cursor, so CoAP's options, protobuf's fields, QUIC's
transport parameters and HTTP/3's frames showed nothing.

**The tag's bits are arithmetic.** A tag decodes with `tag >> 3` and `tag & 0x7`, and
decision 0021 keeps bit operators out of this file, so a shift by a constant is a
division or a product and a mask of contiguous bits a difference of remainders. A shift
by a variable, a mask with holes, `|` or a call is declined, as any length this cannot
read is.

**A varint's value comes back three ways now**: its width, the value held to a length,
and the value itself, which Lua 5.4 keeps exact modulo 2^64. Saturated at 2^48 alone, an
eight-byte protobuf tag read wire type 0 where its low bits say 4, and an item was found
where the walker stops. The forms that refuse a number past 2^64 check that on a float
beside the exact one.

**The differential counts items**: a member shown item by item, a tlv region or a run of
varints, is held to the walker's `count=` where that line carries no `span=`, beside
which the count is the declared one rather than what was walked. Counting every
member's abutting rows instead took a run of records' raw remainder for items.

Held to Wireshark's CoAP dissector over every committed vector, and to a protobuf message
worked by hand; the wide-tag case fails with the saturated value read as the tag.
