# 26.1022: a PUBLISH packet is built

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**MQTT's PUBLISH, the protocol's commonest packet, could not be built.**
Two refusals, both about something other than what stopped them.

`publish_body` takes `parameter u2 qos`, and every arm of it was refused:
"`qos` packs into a group that does not start on a byte boundary". An
argument is no bytes at all; `packed` asked of it as of a field, so a
two-bit parameter became a bit group off a byte boundary. It is excluded
there now, as a peek is.

And the packet's PUBLISH arm ends the message, which 26.973 lets a builder
take whole -- except where the arm's struct takes arguments, as this one
takes `qos = (flags >> 1) & 3`. That arm was validated on its own, which
needs the argument; but the packet's closing validation already descends
into it with the qos it derives, exactly as the reader does. Such a tail is
now `deferred`: its content is left to that validation, in all four. An arm
whose extent is its argument (26.1012) is asked about first, so DNS's
RDATA keeps its length check. `edges` gains two arms of the same shape.

**Measured** against MQTT 3.1.1 section 3.3: QoS 1, topic `a/b`, packet
identifier 10, payload `hi` built body and packet as `32 09 00 03 61 2f 62
00 0a 68 69` in C and Python, and flags saying QoS 3 refused; the agreement
test builds the PUBLISH body arms and the packet alike in all four.

**And a gap the work found, not closed here.** The schema never ties the
remaining length to the body (MQTT 2.2.3: it counts the variable header
and payload), so every packet builder writes the length it is handed and
every reader takes a packet whose length disagrees with its body -- the
agreement test's own PUBLISH case carries 4 over ten bytes. Closing it
moves the schema's committed contracts and is recorded as open.
