Status: recorded -- a builder for the struct whose every member is a
whole-byte fixed scalar. The 45 below over-counted: 26.858 found a run
sized by arithmetic passing for a scalar, and the class is 29 structs
over 15 schemas. C++ and Rust serve the same class since 26.858
Date: 2026-11-04
Source: 26.854, which measured the ladder and found `--layer edit` adding
nothing to three of four targets, and 26.610, which is the specification

## What it is

`situc build --target python --layer edit` emits
`<schema>_build.py`: one `build_<struct>(out, *members) -> int` per struct
it serves, writing each member into the caller's `bytearray` in schema
order and returning the length.

**C's shape, not a Python reinvention.** The sequence is the one
`c/build.py` emits: bounds-check the remaining capacity, write the
member's bytes at the cursor, advance, and when every member is down take
a view over exactly what was written and `validate()` it. That last step
is why this is small, and 26.610 said why it is right: "constraints are
the view's to state and this reuses them rather than restating them: two
checks of one schema is how they come to disagree."

**One class of struct, not one feature of the builder.** Every member a
whole-byte fixed scalar at a static offset -- **45 of the 157 structs C's
builder serves**, over 17 of the 45 corpus schemas. A bit-packed field is
excluded for a reason rather than for convenience: the packed run is
written zeroed and then set in place, which is a second write to a byte
the cursor has already passed, and append-only is the property the rung
was given permission for. C's builder has that case; this increment does
not.

Everything else is **named on stderr**, which is C's own stance -- a
caller who asked for a builder and found their struct missing would
conclude the generator was broken. C's refusals pass through unchanged,
being the same decisions, and a struct C serves that this does not is
named with the class it falls outside, so the increment's boundary is
readable rather than inferred from an absence.

## Why not call the setters

They would reuse the accessor's own arithmetic, which is this tree's usual
answer. Against it: a `reserved` member has no setter, a field inside an
authenticated region has no plain one, and a driving field's setter
invalidates the view it was written through -- so the builder would need
the accessors' decline logic by a second route. And the two backends'
builders would stop being comparable, which is what a differential is for.

## Four faults, all found by RUNNING the generated code

The gate generates the builder for every corpus schema, imports it, builds
each struct it serves with ascending non-symmetric values, and reads every
member back through the ordinary accessors. It found four faults in this
emitter that no text assertion would have:

- **A byte order derived a second time.** Written as `is not LITTLE ->
  big`, which is the exact derivation `_byte_order`'s own docstring records
  as having been wrong twice before -- and netlink's `native` header read
  back as 353637138 where 303240213 went in. The emitter's helper answers
  it now. One question, one predicate.
- **`int(value)` could not survive a member named `int`.** `edges.keywords`
  has one, the parameter shadows the builtin, and `int(int)` calls an
  integer. The wrap was defensive and was the only line that could break;
  the annotation says what the argument is. This is
  `test_a_member_named_for_a_builtin_is_read_and_not_called` met from the
  writing side.
- **A zero-width member.** `ble.ad_structure.value` has `size_bits` 0, and
  `to_bytes(0, ...)` overflows for any nonzero value. Excluded now: a
  member with nothing to write is not a member this class serves.
- **`NATIVE_BIG` was not imported, and then was imported too widely.** A
  `native` member's write reads it and the star import does not carry it,
  so netlink raised `NameError` on its first line; importing it
  unconditionally then turned one `NameError` into fifteen
  `ImportError`s, the base module defining it only where a member is
  native. **The correction was wider than the fault it corrected**, which
  is worth its own sentence: the second state was worse than the first and
  looked like progress.

## The gate asserts the partition

A struct the builder serves has to round-trip; a struct it does not has to
be named. Either cell alone would pass against an emitter that served
nothing, or against one that claimed everything.

And 26.854's own gate moved with the claim: `WITHOUT` is two targets now,
Python is asserted beside C on the other side, and the identity test --
`--layer edit` IS `--layer view` for a target with no builder -- covers
the two that remain. **`example/modbus` rather than `dns` for the served
half**, because none of `dns`'s structs is in this class: asking it of
`dns` would assert Python has no builder anywhere, which is a different
and false claim.

## What is left

C++ and Rust, and the classes this increment excludes: bit-packed fields,
runs, variants, text numbers, varints, delimited members -- which is what
the other 112 of C's 157 are made of. 26.610 and `c/build.py` remain the
specification, and the refusal partition means a later increment empties a
named cell rather than discovering one.
