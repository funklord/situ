# 26.811: An argued member inside a `positional` or `authenticated` block

Status: recorded
Date: 2026-11-02
Source: 0068's open list

    struct pos { u16 block; positional { note(mode = 1) k; u8 z; }
                 entry(block = block) e; u8 after; }
    struct au  { u16 block; authenticated { entry(block = block) e;
                 u8 after; } tag u8[16] covers(authenticated); }

Both blocks hold the struct's own members, placed as though the block
were not there. One asserts staticness and the other marks what a tag
covers. A member inside one reaches every backend, both walkers and the
dissector as an ordinary member of the struct, so steps 2 to 4 already
built it. Only the refusal had to move: `check_parameter_nesting` now
admits `wellformed._transparent_members` beside a struct's own members
and its arms' members.

A sealed or coded region's interior is a transform's input rather than
bytes on the wire, and stays refused.

## Tests

`test_a_block_s_member_takes_its_arguments.py`: five messages over both
blocks, the four backends and both walkers to one verdict, the dissector
against the walker, and a sealed interior still refused. With the
refusal restored, the agreement test fails.
