# 26.1028: a wide peek is held by the reader

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**Matroska's eight-byte Cluster could not be built.** `wide_cluster`
peeks all eight bytes of an EBML size -- all ones is a Cluster of unknown
size, anything else one whose size is stated -- and every arm was refused:
"a peeked 64-bit discriminant, and this writer checks the top of an arm's
first byte against the case it was called for". Bytes beginning with
another arm's case are a valid message of THAT arm, so the check is
needed; it just cannot be made from the first byte.

**The whole message can make it.** Once written, the reader's own getter
for the peeked discriminant is asked, and must say this arm's case -- or,
for the default arm, none of the named ones. Any width, any offset, any
encoding the reader knows, and no second derivation of how the peek
reads. The first-byte test stays for a discriminant that fits in the
arm's first byte. C only: the other three refuse such an arm.

**Measured**: a Cluster holding one Timestamp element (`E7 81 00`) with
its size as an eight-byte EBML number is built; and on an inline schema
whose two arms hold the same struct, `01 02` handed to the default arm's
builder is refused, which it is not with the getter check removed -- the
one case in which nothing else refuses it. The refusal message is gone,
and so is its row in the table of refusal claims.
