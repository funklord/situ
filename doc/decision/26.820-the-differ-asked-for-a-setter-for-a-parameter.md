# 26.820: the differ asked for a setter for a `parameter`

Status: recorded -- fixed; the other half is 26.818
Date: 2026-11-03
Source: `project.md` section 26

**26.818 was half a fix and the half that was missing is the one that
made the bug invisible.** The emitter wrote a stale-marking setter for a
`parameter` -- storing at a nested member's base, which is the first byte
of the member after it -- and `differ.writes` asked the four-way drivers
to call it. Both carried the same omission, so the drivers agreed, the
differential was green, and the write landed on the wrong byte in all of
them at once.

It surfaced the moment one half was fixed:

    error: implicit declaration of function 'situ_au_e_block_set';
           did you mean 'situ_au_block_set'?
      in c_driver.c, from test_a_block_s_member_takes_its_arguments.py

`au` is 26.811's construct -- `struct au { u16 block; authenticated {
entry(block = block) e; u8 after; } tag ... }` -- and `entry`'s `block` is
`parameter u16 block [stream]`. So the driver was writing a parameter,
through a transparent block, into whatever byte the base pointed at.

## The fix

`differ.writes` has two enumerations and the covered one needed 26.818's
two carve-outs, stated the same way: a `parameter` is not a field, and a
nested member's interior at a dynamic offset is addressed by that
member's own type rather than by the parent. The second loop already
carried the special case for a run's element (`"[]" in placement.path`,
invariant 74) and for a sealed interior, which is the same rule twice over
in narrower form.

**The test for the carve-out is the member's TYPE, not its path
component.** Written first as "does any path component name a struct",
which finds nothing: `au.e.block` has components `e` and `block`, and the
type is `entry`. It has to find `au.e` among the struct's entries and ask
what `type_name` that placement holds.

## Verified

- Over the 46 corpus schemas the differ asks 497 writes before the change
  and 497 after, so the carve-outs remove nothing the corpus had -- `au`
  is declared in a test file. Every one of those asks has a setter the C
  header defines.
- `test_six_readers_agree` passes, which is the test that found it.

## The gate, and what it does not cover

`test_the_differ_asks_for_setters_that_exist.py` compares the two sets
over every corpus schema: every write the differ asks for must be a
setter C defines, because a driver calling a function nothing defines
does not compile.

**It is vacuous for the construct that produced this**, measured by
reverting the carve-out and watching it stay green: `au` is not in the
corpus. That is written into the test's own docstring rather than left
for a reader to discover, and the construct stays covered where it
already was.

Two things the gate needed that are worth carrying:

- **Ask the driver's own question.** Written first over
  `resolved.structs.values()` with the name built by an f-string, it
  reported every register in `example/register` as missing a setter --
  an MMIO register's accessors take a `volatile uint8_t *` and are not in
  the write pass at all. The driver uses `differ.structs_of` and `ident`,
  so the gate must. **A test that asks a different question from the
  thing it checks is the fault it is checking for.**
- **Assert it is not comparing two empty sets**, which the comparison
  itself cannot tell.

## The lens

**A fix to one of two places that agree makes a silent fault loud, and
that is the fix working.** The implicit declaration looked like a
regression from 26.818 and was the first honest signal the pair had ever
produced. So when a change to one side of a duplicated question breaks
something, the question to ask is not "what did I break" but "what was
this agreeing about" -- and the answer here was a write to a byte that
belongs to another member.

It is also the fourth consumer this run that was wrong and silent about
the same lifted rule -- two test files asserting a refusal rule 5 allows
(26.815, 9b5295f and this run's `test_a_parent_hands_its_child_an_argument`),
the walker test that could not acquire an argued struct, and this. The
instruction that keeps earning its place: **ask every consumer, not the
one that failed.**
