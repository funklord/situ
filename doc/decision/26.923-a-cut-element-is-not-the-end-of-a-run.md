# 26.923: a cut element is not the end of a run

Status: recorded
Date: 2026-11-07
Source: a split between the walkers on `example/hpack`, and a verdict by hand

**All six readers passed a message with bytes missing.** With `e { uvar v; }`,

    struct r4 { u8 n; e es[n]; u8 last; }

`01 ff` declares one element, cuts it, and has no `last`, and every reader said
whole. It is on the pushed tree as well. A varint the frame cuts short measures zero
(26.920), so the element's extent was zero, and every walk read zero as the end of
the run and stopped before the element's own validation.

Nothing could see it. The six agree, and the differential compares them. It surfaced
because `field` in `example/hpack` reached it by a different route in each walker,
and the one split was then computed by hand.

**A zero means the frame fell short, unless the element can be empty.**
`traverse.never_empty` asks for a minimum above zero: eight sites in the four
emitters and four in the walkers. `nothing es[n]` stays what it was, and is the
control.

**That control found two more.** The C walker divided by a zero element width, which
is SIGFPE, and C held `nothing es[5]` to five bytes of frame, where the other three
hold it to none.
