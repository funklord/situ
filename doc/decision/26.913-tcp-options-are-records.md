# 26.913: TCP options are records

Status: recorded
Date: 2026-11-06
Source: the lens 26.912 left, a limit written down and not tried

**`example/tcp` left its options as bytes, saying a `tlv` would have to lie.**
That is true of `tlv`: End of Option List and No-Operation have no length, so
"skip it by its length" has two exceptions. It was never true of a run of
records whose arms say which kinds carry a length, and `[holds]` (26.898) gives
that run the bytes `data_offset` names:

    u8 options[(data_offset - 5) * 4] [holds = option_list];

**One rule stood in the way, wider than its reason.** `[holds]` was refused in
anything but a direct member, because a parent reaches the run through a view
accessor and an arm or a coded region has none. A transparent block has one:
`authenticated` and `positional` assert something over members that stay the
struct's own (section 9.2). TCP's options are inside the checksum's block, so
the refusal took exactly the shape a checksummed header needs. The refusal of an
arm stands, and stays pinned. No backend or walker changed: all four and both
walkers read a held run in such a block, by the verdict table in
`test_a_run_of_bytes_holds_a_struct.py`.

**Measured against tshark.** `test_tcp_options_read_as_records.py` holds a SYN
to that tool's decode, through `text2pcap -i 6`: kinds, lengths, MSS 1460,
window shift 7, timestamp 123456. An option claiming past `data_offset`'s bytes
is refused with a payload behind it, and a length under 2 is refused.

**Not fixed: a write through a child view does not stale the parent's
checksum.** `options_view` returns an `option_list`, and its members' setters
know nothing of the checksum around them, where the parent's own setters mark
it. Measured, a plain nested `inner i` in such a block does the same in Python,
so `[holds]` adds a door to an existing room rather than a new one. It is the
question 26.438 left about a parent and a nested tag, from the other side.

`example/ipv4` left its options as bytes too and has RFC 791's same grammar, so
it takes the same shape, held to tshark over Router Alert and Record Route.

**That found a fault in the dissector.** `_extent_functions` orders Lua's
`local function`s by what a struct's own members name, and reads no arms, so
`ipv4_option_extent` came before the `sized_option_extent` its arm calls, and
died as a nil call on the first packet. `tcp_option` had worked only because of
how its name sorts. It now waits on arms, and on nothing recursive, which has no
extent. Over 38 corpus dissectors, old against new, only `modbus` and `mqtt`
move, and those two only reorder.

The search for that shape found a second one beside it. The loop emitting a
run's span read own members too, so a run held directly in an arm called a
function nothing defined, on the first packet taking that arm. No corpus schema
has one. `test_a_member_after_an_arm_is_found` fails without the fix.

**And in a test.** `test_the_canonical_ipv4_header_comes_out_byte_for_byte`
passed a three-byte array with a length of four. The builder now checks what a
run holds, so the stray fourth byte became an option claiming past its bytes and
the build was refused. The array is four bytes and the expected output is as
it was.

Padding after End of Option List reads as more of them, since 3.1 says it is
zero. A sender padding with anything else is read as further options.
