# 26.1027: a tag in bits is stored by its reader

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**A USB token could not be built**, nor an SD card command: "`crc` is a
5-bit tag, and the runtime stores 8, 16, 32 and 64". Both carry a CRC
packed into bits beside other fields -- USB's five bits after a seven-bit
address and a four-bit endpoint, the MMC command's seven bits below a stop
bit.

**The reader already writes it.** For a tag a codec computes, every reader
emits `_store`, which puts a value where the tag's accessor reads it, bits
and all (0046). So C's builder writes the packed group with the tag's bits
zero and no caller value, then -- the message whole -- computes the tag,
stores it through the reader and checks it, the same compute, store, check
26.622 settled for a tag in whole words. A tag over a pseudo-header, or
whole bytes the runtime has no word for (a CRC-24), keeps its refusal. C
only: the other three refuse the part.

**Measured against two things that are not situ**: every USB address with
endpoints 0, 1, 5 and 15 matches a CRC5 written in the test from USB 2.0
section 8.3.5.1, SETUP to device 0 endpoint 0 is `2D 00 10`, and SD CMD0
is `40 00 00 00 00 95`. A 24-bit tag is still refused, which keeps that
refusal's message reachable.
