# 26.1108: a terminated run's framing asks for the terminator without wrapping

Status: recorded
Date: 2026-11-19
Source: the cppcheck lens after 26.1107 -- ten `have < pos` "always false"
findings, one shape

**Each element of a terminated run of records is framed behind two
guards**: `if (have < pos + 1u)` before the terminator is looked for, and
`if (have < pos)` before the element's own `required` is asked. With `pos`
unchanged between them, the second cannot be true -- unless the first
wrapped. `pos` saturates at `UINT32_MAX`, `pos + 1u` past it is small, and
the second guard is what caught that: a deliberate second defence, which a
static analyser reads as dead.

## The change

The terminator's guard asks for its room in a form that cannot wrap,
`have < pos || have - pos < len`, which holds `have >= pos` on its own; the
second guard is then a question already answered, and is not emitted.

## Measured

Over the corpus the ten `have < pos` findings go; the framing tests pass.
