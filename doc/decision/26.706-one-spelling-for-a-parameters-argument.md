# 26.706: one spelling for a parameter's argument

Status: recorded -- fixed in all four backends; 26.705's first family
closed
Date: 2026-10-27
Source: `project.md` section 26

26.705 reproduced two name-collision families and recorded both rather
than guessing, because each had two viable designs. The copyright holder
settled the first: **prefix the argument everywhere, like C does.** This
is that change, what it cost, and the four places it was not where
anybody would look.

## The premise that was false

`traverse.argument_name` prefixed C's argument and said in as many words
why the others did not need to: *"they put the value on the view object,
where a schema's name cannot collide with anything, while C has no such
object."* The view object is exactly where it collides.

Of 28 backend-and-name pairs -- seven names declared as `parameter u8
<name> [stream]` sizing a run -- seven did not build:

    bytes   rust  error[E0415]  identifier bound more than once
    data    rust  error[E0415]  -- and python SyntaxError
    have    rust  error[E0308]  mismatched types, through a local
    cls     python  SyntaxError  duplicate argument in function definition
    msg     python  SyntaxError
    offset  python  SyntaxError

`parameter u8 bytes` is the one to read twice. Rust's view holds the
message in a field called `bytes`, so the struct declared `bytes` twice
and `self.bytes` was the slice on one line and a `u8` on the next --
inside the expression that sizes a run. Python's four are the
generator's own function parameters, and a duplicate there is a
`SyntaxError`: the module does not import, which is the one failure
Python cannot defer to a call. **Three of the four and not all four are
`at`'s** -- `at(cls, msg, offset, length, *, <name>)` takes `cls`, `msg`
and `offset`, while `data` collides one method further on, in
`required(cls, data: bytes | bytearray | memoryview, *, data)`. The
first version of this entry said all four were `at`'s; 26.705 had it
right and the summary of it did not.

**And `at`'s fourth local falsifies the population 26.705 claimed.**
`parameter u8 length` fails Python on the committed compiler with the
same `SyntaxError`, so that entry's "these seven are the whole
population for those two backends" is wrong -- at least eight. What
makes it not matter is the design the holder chose: a prefix closes the
class without anybody having to know its membership, where a reserved
set per backend would have been maintained against exactly this list.

After the change all 28 build. The control was run against `git archive
HEAD` rather than by reverting in place, so the failing set above is a
measurement of the committed compiler and not of a patched one.

## 205 bare spellings, and the four that looked like the population

Each backend has an obvious place where the argument is named -- a
signature helper, a field declaration -- and prefixing those four left
**205 bare spellings**, counted by a scratch sweep over the four
backends and nine `situc build` modes: the default, `--materialize`,
`--owned`, `--messages`, and `--layer` for each of `edit`, `frame`,
`relate`, `converse` and `drive`.

**That 205 is not reproducible from this tree and a later reader should
not try.** It counts an intermediate state that was never committed --
the four helpers prefixed and nothing else -- so it is a note on how the
work went rather than a measurement anybody can repeat. What is
reproducible is the test it became, and the figure to quote is that
one's: 41 cases, of which 31 fail against `git archive HEAD`.

The test keeps the sweep's shape and narrows its ground: a parameter
named `zzqq`, generated for all four backends across the `view`, `edit`
and `frame` layers -- `relate`, `converse` and `drive` emit the frame
layer beside their own files, so those three are reached through it --
with every token occurrence required to carry the prefix, Python read
through `ast` and the others through a comment scanner, because comments
legitimately name the schema's own `zzqq`.

Where the rest were:

- **The owned copy's field, in all four backends.** `--layer edit`
  declares a struct of plain fields and copies the argument in from the
  caller. C's was `block` while C's own argument was already `arg_block`,
  so C had carried the divergence all along.
- **The frame reader's field and its stored argument**, in Rust and
  Python.
- **A second count-read path in Rust and Python.** Its own comment said
  so: *"the second of the two spellings, which is where one of them gets
  missed"*. It was.

A test that generated one backend's view would have passed with every one
of those in place, which is the argument for sweeping rather than
asserting.

## The change collided with one of its own siblings

`cpp/frame.py` spelled the frame reader's member `arg_<name>_` and took
the constructor's parameter from `_argument_local`, which was `<name>_`.
Once `_argument_local` became `arg_<name>_` the member would have been
initialised from itself. Its docstring had explained the trailing
underscore by saying every member of that reader ends in one -- a reason
that held only while the argument went unprefixed.

Resolved by giving it the shape `class s` already uses: member
`arg_<name>`, parameter `arg_<name>_`. Caught by
`test_every_schema_frame_layer_compiles`, which exists because three of
the four frame layers were once generated and never built.

## The prefix goes on before the sanitiser, not after

Each backend has an identifier sanitiser and they do not agree, so the
prefix is applied to the schema's raw name and the sanitiser runs on the
result. **The other order was written first and is wrong**: it produced
Rust `arg_r#fn` for `parameter u8 fn`, which is not an identifier at all,
`_ident` having escaped the keyword as `r#fn` before the prefix landed in
front of the escape. It compiled for `blk` and for every name in the
collision population, so nothing in those 28 cells could see it; it was
found by asking what a keyword-named parameter does.

Prefixed first, `arg_` plus anything is a keyword in none of the four
languages, so no escape is called for and none is applied. Six keyword
names -- `class`, `fn`, `match`, `type`, `new`, `int` -- build in all
four backends, 24 of 24.

**And it retires a reserved identifier that predates the prefix.** For
`parameter u8 class`, C++ spelled the FUNCTION-LOCAL `class__`:
`bare_name` suffixed the keyword to `class_` and `_argument_local` added
its own underscore. Two underscores anywhere in an identifier are
reserved to the implementation. It appeared 67 times across the layers
-- in `at`, in the view's constructor, in `framed_from`, and as the
frame reader's constructor parameter -- and it compiled under
`-pedantic-errors -Werror`, which is why it had never been noticed. The
pair is `arg_class` and `arg_class_` now.

**Said carefully because the first version of this entry said it wrong**,
calling `class__` the frame reader's MEMBER. It was not: that member was
`arg_class_`, with one underscore, and the view class's was `class_`.
`class__` is a parameter spelling throughout. `traverse.py` carried a
third version of the same slip, `arg_class__`, which was never emitted at
all. The reserved identifier is real and was none of those three.

## The hazard the prefix created, and why it is a front-end refusal

`u8 arg_n;` beside `parameter u8 n;` is now two members under one
generated name, and **this schema compiled everywhere before the
change**. Afterwards there were three answers to one schema, measured:

    C++     error: 'arg_blk' conflicts with a previous declaration
    Python  refused by 0062's parse of the emitted module
    C       unaffected -- prefixed free functions, their own namespace
    Rust    COMPILES -- a field and a method of one name, legal there

Rust is why this is refused rather than left. A compile error is a bad
answer and a silent one is worse, and the two spellings there mean
different members while reading as one member with two values.

`check_parameters` refuses it at the schema line, for all four backends,
keyed on **the spelling of an argument this struct actually declares**
rather than on the prefix: `arg_blk` is an ordinary member name in a
struct that takes no `blk`, and a struct that takes one may still have an
`arg_other`. Both controls are asserted. The refusal walks arms as well,
since `struct.members` has a hole in it where arms are (26.432).

## What it cost, measured

**The corpus changes in one struct.** Every `.situ` in the tree generated
for all four backends, before and after: `test/schema/edges.situ`'s
`negotiated` differs in C++, Rust and Python, and nothing else differs
anywhere. `negotiated` is the only struct in the tree declaring a
`parameter`.

**C's output is byte-identical, and the first reason given for that was
wrong.** It said the sweep does not pass `--owned`, which implies
`--owned` would have shown a difference. It does not: `situc build
--target c --owned` on `edges.situ` is identical between the two trees,
because situc refuses an owned form for `negotiated` -- *its size is
decided by the data, so an owned struct would need a pointer or a
worst-case array* -- so there is no owned struct for the changed field
to be in. C's `edit.py` change shows on a minimal parameterised schema
at `--layer edit` (`uint8_t blk;` becoming `uint8_t arg_blk;`) and on no
schema in this corpus. Re-measured at the `drive` rung, which emits
every rung below it: still only `edges.situ`, and C still identical.

**No other EMITTER spells it.** Every emitter was run on `edges.situ`
before and after -- `gen-codec-tests`, `gen-tamper`, `gen-checks`,
`gen-dissector`, `gen-fuzz` for two targets, `gen-derived` for three,
`doc`, `map`, `wire`, `explain`, `advise` -- and every output is
identical. Non-vacuous: each produced between 12 KB and 517 KB for that
schema, and **six name a bare `block`** -- `doc` 8 times, `gen-dissector`
5, `map` 4, `wire` 3, `gen-checks` 2 and `gen-fuzz` once. All six are
right to, and each for its own reason: `doc`'s byte diagram and `map`'s
and `wire`'s member listings describe the schema, the dissector's
Wireshark preference is named for the author's own word, and the skip
messages in `gen-checks` and `gen-fuzz` quote the member they are
declining. None emits `arg_block`.

A seventh spelling is a false positive worth naming, because the obvious
grep finds it: `gen-derived` contains `block` once per target, in *"a
(8, 4) block code, systematic"* about extended Hamming. Not this
`block`. The first version of this entry said five and justified four.

**And one consumer did, which that sweep structurally could not reach.**
`situc verify` imports the generated Python and calls `at` with the
arguments `--arg` gave it, keyed by the schema's name:

    TypeError: frame.at() got an unexpected keyword argument 'n'

**It needs a vectors file, so a loop over the subcommands against a bare
schema never reaches it** -- the sweep above ran eleven emitters and
skipped this one for want of a second argument, which is the same hole
`gen-tests` sits in. The suite caught it, in
`test_verify_takes_the_argument_on_the_command_line`.

`verify` is now the one place the two spellings meet, deliberately:
`--arg` keeps the schema's name, because that is what the author wrote
and what the missing-argument refusal quotes back, and the keyword passed
to `at` is `traverse.argument_spelling(name, py_name)`. The call is
commented to say so, since a reader finding `--arg n=2` beside
`at(arg_n=2)` would otherwise read it as a bug.

**What went right is the diagnostic**, which said *"this is a fault in
situc, not a verdict on the bytes -- the vector may be perfectly good"*.
A command that reported this as a non-conforming vector would have sent
somebody to their own bytes for a fault in the compiler.

**The test's control is 31 of 41.** Copied unchanged into the `git
archive HEAD` export, the new module fails 31 and passes 10; on this
tree all 41 pass. The ten are the ones about C, which already prefixed:
its `view` and `frame` sweep cells, its cross-backend assertion, C++'s
`frame` cell, which also already prefixed, and the six keyword cases for
C.

The compile tests added to the other two backends: **Python 5 of 5**
fail there, and **Rust 4 of 7** -- the three keyword cases pass on the
committed tree, which they should, since `r#fn` is a valid identifier
and the fault the ordering introduced was only ever in a draft. An
earlier version of this entry said 13 of 17 and 4 of 4, both taken
before the keyword cases were added, and both left behind when they
were.

## What two independent audits found afterwards

Both ran read-only against the working tree and a `git archive HEAD`
export, and between them they found one defect in generated output, two
stale figures in this entry, one test that had gone vacuous, and two
pre-existing faults in the C backend. The figures are corrected in place
above; the rest is here.

**A comment in generated Rust named a field that no longer existed.** The
`// No n()` note that explains why a parameter has no accessor spelled
both the absent method and the present field from one variable, so when
the field became `arg_n` the comment went on saying

    // No blk(): `s.blk` is a parameter, so the field
    // `blk` above IS its value

and pointed a reader at `view.blk`, which does not compile. The two
spellings are genuinely different -- the method that is NOT emitted
carries the schema's name, because that is what a caller would have
typed, and the field that IS emitted carries the prefix -- so the fix is
to render them from different expressions. **It was the only bare
spelling left in any backend's output**, and the token sweep did not see
it because the sweep reads identifiers and this is a comment. C's and
C++'s equivalents name the schema member and are right as they stand;
Python emits nothing.

**README documented three of the four signatures bare**, which is the
surface a caller reads before writing a call. It now carries all four,
checked against the generated text.

**And a C++ test lost the power it was named for.** `test_an_argument_
does_not_collide_with_the_factory` sweeps seven names a schema may take
-- `owner`, `offset`, `length`, `out`, `data`, `have`, `need` -- and
asserted that the trailing underscore on the local is what keeps them
from the factory's own. Measured now, by generating each of the seven,
rewriting `arg_<name>_` to `arg_<name>` and compiling: **all seven
compile.** The prefix closes that hazard, so the underscore is a
convention against a confusing shadow rather than a defence, and the
test's own docstring says so. It is kept because the seven names are
still worth building, and the two docstrings that gave the underscore's
old reason -- `_argument_signature`'s and the factory test's -- say which
half survived.

**Seven more comments justified the absent accessor by the collision the
prefix removed**, in `rust/emit.py` twice more, `cpp/emit.py` twice,
`python/emit.py`, and two test docstrings. Each kept the load-bearing
half: a parameter occupies no bytes, so an accessor reads the member
AFTER it. Python's had a second real reason that is also gone -- a
property is a data descriptor, so `view.n = n` in `at` would have raised,
and a property `n` beside `arg_n` shadows nothing.

**26.395 and 26.398 are superseded in part by this entry and are not
edited.** 26.398's title *is* the retired reason -- *a field and a method
of one name, where the field is right* -- and 26.395 gives it as why
Rust's field is public. Both were accurate when accepted; the field is
`arg_n` now and the two names are distinct, while the reason that
survives in both is the wrong byte. A record is not edited once accepted,
so the pointer is here.

## Two faults in the C backend that this did not cause

Found by the same audit, reproduced against `git archive HEAD` with
identical output, so neither is this change's and neither is fixed here.
Both are the shape `edges.situ:1942` already names -- a parameter
reaching a function that does not take it -- and both are invisible to
the suite because `negotiated` is the tree's only parameterised struct
and carries no tag and no vectors file.

**`gen-tests` emits C that does not compile.**
`situc/codegen/c/vectors.py` emits a second artifact over a schema, which
is `refuse_parameters`' whole population, and does not call it. Three
generators do -- `c/fuzz.py`, `c/tamper.py` and `c/checks.py` -- and the
function's own docstring names seven, listing the differ and the three
`derived` emitters besides. Those four decline by other means or say they
read no member and so need none, so **the list is stale in the one place
that exists to be the single copy of this refusal**, and `vectors.py` is
missing from both the list and the code. Reproduced with a one-vector
file over `parameter u8 blk`:

    assert_int_equal(situ_s_validate(view), SITU_OK);
    situ_s_blk_set(&msg, view, situ_s_blk_get(view));

    error: too few arguments to function 'situ_s_validate'

`validate` takes `(view, arg_blk)`, and `situ_s_blk_get`/`_set` are
accessors the backend deliberately does not emit for a parameter.

**A tag's covered span drops the argument tail.** `c/emit.py`'s
`_covered` and `_check` signatures are fixed strings while the span
expressions they contain can name `arg_<n>`:

    struct s { parameter u8 blk [stream];
               authenticated body { u8 payload[blk]; }
               checksum u8 sig[2] covers(body); }

    static inline situ_err_t situ_s_sig_covered(situ_view_t view,
            uint32_t *offset, uint32_t *len)
    ...
    error: 'arg_blk' undeclared

C alone; C++, Rust and Python take the same schema. The fix in both is
`self._argument_tail(struct)` on the signature, which the offset accessor
beside them already carries.

## What is not closed

26.705's **second** family stands: a struct or enum whose own NAME is a
C++ keyword produces non-compiling C++, because `class_name` renames a
class a member has taken and never consults `KEYWORDS`. That is a
different decision -- it is about a type name, where this was about an
argument -- and the instruction settled this one.
