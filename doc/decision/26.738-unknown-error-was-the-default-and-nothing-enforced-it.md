# 26.738: `unknown = error` was the default, and nothing enforced it

Status: recorded -- fixed in all four backends; both walkers decline
Date: 2026-10-29
Source: `project.md` section 26

Found while fixing 26.737. Section 14.5 says "Unknown TLV tags are rejected
by default", and `ast.Tlv` defaults `unknown` to `error` for the reason it
gives: an unknown tag is a malleability surface. Measured with

    known = { 1 : { name = mtu, type = u8 } }      // no `unknown` clause

an item tagged 2 validated clean in all four backends. The policy reached
the capability map, where `preserve` makes a region non-canonical, and
reached nothing that reads a message.

## The reading this needed, and the decision

`unknown` is defined relative to `known`. A region that declares no tags
-- CoAP's options in `edges.situ`, sized by a nibble of each tag -- says
nothing about which tags exist, so none of its items is unknown. Read the
other way, the default would refuse every item of every such region, which
no schema means. So **`unknown = error` refuses only where `known` names
something**. `skip` and `preserve` admit what they do not know, by
definition. `traverse.tlv_admitted_tags` is the predicate, asked by all
four emitters and by the packer.

The tag is matched on the part decision 0023 names (`tag_identity`), as
`find` matches it, and on the raw tag where there is none. The test's
`numbered` region is the case that tells them apart: CoAP option number 3
arrives with a raw tag of 0x21.

## The fix

Each backend's `_whole` (26.737) refuses, with CONSTRAINT, an item whose
identity is not one `known` names. It is the same walk, so a message is
read once.

## The walkers decline, and why that is the answer for now

The packed image carries neither the `known` tags nor the program for the
identity part, so a walker cannot enforce the policy. Answering OK, as
both did, is the confident wrong answer 26.733 says a reader must not
give. So the TLV row's flags byte gains bit 1, "names `known` tags and
refuses every other", and both validators return `cannot-say` for such a
region. Bit 0 is the ordering rule and was not documented anywhere; both
bits are described where the packer sets them now.

Carrying the tags and the identity program would let the walkers enforce
the policy. That is a format change of the 26.343 kind, and it is left
open rather than folded into this fix.

Also measured, not changed: the walkers decline every region of the simple
`length_type` form whatever its policy, because the image carries no
selector for it. That predates this, and it is why the walker test's
policy case uses the selector form.

## Not yet looked at

`duplicate_tags` also defaults to `error` (14.5, `ast.Tlv`), and nothing
suggests anything enforces it either. Measure it before assuming.

## Verified

`test/unit/test_a_tlv_region_is_validated.py` gains six cases over four
regions -- strict, `skip`, and the same pair matched on `tag_identity` --
asserting the exact verdict in all four backends, and `cannot-say` from
both walkers wherever the region refuses. Controls: with the change
stashed, the four answer `validate 0` for "numbers 1 and 3, only 3
known", and each walker's test fails with its own half stashed.
