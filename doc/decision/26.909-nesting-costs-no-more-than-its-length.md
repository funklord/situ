# 26.909: Nesting costs no more than its length

Status: recorded
Date: 2026-11-06
Source: a libFuzzer timeout on `example/json`, 20 bytes saved as a 3-second hang

A generated validator took time exponential in nesting on input somebody chose.
`[` repeated and a cut string: 8 levels 0.005s, 14 levels 8.6s in C, and 10
levels 3.0s in C++. `[depth = 64]` bounded the stack and not the work, so about
thirty levels never returned. Both walkers had it too behind their default
ceiling of eight: raised, as the note on `WALK_DEPTH_MAX` tells a host tool
reading deep JSON to do, they went the same way.

- Why it multiplied. A level measured its child more than once. An extent summed
  terms that each found their own base by measuring what was in front of them,
  a `while` condition's getter measured the element just measured, and a length,
  discriminant, count or argument read behind the recursion did the same from
  inside the sum. Each dropped to the plain form at depth zero as well, so the
  `[depth]` guard did not bound those.
- What changed in the four backends. `traverse.cursor_walk` says how to measure
  a recursive struct with something behind its recursion, and each backend's
  extent for such a struct is now statements: each member measured once from a
  cursor, the saturating arithmetic of the offset chain beside the plain sum
  `extent` always was, the depth carried. A struct with nothing behind its
  recursion is emitted as it was, so `example/json` is the one corpus schema
  whose output moved.
- A field read behind the recursion is recorded as the cursor passes it.
  `traverse.read_behind_recursion` names them, `_extent_marked_at` fills an array
  on the caller's stack, and a `while` walk reads the element from that. A field
  between two variable members needs no special case, which is why this is one
  mechanism and not the arithmetic from the element's end first proposed: that
  covers `sep` at the end of `element` and not `sep` with a member behind it.
  A helper reading such a field (a counted run's `_count`, what a member hands
  its child) has a `_marked` copy taking the array. A varint, a text number and
  a delimited arm find themselves through their offset, so each has `_from`
  copies of its accessors. Nothing allocates and no public signature moved.
- What changed in the walkers. Neither has a place for a cursor to live, since
  every read goes through `chain_bits`. So what each member measured is held for
  the length of a measurement, on the `View` in Python and on the stack of the
  walk in C, and a `while` walk keeps it for its condition. In Python it is
  dropped when `struct_extent` returns, because a write moves what it holds.
- What it costs. C holds the first 32 members of a struct, a member past that
  being measured each time it is asked for. A level of a C walk takes more
  stack; the note on `WALK_DEPTH_MAX` has the new figures, which it had not been
  keeping up with before this.
- Verdicts. 5689 old-against-new comparisons through the four backends, before
  the last edits here: no `validate` line moved, and at `[depth = 64]` nothing
  moved at all. At `[depth = 4]` 153 messages changed an accessor or `required`
  answer. 141 of them differ only where `validate` says 2, which is the plain
  form restarting the count, inferred to be past `[depth]` rather than shown to
  be; the other 12 were too slow on the old code to compare. sexpr, counted,
  delimited, member and between were not compared old against new, because two
  shards ran out of time, so `test_six_readers_agree_on_each_shape` holds them
  to each other and to both walkers instead. Walkers: 28 of 1272 pairs changed,
  each the C walker going from `cannot-say` to the Python walker's answer.
- A lead carries the depth. C's stride took it and the other three restarted
  the count, so past `[depth]` they found `sep` somewhere else. The test's lead
  shape found it, and a lead on a recursive member after a variable one did not
  compile in C before this.
- A delimited arm behind a variable member ran the Python walker to the end of
  the stack on a one-level message: the arm scans from its offset, and the offset
  summed the variant, which asked for the arm. An arm starts where its variant
  does, and `chain_bits` now says so.
- `cannot-say` near the bound stays. `variant_bits` spends a level per hop to
  bound a malformed image and says so, so where an arm recurses the C walker
  stops around half of `[depth]`. It is not a contradiction: the test holds two
  answers to each other and lets either walker decline.
- What is left at n^3. A validator asks each level for its nesting, and that
  walks every level beneath it, so where nesting grows with the message 2n costs
  about 7 times n. `[depth]` is what stops that, at n * depth^2. Asking once at
  the top would take it to n^2, but an inner view is narrower than the outer one
  and nothing here shows the two nesting answers are the same, so that was left.
- Declined. A memo in the view for the generated code: `situ_view_t` is passed
  by value and is public. Fixing the cost per message with a work budget: a
  verdict that depends on a counter is a new refusal.
- What the test's shapes found that nothing had built. A `while` over a varint
  or an enum behind a variable member crashed the C++ build and did not compile
  in Rust: the condition knew scalars at a constant offset. `pad_to` behind a
  recursive member had no extent in C++, Rust or Python, and in C the cursor
  added zero for it, so the extent left the padding out of the sum its own `at`
  had moved past: a pad's length is now `at`'s distance to the next multiple, in
  all four. A fixed-width text number at a dynamic offset had no `_value` in
  Python. A `while` field the frame cuts ended the run in the four backends and
  refused the run in the Python walker, which then passed the cut message; it
  ends the run there too.
- Not shown to be polynomial. A struct with a pad arm: `cursor_walk` answers None
  for one, and behind a recursive member it does not build in C and crashes in
  Python, as it did before this. A struct of more than 32 members in the C
  walker, which measures a member past that each time it is asked. tlv, indexed,
  coded and sealed regions behind recursion, which were not measured. The Python
  walker is about n^3 and is measured at 15 and 30 levels, sixty being over the
  test's budget under a profiler.
