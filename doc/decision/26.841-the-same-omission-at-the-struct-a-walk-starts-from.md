# 26.841: the same omission at the struct a walk starts from

Status: recorded -- fixed; the mechanism of discovery is now three for

Date: 2026-11-03
Source: `test_walker_c.py::test_they_agree_about_the_corpus_being_well_formed`
on `edges.situ`, after 26.839 added `arm_holder` to it

## Both walkers had it, and each cited the other as the reason

This is the part worth the entry. The C walker's entry check read the
struct row's `size_bits` and skipped every variable struct. So did the
Python walker's -- and its comment said why:

> `size_bits` is `NONE` for a variable struct, which is the C walker's own
> condition: the image does not carry a minimum for one, so neither reader
> checks it and the four backends -- which have `SIZE_MIN` from the
> compiler -- can still refuse where these two cannot.

**That was true when written and became false at 26.577**, when the image
grew `size_min_bits`. The sentence was never revisited, and the C walker
had no comment at all -- so one reader's gap was documented as a
consequence of the other's, and the other's was simply there.

Two readers agreeing because each had copied the other's gap is the one
way a differential can be silent about a fault both sides share. It is
also why the compiled accessors are the tiebreaker and not the pair:

    keystore needs at least 87 bytes; 46 given

over the frame where the C walker said BOUNDS (correct, after this fix)
and the Python walker said CONSTRAINT.

**So fixing one of a pair of readers made the pair disagree, and that is
the fix working.** The sequence is worth keeping: the C side went first,
the differential went red on `keystore`, the accessor settled which side
was right, and the Python side followed. A differential that goes red
after a fix is not evidence the fix was wrong.

## The finding, in four lines

`edges.keywords` is ten bytes of fixed members and then
`u8 body[class + 1]`, so it needs eleven. Over an eight-byte frame the
Python walk refuses on acquisition and the C walk reported the message
**well formed**, having answered for the members that happened to fit.

The entry check reads the struct row's `size_bits`, which is `NONE` for
any variable struct, so it skipped every one of them. The row's
`size_min_bits` is what applies there, and it reads that now when the
fixed size is absent.

The comment above that check already said what it was for -- "Without it
the two agreed about every well-formed message and disagreed about short
ones, C answering for the members that happened to fit" -- and it was true
of the fixed case it covered. 26.837 gave the C walker the same number for
a NESTED struct's minimum; this is the identical omission one level up, at
the struct a walk starts from. The number has been in the image since
26.577 and the Python walker was its only reader.

That makes four fixes in one day whose shape is "correct for the case that
produced it, absent for the class", and the lesson is 26.837's rather than
a new one.

## What IS new: three for three on resampling

Every corpus addition this session has resampled
`test_walker_c.py`'s seeded sweep and turned up a latent disagreement in
something unrelated:

| the addition | what it resampled into |
|---|---|
| 26.833's three marker structs | `blocked_arg.one` read five bytes where its width was four (26.837) |
| the same | a truncated `negotiated` walked into, answering VERSION where five readers answer BOUNDS (26.837) |
| 26.839's `arm_holder` | `keywords` well formed over a frame three bytes short, in C (this) |
| fixing that | `keystore` CONSTRAINT over a frame 41 bytes short, in Python (this) |

The sweep draws from a fixed seed against every struct in a schema, so
adding structs renumbers the shapes and changes which (struct, buffer)
pairs are asked at all. Three additions, three findings, none of them in
the construct that was being added.

**So the yield is not a coincidence and it is worth planning around.** A
corpus addition is a cheap lottery ticket on every latent disagreement the
old sample missed -- and the corollary is less comfortable: the sweep's
coverage of the schemas it has had all along is whatever one seed happened
to reach. Re-seeding it deliberately would find the rest, and is a change
to a shared harness rather than something to do while passing through.
Recorded here as the thing to weigh, not as a decision taken.
