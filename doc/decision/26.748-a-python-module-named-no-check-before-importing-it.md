# 26.748: A Python module named `NO_CHECK` before importing it

Status: recorded -- fixed
Date: 2026-10-29
Source: `project.md` section 26

The Python emitter built the module's import list first and its classes
after. One condition in that list -- `_names_a_member`, whether any struct
publishes check ids and so needs `NO_CHECK` -- asks `_check_groups`, and
a versioned member's check is emitted only where its getter already was
(26.74). Asked before any getter had been emitted, the answer was no; by
the time `validate` was generated it was yes. So the class said
`NO_CHECK = NO_CHECK` in a module that never imported it:

    struct s [version = ver] { u8 ver; u4 hi; u4 n; u16 run[2]; u16 tail;
                               u16 added [since = 2, must_eq = 4660]; }

    NameError: name 'NO_CHECK' is not defined

The arrangement where the early answer was wrong is a constraint behind a
`[since]` in a module where nothing else carries a check, which no corpus
schema has. The composed sweep reached it in every `packed`-driver cell
with the `constrained` version axis.

## The fix

`module()` generates the body first and builds the header from what the
body emitted. `_names_a_member` was already asked twice -- once for the
header and once in `validate` -- so this changes when, not how often.

`test_a_python_module_imports_what_it_names.py` imports the module of
that schema and fails with the old order.
