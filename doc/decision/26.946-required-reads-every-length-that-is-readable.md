# 26.946: `required` reads every length that is readable

Status: recorded
Date: 2026-11-09
Source: the copyright holder's answer to 26.693 -- "yes, required reads every readable length"

**`required` reads a length as soon as the bytes holding it have arrived.**
26.693 found that it reported a lower bound rising as bytes came in, so a
caller was told one figure, fetched it, and was told another; it asked
whether `required` should read every readable length so that the first
answer is the last. The holder answered yes.

## What was late, and why

Each backend guarded a length read with "the bytes before this member have
arrived" -- `have < pos`, the member's base. That is sufficient, since a
length field always precedes what it sizes, and the C emitter's docstring
recorded the cost as one more read. It is more than one when the length
field sits early in a fixed header:

    udp_header: u16 length at offset 4..6, payload at 8

    before   [0:8] [1:8] ... [5:8] [6:8]  [7:8]  [8:10] [9:10] [10:ok,10]
    after    [0:8] [1:8] ... [5:8] [6:10] [7:10] [8:10] [9:10] [10:ok,10]

The 26.693 example itself, `widelen { u32 len; u8 d[len]; u16 t; }`, had
already been mended: its length ends where its run begins, so the base
and the length's end coincide. udp, arp's four address runs, ipv4's
options, netlink's `nlattr`, BLE's AD structure, and ID3's extended header
were the shapes where they do not.

## What changed

`traverse.length_readable_from(struct, placement, structs)` answers how many
bytes a length needs: the end of the furthest field its expression names,
where every named field is a scalar at a static offset and the expression
calls nothing but `min`, `max` and `align_up`. It reads `size_expr`, or
`sized_by` where the length is a bare field name, which is how `u8 d[n]`
is held and how arp was missed on the first pass. Anything else answers
None and keeps the base.

All four emitters use it in the same place -- the guard before a sized
member that is not walked element by element -- so the four frame layers
still agree; `test_four_backends_frame_alike` compares them prefix by
prefix and passes.

## How it is held

`test_required_reads_a_length_once_it_arrives`, in
`test_required_over_the_corpus.py`, sweeps every `_required` in C over the
corpus: for each truncated prefix it sets the next byte to all 256 values,
each call in an allocation of exactly its own length and under ASan and
UBSan. If every value gives the same answer, the byte told `required`
nothing; if that answer still differs from the one before by more than
the single byte a delimiter or varint honestly asks for, a length was
readable and unread. A saturated answer is not counted, since the byte may
have mattered and the rest already pushed the length past a `u32`.

With `length_readable_from` stubbed to return None, arp, ipv4, netlink and
udp fail by name.

## A nested struct's own minimum

The same sweep found a second shape, which is a loose lower bound rather
than a length read late. The guard before a variable member answered
`at`, the fixed members only, so `record { u8 kind; stamp taken; str
name; }` was told 7 at six bytes and 9 at seven: `str`'s two bytes needed
no reading. `traverse.nested_floor` credits a single nested struct member
with `framing_floor` of its type in that guard, in all four backends. The
figure is never above what the nested struct's own `required` answers for
an empty buffer (`test_the_framing_floor_is_never_above_what_an_empty_
buffer_is_told`), so the answer after the guard cannot fall below it, and
the monotonicity sweeps pass. Stubbed to zero, importer and mqtt fail.
Five structs left `READS_LATE` with it: importer's `record`, MQTT's
CONNECT body, and `edges`' `holds_arg_only`, `oob_element` and `oob_run`.

## A counted run's count

A counted run of records is walked element by element from its base, so
its count went unread until the run began, though dnsname's four counts
sit in its twelve-byte header: an eleven-byte prefix of all `0xff` was told
12 and the next ask 262153. A counted run now takes the same early guard,
from where its count's fields end (`length_readable_from(...,
counted=True)`), and the walk's check before an element that has not begun
answers `at` plus each owed element's floor, `(count - n) * floor`, in all
four backends. The walk already credited the elements after a short one
the same way (26.724), so the figure is the one the walk reports a step
later and cannot be undercut by it. Stubbing the counted case out puts
dnsname back.

## A variant's arm

A variant is framed through the arm its discriminant selects, behind a
guard on the variant's base. `discriminant_readable_from` answers where
every field that chooses and measures the arm ends -- all of
`_sources_read`, not the discriminant alone -- and all four backends guard
there, outside the variant and inside its framing; Rust clamps the slice
it hands an arm, which would otherwise panic past the end. ID3's tag,
choosing its extended header by a flag ending at byte 6, was told 10 at
nine bytes and 16 at ten; it is told 16 from six.

The first version guarded on the discriminant alone, and ASan stopped it
on its first run: flac's arms are sized by `length`, three bytes past the
type, and the arm's framing read it from a one-byte buffer. The exact-size
allocations are what made that a crash rather than a wrong number.

## A `while` run's first element

A `while` run holds at least one element -- its condition is asked of an
element already read -- and its walk asks for that element's floor the
moment the run's base arrives. `nested_floor` owes it in the guard before
the run too: netlink's `attrs` was told 16 at fifteen bytes and 20 at
sixteen, and is told 20 from six. Netlink stays in `READS_LATE`, because
below six bytes the variant's guard answers and owes only its own member:
owing a later member's floor from an earlier guard would need every early
return inside the members between to owe it as well, or the answer could
fall. `test_a_while_run_owes_an_element` holds the fifteen-byte answer
directly, since the sweep cannot see a struct that is still late
elsewhere; stubbing the `while` case out fails it.

## What is left

Nine structs still learn something a round trip late, held in
`READS_LATE` with the branch each is framed by. The test fails if one stops
reading late, so the list can only shrink honestly:

- a run of records ending where the bytes say (flac's stream head),
  whose first element's length is readable before the walk can start;
- flac's metadata block, a variant with something read after its arm is
  chosen, and netlink's message below six bytes, where an earlier guard
  owes only its own member;
- lengths named by a varint or placed after one (SQLite's leaf cell,
  `edges.text_driver_moved`);
- `[since]` members (`edges.versioned`);
- nested structs the floor does not reach (`edges.chains`,
  `edges.hands_on`, and `edges.blocked_arg` inside an authenticated
  region).

One class is deliberately not counted: a delimiter scan or a varint
answering `have + 1`. The byte that arrives there does carry information;
the answer is the best one available until it does.
