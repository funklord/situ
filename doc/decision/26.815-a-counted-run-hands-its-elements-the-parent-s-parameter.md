# 26.815: a counted run hands its elements the parent's parameter

Status: recorded -- 0068 step 5's run half, built in C
Date: 2026-11-02
Source: `project.md` section 26; decision 0068 step 5

Step 5 of 0068 is a parent handing a child an argument of the parent's
own rather than a constant. `26.812` built it for a single nested member
and left the run half refused by `check_parameter_nesting`, because a run
multiplies the emitters: `_count`, `_at`, `_span_from`, `_span` and
`_fits` are five more signatures, and in C each is a trailing parameter
list rather than a field on a view.

    struct relays_on_runs {
            parameter u8  block [stream];
            u8            n [max = 4];
            negotiated(block = block)  counted[n];
            u8            after;
    }

## The fault, which is this week's fifth instance of one shape

**Two places answering one question from different text.** The run's
accessors asked `_member_reads_arguments` -- "does this member's length
expression name an argument" -- and the definitions were built from
other text entirely. Both are true statements about the member, and they
are not the same question.

It showed as the error count moving rather than falling. Widening the
shared predicate fixed `_one_view` and broke `_count`: a counted run's
`_count` reads the count field `n` and nothing else, so the wide
predicate's yes handed it a parameter it does not declare. Narrowing it
to the call site caused infinite recursion -- the predicate renders the
length expression, which renders the member call, which asks the
predicate. Both wrong fixes are recorded in `26.812` because both looked
right.

## What answers for both sides

`_hands_own_argument` asks one question and never calls the length
renderer: does the text handed to the child name one of this struct's
own arguments?

    def _hands_own_argument(self, struct, placement) -> bool:
            if not self._arguments(struct):
                    return False
            text = self._child_args(struct, placement)
            return any(re.search(rf"\b{self._argument_name(held)}\b", text)
                       for held in self._arguments(struct))

`_handed_tail` and `_handed_call` are that one predicate rendered as a
parameter list and as an argument list, so a signature and every call to
it read the same text by construction.

`_count` is the exception and needs four answers rather than one, because
its four branches are four different functions:

- a **literal** count is a `#define`, with no function and no call;
- `[remaining]` over elements of **one size** is a division, whose body
  names the argument only through `base` -- see `26.814`, a fault of the
  same shape in a branch where the element is not argued at all;
- `[remaining]` over elements with **no single size** is a walk, which
  hands each element its arguments;
- a **counted** run is an expression over the count field, which usually
  names nothing.

So the branch that emits the definition also records what to pass, and
the call site reads that rather than asking again.

## The sixth site, which the compiler found and reading had not

`check`'s call to a run's `_fits` predicate is emitted a long way from
the predicate's definition, and it passed a bare `view` while the line
below it passed the argument to `_span`:

    if (!situ_relays_on_runs_counted_fits(view)) {
    ...
    if (situ_remaining_u32(view.limit, 1u)
        < (situ_relays_on_runs_counted_span(view, arg_block))) {

Two adjacent lines of one emitted function disagreeing about the same
struct. `make test-c` caught it; nothing else would have.

## Verified

- `edges.situ` gained `relays_on_runs` (counted), `relays_on_fixed`
  (literal) and `relays_on_rest` (walked), so three of `_count`'s four
  branches are in the corpus and the fourth is `26.814`'s.
- All four backends generate them. The generated C and C++ compile under
  `-Wall -Wextra -Werror -Wconversion -Wsign-conversion`, and the
  generated Rust under `rustc -O`.
- **The bytes, read twice from independent emitters.** A 20-byte message
  at `block = 2` -- `n = 2`, two nine-byte `negotiated`, then `after` --
  read through C and through Python: the count, `_fits`, the span of 18,
  each element's `payload`, `trailer`, `checksum`, `kind` and arm `flag`,
  and `after` at offset 19. Both agree with the hand-laid bytes.
- `make style`, `make typecheck`, `make lint` and `make test-c` pass, and
  all 92 committed images match a fresh generation.

## What is still refused

`check_parameter_nesting` still refuses a member inside a `sealed` or
`coded` region and an `indexed` region's element, and a struct naming
itself. Those are 0068's remaining open ground.
