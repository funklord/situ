# 26.740: `duplicate_tags = error` was the default, and nothing enforced it

Status: recorded -- fixed in all four backends; both walkers decline
Date: 2026-10-29
Source: `project.md` section 26

Measured while recording 26.738, which named this as unexamined. 14.5 and
`ast.Tlv` make `duplicate_tags = error` the default, because a repeated
tag is a malleability surface: two items carrying the same field, of
which a reader takes one and a verifier perhaps the other. With
`known = { 1 : { name = mtu, type = u8 } }` and no `duplicate_tags`
clause, two items tagged 1 validated clean in all four backends.

## The reading, and the decision

The same one 26.738 took, for the same reason. **Only tags `known` names
are limited, and not those it marks repeated** (`type = u8[]`). A region
that names no tags says nothing about which may repeat; read literally,
the default would refuse CoAP's repeatable options in every region that
lists none. Tags outside `known` are refused outright under `unknown =
error` and unlimited under `skip` or `preserve`, which say nothing about
how many there are. `duplicate_tags = allowed` limits nothing.
`traverse.tlv_single_tags` is the predicate.

## The fix

Each backend's `_whole` keeps one counter per limited tag and refuses the
second occurrence with CONSTRAINT, in the same walk 26.737 and 26.738
use. The tag set is the schema's, so it is bounded, and nothing is
allocated -- C, C++ and Rust declare a local per tag.

The walkers decline, as for 26.738: bit 2 of the TLV row's flags marks a
region that limits a tag, and both validators return `cannot-say`.
`walker.image`'s set became `tlv_unenforceable`, since it no longer holds
only regions that refuse unknown tags.

26.738's walker test region declared `unknown = skip` and left
`duplicate_tags` at the default, so tag 3 became limited and the walkers
began declining a region whose verdict the test is there to see. It
declares `duplicate_tags = allowed` now.

## Verified

Five cases over two regions: once, twice, a repeated-declared tag twice,
an unknown tag twice under `skip`, and `allowed`. They assert the exact
verdict in all four backends and `cannot-say` from both walkers where a
tag is limited. Controls: with the change stashed the four answer
`validate 0` for "tag 1 twice". Python's mask set back from 6 to 2 makes
its walker answer where it must decline, and C's half stashed does the
same.
