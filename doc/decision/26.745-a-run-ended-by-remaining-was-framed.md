# 26.745: A run ended by `remaining` was framed

Status: recorded -- fixed
Date: 2026-10-29
Source: `project.md` section 26

`remaining` is how far the frame reaches. `required` is asked of a prefix
of a stream, where the frame's end is the very thing being asked, so a
struct whose length depends on `remaining` cannot be framed from a prefix
at all. `traverse.frameable` refused a `[remaining]` member by other routes
and had no case for `remaining` inside an expression:

    struct hops {
        hop  step[] while (remaining > 4);
        u16  trail;
        u16  mark;
    }

The run ends four bytes before the frame does. On a prefix the frame IS
the prefix, so the run stopped four bytes before the prefix ended and
`trail` and `mark` were counted on top. **All four backends called a
message complete at 8 bytes where it is 12** -- and at 48 where it is 52,
and at 964 where it is 968: always short, which is the direction in which
a caller parses past what it was handed.

## How it was found

By a witness that shares nothing with the four. The corpus differential
compares them with each other, and all four ask `frameable`, so they agreed.
`test_required_against_the_walker.py` draws buffers, keeps those Python's
`validate` accepts, and holds `required` against the walker's
`struct_extent` over the whole buffer: complete at fewer bytes than the
walker measures, or complete one byte short of it, is a failure. Over the
corpus at 200 draws a struct, 18,298 buffers validated, and `hops` was the
only struct `required` answered short -- 96 times.

Asking for MORE than the walker measures is allowed and common, and the
test does not refuse it: a JSON number or an S-expression symbol ends at
a byte that has not arrived when the message fills the buffer exactly.

## The fix

`frameable` refuses a variable member whose `repeat_while` or `size_expr`
names `remaining`. **And C++, Rust and Python now ask it.** Only C's
`_required` asked `frameable` about the struct itself (26.729); the other
three applied their own conditions, which had matched it over the corpus
until this case, so they went on framing `hops` while C declined -- caught
by `test_the_differential_frames.py`, which holds each backend's emitted
set to the drivers'. `hops` has no `required` in any backend now, nor a
Reader in the frame layer, and the drivers frame 221 structs where they
framed 222.

The test fails with the change removed, on `hops` and nothing else.

## What the same instrument showed and this does not fix

`edges.versioned` validates at 8 bytes with `ver = 91`, where its version
says `extra` is carried and the frame holds only one of its two bytes --
in all four backends and both walkers. `required` and the walker both say
9. The accessor tells the cases apart (`SITU_ERR_VERSION` for a message
older than the field, `SITU_ERR_BOUNDS` for one that claims it and is
short); `check` tests only the struct's minimum. That is 26.746.
