# 26.782: `[remaining]` in an arm must be last in its frame

Status: recorded -- fixed
Date: 2026-10-31
Source: found while walking the run shapes 26.779 left (26.781)

    struct S { u8 k;
               variant v switch (k) { case 1: piece recs[remaining];
                                      default: u8 one; }
               u16 z; }

Section 8.5 says a `[remaining]` run must be the last member of its
frame, since a member after it has no bytes to occupy, and
`layout.array_extent` refuses `u8 rest[remaining]; u8 z;`. The variant
above was accepted. Each arm is placed as a list of one, so its member
was always the last of that list, and the run swallowed the bytes `z`
was to occupy. No backend measured the arm, so nothing noticed: `z` was
placed by nothing, and the walk 26.779 added for a run in an arm skips
`[remaining]`.

## The change

`place_members` takes `last_in_frame` and hands it to `place_variant`
and `arm_extent`, so an arm's member is last only where the variant is.
The default keeps every other caller as it was. The corpus has no such
arm and generates byte-identically.

## Tests

`test_layout.py::test_nothing_may_follow_remaining_in_an_arm`: refused
with a member after the variant, and still accepted where the variant
is last. It fails with `situc/layout.py` reverted.
