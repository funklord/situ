# 26.760: An arm inside a sealed region is guarded

Status: recorded -- fixed; corrects 26.759's "still open" note
Date: 2026-10-30
Source: `project.md` section 26

    tag u8 mac[16] covers(body);
    sealed body(sealing_aead) {
        u8 k;
        variant v switch (k) { case 1: u16 a; default: u8 b; }
    }

`traverse.arm_of` found an arm's variant among the struct's own members
by the first component of the member's path. For `inside.body.v.a` that
is `body`, the region, so no backend knew `a` was an arm. Each read it
through the gate as a plain member, at the arm's offset whatever `k`
said, and C, C++ and Rust also wrote it there through a covered setter.

An 18-byte message is whole with `k = 2`, the one-byte arm. C's
`situ_inside_body_v_a_get` read the two-byte arm one byte past it --
ASan, heap-buffer-overflow, on a message `situ_inside_view` accepted.
C++'s gated getter was the same unbounded load, and Rust's indexed the
slice and so would panic -- both read from the generated code rather
than run. Python named the arms `a` and `b`, dropping the variant, where
the other three said `v_a`. That is the "gated arm reader Python lacks"
26.759 recorded; the real fault was that all four lacked the guard.

A waived region (`[allow_unverified_read]`) reads the same arms on the
plain view and had the same fault in all four.

## What changed

- `arm_of` also finds a variant directly inside one of the struct's
  sealed regions (`traverse.in_a_region`). A plain `coded` region is left
  out: no backend emits an accessor into its interior at all.
- Each backend gives such an arm, through the gate, the plain arm's
  accessor: the discriminant read through the gate's own getter, then
  `version` for an arm not chosen and `bounds` for one the frame does
  not hold. C and C++ take an out-parameter, Rust returns a `Result`, and
  Python raises. A scalar at a constant offset only; any other arm shape
  in a gate is declined in words by all four.
- A waived region's arms go to the plain arm family, which reads the
  discriminant through its interior accessor (`body_k`).
- No backend emits a setter for an arm in a sealed region, as none does
  for a plain arm.
- The differ asks gated arms the way `ARM_VALUE` asks a plain one --
  `ok=` and the value -- inside the `SEALED` probe, and a waived region's
  arms as `ARM_VALUE`. It had asked them as plain scalars.

Over the 43 committed schemas the four backends' output and every packed
image are byte-identical before and after: none has a variant in a
sealed region.

## Tests

`test_an_arm_inside_a_sealed_region_is_guarded.py`: all four answer the
sealed and waived forms identically and exactly, including the message
that holds only the shorter arm; C and C++ under ASan and UBSan read no
arm past the frame. With `arm_of`'s new branch removed, all four tests
fail.
