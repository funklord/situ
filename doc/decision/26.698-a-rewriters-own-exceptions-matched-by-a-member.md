# 26.698: a rewriter's own exceptions, matched by a member

Status: recorded -- `bytes` fixed; `as_ref` cannot be fixed this way
Date: 2026-10-27
Source: `project.md` section 26

**The Rust setter rewrite carries two exceptions, and a member's own
accessor can match either.** `codegen/rust/emit.py`'s `reading()` turns
`self.X` into `self.as_ref().X` in a setter body, because the offset
helpers live on the immutable view:

    re.sub(r"self\.(?!as_ref\(\))(?!bytes\b)", "self.as_ref().", text)

The first exception stops it rewriting its own output into
`self.as_ref().as_ref()`. The second leaves `self.bytes` alone, that being
the one thing both view types have. **Both are matched by a member named
for them**, so the rewrite is skipped and the expression resolves to
something else:

    u8 bytes  [max = 4]; u8 b[bytes + 1];
      error[E0599]: no method named `bytes` found for mutable reference
                    `&mut SMut<'a>` in the current scope
    u8 as_ref [max = 4]; u8 b[as_ref + 1];
      error[E0605]: non-primitive cast: `S<'_>` as `u64`

Both in the arithmetic and `reserved` constructs; `i` is clean in all of
them. This is 26.696's shape -- a rewriter's guard matched by generated
text -- in a third place, and the first two were in `names.py`.

## `bytes` is distinguishable; `as_ref` is not, and that is the finding

**The data field is `self.bytes.len()` and an accessor is `self.bytes()`,
so the paren tells them apart.** The exception now reads
`(?!bytes\b(?!\s*\())` -- except `bytes` when it is NOT a call -- tested
as a discriminator before it was applied, over the field spellings that
must stay excepted (`.len()`, as an argument, indexed, bare at the end of
the text) and the accessor that must not.

**For `as_ref` there is nothing to discriminate on: the guard and the
collision are the same string.** A member named `as_ref` emits
`self.as_ref()`, which is byte-for-byte what the rewrite emits, so no
pattern over the rendered text can tell them apart. That is a property of
the approach rather than of this regex.

**The structural fix, and why it is not taken here.** The `as_ref`
exception exists only because `_store` pre-applies `as_ref()` to a marker
predicate -- its own comment says *"every other setter site needs one, and
this rewrote that into `self.as_ref().as_ref()`"*. Remove that
pre-application, let `reading()` apply it uniformly, and the exception is
unnecessary and the collision gone. But the same comment records that **a
marker-governed member behind a variable-length one is the only shape that
reaches both, and no schema here has one** -- so the change would be made
to a path no test could cover, which is worse than leaving a loud
compile-time failure in place. Recorded with the route rather than
attempted.

## Proofs

**46 generated Rust modules byte-identical** across the `bytes` fix, and
all 46 compile under `-D warnings`. That is the control for the exception
still covering what it was written for: had the narrowing let
`self.bytes.len()` through, every schema with a dynamic setter would have
moved.

**Control:** reverting the exception fails
`test_a_member_named_bytes_is_not_mistaken_for_the_data_field` with the
`E0599` above, and the sibling test asserting that a marker predicate is
still reached through `as_ref()` keeps passing -- so the narrowing did not
cost the guard its original job.
