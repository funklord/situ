# 26.370: A byte has no byte order, said twice and not a third time

Status: recorded
Date: 2026-09-16
Source: `project.md` section 26, where it was written

**`situ_get_be8` is a function the runtime does not have and never will.**
A checksum's `check` reads the stored sum with `situ_get_be<width * 8>`,
and at one byte that is what it spells. C++ spells the same thing for the
same reason, since it calls C's helpers.

**The idiom was already written down twice in the same file.** C's index
read and its fixed-length read both special-case a width of one and take
the byte directly -- `situ_base(view)[at]` -- because a single byte has no
order to read it in. The checksum path is the third site and the only one
that never got it, and the reason is exactly why it stayed invisible: no
schema in this tree had a one-byte checksum, so the line could not be
generated at all.

**It became a build failure the moment `crc7_mmc` derived.** 26.369's loop
made the helpers appear for `mmc_command`, whose CRC-7 is one byte, and
`make test-c` stopped compiling. The defect is older than that commit by
whatever age the emitter has; what the commit did was make it reachable.

**Three defects from one corpus entry in two days** -- the coverage span,
the fifth `gen-checks` site, and this -- and the property they share is
that each was unreachable rather than unnoticed. A gate cannot fail on a
shape no schema writes, and `edges.situ` exists to write the shapes no
worked example does. That is the argument for putting a construct in the
corpus rather than in a test, stated three times by measurement rather
than once by preference.
