# 26.772: Append-only orders every member

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

    struct sealv [version = ver] {
        u8 ver;
        sealed body(sealing_aead) { u8 a; u16 b [since = 2]; }
        tag u8 mac[4] covers(body);
    }

19.4's one rule is that versions never decrease across a struct's
members. `check_versions` ordered only `Field` and `Reserved`, so a tag
after a versioned member was never in the order, and nor was a pad, a
variant or an opaque region. The schema above was accepted. Its minimum
was taken where `b` starts (`_first_versioned`, two bytes) while `mac`
sat at a constant 4..8, and every accessor that trusts the minimum (20.2)
read past it: Rust panicked (`range end index 8 out of range for slice
of length 6`) on a whole version-1 message.

Every member that occupies bytes is in the order now. A transparent
block and a variant's arm own none and are left out. A tag after the
versioned member is refused with append-only's own diagnostic, and the
same tag before the region is accepted. All 43 committed schemas still
build; the change can only refuse, so generated code is unchanged.

Found probing a `sealed` sibling of 26.771's versioned region.

## Tests

`test_wellformed.py`: the tag after the region is refused naming `mac`,
and the tag before it is accepted. With the change reverted the first
fails.
