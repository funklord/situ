# 26.1026: the other three pad to the next member

Status: recorded
Date: 2026-11-14
Source: 26.1024, which was C's alone

**26.1024 let C write a mid-struct pad up to where the reader puts the
member after it** -- cpio's name padding. Python, C++ and Rust refused the
role.

**Now all four**, the same way: each asks its own reader for the next
member's offset over the whole backing (Python's `data_offset` property,
C++'s and Rust's `data_offset()`), refuses one behind the cursor, and
writes zeros to it. C's plan names the member the pad runs up to, which
the other three read rather than recomputing. Only in a struct taking no
arguments, like 26.1025's role.

**Measured**: Python's builder writes the two-entry archive of 26.1024 --
248 bytes, the name padding zeros -- and GNU cpio extracts `hi\n` from it;
the agreement test compiles the role in all four.
