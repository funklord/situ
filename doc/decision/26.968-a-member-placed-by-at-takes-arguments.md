# 26.968: a member placed by `at` takes arguments

Status: recorded
Date: 2026-11-12
Source: describing a whole TIFF (26.961's other case)

**A TIFF's first directory could not be described.** It sits wherever
the header's `ifd_offset` says and every entry in it is in the header's
byte order, so it is a struct placed by `at` and handed an argument:

    ifd(order = byte_order) first at ifd_offset;

`check_parameter_nesting` refused a located member handed arguments as
unbuilt. With 26.967 a located struct is measured and validated where
the message places it, and the handed values thread through the same
places a nested member's do: C's extent and validate, C++'s `required`
and constructor, Rust's `required` and `new`, Python's `required` and
`at`. So the refusal is lifted.

Three faults came out on the way, all older than this:

- **Rust built the elements of a run of structs that take an argument
  without it** -- the counted run's fixed-element accessor and the fixed
  array's both -- so a directory's `entries[count]` did not compile. The
  walked form, for elements with no single size, had always handed it on.
- **The dissector measured a located struct at the cursor** -- byte 8,
  the end of the header -- rather than at `ifd_offset`, so the directory
  never fit and was never shown.
- **And declared no field for one**, so the first file that did reach it
  was a Lua error.

## Verified

`test_a_located_member_takes_arguments.py`: a TIFF laid out by hand in
each byte order, a directory entry breaking a constraint in either, a
count past the file and a directory past its end -- verdicts worked out
by hand, in all four backends and both walkers; a fixed array of
argument-taking structs; and the dissector showing the directory at its
offset. Files ImageMagick wrote in each order read the same fifteen
entries, at the offset `tiffinfo` reports.
