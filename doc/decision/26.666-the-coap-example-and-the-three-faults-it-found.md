# 26.666: The CoAP example, and the three faults it found

Status: recorded
Date: 2026-10-21
Source: `project.md` section 26

26.142 went looking for the next protocol to carry as a worked example,
chose CoAP, and could not describe its options at all. Two language
additions later (0065, 0066) and one defect in the tag reader later
(26.664), it is `example/coap`. Writing it found three more faults, and
each was invisible for a reason worth keeping.

## What the example describes, and what it refuses

The fixed header, the token, and the options: version, type, token
length, code, message id, `u8 token[token_length]`, and a `tlv` region
whose option numbers accumulate. A `GET /temp` with a Uri-Query reads as
options 11 and 15, the second of which is in no byte of the message.

**The extended escapes are refused rather than guessed at.** A delta or
length nibble of 13 means one further byte follows and 14 means two,
biased by 13 and 269, and a value whose size is read from bytes AFTER
the tag is not one of 9.5's five rules. `0xFF`, the payload marker, is a
sentinel in the item stream rather than an item. All three decode as a
nibble of 13 or more, so one decoded part catches them:

    escape = ((tag >> 4) / 13) + ((tag & 0x0F) / 13),
    value_size = switch (escape) { case 0: length, default: error },

which is zero exactly where both nibbles are readable. Integer division
because the expression language has comparisons in constraints only
(section 10), and `n / 13` is 0 below 13 and 1 above it for every value
a nibble can hold.

## `/` is integer division in situ and float division in Python

The `escape` part above returned **1.1538461538461537** in the generated
Python, and the dispatch compared it against 0 -- so every option was
refused as "a wire type this schema does not size" and the region read
as empty, in one backend of four.

**The fix already existed and the hazard was already written down.**
`names.translate_operators` takes a `div` argument for exactly this,
and its docstring says: "`/` is integer division in C, C++ and Rust and
float division in Python and Lua, so `body[n / 2]` generated a Python
slice bound of `2.5`". The Python backend calls it in one place --
`_over_fields` -- and the tlv parts and the dispatch selector are
spliced raw, which was the one path that bypassed it. Both go through
`_pythonic` now.

**Why nothing caught it.** No corpus schema had an operator needing
translation inside a tag part: protobuf's are `tag >> 3` and
`tag & 0x7`, and `edges`' are the same two. `>>` and `&` mean the same
thing in both languages, so the splice was correct for every schema in
the tree and wrong for the first one that divided.

## A `tlv` region behind a variable-length member named an undefined
## function

CoAP's options follow a token whose length the header declares, so the
region is at a dynamic offset -- the first in the tree. C emitted
`situ_coap_options_offset(view)` in `first` and defined it nowhere: the
member emitter returns early for a `tlv` region, and the branch that
emits a dynamic member's offset function sits past that return.

The comment immediately below that branch describes the fault in as
many words -- "Emitting the accessors anyway named an offset function
that was never defined, which C happens to refuse; a language that
resolved it later would have taken the wrong bytes instead" -- having
been written when the same thing happened for another kind. One early
return was not covered by it.

**C is the only backend that said so**, because C is the only one whose
output is compiled against a declaration. The other three compute the
region's start inline, which is why the Python column parsed the header
correctly while C would not build.

## What adding a schema costs, which is five tests saying so

The gate refused the commit five times over and every one was the
corpus's registration machinery working: `test/generated/Makefile` names
its schemas by hand; a vector spells an enum as the generated header
does (`SITU_MESSAGE_KIND_CONFIRMABLE`, not `confirmable`), because
`gen-tests` drops that into cmocka and `situc verify` reads the same
macro table; an example is oracled or excused by name; and two pinned
floors assert the corpus COUNT so that a new schema forces a
re-measurement. Both were re-measured here -- the walker's overlap from
760 to 776 of 835 asked, the dissector's from 3837 to 3896 of 4883
shown -- which is 26.588's rule working as designed rather than a
nuisance: a floor left at an older total goes slack by exactly what the
new schema contributes.

## tshark agrees about every vector, and it is still not an oracle

Nothing on this machine can WRITE a CoAP packet, which is `ntp`'s
position. Something can read one, so it was asked:

    Constrained Application Protocol, Confirmable, GET, MID:32052
        01.. .... = Version: 1
        .... 0010 = Token Length: 2
        Token: 1234
        Opt Name: #1: Uri-Path: temp    1011 .... = Opt Delta: 11
        Opt Name: #2: Uri-Query: a=1    0100 .... = Opt Delta: 4

Every field, and **Type 11 and Type 15 for a message whose second delta
is 4** -- the accumulated number of 0066, read back by somebody else's
dissector. The other four vectors dissect as ACK, RST and CON as
intended.

It goes in `UNORACLED` anyway, with the measurement written into the
entry. The bytes were hand-built from RFC 7252 in this repository, so
comparing two readings of them checks this project's READING and not its
OPINION about what CoAP looks like, and the second is what a corpus is
for. If a generator appears the dissector is already here and the oracle
is a small function.

## What is still not covered

No vector carries an extended option or a payload, because the schema
refuses both: a vectors file states what a reading must produce, and
"refused" is not a value it can express. The refusal is a unit test
instead.

`situc explain coap.options` should enumerate why the region is
sequential and unaddressable, as protobuf's comment asks of its own.
Not checked here beyond the capability map agreeing, which is what the
committed `.map` holds it to.
