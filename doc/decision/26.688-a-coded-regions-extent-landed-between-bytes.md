# 26.688: A coded region's extent landed between bytes

Status: recorded -- fixed
Date: 2026-10-25
Source: `project.md` section 26

Reported by bbq-predictor as the fourth of its minor items, as "a
fractional expansion ratio prints sizes in bits where `explain` gives
bytes". The printout was the symptom. What it was hiding is a generated
`SIZE_MAX` one byte short of the message it promises to hold.

## The fault

**The expansion arithmetic is in bits (0046), and a ratio can land
between bytes.** `ratio_bounded(1001, 1000) + 20` over a 446411-byte
interior:

    interior   446411 bytes = 3571288 bits
    scaled     ceil(3571288 * 1001 / 1000) = 3574860 bits
    addend     + 20 bytes                  = 3575020 bits
                                           = 446877.5 bytes

A member occupies whole bytes -- the one after it starts on a byte
boundary and the message is byte-addressed -- so half a byte is not an
extent anything can have. The map said so out loud, which is how it was
found:

    month_tail.columns  size=Bounded(2, 3575020bit)

**And `size_max_bytes` is `size_max_bits // BITS_PER_BYTE`, a floor.** So
the struct's 3575036 bits, which is 446879.5 bytes, reached the generated
header as

    #define SITU_MONTH_TAIL_SIZE_MAX   446879u

where the worst case is 446880. A caller sizing a static buffer from
situ's own promise is one byte short of the largest message that promise
covers -- which is the use `max_size` exists for, and the kind of
guarantee this compiler is for.

## The fix

`_whole_bytes` rounds the expansion's output up to a byte multiple,
before anything divides it. Both bounds, and the low one for the same
reason: the fewest WHOLE bytes a region can occupy is the ceiling of its
bit minimum, and flooring that would admit a buffer one byte short at the
other end.

Rounding there rather than at the division is the point. A floor and a
ceiling are both wrong answers to a question that should not arise: the
extent is whole bytes before any consumer sees it, so the map, `explain`,
the `max_size` predicate and the generated macro cannot disagree about
which way it went.

Measured after, on the reporter's own schema:

    month_tail.columns  size=Bounded(2, 446878)
    struct month_tail   size=4..446880
    #define SITU_MONTH_TAIL_SIZE_MAX   446880u

446878 is the figure bbq-predictor predicted for the region.

## Why `ratio_exact` never showed it

The corpus has `ratio_exact(2, 1)`, where every interior size doubles
into whole bytes, and this pass's own first probe was `ratio_exact(4, 3)`
over 255 bytes -- 340 exactly. Both divide. It takes a ratio whose
product is not a whole number of bytes, which `ratio_bounded(1001, 1000)`
is and nothing in the tree had.

So the arithmetic was right in bits for as long as anybody looked, and
wrong in bytes only for inputs nobody had. The reporter's schema is a
real format with a real compressor, which is 26.675's finding again: a
consumer reached a composition the corpus does not have.

## The two items beside it

`edges.situ` gains no fixture for this, deliberately -- the shape needs
an `extern` codec with a bounded ratio, and the corpus's codecs are
derived or exact. `test_codecs.py` is where the arithmetic is tested and
is where a case belongs; that is the next pass rather than this one.

bbq-predictor **withdrew** its "every diagnostic prints twice" item on
2026-10-25, having gone back to its own transcript: two commands on one
shell line, each printing once. Worth recording because the probes this
tree ran to look for it -- four subcommands, errors, warnings, parse
errors, text and JSON -- found nothing and could not have.

Its fifth item reproduces and is open: `explain` calls a member after a
non-seekable coded region `Dynamic` with `Random` access and offers
"move the variable-length member after this one", while the generator
emits "its offset cannot be resolved". Nothing in the bytes says where a
non-seekable region ends, so no generator can place what follows -- the
explanation names the wrong cause and a remedy that cannot work, where
the real one is a length before the region.
