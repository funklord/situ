# 26.1167: a known tlv value holds its type

Status: recorded; built in the four backends, declined by both walkers
Date: 2026-11-23
Source: openmlx4 (inbox 20261123T1138Z), measured on situ b55f6812

## The finding

openmlx4's FS2 image-info region names its items' types:

    known = {
        1 : { name = fw_version,    type = u8 },
        2 : { name = fw_build_time, type = fw_build_time },
    }

and nothing held a value to its type. A date whose binary year the
struct refuses (`07 E1` where BCD wants `20 17`) verified inside the
region; an 8-byte struct verified in a 3-byte value; `type = u32`
verified with 2 or 10 bytes. openmlx4 asked which `type` means: one value
of the type, or an element type filling the length.

## What `type` means

**The element type filling the item's length.** That was already the
code's and the corpus's reading, which the first answer sent to openmlx4
got backwards and then corrected: example/protobuf declares
`2 : { name = username, wire = 2, type = u8 }` over a length-delimited
string, and `type = T[]` says the TAG may repeat (`tlv_single_tags`,
26.740), not that one value holds a run. So 12 bytes of `type = u32` are
three, 16 bytes of a date are two, and 16 bytes of `type = u8` are a
string.

## What is held

`traverse.tlv_typed_tags` names the tags whose element has a fixed width:
a scalar of two bytes or more, or a struct of fixed size taking no
arguments. Each backend's `_whole` -- the check `validate` runs over the
region (26.737) -- refuses, for an item with such a tag, a value that is
not a whole number of elements (CONSTRAINT), and runs a struct element's
own `validate` over each element, whose refusal is the region's.

Left out, each for a reason:

- **A byte-wide scalar** divides every length; there is nothing to check.
- **A scalar whose wire rule already fixes a multiple of its width** --
  protobuf's `f32` on wire 5 is four bytes by its rule. Naming it would
  only make the walkers decline a region they can answer for.
- **A varint, an enum, a struct of varying extent** -- no width to divide
  by; left as before rather than given a rule of their own here.

## The walkers

The image carries neither the tags nor the element type, so the region's
row gains bit 3 and both walkers decline it (`cannot-say`), as they do
for `ordering`, `unknown = error` and `duplicate_tags` (26.738-26.741):
never `0` for a value the four refuse.

## Found on the way

C and C++ read a three-byte length or tag as its first byte alone, and
openmlx4's region is `length_type = u24`; fixed first, in its own commit
(4cb44215).

Held in `test_a_known_tlv_value_holds_its_type.py`: eleven hand-worked
verdicts in all four backends, the struct declared after the region so
C and C++ must name its validator ahead of its definition, and both
walkers declining. The test fails with any one backend's check removed.
