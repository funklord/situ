# 26.966: a codec places nothing after it, whatever came first

Status: recorded
Date: 2026-11-12
Source: the coded-region sweep (26.962), its bounded and unbounded shapes

**A region whose codec has no closed-form expansion makes every member
after it unplaceable -- and the layout said so only when the region was
the struct's first dynamic cause.** `state.decode_cause` was set inside
the test that records the first cause, so

    struct s { u8 m; u8 pre[m]; u8 n; coded body(c) { ... } u8 k; }

with `expansion = unbounded` or `ratio_bounded(2, 1)` recorded `pre` as
`k`'s cause and nothing about the codec. `traverse.offset_unresolvable`
reads `dynamic_cause_codec`, so it called `k` placeable; all four
backends correctly declined it, and the differential's driver asked for
`situ_s_k_set` and did not compile -- six shapes of the sweep. The same
schemas with the region first were fine.

The codec is recorded whenever such a region is met now, independently
of the first cause. No committed map changed: the map prints the first
cause, which is unchanged.
