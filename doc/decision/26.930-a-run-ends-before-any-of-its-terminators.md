# 26.930: a run ends before any of its terminators

Status: recorded
Date: 2026-11-08
Source: a Matroska Cluster of unknown size, which 26.925 left out

**A Cluster a writer could not go back to size runs to the next element of the
Segment's own level.** GStreamer's `webmmux streamable=true` writes every Cluster's
size as the eight-byte unknown, and so does a browser's MediaRecorder. 26.925 called
that a question about what an ID means. It is a question about bytes: the Segment's
own elements have nine IDs, and the Cluster ends before whichever of them comes
next, or at the end of the file. So

    element children[] before "\x1F\x43\xB6\x75" | "\x1C\x53\xBB\x6B" | ... | end;

says it, and three faults stood in the way, each in all six readers:

- **`before` on a run of records consumed its terminator.** The Cluster measured
  4379 where it holds 4375 and swallowed the next Cluster's ID. `before` was built
  for byte runs, where the dissector already said the terminator is the next
  member's; the run walks never asked `delimiter_consumed`.
- **Several terminators were refused for a run of records**, on the grounds that a
  run checks them only where an element would start. That is the walk the run
  already does, asked of each alternative, and the walkers' code looped over a list
  already.
- **The walk was guarded by the terminator's own room**, `at + len <= limit`, so
  under `before` or `| end` an element shorter than the terminator in the frame's
  last bytes was dropped: two two-byte items under a three-byte terminator counted
  one. Where the terminator must stand that guard is harmless, and every such run
  keeps its generated text: `codegen.record_simple` says which.

**`required` declines both shapes** rather than answer for one: on a prefix, whether
the run ended turns on bytes that may not have arrived, the next member's opening or
the rest of a longer alternative. And `frameable` now asks an arm that is one struct
whether it frames: `wide_cluster` chose `open_cluster` and called itself complete at
110 bytes of 191. An arm that leads back to its own struct is the cycle's question and
is skipped, as `seen` answered it no from one entry and yes from another.

The builder already refused both shapes, as a run whose end it cannot state, and the
checks' synthesised instance declines `before`.

**Witnesses.** GStreamer 1.26.2 wrote `example/matroska`'s `streamed` vector, four
Clusters of unknown size; ffprobe reads its packets as 19, 35, 36 and 21 bytes, and
the first three are the SimpleBlocks' 23, 39 and 40 less their four-byte headers. A
nine-kilobyte file of three Clusters gave the 26, 27 and 6 children a separate
walk written for the purpose counted. The test's messages are worked by hand.

**A member's minimum counted a terminator it does not own**, and the first of several
rather than the shortest. `before` leaves it to the next member and `| end` to the
frame, so `delimited_extent` floors at none for those and at the shortest alternative
otherwise. Five committed maps move down: id3's tag from 11 to 10, as a tag with no
frames may end at the frame; http's header line from 3 to 2, as a value may end at a
lone `\n`; json's `number` and `value`, sexpr's `symbol` and `sexpr`, and
`open_cluster`. A `,` handed to json as a value is CONSTRAINT in all six now, which it
is: the frame holds it and no arm admits it.

**Not here.** A Cluster's size of unknown in a width other than eight bytes, which no
writer met here uses.
