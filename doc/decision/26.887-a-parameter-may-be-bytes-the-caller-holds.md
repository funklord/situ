# 26.887: A parameter may be bytes the caller holds

Status: recorded
Date: 2026-11-06
Source: the holder, answering the question 26.470 left

    codec aes_gcm { nonce_bytes = 12; key_bytes = 32; ... }

    struct record {
        parameter u8 iv[12];
        parameter u8 k[32] [secret];
        u16 kind;
        sealed(aes_gcm, nonce = iv, key = k) { u8 fragment[kind]; }
        tag u8[16];
    }

26.470 found the 12-byte nonce of AES-GCM and ChaCha20-Poly1305 could not
be carried out of band: a `parameter` was a scalar, and scalars stop at 64
bits. The holder's answer is yes, and 0050's zero-width reasoning turns out
not to stand against it. A member of zero width has no position. It does not
follow that it has no size.

## What it is

A `parameter` with an array spec is **material**: bytes the caller holds, of
a width the schema fixes, read by a region's `nonce =` or `key =` and by
nothing else. It must be a run of `u8`, sized by a number or a `const`, and
may carry `[secret]` and no other attribute. Its width is the reason to
declare one, so a size only the caller knows is refused.

**It has no value, so no expression may read it**, and the refusal says so
rather than "not in scope". That is what the next section rests on.

## It reaches no view, and that is the decision

A scalar parameter is carried on every view because expressions read it. A
region's `nonce =` reaches no backend for any kind of member. situ runs no
primitive: `verified` is the caller's, and the caller hands the nonce to
their own AEAD. They already hold these bytes, and a view holding a second
pointer to them would be a dead argument in every signature, in four
languages, on every acquire, doing nothing.

So material is not a `Placement`. `StructLayout.material` holds it, and the
map, the wire signature and the advisor read it. `traverse.parameters` does
not list it and `ast.Field.argument` is false for it. The 90-odd sites in
four backends, both walkers and the image that iterate placements were not
touched, and a struct holding only material takes no argument and nests like
any other. Measured on the schema above: no `arg_` in the generated C.

**A consequence worth stating:** a scalar `parameter u64 iv` read only by
`nonce =` is still carried, as it was. Nothing here changes it.

## The key

`key = epoch` selects a key, and 0040 refused a byte run there because a
selector needs a value. `key = k` naming material is the key itself, a
second meaning that the declaration decides: a selector has a value and
material has bytes. `key_bytes` on the codec is held against material only,
since a selector's width says nothing about the key's. That is the check
section 14 recorded as missing.

## Rendered

    p.iv        parameter bytes=12
    parameter -  u8[12]  iv

`situc wire --check` sees a change of width, and the advisor's short-nonce
rule reads the width and costs nothing on the wire.

## Rejected

**Carrying it on the view.** Measured at about 90 sites for an argument no
line of generated code would read.

**A placement with a new kind.** Every iteration would have to step over it,
and 26.408's record is what happens to a shape only some iterations know.

**A new keyword.** `parameter` already says the caller supplies it, and an
array spec already says how wide.

## Not built

A pin against held bytes, `u8 cookie[8] [must_eq = expected]`, is the first
thing that would read material. It is refused today, as any read is.
