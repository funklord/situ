# 26.974: the differentials compare what a marker governs

Status: recorded
Date: 2026-11-12
Source: walking the goal gap -- why 26.963 had gone unseen

**No differential compared a value a byte-order marker governs.** The
drivers the four-way differential generates skipped any scalar whose
`placement.marker` was set, under a comment about the marker itself ("a
marker resolves byte order rather than holding a value"); but every
member a marker governs carries the marker's name there, so all of them
were skipped -- each value of a TIFF header or a pcap file. The walker's
listing skipped them too, to match. And the dissector's comparison drew
random bytes, which almost never hold a marker literal, so the one path
it could compare was big-endian. 26.963's dissector, which read every
governed member big-endian, agreed with the walker on every draw.

The drivers ask a governed member's value like any scalar's, the walker
lists it in the order the marker states, and the dissector's comparison
repeats each draw with the struct's marker at each of its literals.
Measured: TIFF 0 -> 90 compared answers, pcap 0 -> 108, `edges` 1683 ->
1734, with no difference; run against the dissector from before 26.963
it reports 30 on TIFF alone.

`test_the_differentials_compare_what_a_marker_governs` holds the TIFF
comparison above 60 answers and the pcap header's values in all four
backends' output.
