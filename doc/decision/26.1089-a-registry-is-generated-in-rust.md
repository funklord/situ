# 26.1089: a registry is generated in Rust

Status: recorded
Date: 2026-11-18
Source: 0070, step 6

**The C registry (26.1081) in Rust's idiom.** Each registry is an
`<Name>Entry` struct -- key, family, safe, `Option` bounds, sizes, default,
unit, summary, window, one `u32` per declared policy, and the cell's type --
and a unit struct `<Name>` whose `ENTRIES` is the table, with `find`,
`check`, `value` and `safer` as associated functions. `check` is a
`Result<()>` carrying the cell type's own error, or `Error::Constraint` for
a stated bound; `value` is a `Result<i64>`, `Error::Constraint` where the
cell has no value. Policy words are `pub const` bits (`SCOPE_ESTATE`).

With it, all four backends and both walkers generate or read a registry,
and each is held to the same 33 cases.

## Measured

`test_a_registry_is_generated_in_rust`: the 33 cases and the row, built
under `-D warnings`. Sabotaged: an upper-case family word admitted fails
it. Rust codegen, the four-way and the framing comparison over `edges`,
whose registry is compiled as a library under `-D warnings`.
