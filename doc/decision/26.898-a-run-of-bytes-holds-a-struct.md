# 26.898: A run of bytes holds a struct

Status: recorded
Date: 2026-11-06
Source: the goal gap, walked from section 1 under the holder's rule that a
sane protocol's need is ours

    struct extension      { u16 kind; u16 length; u8 data[length]; }
    struct extension_list { extension all[remaining]; }
    struct client_hello   { ...; u16 extensions_length;
                            u8 extensions[extensions_length]
                               [holds = extension_list]; }

Nothing said "these records take N bytes". A count counts elements, and
`[remaining]` is the frame's, so a nested list could not be given a frame of its
own. TLS extensions, BGP path attributes, IS-IS TLVs and records followed by a
CRC are all this shape, and `rec r[remaining]; u32 crc;` was refused.

## The rule

`[holds = T]` goes on a run of `u8`. To its parent the member is that run in
every way: offset, length, `required`, builder, walker measurement and
dissector are unchanged, and a tail after it is 26.894's. So

    struct guarded { u8 body[remaining] [holds = list]; u32 crc; }

needed nothing further.

What is new is two things. A `<member>_view` accessor gives `T` over exactly
those bytes, so `[remaining]` inside it ends where the run ends. And `validate`
descends: a rule broken inside, or an element cut by the run, refuses under the
run's check id. Bytes `T` does not reach are treated as at the top of a frame:
`T` decides, and a fixed `T` shorter than the run leaves them unread.

The image carries it in a section of its own, HOLDS (29), so an image with no
such member is unchanged. Both walkers descend with the run's end as the limit.
The wire signature says `holds=T`, breaking, since it decides which messages
are valid. A child that cannot be validated makes the parent `cannot-say`.

## Refused

- **On anything but a run of `u8`.** A wider run has a byte order to state.
- **Inside an arm or a region.** A parent reaches it through a view accessor and
  those have none. Nest a struct carrying the run: a `case` holding a struct
  that holds is `example/tls`'s record, handshake and hello.
- **A child taking arguments.** Nothing hands them.

## A container of containers

    struct box   [depth = 8] { u8 kind; u8 len; u8 body[len] [holds = boxes]; }
    struct boxes [depth = 8] { box all[remaining]; }

ISO-BMFF, RIFF, EBML and BER are this, and 0054 named them. `[holds]` is an edge
in the type graph, so such a cycle needs `[depth]` as any other does, and each
`nesting` probe descends through the run's view. Past `[depth]` a message is
malformed, and a walker past its ceiling says `cannot-say`. Nothing measures a
run's interior, so `report._validate` counts its own descent, as the C walker's
`depth` does.

It found that C++'s deferral across a cycle missed a signature on two lines
and took `::situ::box` for the front of `::situ::boxes`.

## Rejected

**`T x [frame = n]` on a nested member.** Every site that measures a nested
member, in four backends and two walkers, would have learned a second way to
measure one. A run of bytes is already measured everywhere.

**Lifting 26.894's limit for records directly.** Each record-run site reads the
view's limit for where the walk stops, and a tail would have to reach all of
them, for one spelling. It solves the trailer and not the byte length.

## What is not built

The builder writes the bytes: a caller encodes `T` and hands them over, as for
any run (26.614). The dissector shows the run as bytes.

## Verified

`example/tls` reads three ClientHellos OpenSSL wrote, record to extension. The
extension types each lists were compared with tshark's, in order, and agree;
all four backends and both walkers answer alike over ten messages of `hello`
and `guarded`.
