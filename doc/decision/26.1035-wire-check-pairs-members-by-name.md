# 26.1035: wire --check pairs members by name

Status: recorded
Date: 2026-11-14
Source: openmlx4, inbox 20261114T0049Z (`suggestion/openmlx4.md`
2026-11-14), measured against 73e8e79a

**`situc wire --check` reported moves that did not happen.** openmlx4
wrapped existing fields of `fs2_header` in `authenticated` regions and split
one 28-bit field into a checksum byte and twenty bits; every later field was
reported as moved and breaking ("info_ptr_checksum moves @0x002c ->
@0x002b:5"), while the regenerated contract had each one where it was.
Members were paired by their index in the member list, so one inserted line
shifted every comparison after it. A contract check is worth only as much
as its "breaking" can be taken at its word -- the opposite fault to
35cbad07's, and the same cost.

**Members are now aligned by name** (`difflib`'s matcher over the two name
lists) and a member present in both is compared with itself. What is left
is removed, inserted, or appended as before; a run of equal length is
compared position by position, which keeps a rename at the same bytes the
API change it always was; and a run replaced over exactly the bits it held
is one finding, "X replaced by Y, Z over the same bits". Duplicate names,
which a struct does not have, fall back to positions.

**Measured**: openmlx4's own reproduction now reports the split and the
new checksum declaration and no moves; every committed contract still
checks clean; and an inline split-and-wrap case reports no move, which
fails against the index pairing with "flags moves @0x0007 -> @0x0005".
