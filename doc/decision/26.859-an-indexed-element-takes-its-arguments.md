# 26.859: An `indexed` region hands each element its arguments

Status: recorded
Date: 2026-11-04
Source: 0068's open list, where 26.819 measured it as one missing argument

    struct page { u8 block; u8 n;
                  indexed(offset_type = u8, count = n) {
                      cell(block = block) cells[]; } }

A table finds each element and then measures it, and 26.819 found the
measuring side one argument short. It was more than that: `place_indexed`
builds its own placement and never carried the arguments, so the image had
no ARGUMENTS rows for a region. The placement carries them now, and the
range check applies.

The value is the parent's and every element gets it, as a run's does
(rule 4). Each backend's `_at` measures with it, and `_indexed_elements`
validates with it where it had skipped any element taking parameters. Both
walkers bind it once per region. The dissector needed nothing: 26.809's
`handing` wraps any member with arguments that is not one nested struct.

**A parent's own parameter handed on stays refused here.** A field is read
over the view `_at` already holds; a parameter would need C's `_at`,
`_count` and `_offset` to take the parent's tail, which 26.815 built for a
run and nobody has built for a table.

## Tests

`test_an_indexed_element_takes_its_arguments.py`: five messages, the four
backends and both walkers to one verdict, the dissector against the walker,
and the refusal above. `edges.situ` gains `hands_on_indexed`.
