# 26.720: The sweep compiled a driver for every packet

Status: recorded -- the three corpus sweeps build one driver each and run
it per packet
Date: 2026-10-28
Source: `project.md` section 26

`test/unit/test_walker_c.py` ran in **46 minutes 43 seconds** for 213
cases. Nearly all of it was `cc`, recompiling a driver that had not
changed.

The split was already there and already argued. `_build_driver`'s
docstring says it:

> Split out from `_drive` because compiling is the whole cost: a driver
> is about five seconds and running it is milliseconds, so a test asking
> thirty messages spent thirty compilations on one binary. The one-shot
> wrapper below keeps every existing caller unchanged.

Every existing caller was indeed unchanged, and the three sweeps written
afterwards -- the verdict (26.349), which check refused (0051) and every
offset (26.538) -- were written against the one-shot wrapper. Each deals
two packets per struct over every struct of every schema, so each paid a
whole compile for every answer.

Measured on `example/udp`, the same driver and the same ask:

    build   2.61 s
    run     0.002 s
    ratio   about 1500

## What it cost, and what it was really costing

The three sweeps are **138 cases in 3 minutes 25 seconds** with the build
hoisted, and the whole file is **216 cases in 11 minutes 13 seconds**,
from 213 in 46 minutes 43 seconds. A factor of 4.2, and nothing about
what it compares has changed: the same seeds, the same deals, the same
assertions, 213 passing before and 216 passing after -- the three extra
cases being 26.718's and 26.719's.

More is there for the taking and is deliberately left. `--durations`
names `test_they_agree_about_whether_a_message_is_well_formed` at 98.85
seconds, then 34.33 and 22.90, and every one of them is a one-shot caller
asking a handful of messages about a schema it wrote itself -- which is
the shape `_build_driver`'s docstring describes in as many words. Fifty
such callers at one compile each is a minute and a half of the eleven,
and the ones asking many messages are where the rest is. The sweeps were
done first because they were four fifths of it.

The number that matters is not the wall clock, though. **A sweep nobody
can afford to extend is a sweep that stops being extended**, and this one
has a measured gap: only three questions are asked of the two walkers
over the corpus, while VALUES -- what the two readers actually read out
of the bytes -- are compared on `example/udp` with one message and on the
schemas this file writes inline, and nowhere else. The Python walker is
held to the four compiled backends on values over the whole corpus
(`test_walker.py`), so the hole is specifically the C walker's. Adding a
fourth sweep at 15 minutes a time is a different proposition from adding
one at 70 seconds.

## The change is the parameter the helper was split out for

`_drive` takes an optional driver and builds one only when the caller has
none, and `c_why`, `c_verdict` and `c_offsets` pass it through. The three
sweeps build theirs once, before the loop over structs, from the blob
they have already packed.

Nothing else moves. Every one-shot caller in the file -- and there are
about fifty of them, each asking a handful of messages about a schema it
wrote for the occasion -- is unchanged and still pays its one compile.

## The lens

This is the third finding of the day in the same place and from the same
question, which is `working-practice.md`'s rule about deriving the next
lens from the last bug. 26.718 was the driver's message buffer and 26.719
the program's; both were cases of **a mechanism settled in one place and
not carried to the place beside it**. So was this: the reason to build
once is written down, in the function that exists to allow it, and the
callers that needed it most never read it.

Worth separating from the other two honestly. They were defects -- a
harness that corrupted its own image, and a tool that answered about
bytes nobody sent. This is not: the sweeps were correct and slow. It is
here because the slowness was buying nothing and was deciding what the
differential is allowed to ask.
