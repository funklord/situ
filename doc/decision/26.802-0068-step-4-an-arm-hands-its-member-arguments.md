# 26.802: 0068 step 4 -- a variant arm hands its member the arguments

Status: recorded
Date: 2026-11-02
Source: 0068, step 4

    struct arms { u16 block; u8 kind; u8 n;
                  variant body switch (kind) {
                      case 1: entry(block = block) one;
                      case 2: entry(block = block) many[n];
                      case 3: entry(block = 1) wh[] while (tag != 0) max 4;
                      case 4: entry(block = block) rest[remaining];
                      default: u8 raw; } }

An arm's member may now take arguments, whether it is a single struct or
any run of them. Each argument is an expression in the struct that owns
the variant, so it can read a member before the variant, as the
discriminant does.

## The change

`wellformed.arms_of` adds the arms of a struct's own variants to what
`check_parameter_nesting` builds. In the four backends, the arm paths
pass the arguments where 26.779 to 26.790 measure and validate an arm:

- the arm's sub-view and its site extent (`_arm_extent` in C,
  `_arm_member` in the other three);
- the arm's own `validate`;
- the walks over an arm's run (`_arm_run_walk`) and over the tail after
  an arm's `while` or delimited run (`_arm_ended_walk`).

The arm's element validation already went through step 3's
`_element_validation`. Python emits `_make_<member>` for an argued run in
an arm too, and the arm's walks call it.

Both walkers bind the arm's arguments where they choose an arm: Python in
`walk._arm_bits`, `report._validate`'s arm branch and `_arm_validates`;
C in `arm_bits` and `arm_validates`, which hands the element binding to
the counted and `[remaining]` walks.

## The corpus

`edges.situ` gains `hands_on_arms`: a single argued arm, a counted run of
them in another arm, and a member after the variant.

## Tests

`test_an_arm_hands_its_member_an_argument.py`: two structs, twelve
messages, four backends and both walkers, one verdict each. The step-2
refusal of an arm becomes a refusal of a member inside a block.
