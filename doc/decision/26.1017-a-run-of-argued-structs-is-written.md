# 26.1017: a run of argued structs is written

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**A pcap file and a TIFF directory could not be built.** pcap's
`record(order = magic) packets[remaining]` and TIFF's `ifd_entry(order =
order) entries[count]` were refused as "a run of `record`, not of bytes":
the element frames itself, but its `_required` takes the byte order as
well, and `frames_itself` matches the argument-free signature exactly, so
the writer had nothing it could call.

**It has a value wherever the caller has already handed one over**: the
file's endian marker, written earlier in this struct, which the caller
passes as the literal the reader hands each record; or the struct's own
argument. C's builder passes it to each element's `_required` and
`_validate` in the walk, as the reader does. An argument computed from
anything else keeps the refusal. `edges`' `relays_on_runs` is built the
same way.

**And a fault the work found.** A size field's walk was keyed on the run
having no element width, which holds for a variable struct and not a fixed
one: TIFF's 12-byte `ifd_entry` has a width, so its `count` was written as
the BYTE length of the entries -- 96 for eight. No fixed struct run behind
a count field had a builder until now, so nothing had written one. It is
keyed on the element being a struct of the schema.

**Measured by the real consumers**: a little-endian capture with one
Ethernet header, read by tshark as a 14-byte frame of EtherType 0x88b5 at
1700000000.000005; a big-endian record in it refused, and accepted in a
big-endian file. A little-endian `tiff_header` and an eight-entry `ifd`
for a 1x1 greyscale strip, decoded by Pillow as one pixel of 0x80; under
`MM` the count is written big-endian. C only.
