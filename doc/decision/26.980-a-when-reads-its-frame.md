# 26.980: a `when` reads its frame

Status: recorded
Date: 2026-11-13
Source: fuzznet's call schema -- "a fixed body's message carrying nothing
after it" was left in hand-written C

fuzznet's `node/live.c` keeps a table of each arm's size so that a call
message whose body is fixed is refused when bytes follow it: a sixth
description of the layout, beside a schema that could not say it. The
expression language had the word -- `remaining`, the bytes to the end of
the enclosing frame from where it is read -- and both walkers already
evaluated it in a `when`, the C walker handing a program the frame's
length and `walk.py` measuring from the view's start. The four backends
raised `UnknownName` out of the generator.

They read it as the view's length now -- `view.limit`, `raw_.limit`,
`self.bytes.len()`, `self._len` -- and the dissector as `tvb:len()`, so
`when 3 + size(s.body) != remaining refuse bytes_after "..."` is one
statement every reader holds. `test_a_when_reads_its_frame` asks the four
and both walkers over the struct exactly, a byte past it and a byte short,
and the dissector for its expert info; the four and the dissector fail
with the change reverted.

What it does not do yet: the dissector reads no `size()` in a `when` at
all, and declines such a predicate with a comment, so this statement has
no expert info until it does. And writing the sum is the author's -- a
`[fills_frame]` that states it from the layout is the next step.
