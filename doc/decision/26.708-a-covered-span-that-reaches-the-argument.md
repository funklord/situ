# 26.708: a covered span that reaches the argument

Status: recorded -- fixed in C; the other three took the shape already
Date: 2026-10-27
Source: `project.md` section 26

The C backend emitted a header that does not compile whenever a tag's
coverage ends at a member the caller's argument sizes. Found by an
independent audit of 26.706 and reproduced against `git archive HEAD`
with the same two errors, so it predates that change.

## The reproduction

    struct s {
            parameter u8 blk [stream];
            authenticated body { u8 payload[blk]; }
            checksum u8 sig[2] covers(body) is ic;
    }

    static inline situ_err_t situ_s_sig_covered(
            situ_view_t view, uint32_t *offset, uint32_t *len)
    {
            uint32_t start = 0u;
            uint32_t end   = situ_s_sig_offset(view, arg_blk);

    error: 'arg_blk' undeclared (first use in this function)

**The signature was a fixed string and the span expressions inside it are
rendered.** `situ_s_sig_offset` already carries the argument tail, which
is what makes the body right and the signature wrong -- the two halves of
one function disagreeing, which is this tree's worst-rated shape because
no assertion about either half can see it.

**C alone.** C++, Rust and Python generate and build the same schema:
they put the argument on the view, so a method over it needs no tail.

## Three functions, not one

The codec form emits a chain and the tail has to go down it:

    covered   reads the spans
    compute   calls covered
    check     calls compute, and reads the stored value's own offset

`check`'s tail is the union of what `compute` takes and what that second
span expression names, which are independent: a coverage can be fixed
while the checksum's own offset is dynamic, or the reverse.

## The tail is asked of the span text, not of the struct

A tail added wherever a struct has an argument would compile and would be
wrong twice: an unused parameter under `-Werror` for a tag that does not
read one, and a signature change for schemas that never needed it. So
`_covered_tail` asks `_argument_tail_in` of the span expressions, and
`_covered_args` answers the same question for the call site -- declaration
and call derived from one body, which is the only arrangement in which
they cannot drift. That shape already existed for located members, where
`at off` reaches the argument and `at 4` does not; this is its fourth
site.

`_argument_args_in` was added beside `_argument_tail_in` for the call
half, which had no sibling. **The bit-span form cannot be affected** --
its offset and extent are literal integers -- and the refusal form emits
no function, so the byte-span branch is the whole population.

## Proofs

Both shapes compile, with and without a codec. The control is the other
direction and does not discriminate the fix on purpose: a coverage over a
FIXED region in a struct that takes an argument must get **no** tail, so
over-declaring fails it while the original fault does not. Against `git
archive HEAD` the two compile tests fail with the two errors above and the
control passes, which is what a control for over-declaring should do.

Corpus C output is byte-identical over all 46 schemas, because no schema
in the tree has both a `parameter` and a tag.

## Why the suite could not see it

`test/schema/edges.situ`'s `negotiated` is the tree's only struct
declaring a `parameter` and it carries no tag. So this is the fifth
instance of the class that schema's own comment names -- *the C backend
alone had four shapes where a parameter reached a function that did not
take it* -- and it was still live because putting the construct in the
corpus covered the shapes it was written with and not the ones it was
not. The construct found four faults the day it landed; the fifth needed
a tag beside it.
