# 26.736: a `[remaining]` run dropped what it could not divide

Status: recorded -- fixed in all four backends and both walkers
Date: 2026-10-29
Source: `project.md` section 26

Found by the lens 26.735 handed on: a `check` that cannot see a walk
which stopped early. A bare `x[remaining]` is sized by the frame, and
every reader turned those bytes into elements and dropped what was left.
Two shapes, measured with the four-way harness:

    struct w { u8 a; u16 v[remaining]; }
    { 1, 1, 0, 2 }               v count=1   validate 0

    struct u { u16 packet_id; mqtt_string filters[remaining]; }
    { 0, 1, 0, 5, 'a', 'b' }     filters count=0   validate 0

The first divides three bytes by two and loses one. The second is an MQTT
UNSUBSCRIBE whose only filter claims five bytes and holds two. The count's
walk stops at the element it cannot place, so the packet reads as having
no filters, and `validate` passes it. Both walkers agreed, and so did all
four backends.

## Why each reader passed it

26.676 gave counted runs of records `_fits` and deliberately left
`[remaining]` out: "no declared count to fall short of". That is true, and
it answered a different question. A frame-sized run has no count to fall
short of, but it can still have a last element the frame does not hold.
And `declares_its_own_length` excludes `[remaining]` on the grounds that it
"*is* what is left -- it cannot claim more". That is also true, and it is
not the same claim as "what is left is whole elements".

## The reading

A frame-sized run of `T` says the rest of the frame is `T`s. Bytes no `T`
accounts for are bytes the schema does not describe, and everywhere else
the schema describes every byte of a frame. So a remainder is malformed,
and BOUNDS is the error the backends already give for a member that
overruns its frame. Nothing in the tree decided otherwise, and no test
pinned the lenient reading. It is recorded here as a decision because it
changes verdicts: mqtt's two `filters[remaining]` runs now refuse what they
used to accept.

## The fix

- `traverse.remaining_stride` gives the width of one element where it is
  fixed and wider than a byte. `check` holds what the frame leaves to a
  multiple of it, in all four backends. A byte-wide run divides anything,
  and a variable element has no stride.
- A `[remaining]` run of records gets a `_fits` that walks to the end of
  the frame rather than to a count. `check` calls it in all four
  backends, both halves dropping the old guard at once. That guard once
  went dead in C alone, so the four disagreed about check numbering
  (26.676).
- Each walker gets `remaining_run_fits`: the same walk to the end for
  records, fixed or variable, and the divisibility test for scalars.

## Verified

`test/unit/test_a_remaining_run_is_whole_elements.py` runs seven cases
through the four built backends and both walkers, and asserts the verdict.
Controls: with the emitter half stashed, the four answer `validate 0` for
`words, a byte over`. With either walker's half stashed, that walker
fails on the same case.
