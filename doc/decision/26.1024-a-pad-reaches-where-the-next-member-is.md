# 26.1024: a pad reaches where the next member is

Status: recorded
Date: 2026-11-14
Source: the goal gap -- builder refusals over the example schemas

**A cpio archive could not be built.** The newc entry pads its name to a
multiple of four from the header's start, `reserved u8
[align_up(HEADER_BYTES + header.namesize, 4) - (HEADER_BYTES +
header.namesize)]`, and C's builder refused it: the expression calls
`align_up`, so no field can be solved for.

**None needs to be.** When the writer reaches the pad, every field its
length reads is down, so the reader's own offset of the member after it
says where the pad ends -- asked over the whole backing, as 26.1015 asks
for a located run. 26.1004 answered the pad after the data the same way
through `_required`, which measures only to the struct's end and so serves
only the last member; this is the one in the middle. Zeros, where the
reserved policy allows them, up to that offset; an offset behind the cursor
is refused. C only: the other three do not write this role.

**Measured by GNU cpio**: a two-entry archive, `hi.txt` holding `hi\n` and
the `TRAILER!!!` entry, each with three bytes of name padding and the first
with one of data padding, is listed by `cpio -it` and extracted by `cpio -i
--to-stdout` to the three bytes written.
