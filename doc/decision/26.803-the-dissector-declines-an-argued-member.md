# 26.803: The dissector declines a member its parent hands arguments

Status: recorded -- fixed (declined); passing the arguments is 0068 step 6
Date: 2026-11-02
Source: found while planning 0068 step 6

    struct entry { parameter u16 block [stream]; u8 tag; u8 data[block]; }
    struct vol   { u16 block; entry(block = block) ent; u8 after; }

Since 26.799 this builds, and the Lua dissector got it wrong. It reads a
parameter from the struct's own preference (`entry.prefs.block`), which
is right when `entry` is the top of a capture. Under `vol` the message
says what the argument is (`vol.block`). The dissector still read the
preference, so it sized `ent` with a number nobody set and placed `after`
on it, as did `vol_extent` and every extent built on that. The four
backends and both walkers were right, and the dissector was confidently
wrong.

## The change

`_member_body` declines a member that has arguments, through
`_uncomputable`, which stops the walk instead of guessing. `_length`
answers None for one, so no enclosing extent function is emitted, and
neither is a variant's length when one of its arms is such a member.

**And a variant that declines now stops the cursor.** `_variant` answered
"one arm has no length this dissector can compute", and "the
discriminant cannot be read", as a bare comment with no `_LOST`. That
left `at` where the variant began, and every member after it was placed
there. `edges`' `hands_on_arms.after` was shown at 51 where the walker
reads 58. That is the hazard `_uncomputable` exists for (its docstring
counts four such branches), and these were a fifth and a sixth. Both now
go through it.

This is the sound half of 0068 step 6. The complete half passes each
argument into the child's extent and dissector: through an `args` table
on the extent function, and a value the parent sets before
`Dissector.get(...):call`, since Wireshark's call takes no arguments.
Rule 5 guarantees the source is always readable, because a constant or a
parent field is in the capture and a `[stream]` parameter is a
preference.

## Tests

`test_a_dissector_declines_an_argued_member.py`: a nested member and an
arm are declined, the child's preference is not read under the parent,
the parent claims no extent, and the variant stops the cursor before
`after`. With `situc/dissector.py` reverted, both fail.
