# 26.759: A region measured from inside places nothing after it

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

From outside a coded region its bytes are the codec's output, so a length
read there is not a length of anything (26.440). `traverse.region_extent`
refused the WALKS -- a delimited run, a `while` run, a counted run of
records, `[remaining]` -- through `unmeasurable_inside`, and listed every
other variable interior member for the backends to measure. Three READS
were in that list, and the backends answered them three ways:

| inside a closed-form region | C | C++ | Rust | Python |
|---|---|---|---|---|
| `piece p` (`u8 len; u8 body[len]`) | header does not compile | reads `len` from the codec's output | same | same |
| `variant v switch (k)`, `k` inside | `UnknownName` | `UnknownName` | `UnknownName` | `UnknownName` |
| `u16 vals[n]`, `n` inside | declines (26.440) | declines | declines | declines |

The first is the dangerous one: over `coded body(doubling) { piece p; }
u8 after;` three backends placed `after` by reading `piece.len` out of
doubled bytes, a wrong parser that compiles and runs. C named
`situ_inside_body_p_extent`, which it emits nowhere, and did not build --
the good failure, which hid the real answer.

`traverse.length_read_inside` names all three -- a count or size
expression naming a member of the region, a variant whose discriminant is
one, a nested struct of no single size -- and `region_extent` returns None
for them as it does for a walk. Every backend already declines what
follows a region with no rule, and now does so here. The differ's
`_region_walks` asks the same predicate, replacing 26.758's local copy of
its first clause, so the two cannot drift.

The same shapes driven from OUTSIDE the region are 26.35's rule and are
unchanged: a discriminant before the region, and a fixed-size nested
struct inside it, still place what follows.

## What else changed

- `pack` called every region with no rule "the codec's expansion has no
  closed form". It now says the interior's length is read from inside
  the region where the codec is closed form.
- Over the 43 committed schemas, the four backends' generated code and
  every packed image are byte-identical before and after (258 files).

## Tests

`test_a_region_measured_from_inside_places_nothing_after_it.py`: the
nested and discriminant forms build all four drivers, agree, and ask
nothing after the region; the outside forms place `after`; the sealed
discriminant generates in all four. With `region_extent`'s new check
removed, the three inside cases fail and the two outside ones pass.

## Still open

Two gated readers, 26.752's family: Python has no gated reader for a
variant's arm inside a sealed region (C, C++ and Rust do), and C has none
for a member of a nested struct inside one. The differ asks both, so the
sealed forms of these shapes are not yet compared.
