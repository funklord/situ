# 26.763: Nothing inside a sealed arm is read unguarded

Status: recorded -- fixed; completes 26.760
Date: 2026-10-30
Source: `project.md` section 26

    sealed body(sealing_aead) {
        u8 k;
        variant v switch (k) { case 1: pair p; default: u8 z; }
    }

26.760 guarded a scalar arm of a variant inside a sealed region and
declined every other arm shape. It left the MEMBERS of a struct arm
alone: `v.p.a` and `v.p.b` are not arms, so every backend still read them
through the gate as plain members, at their offset whatever `k` said. At
`2b0f3c2`, before 26.760, the four-way drivers built with ASan show C and
C++ reading `v_p_b` past the frame (heap-buffer-overflow) on a message
that chose `z`, and C read a run arm `u8 r[3]` past it the same way.

26.760 also made one thing worse. C's `validate` found the struct arm,
now that `arm_of` sees it, and called its `_view` -- which nothing emits
for a sealed arm -- so the generated C did not compile. That would also
have validated ciphertext: `validate` runs on the plain view. And a run
arm, declined by all four, was still asked by the differ's gated byte
probe, so the C driver did not compile.

## What changed

- `traverse.within_a_region_arm` names a member that lies inside an arm
  of a variant in a sealed region. All four decline it in words, in the
  gate and in a waived region alike, and none gives it a setter.
- C's `validate` leaves an arm in a sealed region alone.
- The differ asks neither an arm nor anything inside one as a plain
  gated scalar or byte run.

Over the 43 committed schemas the generated code and packed images are
byte-identical.

## Found by

The probe that came out of 26.760's lens: thirteen shapes inside a
sealed region, four ways, with C and C++ built under ASan and UBSan.
Everything else agreed. It also found `[since]` inside a sealed region
generating C that does not compile (26.764), which predates this
session.

## Tests

`test_nothing_inside_a_sealed_arm_is_read_unguarded.py`: a struct arm
and a run arm, sealed and waived, build all four drivers and agree; no
backend emits a reader for `v_p_b`. With the predicate removed the
reader comes back in all four; with C's `validate` skip removed the
struct arms do not build; with the differ's skip removed the run arm
does not.
