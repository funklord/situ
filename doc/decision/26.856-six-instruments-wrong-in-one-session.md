# 26.856: six instruments wrong in one session, and the two shapes

Status: recorded -- a method finding that spans 26.848 to 26.855, written
because each record carries its own instance and none carries the pattern
Date: 2026-11-04
Source: folding the session that produced 26.848, 26.850 to 26.855

## The six

Every one of these was a measurement taken to check something else, and
every one gave a confident wrong answer first.

1. **Auditing "all nine struct-arm reserved members are enforced"** with a
   grep for `<type>.<leaf> is reserved`: 14 of 36 reported missing. C and
   C++ write `/* reserved u1 [must_be_zero] */`, with no path in it.
2. **The same claim, re-measured** by counting refusal SITES per backend
   with a per-backend pattern: Rust reported zero. Rust emits the
   comparison with **no comment at all**; reading one generated
   `check_which` settled it in a line.
3. **Counting Python's pinned-run checks** by the docstring's shape: 53
   over 22 schemas, where the answer is 11 over 7. The scalar form's
   docstring satisfied the test meant for the run form. Counting by the
   generated comment the run branch emits gave the right number.
4. **The pad-arm accessor gate**, written as a list of definition
   spellings -- `def x`, `fn x`, `x(view`, `std::uint8_t x` and three
   more: C++ passed falsely, its accessor being
   `[[nodiscard]] ::situ::rt::err body_pad(std::uint8_t &out) const
   noexcept` and matching none of the seven.
5. **The same gate, rewritten as a substring test** over comment-stripped
   source: it then fired on the FIX's own loop variable, `body_pad_at`.
   A word boundary is the question as meant.
6. **Two controls that could not fail.** The `DIGITS_VALID` comparison in
   both walkers was neutralised and the gate stayed green: a fixed-width
   text number's ceiling is derived from its own digits, so no
   three-digit spelling can exceed it and the row is a tautology.
   `decimal u8 code[3]` has a ceiling of 255, which three digits CAN
   spell, and `"999"` is the input with an edge.

## The two shapes

**Five of the six inherited one backend's habits.** 1, 2, 3 and 4 are the
same fault: a detector written from the output of whichever backend was in
front of me, asserted of four. The fifth, 5, is the mirror -- a detector
correct about the code before the fix and wrong about the code after it,
because the fix introduced a legitimate use of the thing it forbade.

**The sixth is `evidence.md`'s vacuous pass with a sharper edge**: not a
check over an empty set, but a check over a set whose every member
satisfies it BY CONSTRUCTION. Nothing about the sabotage looked wrong; the
signal was that it passed.

## What to do instead, which is cheaper than any of the fixes

**When a cheap detector disagrees with a claim about generated code, read
the generated code for ONE case before building a better detector.** Steps
1 and 2 above are the same hour spent twice, and the thing that answered
was thirty seconds of reading Rust's `check_which`. A second pattern over
four backends is a second chance to inherit one backend's habits.

**And for a bound, name the input with an edge before trusting the
control.** A bound derived from the field's own width is unfalsifiable by
anything the field can hold; the case has to come from a field whose type
is narrower than its spelling can express.

## Why this is a record and not a memory

The six instances are each written where they happened -- 26.848's two,
26.850's and 26.852's controls, 26.853's two -- and a reader meeting one
of them has no reason to think it is a class. The count is the finding:
one session, six instruments, and the five that shared a shape shared it
because the detector was written from one backend's output every time.
