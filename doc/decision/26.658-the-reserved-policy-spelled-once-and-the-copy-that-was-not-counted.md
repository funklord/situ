# 26.658: The reserved policy, spelled once, and the copy nobody counted

Status: recorded
Date: 2026-10-19
Source: written as a record

26.636 left this open as *"three copies of `_reserved_policy` remain in
the C++, Python and Rust backends"*. Measured before editing anything,
it was **four** functions and **nine** further sites.

	4  functions returning `str | None`   cpp, python, rust, c/checks
	9  a policy SET spelled as a tuple    6 files
	2  aliases already reading `traverse`  c/emit, c/owned

The fourth is `codegen/c/checks.py`, which holds the same convention
behind a `Placement` guard, so a count taken by grepping the three
backends could not see it. **A count inherits its detector**, and the
detector here was the sentence that described the problem.

## They were identical, which is the finding rather than a reprieve

All four bodies matched byte-for-byte. The cost of a duplicated schema
rule is not today's disagreement but the next policy: adding one to
`RESERVED_STATED` is a one-line change that the frozenset picks up and a
literal does not, and **the failure is silent in the worst direction**.
An unrecognised policy falls through to the default, so a field the
schema says must hold ONES would be zero-filled by a writer and checked
for zero by a validator -- the two halves disagreeing about the same
field, each quietly.

## What replaced them

`traverse.reserved_constraint` is the one home for the checked-policy
question -- `reserved_policy`'s sibling, which says what the policy IS
where this says what `validate` must CHECK, folding `preserve` and
`unknown` into None because those bits are carried rather than checked.
The three backends alias it, `c/checks.py` delegates and keeps only its
guard for a non-reserved member, and the nine tuples are
`RESERVED_STATED` and `RESERVED_OPEN`.

## The guard asserts a shape, because the names are ordinary words

`test_the_reserved_policy_is_spelled_once` has two halves. One is that
no module outside `traverse` spells a policy SET, keyed on the PAIR
rather than on a name: `unknown` and `preserve` have 61 uses across the
tree, most of them nothing to do with section 8.8, so a check keyed on
single names would report the tree's vocabulary instead of this rule's
copies.

The other asserts the two functions' RELATIONSHIP over whatever the sets
contain -- every stated name answers itself, every open name answers
None, and the empty case answers the documented default -- so a policy
added to either set is covered without this file being touched.

Both were sabotaged: respelling a set in `python/emit.py` was caught with
file and line, and putting `must_be_one` into both sets failed on the
intersection assertion. 2053 passed over the suites that reach these
paths.
