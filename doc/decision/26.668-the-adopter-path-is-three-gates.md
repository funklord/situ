# 26.668: The adopter path is three gates, and none substitutes

Status: recorded
Date: 2026-10-21
Source: `project.md` section 26, from `suggestion/openmlx4.md`

`openmlx4` closes its report with what it would take today: a committed
schema and map, **both** `situc map --check` and `situc verify` in `make
check`, and vectors from a real card rather than from its own fixture.
Its reason for the pair is right and is quoted here because it is the
argument this record extends: *"Both gates, because `map` alone accepts
schemas the compiler refuses."*

**Tested fully from an adopter's position**, which is the only position
that answers the question: a five-field NV schema written outside situ's
tree, its artifacts committed beside it, and every gate driven through
`bin/situc` as a Makefile would.

## Three faults, one per gate, each invisible to the other two

    a field order swapped, both artifacts regenerated
        map --check  passes     wire --check passes     verify FAILS
    `[max = 7]` added to a field
        verify passes           map --check passes      wire --check FAILS
    a member renamed
        verify passes           map --check FAILS       wire --check FAILS

**The middle row is the finding.** `map --check` does not report a value
domain, because a domain is not a capability: `[max = 7]` and
`[must_eq = 1]` both move the wire signature and **neither moves the
map**, measured rather than reasoned. So the pair `openmlx4` asks for is
silent about a narrowed or widened bound -- and for NV parameters written
to a card's flash, the bound is the contract. `situc wire --check` is
where a sender's constraints live, and 19.3's compatibility linter is
the gate that catches them.

The first row is the one `openmlx4` already argues for, in the stronger
form: regenerate BOTH artifacts and both are current, because the schema
is internally consistent and simply wrong about the bytes. Only a corpus
from outside can say so, which is why their ask for vectors from a card
rather than from `test/imggen.h` is the other half of the same point.

## What each gate is for, in one line

- `map --check` -- the capabilities: offsets, extents, alignment, repr,
  atomicity. A reviewable diff when a layout edit costs a capability.
- `wire --check` -- the contract a sender must satisfy and a receiver may
  rely on: constraints, bounds, coverage, the item grammar's arithmetic.
- `verify` -- the bytes: a schema's reading of a corpus somebody else
  produced.

Held by `test_the_adopter_gates_are_three_and_none_substitutes` rather
than asserted, with the control above it: all three pass on what was
committed, so each failure below is the fault and not the setup.

## The third gate was documented and the distinction was not

`README.md`'s smaller-bargain section already lists all three, in this
order, and already says `verify` is the one the other two cannot do. So
this is not a documentation gap and `openmlx4` did not miss a feature:
they named two of three in an ask, and nothing in the text said which of
the first two would see a narrowed bound. That sentence is there now,
with the measurement behind it.

Which is the shape worth keeping: **a list of three tools is not the same
document as a statement of what each one alone misses**, and an adopter
choosing a subset needs the second. The list had been right for months
while the only thing that decides a subset was unwritten.

## Two things the testing found

**`verify` caught the test's own arithmetic.** The vector's first byte
was hand-computed as `8A` for `boot_retry_cnt = 5`; `8A` is
`1 00010 10`, so the field holds 2, and the gate said so by name. That
is the one fault class neither committed artifact can reach, demonstrated
by accident on the first run.

**A docstring in `test_examples.py` had called `map --check` "phase 9"
for 77 days.** Both it and `verify` landed 2026-08-05 in one commit, and
the stand-in test written *until* the CLI existed was the only thing in
the tree still saying it did not. `evidence.md`'s shelf-life rule met in
the file whose whole job is holding a snapshot current -- and the reason
it went unnoticed is that the sentence is true-sounding, dated nowhere,
and in a docstring nobody re-reads while the test passes.
