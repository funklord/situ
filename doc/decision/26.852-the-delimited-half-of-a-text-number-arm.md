# 26.852: the delimited half of a text number arm

Status: recorded -- fixed in all six readers, which closes 26.423's
deliberate decline and 26.850's named next piece
Date: 2026-11-04
Source: 26.850, which fixed the fixed-width form and left this one with the
reason 26.423 gave for leaving it

## The construct, and it is in the corpus

    case 1:  decimal u32 code[] until " " max 4 [min = 200, max = 599];

`edges.wide_delim_arm.held.code`, which has been in the tree for weeks. Its
terminator was checked. Its `decimal`, its `[min]` and its `[max]` were
checked by **none of the six readers**, measured across all of them:

    01 "199" " " 5A     four backends 0    both walkers 0
    01 "600" " " 5A     four backends 0    both walkers 0
    01 "ABC" " " 5A     four backends 0    both walkers 0

## Why it was left, which was a real reason

26.423 declined it in all four backends **together, deliberately**, and
said so in each one's source. The obstacle it named: the member path's
blocks read the member's parsed value through an accessor of its own name,
and an ARM's accessor of that name answers its BYTES -- so reusing them
generated `self.held_num < 200` against a `bytes`, a TypeError waiting for
a message. Python's note put the stance plainly: "Before this entry all
four checked NOTHING on a delimited arm, so they agreed; a partial port is
the one outcome worse than the gap."

That is the right instinct and it is why this entry exists rather than a
regression: the four agreed in silence, and agreement in silence is a
state a differential cannot distinguish from agreement in correctness.

**What answers it is 26.850's clause**: parse the SPAN rather than reuse a
parsed accessor. Every backend already hands out the span for a delimited
arm -- C's `_ptr` through two out-parameters, C++'s `held_code(bytes&)` and
`_len()`, Rust's `Result<&[u8]>`, Python's content property -- each guarded
by the discriminant, which is what makes reading it safe at all.

## The fix, and the one thing it needed that 26.850 did not

Four emitters and the packer. **The walkers needed nothing NEW, which is
not the same as needing nothing**: `digits_of` and `parse_digits` already
read a delimited placement through `scan`, so the member path's own scans
answer an arm's span unchanged -- but the two digit KINDS they answer for
on an arm were added hours earlier by 26.850, along with the read-failure
distinction that makes a failed parse `Constraint` rather than `Bounds`.
Without that commit this one would have needed both. Worth stating because
"the walkers needed nothing" is the sentence a later reader would carry
forward, and it is only true in that order.

**The packer needed two changes, not one, and the second is the entry's
lesson.** Writing the spelling and digits rows left the four backends
refusing `199` and both walkers taking it -- half a check, which is the
shape this tree distrusts most. The cause is a classification: a delimited
text number is `Check.DELIMITED`, not `Check.TEXT_NUMBER`, because the
classification names how the span is FOUND and the delimiter is the more
specific answer. So the arm pass's value rows -- `[min]`, `[max]`,
`[must_eq]` -- are gated on a test that a delimited text number does not
survive, and the digits row above it is written by a different branch that
does reach it.

**One construct, two rows, two gates, and only one of them was open.** The
first measurement after the fix is what found it, which is the argument for
measuring each half separately rather than the fix as a whole.

**And the obvious form of that second change asserted a clause of the whole
class.** Letting `DELIMITED` through the value-row test lets EVERY delimited
arm through it, and a delimited byte-run arm carrying a `[max]` would then
get a value row the four backends do not write -- with both walkers
comparing it against a scalar read of a SPAN. No schema in the corpus has
that shape, so no image would have changed and nothing would have said so.
The test is `DELIMITED` **and a radix**, which is what the backends' own
clause asks. Caught before it landed rather than after, which is the only
difference between this instance and the night's others.

## Controls

Three, each neutralised and watched to fail:

- the four emitters' clauses, blanked in-process, fail the four-backend
  delimited case and leave the walkers green;
- the packer's digits rows fail the walker delimited case;
- the packer's `DELIMITED` in the value-row test fails the same case, for
  the other half of the reason.

And the scope is measured rather than argued: 172 generated file sets -- 43
schemas in four languages -- differ in **`edges` alone**, in all four, and
one image is 48 bytes longer. `edges.situ.map` and `edges.situ.wire` are
byte-identical, the constraints having always been in the schema and the
signature.

## What is left of the class

Nothing named. A text number in an arm is now checked in both its forms by
all six readers; a pad in an arm is declined by all six and recorded in
26.848; a tlv arm and a varint arm are declines the generated files name.
