# 26.936: the dissector follows a recursion to its depth

Status: recorded
Date: 2026-11-08
Source: the tally after 26.935, where most of what the dissector still declined was a recursion cycle

**A struct that can contain itself has an extent in Lua now**, bounded as the readers
bound it. Every extent function in a cycle is declared ahead of the rest, so the cycle's
functions can call each other, and each counts how deep it is and measures nothing past
its struct's `[limit]`, or its `[depth]` where there is no limit. A zero extent already
ends every walk and is never dissected, so the bound holds for the dissector calls as
well as the measurements. It said "this file carries no depth" and declined, so CBOR
showed the first array's head and stopped, and so did JSON and the s-expressions.

Asking for a cycle's extent used to run `gen-dissector` out of stack (26.904). It is
asked now as `traverse.has_computable_extent` asks it, assuming that a struct already
being measured measures, and each answer is kept for the schema, since a recursive
struct's question reaches every struct in its cycle.

**A counted run's span takes its count from the caller.** The span read the count from
`at_struct`, which cannot name a count standing past a variable member, so a struct's
extent could name a span that was then never written: `node.kids` in
`test_a_recursive_struct_takes_arguments`, which Lua met as a call to nil. The caller
renders the count where it is readable, with whatever it has captured.

In real tshark, `[1, [2, 3], [4, 5]]` and `{"a": 1, "b": [2, 3]}` show every value and
key, and a hundred nested arrays stop at the sixty-fourth with no error.
