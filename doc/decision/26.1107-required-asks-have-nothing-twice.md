# 26.1107: `required` asks `have` no question it has already answered

Status: recorded
Date: 2026-11-19
Source: the cppcheck lens over the corpus (26.1091, 26.1092), continued --
102 `knownConditionTrueFalse` findings in the generated C, the consumer
noise raidcfgd reported in 26.1074's shape

**Over half of them were one fact asked again.** `required` takes `have`,
the bytes that have arrived, and never changes it; it opens with
`if (have < floor)` where a peek needs bytes, and frames each member behind
`if (have < K)` in order. A later guard on a constant at or below one
already passed cannot be true -- `if (have < 5u)` after `if (have < 6u)` in
ARP -- and a discriminant's `(have >= 1u ? read : 0u)` after a guard on 1
cannot be false. Each is a condition a static analyser names in a
consumer's build.

## The change

`_required` keeps the largest constant `have` has been held to on the path
so far -- the opening floor, then each member's constant guard -- and a
guard or a discriminant's bounds check on a constant at or below it is not
emitted, nor the comment explaining it. The value is threaded through the
nested and variant framing as an argument rather than kept on the emitter:
framing a variant asks `_required` of its arms' structs, and a value on
`self` was overwritten mid-function -- which the first version did, so that
the opening floor the fix rested on read 0 by the time it was asked.

## Measured

Over the corpus: `knownConditionTrueFalse` 102 to 51; `have >= N` 34 to
0, `have < N` 19 to 3. The remaining shapes are other questions -- an
error code a branch has just set (`e != SITU_OK`, 22), a fixed size
compared with itself (12), `have < pos` (10), `end < start` (4).
