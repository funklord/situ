# 26.810: An arm's interior is not behind its own variant

Status: recorded -- fixed
Date: 2026-11-02
Source: `test_nothing_claimed_unplaceable_gets_an_accessor`, on 0068's
`hands_on_arms`

    variant body switch (kind) {
        case 1:  negotiated(block = block) one;
        case 2:  negotiated(block = 3) many[n];
        default: u8 raw;
    }

`traverse.offset_unresolvable` called `hands_on_arms.body.one.trailer`
unplaceable, while all four backends place it through `one`'s own view.
The predicate walks the members in front of the one asked about. A
variant with a counted-run arm blocks what FOLLOWS it (26.785), and the
walk handed it the variant that holds `one`, so a sibling arm's run
"blocked" a member inside a different arm.

No corpus variant had both a struct arm with variable interior and a
run arm until `hands_on_arms`. The differ and the propagation table read
this predicate to skip members, so the fault was a comparison silently
given up rather than a wrong answer.

## The change

The variant that holds the member is passed over: its arms' walks place
what follows the variant, not what is inside one of its arms.
