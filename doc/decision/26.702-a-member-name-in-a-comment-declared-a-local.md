# 26.702: a member name in a comment declared a local

Status: recorded -- fixed
Date: 2026-10-27
Source: `project.md` section 26

**C's `required` decides whether to declare `situ_view_t view;` with a
bare substring test over its own rendered steps, and each step carries
`/* s.<name>: ... */`.** So the test answered about the schema's names as
well as about the code:

    struct s { parameter u8 blk [stream]; u8 view[blk]; u16 tail; }

    error: variable 'view' set but not used [-Werror=unused-but-set-variable]

Measured, five of five: `view`, `preview`, `viewport`, `overview`,
`reviewer`. **Four of the five contain `view` without being it**, so a
word boundary would not have been enough -- the name is in a COMMENT, and
the fix is to strip them before testing. `i` is clean.

**The Rust sibling has stripped comments since it was written and its
comment says why**: `Dirty` appears in a doc comment there, "so a bare
substring search imported it for schemas that never touch one -- and
`unused_imports` is an error under `-D warnings`". This is that, arriving
in C by the same route, and `uses_cursor` one line above is tested the
same way for the same reason: nothing stops a member being named for the
cursor either.

**Blast radius: none.** All 92 generated C files byte-identical, and all
92 compile in both modes under the project's own warning set. No corpus
schema has a member whose name contains `view`.

**Control:** reverting the strip fails the new test with the error above,
with `i` still passing.
