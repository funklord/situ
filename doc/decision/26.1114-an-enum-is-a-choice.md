# 26.1114: an enum is a choice, and every cell editor is constrained

Status: recorded
Date: 2026-11-20
Source: the holder, 2026-11-20: "special widgets for certain datatypes too,
like the searchable combobox for enums ... Do we have a type in situ that
takes a set of predefined values or any value?", and then: "There are a lot
of quirks in Qt when configuring text fields ... you need to test the GUI
constraints, and also that Qtty follows them, as it is new."

situ has had the type since section 8.7: `enum E : u8 { a = 1, ... }`,
closed by default (`default = error`: a value it does not name is refused)
and open with `default = pass` (any value; the names are a vocabulary, not
a fence). The editor showed an enum field as a bare number and took a
number back, because the image it reads carried a closed enum's VALUES --
enough for a walk to check membership -- and no names, and an open enum's
nothing at all.

## The change

- **The image's tail carries the members** (`choices`, section 34,
  `image_choice` in `std/image.situ`): per enum-typed placement, each
  member's name and value and whether the enum admits others. Ancillary
  and under `--metadata` only, like the names it sits beside: a walk reads
  every member exactly as before, and an older walker skips it. A byte-run
  enum (`u8[2] { bmp = "BM" }`) is a signature rather than a choice and is
  left out.
- **The view shows `server (4)`** -- the member and its number, as
  Wireshark does, the number kept for a reader holding a hex dump -- and
  each row carries its `choices` and `admits_other`. `--put` (and so the
  TUI's prompt and the window's cell) takes a member by name, by the row's
  own `server (4)`, or a number.
- **The window edits each cell with the widget its field wants**
  (`gui/cell_editor`): an editable combo whose completer matches anywhere
  in a name (`cast` finds `broadcast`), taking only member text for a
  closed enum and a number too for an open one; a number field that takes
  decimal or `0x` hex; a hex field no longer than its run. Text the
  validator does not accept is never committed, on Return or on focus
  leaving.

## What testing it found

Every case presses real keys into the real editor (`--keys`), through
Qt's delivery and through qtty's `InputRouter`
(`test_the_window_constrains_what_can_be_typed.py`, 24 runs). Two faults
appeared on the first run, both the same on both deliveries:

- **Return did not close an enum's editor.** The view commits on Return
  through an event filter on the editor, and an editable combo's line edit
  and completer take the key first, so a choice sat in an open editor until
  focus left it. The editor now commits on its line edit's Return -- which
  Qt emits only for acceptable text -- and on a pick from the list.
- **Closing a window with an editor open was a segfault.** The table's
  destruction closes the editor after the window's session is gone, and
  closing commits. The window's destructor stops commits first.

Removing the Return fix and the run's length cap failed exactly the ten
runs they govern, five on each delivery; removing the range, the six range
runs, three on each.

## What qtty does not draw yet

Driven in a real terminal (tmux, `--tui`), the enum cell's completer list
is routed and never drawn: typing `cast` shows no list, yet Down selects
`broadcast (5)` and Return commits it. qtty's router tracks the popup (a
visible `QListView` inside the frame) and its compositor draws nothing
there. qtty's to fix; signalled to its inbox (20261120T1120Z). The key
tests above check input and values, not the picture, so they pass; a
snapshot check of the list belongs here once qtty draws it. `--snapshot`
now composes the screen through the router (`snapshot_of_screen`), so it
will show the list when there is one.

## The number field knows its range

`-31` into a `u8` was typed and then refused by the core ("does not fit a
8-bit unsigned member (0 to 255)"). The rule is now asked before the write:
`walk.scalar_range` gives the lowest and highest value `write_scalar`
would store -- the same width, sign and packed-decimal rule, so `bcd2
[bits = 7]` stops at 79 -- `Field.bounds` carries it, and the view gives it
as text (`low`, `high`), since a 64-bit bound is not a double. The number
field refuses a sign on an unsigned field and any digit that takes the
value past a bound; the curses TUI's prompt says the same in words
(`other (0 to 255) = `, `m (client, server, broadcast) = `).

The schema's own `[min]` and `[max]` are not in that range: they are
checks a message can fail, which the verdict reports, not limits on what
can be stored -- an editor that refused 61 seconds could not build the
refused message a test needs.
