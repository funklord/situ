# 26.1102: a `when` may read a `let` of its struct

Status: recorded
Date: 2026-11-19
Source: the README's own claim -- a `let` is "usable by any expression after
it" -- against `when s.total > 10`, which every backend refused as "`s` has
no field `total`"

**A `let` was readable by a size and not by a `when`.** `wellformed` held
each step of a `when`'s path to a member, and a `let` is not one.

## Not inlined

A `let` is computed modulo 2^64 and held to its width (26.1056), so its
expression substituted into the predicate would compute something else: a
`u8` total of 255 and 2 is 1, and `a + b` is 257. A signed `let` would need
its sign extended, which the expression language has no short spelling for.
So every reader asks the let itself:

- the four backends through its getter, which already holds it to its
  width -- C's `situ_s_total_get(view)`, C++'s `this->total()`, Rust's
  `self.total()` (its sign counted in the width the rule computes in),
  Python's `self.total`;
- both walkers through a new op, `LET` (0x0E, a u32 row): the lets section
  already carries each let's program, width and sign (26.1059), so the walk
  runs that row's program and holds the value as the getter does. The
  packer writes the lets before the `when`s so each has a row to name.

The dissector registers the message and declines to evaluate it, as it
declines a `let` it cannot compute exactly in Lua's doubles.

The scope is a `let` of the `when`'s own struct, named in one step. A
`let` of a nested struct is reached through that struct's getter, which a
`when` over the parent does not have; it stays refused as before.

## Measured

`test_a_when_may_read_a_let`: three lets -- a `u16` the sum fits, a `u8`
it wraps, an `i8` that goes negative -- through four backends and both
walkers on eight frames; with the packer's `LET` disabled the walker test
fails. `edges.let_rule` carries the shape through every edges reader.
