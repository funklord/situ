# 26.1044: a chain ends on a sentinel

Status: recorded
Date: 2026-11-17
Source: openmlx4's FS2 report, item 3 -- "the end is a sentinel,
`next == 0xFF000000`, and no situ construct ends a located chain on one"

    struct chain [depth = 64] {
        hdr     head;
        u8      data[head.size];
        variant rest switch (head.next) {
            case 0xFF000000: nothing none;
            default:         chain following at head.next;
        }
    }

**After 26.1041 a located chain built and validated, and no such chain
could validate**: its last `next` points somewhere, and outside the message
that is BOUNDS. The spelling above is the grammar's own -- an optional member
is a variant with a `nothing` arm, as PES and JSON write it -- and was refused
by name: "`at` on a variant arm member is not implemented".

## The rule

**One struct placed by `at` may be an arm.** It occupies nothing in the
frame, so the variant measures it as zero; where the arm is selected it is
reached from the message as a located member is, and validated over its own
extent there. Depth is counted along the chain as 26.1041 counts it.

Every other located arm is still refused by name -- a scalar, a byte run, a
run of structs -- for 26.124's reason: no backend's arm path consults `at`
for one. The overlap that paragraph defers is no new question for a struct
arm: a located member may already land anywhere, the discriminant included.

## What carries it

Each backend's arm accessor is its located accessor behind the arm's test,
refusing `VERSION` for another arm and BOUNDS where the view has no message;
`validate` reaches the arm through the view's owner (C, C++), through
`validate_in(msg)` (Rust, whose struct now takes the message where a located
arm is reached), or through `_view` (Python). The depth probe follows it as
26.1041's does, the arm's guard first in Python. Both walkers measure a
located arm as no bytes of the variant and validate it from the message; the
Python walker's frame-span arm check skips one. The dissector steps over it.

## Measured

`test/unit/test_a_located_chain.py`, the sentinel shape: one section, three,
nine (eight deep, the declared depth) and three apart with a section-shaped
header in the gap all validate in C, C++, Rust and Python; three ending
outside the message are BOUNDS; a section pointing at itself and ten deep are
CONSTRAINT. Nesting agrees in all four. The walkers agree with each other and
with the backends but for the depth, where they cannot say -- nine sections
included, which is 26.1043's open item. C's `required` asks for one
section's bytes in both shapes, and the dissector steps over ten.

FS2's variant is a fixed zero bytes -- `nothing` and the located arm both
are -- so its size is never summed. A located arm beside a variable one is:
`test_c_places_what_follows_a_located_arm` reads the member after such a
variant at offset 2, and with C's variant length counting the arm it read
two bytes late.
