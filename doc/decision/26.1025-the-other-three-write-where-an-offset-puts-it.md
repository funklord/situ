# 26.1025: the other three write where an offset puts it

Status: recorded
Date: 2026-11-14
Source: 26.1015, which was C's alone

**26.1015 let C write a struct's trailing run where an offset already
written puts it** -- BMP's pixels at `file.pixel_offset` -- by asking the
reader where the run lands over the whole backing. Python, C++ and Rust
refused the role, and Python could not have asked: its reader hands the run
back as a memoryview, which keeps no offset into the buffer it was cut
from.

**Python's reader now says where a located member starts**, as a
`<name>_offset` property beside the bytes, under the same frame check. It
is additive, and the one reader that needed it: C answers with the run's
own view, C++ and Rust by the run's distance from the backing's start.

**And the three builders write the role as C does**: ask the reader over
the whole backing, refuse an offset behind the cursor or a run not as long
as the message says, zero any gap, copy. Only in a struct taking no
arguments, whose reader can be asked without them.

**Measured**: Python's builder writes the 1x1 bitmap with its pixels at 54
and at 64, which Pillow decodes as (0x30, 0x20, 0x10), the gap zero, and
refuses an offset of 40 inside the headers; Rust's writes the same bytes
and refuses the same offset; the agreement test compiles and runs the
role in all four.
