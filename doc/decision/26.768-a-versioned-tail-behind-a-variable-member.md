# 26.768: A versioned tail behind a variable member

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

    struct varv [version = ver] { u8 ver; u8 n; u8 d[n]; u16 x [since = 2]; }

26.766 gave a versioned struct its own version's length where every member
sits at a static offset (`traverse.version_steps`). Behind `d[n]` no
member does, so that function declines, and the general path counted `x`
whatever the version said. All four backends framed the whole version-1
message `01 02 05 06` at six bytes, swallowing two bytes of the next
message in a stream, and placed a member after a nested `varv` two bytes
late. Both walkers already skipped an absent tail member wherever it sits
(26.766's `_absent_tail`) and were right.

`validate` refused the same message, in all four. The minimum it opens
with is the layout's `size_bits`, which `_first_versioned` lowers to
version 1's extent only where the first `[since]` member has a static
offset. C++, Rust and Python then asked whether the frame held `x` before
asking whether the version carried it. C asks inside the version guard,
and there the dynamic bounds check matters: the versioned accessor tests
the frame at a static offset and not at a dynamic one, so with the check
simply dropped the three accepted a version-2 message one byte short.

## The change

- `traverse.versioned_tail`: for a struct `extent_parts` measures, the
  version field, the bytes the constant counts for the `[since]` tail,
  and the bytes each version step adds. Only where the tail is fixed
  scalars after every unversioned member, the version field is at a
  static byte offset, and each step ends on a byte.
- All four `required` open `at` without the tail and, after the walk,
  add what the message's version reaches once the version has arrived.
  All four extents do the same, reading the version through the view.
- `framing_floor` leaves the tail out, since it must equal what
  `required` opens at (26.724). With the tail in, a counted run of
  `varv` was told 16 and then 13 as an element arrived.
- `layout._versioned_tail_bits`: the minimum less the tail where no
  `[since]` member is at a static offset.
- C++, Rust and Python ask a `[since]` member's frame check inside the
  version guard, as C does.

The corpus has no such struct and generates byte-identically.

Not done: the Wireshark dissector sums a nested versioned struct's
members the same way, for this shape and 26.766's.

## Tests

`test_a_versioned_tail_after_a_variable_member.py`: the four frame a
version-1, -2 and -3 `varv` at 4, 6 and 5 with more bytes following.
They also place `after` past a nested one, frame a run of one of each at
17, and never let a `required` answer fall as bytes arrive. All four
agree on `validate` for a whole and a short message of each version, and
both walkers place `after` alike. With `situc` reverted, framing and
`validate` fail. With only the floor's tail subtraction reverted, the
run's answer falls from 16 to 13.
