# 26.929: the offset cache counts bits

Status: recorded
Date: 2026-11-08
Source: the gate over 26.928, which made a wrong offset a compile error

**`--materialize` placed radiotap's members early, silently.** The offset cache is
one pass over the members, summing what each fixed one adds, and the plan all four
backends share summed in bytes: each of radiotap's 32 present bits is under one, so
the 4 bytes they occupy counted as none. C's cache also counted an `[align]` pad in an
arm as nothing. With flags present and rate absent, `channel` starts at byte 10, which
its own accessor says; C's cache on master said 5, 4 short for the bits and 1 for the
pad. The other three were not run on master. Nothing compared a cache with the
accessors it stands in for.

26.928 gave a pad at a variable offset a length, which named the pad's own offset
accessor -- one no backend emits for an arm's pad -- and C stopped compiling. The
fault was older than the error.

**The plan keeps its running total in bits** and flushes it as bytes. **An arm that is
only a pad is measured from the offset in hand**, which is where the variant starts:
`codegen.arm_offset` says when, for all four, beside the old rule that only a cursor's
extent hands its offset into an arm. Python and the others had built that pad's start
as a chain from the head of the struct, correct and growing with every member.

`test_materialized_offsets_agree_with_the_accessors` holds C and Python to the
accessor on that message; C++ and Rust were run by hand and say 10 as well.

**A region's interior was summed the same way.** `region_extent` added each fixed
member's bytes, so `coded body(doubling) { u4 a; u4 b; u8 content[n]; }` measured
two for one byte of content where it holds four, and the member after it was read
from inside the region, in all four and both walkers. It counts bits now and
declines an interior no whole bytes hold.
