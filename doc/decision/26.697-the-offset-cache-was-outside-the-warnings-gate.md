# 26.697: the offset cache was outside the warnings gate

Status: recorded -- fixed, and one duplicate function removed with it
Date: 2026-10-27
Source: `project.md` section 26

**`situc build --target rust --materialize` emitted Rust that rustc
refuses.**

    struct s { u8 n [max = 4]; u8 b[n]; u16 tail; }

    error: unnecessary parentheses around function argument
      at = situ_rt::advance(at, (situ_rt::nonneg(situ_rt::leaf_u(...))),
                            self.bytes.len());
    note: `-D unused-parens` implied by `-D warnings`

Without `--materialize` the same schema is clean, measured both ways in one
run. 26.496 made `-D warnings` the standard for generated Rust on the
argument that generated code which warns teaches a reader to ignore
warnings, and **the offset cache was outside what that gate reached.**

**Why the one compiled test for the flag could not see it.**
`--materialize` is exercised by
`test_the_cache_agrees_with_the_per_member_offsets`, over `CHAIN` -- three
delimited runs, `until " "`. A delimited run's length is a scan and
renders bare. A SIZED run's `[max]`-bounded count renders as
`(situ_rt::nonneg(...))`, because the field renderer parenthesises every
read, and as a whole function argument that pair is what `-D warnings`
refuses. **The flag's only compiled fixture had the one construct that
cannot reach the hazard** -- which is `evidence.md`'s
test-covers-the-safe- path, at the level of the construct rather than the
assertion.

**And the corpus could never have caught it.** Measured both directions:
the materialized Rust for all 46 generated modules is **byte-identical
across this fix**, and so is the plain output for all four backends across
230 files. No committed schema reaches a materialized sized run, so the
constructed fixture is the only evidence there is, and the new test carries
it.

## The fix, and a duplicate it removed

`names._unwrap` exists for exactly this shape and says so -- *"the field
renderer parenthesises every read, and `-D warnings` calls a parenthesised
function argument unnecessary"*. It was private, with one caller in
`rust_spelling`. It is `unwrap_parens` now, with three.

**Reaching for it found a second copy of itself.** `codegen/rust/emit.py`
carried `_unwrapped`, which is the same function written twice -- same
guard, same loop, and a docstring making the same argument about `(a) +
(b)` not being a pair. Established behaviourally rather than by reading:
**4,016 inputs, zero disagreements**, against a control (a naive stripper
that just removes the first and last character) which disagreed on 589, so
the comparison can tell two functions apart. The local copy is gone and its
one caller uses the shared name.

That is this workspace's own rule met from the inside: a second copy of a
thing is a second thing to be wrong, and here the two had not yet drifted
-- which is the only reason collapsing them is free.

**Control:** reverting the two `advance` sites fails
`test_the_offset_cache_compiles_for_a_sized_run` with the rustc error
above, which is the check under test speaking rather than a neighbour.

## And mypy found a second defect in the same two lines

**Typing the call surfaced what the untyped f-string had been hiding.**
`_length_expression` returns `str | None`, and both sites formatted it
straight into

    f"\t\tat = situ_rt::advance(at, {length}, self.bytes.len());"

so a None would have reached generated Rust as the four characters
`None` -- **26.485's class**, which this tree has a gate for, in the one
mode that gate does not read. There was no guard at either site, and
nothing said so until `unwrap_parens`' signature made mypy ask.

**It answers None for two documented cases**: a run whose length is the
codec's output (`length_is_transform_output`), and such a run inside a
variant arm. Both look reachable and neither is, over everything I could
write: 42 corpus schemas and six constructed shapes -- an arm holding a
delimited run, an arm holding a `while` run, an arm holding a counted run,
a plain delimited run, and a delimited coded region with a member after it,
which is the shape `edges.situ`'s own comment says was added because
nothing had it.

So it **asserts** rather than branching. What the length should be in that
case is not obvious, and a plausible invented one is worse than stopping --
the same trade 26.442 recorded for two `pack.py` sites no schema reaches.
The assert names the member and cites this entry, so whoever first
constructs the shape gets a sentence rather than `None` in a `.rs` file.

**This is the second time in two days that reaching for a typed helper
found a latent defect beside the one being fixed**, which is an argument
for the narrow-but-typed edit over the broad untyped one.

## Left open

**Nothing in the corpus exercises a materialized sized run.** Putting the
construct in a corpus schema would make every future gate run ask this
question instead of one unit test, and this tree's own experience is that a
construct added to the corpus pays out immediately. It is not free: a new
member in `test/schema/edges.situ` moves layouts and the packed images,
which wants its own verification pass. Recorded as the next step rather
than bolted on here.
