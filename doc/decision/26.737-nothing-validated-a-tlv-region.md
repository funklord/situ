# 26.737: nothing validated a `tlv` region

Status: recorded -- fixed in all four backends and both walkers
Date: 2026-10-29
Source: `project.md` section 26

Found by the lens 26.735 and 26.736 handed on: a check that cannot see a
walk which stopped early. Here there was no check at all. `validate`
said nothing about a `tlv` region in any of the six readers, and each
reader's walk stops at the first item it cannot read and counts what came
before. `example/protobuf`, measured in C and then in all four:

    { 0x08, 0x96 }               a varint value cut       count=0  validate 0
    { 0x12, 5, 'a', 'b' }        a length of five, two    count=0  validate 0
    { 0x0B, 0x00 }               wire type 3              count=0  validate 0

The third is a wire type the schema declares `default: error`. A CoAP-shaped
region, whose value size is a nibble of its own tag, did the same. So
protobuf -- which section 9.7 calls the language's hardest conformance test,
and which section 2 now says situ must handle completely -- had malformed
messages called valid.

## The fix

Each backend's cursor gains a `_whole` beside `first`, `next` and `count`.
It walks the items and returns OK where the walk ends at the region's end,
and otherwise the error that stopped it. That error is already in each
backend's item reader: BOUNDS for an item the frame cuts short, CONSTRAINT
for one no rule admits. `check` calls `_whole` and returns its error under
the member's id.

- Python's `_whole` is a property, because its `validate` relabels an
  access that raises -- `_ = self.x` -- with the member's id.
- Rust's call is `if let Err(e) = ... { return Err(e); }` rather than
  `?;`. The id is set on the line before a refusal, and a `?` line is one
  whether it refuses or not, so a passing check would have left `*which`
  naming the member.
- The walkers' loops became `_tlv_walk` / `tlv_walk`, which return why
  they stopped, and the count reads them. Each walker's validator refuses
  on it. The check kinds are the nearest the image already has --
  `fits_frame` for a cut item, `arm_selected` for one no rule admits --
  rather than a new number in the packed format.

The fix belongs to the shape rather than to protobuf, which is what section
2 asks of protobuf work.

## What it uncovered

Section 14.5 says unknown TLV tags are rejected by default. Measured with
`known = { 1: ... }` and no `unknown` clause, an item tagged 2 validates OK
in all four. That is 26.738.

## Verified

`test/unit/test_a_tlv_region_is_validated.py`: five protobuf cases and three
CoAP cases through the four built backends and both walkers, asserting the
exact verdict. Controls: with the emitter half stashed, the four answer
`validate 0` for a cut varint, and each walker fails with its own half
stashed.
