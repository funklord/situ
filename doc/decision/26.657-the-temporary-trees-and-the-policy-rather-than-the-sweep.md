# 26.657: The temporary trees, and the policy rather than the sweep

Status: recorded
Date: 2026-10-19
Source: written as a record

`tmp_path_retention_policy = "failed"`, set by the holder 2026-10-19,
after the trees were cleared by hand three times: 8.5, 4.7 and 4.7 GiB.

**Each time the COUNT was the policy working correctly.** pytest keeps
the last three roots by design, and a full `make check` leaves 2.4 GiB
of generated code and compiled binaries per schema per backend, so the
default holds about 7 GiB on a filesystem with 22 free. The size is what
made it matter, which is why the fix is the policy and not a `clean`
target -- a sweep over `/tmp/pytest-*` is also the shape
`CLAUDE.md` forbids, since those roots are shared with every other
session of this account.

Measured after wiring it:

	a passing run, 918 tests    2.4 GiB -> 4.0 KiB
	an interrupted run          the working set -> 520 KiB

**The interrupted case is the one that was worst and is now fixed,
which was not the reason for the change.** `running-code.md` records
that pytest prunes at the START of a run, so a run that is killed is
never retired on schedule while the numbering advances anyway -- nine
roots and 6.2 GiB in one evening of killing runs. The reason this fixes
it is that `failed` drops each passing test's directory as that test
ends rather than at session end, so an interrupted run leaves only the
test in flight. 520 KiB, measured on a run killed at its bound.

**And the run that measured it was killed by my own mistake**, pairing
`test_codegen_c.py` with `test_walker_c.py` under a 900-second bound --
143 seconds against eighteen minutes, which 26.649 says to bound
separately. The failure produced the better of the two measurements.
