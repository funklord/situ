# 26.1002: six Rust builders did not compile with warnings denied

Status: recorded
Date: 2026-11-13
Source: 26.1001's lens -- generated code compiled only with `-A warnings`
-- turned on every Rust builder in the corpus

**Measured: 6 of the corpus's 50 Rust builders failed `-D warnings`**, each
compiled as a library beside its module: cpio (13), ustar (8), edges (3),
http (2), smtp (1) and hpack (3). A consumer whose crate denies warnings,
which is common, could not build any of them. Nothing here noticed,
because `test_the_four_builders_agree` -- the one test that compiles every
builder -- passed `-A warnings`, and the Rust lint sweep builds modules and
not builders.

Two shapes, both in `situc/codegen/rust/build.py`:

- **`unused_parens`**: a text number's value written as
  `format_uint(..., (code as u64))`, and assigned as
  `let situ_left: u64 = (code as u64);`. The parentheses stay where a
  method or a comparison follows (`(x as i64).unsigned_abs()`,
  `(x as i64) < 0`, where Rust needs them) and wherever the value has an
  operator in it, and go where it stands alone.
- **`unused_comparisons`**: a varint whose value the schema STATES was
  checked against its limit at run time, `if 0u64 > 4294967295` in hpack.
  A stated value is known when the code is generated, so the check is
  emitted only where it could fail.

**A third, found by the stricter test itself**: a struct named `signed_`
in `test_a_nested_member_is_one_whole_message` (which shares the four-way
driver) was the Rust type `Signed_` and so `Signed_Mut`, an underscore
between letters. `_pascal` now drops trailing underscores, and a collision
with a `signed` is left to the compiler, as 0013 says of collisions. No
corpus struct ends in one.

**Guarded now** by the test that missed it: `test_the_four_builders_agree`
compiles with `-D warnings`, allowing only `dead_code`, since a probe calls
one builder of a module that has many. All 50 builders compile that way.
