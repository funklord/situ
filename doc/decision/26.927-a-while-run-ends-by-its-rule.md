# 26.927: a `while` run ends by its rule, or says the frame may end it

Status: recorded
Date: 2026-11-07
Source: the near miss to 26.926, and a verdict by hand

**All six passed a chain that said it went on.** With `link { u8 next; u8 v; }`,

    struct chain { link es[] while (next != 0); }

`01 02` declares that another element follows, and the frame stops: every reader said
whole. It is 26.926's hole in the other run, found by asking the fix's question of the
sibling construct.

**A blanket refusal would have been wrong.** An IPv6 chain, FLAC's metadata blocks,
radiotap's present words and a JSON list must not stop there; but netlink's attributes
run to the end of their message, and `nla_len >= 4` is true of the last one. Nothing in
`while (c)` says which. So the schema says: `| end`, as `until` took in 26.895, and
without it a frame that stops first cut the run short. `max N` ends a run too, and a
run that reaches it has ended.

Rejected: reading the frame's end as a run's end unless the schema refuses it. That
keeps every schema compiling and every cut chain passing, and the default would be
the wrong answer for most of the corpus.

**The last element read answers**, so C, C++ and Rust take the run's own walk and
return at the condition, and Python asks it of the element the walk stopped behind.
The walkers answer the `terminated` row 26.926 gave a run from their walk. No image
format moves: the row exists, and `| end` is its absence.

`example/netlink` writes `| end`.
