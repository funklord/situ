# 26.981: a struct its frame holds exactly

Status: recorded
Date: 2026-11-13
Source: fuzznet's call schema, the half 26.980 left to the author

`struct message [fills_frame]` says the frame holds the message and
nothing after it. It implies `when size(message) != remaining refuse
message_bytes_after`, the way an invariant implies its refusal (26.897),
so the four backends, both walkers, the signature and the dissector each
have it from the one list.

`size(s)` in a `when` is the struct's own extent: `traverse.measured_extent`
-- a fixed struct's size, or `extent_parts`' constant and variable members
-- rendered by `traverse.size_term`, which is now the one copy of what the
four backends each carried verbatim. The image needs no opcode: the packer
spells `size(s)` as its parts before compiling. Over fuzznet's message
Python reads `10 + <the selected arm's size> != self._len`, which is the
table `node/live.c` keeps by hand.

Refused where it cannot mean anything: a struct with no measurable extent
(`resolve`, which has the layout), and a struct with a member of its own
name, which every renderer's `s.` stripping would read as the same word.
The bare name and `size(s)` in an invariant stay refused (26.979).

On a struct nested in another, `[fills_frame]` holds by construction:
every reader hands a nested struct a view of its own extent, which the
four backends and both walkers were checked to agree on before this was
built on it.

`test_a_struct_fills_its_frame` asks the four and both walkers over
fuzznet's shape -- a fixed head, fixed arms and one arm to the frame's end
-- exactly, a byte after, a byte short and the open arm at any length.

The dissector declines it, with every other `when` reading `size()`: its
expression reader has no `size` yet. That is the next gap.
