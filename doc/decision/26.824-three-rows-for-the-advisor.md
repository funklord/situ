# 26.824: three rows for the advisor, and what each one may not claim

Status: recorded -- the holder answered 26.822; all three rows built, with
the populations re-measured and two of the three corrected
Date: 2026-11-03
Source: 26.822; `project.md` sections 1 and 18.2

26.822 measured the distance between section 1's unqualified claim -- "design
advice: concrete, costed schema changes that would restore lost capabilities"
-- and 18.2's eight rows, found three uncovered causes with a population, and
named the decision as the holder's. The holder's answer was to add them.

So 18.2 has eleven rows and `advise.py` eleven rules. What follows is what
building them changed about the measurement, because **not one of the three
populations was the number 26.822 reported**, and in two of the three the
difference is a condition the rule has to carry rather than a miscount.

## The three rows

| rule | fires on | population |
|---|---|---|
| `pin-a-driven-length` | a bounded member whose length an earlier field decides | 50 |
| `count-a-while-run` | a `while` run whose element is a fixed size | 2 |
| `widen-bit-field` | a run of bit-packed fields sharing a byte | 29 |

Against 26.822's 4, 3 and 2. **A `caused by:` clause count is not a
population**, which is the transferable part: the capability map prints a
blame clause where the axis it weakened is the one a reader asked about, so
the clause count is a count of *questions asked*, not of constructs present.
26.822 said so in its own first line -- "every `caused by:` clause the
capability map prints" -- and then its last section reasoned about the
numbers as though they were instances. Nothing in the record is false; the
error is one of reading, which is the kind a later pass inherits.

## What each rule may not claim

**A driven length whose driver declares no bound cannot be told to pin at its
maximum.** The maximum is then the driver's whole type range: 2^32-1 bytes for
a `u32` length, and 18446744073709551615 for `sqlite`'s `payload_size`.
`[must_eq = 2147483647]` is a number the compiler accepts and nobody can use,
which is 26.163's defect in another form -- that one named an attribute the
compiler accepted and ignored. So the rule has two branches: with a declared
`[max = N]` it names N and prices the padding exactly (21 members), and
without one it asks for the bound first and prices the pin as unchosen (29).
The second branch's detail prints the current worst case, because the number
is the argument.

PNG is the case worth keeping: it declares `[max = 2147483647]` with RFC 2083
cited beside it, so the pin names 2 GB and costs 2 GB. That is the rule
working -- the cost column declining, loudly, in the register 18.2 exists for.

**A `while` run over a variable-size element gains nothing from a count.**
A count says how many elements there are and still nothing about where any of
them is, because each element's own length decides where the next begins, so
`access` stays `Sequential`. Six of the corpus's eight `while` runs are that
shape, including `linked.chain`, which 26.822 counted among its three. So the
population is 2 and the guard is the rule.

The guard is the element STRIDE and not the element struct's `is_fixed_size`,
and it was written as both. Removing the second left every test green --
`element_bits` is set for no variable-length element anywhere in the corpus --
which is the tell that two predicates were answering one question. Asking only
the stride also serves a run over a *scalar* element, which has no struct to
ask and a stride all the same.

**A bit-packed field costs the bytes it needs, not a byte.** The first costing
priced every lift at one byte, which understates a `u12` -- exactly the fields
worth lifting. Found by taking the advice on `u4 a; u12 mid; u4 c`, where the
rewrite costs nothing extra and the rule claimed it saved a byte. The summary
mirrors the propagation row's own words, "widen the field to a whole number of
bytes", because a `u12` does not widen to a byte and the catalog must not
contradict the blame chain printed beside it.

One suggestion per packed run rather than one per field, which is the
judgement 18.2 already made for `uncover-mutable-field` and the same one: the
fields share the byte so their costs do not add, and the schema does not say
which is hot. 29 runs over 20-odd structs where one per field would have been
94.

## Where they rank, and why that was not a free choice

18.2's table is ordered by yield and `rank` carries that order, so appending
three rows would have asserted they are the lowest-yield three.
`pin-a-driven-length` pins an extent exactly as the two rows above it do and
fires on 50 corpus members where `varint-to-fixed` fires on 10, so it is
interleaved at 3 and five existing rules are renumbered. `count-a-while-run`
sits at 5 beside `equalize-variant-arms`, which also buys static addressing
for padding; `widen-bit-field` is last, its yield being three axes on one
field.

## Three gates, and what they caught

- **A rule's `rank` is written twice** -- in `CATALOG` and in every
  `Suggestion` the rule builds -- and nothing compared them. The catalog grew
  by three rows and renumbered five the day the gate was written. A stale rank
  sorts a rule into the wrong class and no existing gate could see it: the
  order would still be an order, and `suggest`'s own sort assertion would
  still hold.
- **`test_every_catalog_rule_has_its_yield_measured` could not see a test
  written below itself.** It split the file on `# -- the suggestion, taken`,
  and that string occurs twice -- once as the heading and once as the literal
  in its own `split` call -- so the default split left everything below the
  gate in `[2]`. The three new taken-advice tests landed there and the gate
  reported the one thing it exists to deny: that the advice had not been
  taken. `maxsplit=1`.
- **`test_a_well_ordered_schema_gets_nothing` asked the whole catalog** about
  a schema the catalog now has something to say about, correctly: pinning `n`
  makes `fine` a fixed-size struct, which it is not. Narrowed to the rule its
  name is about, and it states what else fires rather than dropping the
  whole-catalog claim.

`test_every_priced_rule_costs_what_it_says_on_the_wire` gained cases for the
two new rules whose rewrite is fixed. `count-a-while-run` is not one of them,
and the reason is that gate's own precondition: it measures a cost as the
difference between two smallest frames, which holds only where the rewritten
schema is fixed. A counted run is not -- and its smallest frame is a byte
*smaller* than the `while` run's, because a `while` is a post-condition and
carries at least one element where a count may say zero. The count field still
costs one byte in every frame carrying the same elements, and that byte is
checked against the field itself.

## What is still not a row

Unchanged from 26.822 and worth not re-deriving: case-insensitive comparison,
optional whitespace, an `endian_marker`, and a delimiter that may occur in
content are facts about a format situ is describing rather than designing, and
`tlv` with `unknown = preserve` exists to be extensible. Advising any of them
away is advising a different protocol.
