# 26.1011: verify names only what is unread

Status: recorded
Date: 2026-11-13
Source: hull, situ inbox 20261113T1434Z

**`situc verify` named runs as unread that `validate` reads.** Its verdict
says "conform ... except inside arrays" and lists the runs whose elements
went unchecked, and the list still excluded three shapes the backends had
since learned to walk: a run in a variant arm (26.790), a run of a struct
that names itself (26.791), and a run handing its element arguments (0068).
hull read the list at its word -- `core_message.body.machines.items`,
each `listed` of `machines` -- and concluded situ had not read its elements,
when every backend refuses a bad element there; measured in all four on
that shape, on a run in an arm, and on a run handing an argument.

A gap report that overstates is not the safe direction: it teaches a
reader that "except inside arrays" is noise, which is what `_unwalked`
exists to prevent.

**Now it names what is unread and nothing else**: an element taking
arguments its run does not hand, and an enum array, whose membership no
backend checks. The corpus flags none. `test_a_delimited_run_of_structs`
pinned the stale claim for sexpr's items and now asserts its absence.
