# 26.805: A bound on a `parameter` itself builds, and no backend checks it

Status: recorded -- fixed
Date: 2026-11-02
Source: found while building 0068 step 5

    struct t { parameter u8 b [max = 10]; u8 x; }

Accepted, and the four backends gave three answers:

- C called `situ_t_b_get`, which nobody emits, and did not compile.
- C++ called `this->b()`, which does not exist, and did not compile.
- Python and Rust emitted no check at all.

26.545 settled, on the holder's instruction, that a bound on a parameter
is kept. The solver reads it, so the argument a caller supplies is
bounded where a size or another argument depends on it. Nothing in that
decision asks `validate` to check it, and `validate` reads the message,
which does not carry the argument.

## The change

C's `_checks_for` and C++'s `_check` emit nothing for a parameter, which
is what Python and Rust did. The four now agree, and the check ids agree
because no backend gives the parameter one.

**This record first said the opposite**, and the commit that wrote it is
in the history: a refusal of `[must_eq]`, `[min]` and `[max]` on a
parameter. The full suite caught it, because
`test_wellformed.py::test_a_numeric_bound_is_kept_where_a_value_is["a
parameter"]` holds 26.545's decision. A refusal would have undone a
settled rule to cure a code generator, so the refusal is reverted and the
generator is fixed instead.

## Tests

`test_a_parameter_s_own_bound_builds.py` builds a bounded parameter and a
bounded `[stream]` one that sizes a member, in all four. With
`situc/codegen/{c,cpp}` reverted it fails.
