# 26.805: A value rule on a `parameter` is refused

Status: recorded -- refused
Date: 2026-11-02
Source: found while building 0068 step 5

    struct t { parameter u8 b [max = 10]; u8 x; }

Accepted, and the four backends gave three answers:

- C called `situ_t_b_get`, which nobody emits, and did not compile.
- C++ called `this->b()`, which does not exist, and did not compile.
- Python and Rust emitted no check at all.

26.798 taught a bound that names a parameter to read the argument. This
is the other side of the same question: a rule ON the parameter. Every
backend's scalar check reads the member's value through its getter, and
a parameter has none.

## The change

`check_parameters` refuses `must_eq`, `min` and `max` on a parameter. A
rule the schema states and no generated code holds is what 14.5 calls
worse than stating nothing. `validate` reads the message, and the
argument is not in it.

The alternative was to check it in `validate`, against `arg_b`. That is
four backends' check groups and both walkers gaining an id for an
argument, which is a feature to ask for rather than a fix. It would also
give 0068's argument range check a narrower interval to prove against
(`b + 1` fitting a `u16`). Until a format needs it, a narrower type says
the same.

No corpus schema has such a rule.

## Tests

`test_a_parameter_takes_no_value_rule.py`: each of the three rules is
refused, and `[stream]` is still accepted. With `situc/wellformed.py`
reverted, the three fail.
