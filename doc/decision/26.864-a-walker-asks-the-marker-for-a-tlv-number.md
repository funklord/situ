# 26.864: A walker asks the marker for a tlv tag or length

Status: recorded
Date: 2026-11-05
Source: 26.863, the next instance of its shape

A region under `[endian = from(marker)]` has no order in the image, and the
packer's "big unless little" made that big. 26.833 fixed this for the four
generated readers, and the walkers kept it: a message with a little marker
and a `u16` tag was valid to the four and BOUNDS to both walkers. A big
marker agreed by luck.

Bit 3 of `tag_flags` and `len_flags` says the marker decides. The Python
walker asks `marker_order`, for the tag and a `prefixed` length alike. The C
walker declines for more than one byte, since it does not resolve a marker
for a member either. Under 26.863's change to `validate`, that decline
reaches the caller.

`test_a_native_tlv_tag_is_read_natively.py` holds all six on both orders, for
a tag and for a length.
