# 26.1045: a `when` reads where its struct sits

Status: recorded
Date: 2026-11-17
Source: openmlx4's FS2 report -- "fs2.c checks it, and that `next`
increases"; `fs2.c` refuses `next <= at`, `at` being the section's own
address

    when chain.head.next != 0xFF000000 && chain.head.next <= offset(chain)
        refuse backwards "a section points at or before itself";

**After 26.1044 FS2's chain could be written and ended, and its other rule
could not.** A section pointing back at or before itself is a loop the depth
only bounds, and `fs2.c` refuses it outright: measured there, a GUID section
pointing at itself recorded the same section 64 times and accumulated the
image CRC over 64 copies. The obvious spelling,
`chain.rest.following.head.next <= chain.head.next`, reads into an arm and
through a located member, and both are refused by name -- a `when` reads one
frame.

## The rule

**`offset(s)` of the struct a `when` is on is where that struct sits in the
message**: zero for the one a reader was handed, and a link's own address
down a chain. It is the only `offset` a `when` may read; `offset(member)`
and `count` stay refused, since no reader evaluates either at run time. A
member named like its struct makes `offset(s)` ambiguous and is refused, as
for `size(s)`.

## What carries it

C and C++ take the view's distance from its owner's base -- the message
`check` already reaches located members through -- and zero for a view with
no message. Python reads `_at`. Rust takes the distance of its slice from
the message `validate_in` and a new `messages_in` are handed, so a struct
whose `when` asks it takes the message as a located one does. The image has
an ambient opcode for it, `HERE`, like `REMAINING`: the Python walker
answers the view's start, and the C walker asks its loader, which answers
the distance from the root 26.1043 threads through.

## Measured

`test_a_located_chain.py`, the forward shape: a chain going forward and one
with a gap validate, one whose second link points back is CONSTRAINT, in C,
C++, Rust and Python and in both walkers; a self-loop is CONSTRAINT to the
backends and "cannot say" to the walkers, past their depth. Python's output
passes `mypy --strict`.
