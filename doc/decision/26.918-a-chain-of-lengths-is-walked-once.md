# 26.918: a chain of lengths is walked once

Status: recorded
Date: 2026-11-06
Source: measuring whether 26.916's gated read multiplied without a recursion

**A struct's accessors cost three times as much for every length-prefixed
member in front of them.** Each field a length reads found itself by summing the
lengths ahead of it, each of which read a field the same way, and read it twice,
once for the bound and once for the load. In all four backends, in function
calls for `validate` and `required`:

    strings      2      4      6       8        10         12
    C          216   2242  20652  186518   1679488   15116394
    C++        390   2106  17646  157602   1417302   12754698
    Rust        18    116    982    8760     78746     708604
    Python    4513   6031  19837  144235   1263961   11341639

Nothing in the message decides this, so 26.909's costs, which hold a schema
still and grow the message, could not see it. It is older than this year's
nesting work and was not what the measurement set out to find: the flat form
costs what the nested one does. Twelve fields took 2.25 seconds per read in
Python, SSH's `SSH_MSG_KEXINIT` has ten name-lists, and twenty would be 3.5
billion calls.

**One pass front to back reads each once.** `offset_walk` reuses 26.909's cursor
steps: a function that records where each such field is, reading each from the
marks it has already made, and each of those fields' offsets asks it. The same
twelve strings now cost 25651, 31085, 3188 and 26383. The pass stops at the last
field it has to find, and the members behind keep their sum, which now costs a
polynomial because what it sums does.

**Two or more, because one has nothing to multiply.** Most structs emit what
they did. In the corpus `example/dnsname` and `example/tls` move, and no others.

Rejected: reading each offset once in the accessor, which leaves two to the
power of the links, since the sum still reads every field ahead. Chaining each
offset off the previous field's, which is linear until a length reads two
fields, when it is Fibonacci. A cache on the view, which a write has to
invalidate and a C view, being a value, has nowhere to hold.

**Not walked, and so still three to the link:** a struct with a version's tail,
one that ends in its frame, a recursive one, which has 26.909's pass, and a
member with an alignment that depends on an arm.

**The walkers had it too, at two to the link, and this record first said they
did not**, reasoned from their walking front to back. A test asked, and the C
walker took 89.8 million calls at twelve strings. Each reads a field by summing
what is in front of it, and 26.909's memo of what members measured was only held
during a measurement. Holding it for the length of a sum makes that 2.2 million,
and 1.06 million to 22 thousand in Python. The dissector has a running offset and
has nothing to fix.

The memo in C holds thirty-two members, so a struct longer than that costs what
it did past them. It is 592 bytes of stack on first entry to a frame, out of line
because inlined it was 528 more on every level of a recursion, which holds its
frames already. One level is now 2912 bytes where it was 2800.
