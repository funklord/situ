# 26.790: A run of structs in a variant arm validates its elements

Status: recorded -- fixed
Date: 2026-10-31
Source: 26.789's "not yet", the holder's direction carried into arms

    struct arms { u8 kind; u8 n;
                  variant body switch (kind) {
                      case 1: piece recs[n];   case 2: pt pts[n];
                      case 3: pt q[2];         case 4: piece wh[] while (len != 0) max 4;
                      case 5: piece de[] until ";";
                      default: u8 raw; } }

26.789 validated the elements of every run outside an arm. A run in an arm
reaches `validate` through the variant, which has its own family of checks
(26.779 to 26.786). So `[max]` on any element there still validated clean
in all six.

## The change

- **Each backend's `_arm_run_elements`.** It is 26.789's
  `_element_validation`, run from where the variant starts and under the
  discriminant value that selects the arm. It sits in the variant's own
  group, so a refusal names the variant, as every other refusal about an
  arm does.
- **The arm's tail moves to a second pass.** Where no backend measures the
  variant, the members after it are held to the frame by the arm's check
  (26.779, 26.785). That ran in the same pass as the arm's own frame, so it
  came before the arm's elements. Both walkers, like the top level, reach
  those members last, as members of their own. So a cut `kv` in an arm
  followed by `u16 after` answered BOUNDS in the four and CONSTRAINT in the
  walkers. `_arms_fit` now takes `tails`: the first pass holds the arm
  alone, and `_arm_tails` asks for the tail after the elements.
- **Both walkers.** The Python walker's `_arm_validates` and the C walker's
  `arm_validates` hand each run to the element walk 26.789 wrote, with the
  variant's start. `_run_elements` and `run_elements_validate` take that
  start. The C walker records the variant as the failing member.
  `_arm_validates` and `_arm_selects` can now answer None (an element this
  image cannot validate), and the caller passes it on rather than reading
  it as OK.

C already had an `_arm_elements` (for an indexed arm), so the new one is
`_arm_run_elements` in all four. The first build shadowed the old one, and
`edges` did not generate.

## What moved

In the corpus, `edges.unwalkable_arm` alone. Its arm validates each `piece`
and then holds the tail. No check id moved.

Tests that pinned the old answer now give the new one:
`test_a_run_in_an_arm_is_walked.py`'s `[max]` cases are 2, and
`test_an_ended_run_in_an_arm.py`'s cut `kv` is 2. A `kv` below its two-byte
minimum is 1.

## Tests

`test_a_run_validates_its_elements.py` gains the arm shapes above, eleven
messages in all four backends and both walkers. With `situc` and `walker`
reverted, both cases fail.
