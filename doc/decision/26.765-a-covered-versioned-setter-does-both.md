# 26.765: A covered versioned setter does both

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

    struct plain [version = ver] {
        u8 ver;
        tag u8 mac[4] covers(part);
        authenticated part { u8 a; u8 b [since = 2]; }
    }

`b` has two setters' worth of obligations: it is present only from
version 2 (19.4), and writing it leaves `mac` stale (14.2). Each backend
wrote one of the two setters and dropped the other's obligation:

| backend | setter written | version and frame | marks `mac` |
|---|---|---|---|
| C | covered | no | yes |
| Python | covered | no | yes |
| C++ | versioned | yes | no |
| Rust | versioned | yes | no |

C's `situ_plain_b_set` stored `b` at offset 6 into a whole six-byte
version-1 message -- one byte past it, read from the generated code.
Python asked nothing about the version either. C++ and
Rust refused the older message and marked nothing, so `transmittable()`
went on calling a message with a stale tag ready to send: the claim the
capability map's `auth = Covered(mac)` exists to make.

Each now does both: version, then the frame, then the write, then the
mark. C's covered setter returns `situ_err_t` for a versioned member, as
its plain versioned setter always has. C++ and Rust's versioned setter
takes the message or the dirty word where a tag covers the member. Over
the 43 committed schemas the output is byte-identical: none has a
covered versioned member.

## Tests

`test_a_covered_versioned_setter.py`: C and C++ under ASan and UBSan
refuse version 1, refuse a version-2 frame without `b`, and write and
mark otherwise; Python refuses version 1; Rust's setter takes the dirty
word and marks it. With the four changes reverted all four fail.

## Noticed, not chased

`required` answers 7 for a whole six-byte version-1 message of this
struct, asking for `b` that version 1 does not carry. All four agree, so
it is either 26.753's honest-lower-bound question again or a fault; it
is in the open register.
