# 26.1077: a text number or a token may run to the frame less a fixed tail

Status: recorded
Date: 2026-11-18
Source: 0070's second measurement -- fuzznet's DURATION cell, `14d`

**`[remaining]` left the members after it their bytes only for plain
`u8`** (26.894, 26.905), so digits then a one-byte unit had no spelling:
`decimal u32 count[remaining]; time_unit unit[1];` was refused as
"`[remaining]` must be the last member of its frame". A text number's digits
and a token's spelling are bytes read as something, and their span is the
same frame less the tail; every reader already sizes a `u8` run that way,
from the run's `tail_bytes` and `tail_ast`.

## The rule

- A `[remaining]` run may leave a fixed tail when it is bytes: plain `u8`,
  a text number, or a token set. A run of records still may not -- it has
  no span to take the tail off.
- No reader changed: the layout's tail is what the four backends and the
  packer's size program already read.

## Measured

`test_a_text_number_may_leave_a_tail`: eight frames through the four
backends' listings (`count ok= value=`) and verdicts, and both walkers'
verdicts -- `14d` clean, the unit wrong, an empty count, `007s` under
`[minimal]`, `1.5h`, one past `u32`. `edges.duration_cell` carries it.

**Not reached: `decimal u64` over an unbounded span.** Both walkers answer
"cannot say" for one, because its derived ceiling, 2^64 - 1, does not fit
the image's signed bound; the four backends read it. fuzznet's counts stop
below 2^63, and the gap is recorded on its own.
