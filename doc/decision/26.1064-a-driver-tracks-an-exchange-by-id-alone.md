# 26.1064: a driver tracks an exchange by its id alone

Status: recorded
Date: 2026-11-17
Source: fuzznet, inbox 20261117T1816Z -- its resends run on the generated
driver since a2f8f3c4 (its project.md sec 1227), measured unchanged

**A caller that matches replies itself had to hand `track` a request it
never meant anything to match.** 26.1055 gave the drivers `track`, `end`
and an expiry hook so fuzznet could run its schedule on them, and it now
does. It matches each reply after opening it: the relation's key,
`head.msg`, is inside bytes the driver cannot read. But `track` took a
request view and recorded its key, so fuzznet hands it a blank 144-byte
frame per exchange. That spends a key slot per exchange on nothing, and
the key it records is the all-zero one -- which any all-zero reply then
matches, through `on_message` or `peek`, ending an exchange its owner is
still waiting on. fuzznet never calls `on_message`, so it is not hit
there; a protocol whose key is sealed is not rare, and the next caller
need not know to avoid it.

## The rule

In all four drivers, additively:

- **`track_by_id`** (C's `_track_by_id` and `_track_by_id_with`, C++'s
  `track_by_id`, Rust's `track_by_id` and `track_by_id_with`, Python's
  `track_by_id`) takes the bytes, the id, the time and the same policy
  overrides as `track`, and no request. No key is read or held, so no
  reply matches the exchange; it ends by `end(id)` or by expiring, and
  resends and the expiry hook are `track`'s.
- C's keyed `track` is the table's record and then the same slot fill, so
  the two cannot drift; C++ and Rust fill one slot through a private
  `hold` and mark it `keyed`, which `on_message` and `peek` require;
  Python keys the exchange `("id", id)`, which no reply's int or bytes
  equals.

## Measured

`test_a_driver_tracks_an_exchange_by_id_alone.py`, the same scenario in
the four: a keyless exchange sends nothing; a blank reply peeks
CONSTRAINT; a keyed exchange beside it still peeks its id; the keyless
one expires on its own policy and the hook names it; `end` is OK and
then CONSTRAINT. With C++, Rust or Python marking the keyless slot keyed
under the zero key, each fails on the blank peek. C's holds by
construction: `_track_by_id_with` never touches the table.
