# 26.947: a versioned arm frames as absent

Status: recorded
Date: 2026-11-09
Source: the copyright holder's answer to the open entry on `edges.versioned_arm` -- "frame it as absent"

**A variant arm carrying `[since = N]`, selected in a message whose version
is below N, occupies no bytes.** `edges.versioned_arm` is

    struct versioned_arm [version = rev] {
        u8  rev;
        u8  pick;
        variant held switch (pick) {
            case 1:  u8  always [max = 7];
            case 2:  u8  later  [since = 2, must_eq = 9];
            default: error;
        }
    }

and `rev = 1, pick = 2` is now two bytes long to every reader that frames.

## What the readers said before

    message   required (C)   walkers' extent   view + validate   later_get
    01 02     truncated, 3   3                 ok                VERSION
    01 02 09  ok, 3          3                 ok                VERSION

The layout already said two to three bytes (`SIZE_MIN 2`, `SIZE_MAX 3`),
because its minimum is where the first `[since]` member starts, and the
accessor has refused the arm since 26.424 -- but `extent_parts` counted the
variant as a fixed byte, its two arms being one byte each, so `required`
answered a constant 3, and both walkers summed the chosen arm whatever the
version. The 2026-11-03 re-measurement found the choice was between two
refusals of a message no honest writer produces; the holder chose absent,
which is also the reading every other reader already took.

## What changed

- `traverse.has_a_versioned_arm` makes such a variant variable in
  `extent_parts` and `framing_gaps`, so it is measured through
  `_variant_length` rather than counted as a constant.
- All four backends' `_variant_length` gate a `[since]` arm on the version:
  the arm's length where the version reaches it, zero where it does not.
- Both walkers' variant extent (`walk._arm_predates`, `situ_walk.c`'s
  `arm_predates`) answers zero for such an arm. A version that cannot be
  read yet leaves the arm counted, the longer answer, as `absent_tail`
  already does for a member.
- The walker's listing treats the arm as unchosen at an older version, as
  every backend's accessor does, so `held_later` reads `ok=0` at `rev = 1`
  where it read `ok=1 value=9`.

## How it is held

`test_a_versioned_arm_frames_as_absent` asks C's and Python's `required`
and both walkers' width of the variant over four messages. Stubbing
`has_a_versioned_arm` and `_arm_predates` fails all three tests, and
setting aside the `situ_walk.c` change fails the walker test. C++ and
Rust are held by the same file through the differential drivers'
`required()` line, which all four print an answer per prefix to: every
prefix of `01 02 09` asks for 2 and the second byte completes it, where
the four-backend framing sweep's fills never select the version-2 arm at
version 1.
