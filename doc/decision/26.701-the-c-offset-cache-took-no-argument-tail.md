# 26.701: the C offset cache took no argument tail

Status: recorded -- fixed, and the third backend's sweep covers both modes
Date: 2026-10-27
Source: `project.md` section 26

**`situc build test/schema/edges.situ --target c --materialize` generated
C that does not compile.** A committed schema, in a mode nothing swept:

    edges.h:18142:60: error: 'arg_block' undeclared (first use in this function)
    edges.h:18138:56: error: unused parameter 'view' [-Werror=unused-parameter]

    static inline void situ_negotiated_offsets(situ_view_t view,
                                               situ_negotiated_offsets_t *out)
    {
        uint32_t at = 0u;
        at = at + ((uint32_t)situ_nonneg_u32(situ_leaf_u64(arg_block)));

The plain-mode sibling takes it -- `situ_negotiated_payload_len(situ_view_t
view, uint8_t arg_block)` -- so the body's spelling was right and the
signature was short.

**`_argument_tail`'s own docstring enumerates the functions that still
spell `situ_view_t view` alone and says "Neither has a schema in this
tree".** It names a run of variable-sized structs sized by an argument,
and a delimited or `while` run's stride helpers. **The offset cache is a
third, and it is the one that does have a schema** -- `edges.situ`'s
`negotiated`, reachable the moment anybody passes `--materialize`. The
list was short by one and the missing entry was the only live one.

The same docstring also says why the symptom is this and not a wrong
byte: *"a read of an argument renders as a bare identifier, so a function
that embeds one without having been given the tail names something that
is not there and gcc says so."* That held. Nothing was reading the wrong
memory; the header simply did not build.

**Fixed with the helpers that already existed**: the signature takes
`_argument_tail(struct)`, `_argument_unused` writes `(void)` for an
argument the steps do not name, and `(void)view;` covers the case where
the steps read only arguments and constants -- which is exactly
`negotiated`, and why the second error appeared the moment the first was
fixed.

## Why nothing saw it, and the gate half

**26.699 -- written hours earlier, by me -- parametrised the C++ and Rust
corpus sweeps on the mode and left C reading the plain one**, because the
C corpus is compiled through the Makefile and `grep -n materialize
Makefile` is empty. So that entry closed the gap for two of the three
compilable backends and left the third open, in the mode it had just
established has a history of hiding breaks.

`test_every_schema_generates_and_compiles` is parametrised now, 92 cases.
Reverting the signature fails
`[schema/edges.situ-materialized]` while `[-plain]` passes.

**All 46 materialized C headers compile under the project's own warning
set now**, and plain-mode C is unaffected by construction: the cache is
emitted only under the flag, and `_argument_tail` is empty for every
struct in the corpus that takes no parameter.

**Found by a sweep looking for something else.** A worker enumerating
regexes over rendered output reported it as a thing noticed beside the
population it was sent for, with the reproduction and the note that
`grep -n materialize Makefile` is empty. Verified here independently
before anything was changed -- the break, the clean plain-mode control,
and the generated signature.
