# 26.920: a header can end in its body's length

Status: recorded
Date: 2026-11-06
Source: 26.916's refusals, read against the holder's "anything a protocol needs is ours"

**`u8 tail[h.n]` was out of scope where `n` is a varint of a nested `h`.** So a
QUIC or MQTT header could not be a struct of its own: every packet type repeated
it, or the length moved out of the header it belongs to. Behind a length a text
number was refused too, which 26.916 did rather than read it wrongly.

**Both read through the struct that holds them.** `h`'s own `_value`, over a view
from where `h` starts, has the decoder and knows where `n` is, however much of
`h` stands in front of it. So `struct h { u8 m; u8 d[m]; l first; q n; }` works,
and there is no second decoder in the parent. One level, as scope has always
offered, and zero where the frame does not reach it, as any length read is.

**By `h`'s offset and not by `h`'s accessor.** The accessor finds `h`, and inside
26.918's pass finding `h` is what the pass is doing, so the read recursed. An offset
expression is what that pass already rewrites to its mark, and it measures nothing,
where the accessor measured `h`'s extent first.

**A walker reads one at a static offset in a struct at a static offset**, and says
`cannot-say` otherwise, as it has for any field of a struct behind a length: a
program reads by a placement's offset, and a varint behind others in `h` has one
only inside `h`. The packer refuses to write that program. The dissector declines
as it does for any varint.

**This found two faults beside it.**

C++, Rust and Python left `at` undeclared in `_extent` where 26.918's pass had
replaced the running sum: a variable nested struct in a walked chain. C++ and Rust
did not compile and Python raised, on a shape 26.918's own tests hold still by
using a fixed `hdr`. That was this chain's own and never reached master.

Rust cast every read in an expression to `usize`, a length's type. `i8 x; when s.x
>= 0` read -1 as a huge number and refused it where the other three did not, and a
`case -1` did not compile. A rule or a discriminant over a signed field is `i128`
now, wide enough for a `u64` beside it; one with no signed field emits what it did.

Rejected: a varint decoder in the parent at a constant offset, which `h` with
anything variable in front of `n` would still refuse. An accessor on the parent per
nested varint, in all four, for a read only expressions make.
