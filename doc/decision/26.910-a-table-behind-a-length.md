# 26.910: A table behind a length, and a pad arm in a cycle

Status: recorded
Date: 2026-11-06
Source: measuring the regions 26.909 said were not measured

- An `indexed` region behind a member the message sizes generated C that did not
  compile. C spelled two things `_offset`: entry N's offset, and where the region
  starts, and only the first was emitted. So a variable header in front of an
  offset table failed in one backend of four, with no recursion needed. The start
  is `_start` now, as a lead's is. No corpus output moved.
- Costs measured behind recursion: an `indexed` region grows about 3.8 times per
  doubling of levels in C++, Rust and Python, the same as the shapes in 26.909.
  tlv, coded and sealed regions behind recursion are still not measured.
- A pad arm at a run-time offset in a struct that holds itself is refused, naming
  the member. Framing declines it in all four (26.889), which a top-level struct
  survives because nothing asks it for its length. A recursive one is asked by its
  own parent, its later accessors were declined, its setters still named them,
  and the output did not compile. Giving it an extent is the cursor carried into
  framing, which 26.889 left for when framing has one. `pad_to` as a member behind
  recursion is built, by 26.909.
