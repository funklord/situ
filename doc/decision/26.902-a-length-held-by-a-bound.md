# 26.902: A length held by another field's bound

Status: recorded
Date: 2026-11-06
Source: the goal gap, by writing real protocols until one was refused

    u32 packet_length;
    u8  padding_length [max = packet_length - 1];
    u8  payload[packet_length - padding_length - 1];

SSH's binary packet and HTTP/2's padded frame state a length as the difference
of two fields. Both were refused as "may be negative", with nothing a schema
could write: `[min = N]` bounds one field, and these need one field held by
another. The bound above already parsed and already refused a message in all
four backends. What was missing was the solver reading it.

## Decision

`relational_floor` writes the length as a sum of fields, replaces a field
subtracted by what bounds it from above and a field added by what bounds it
from below, and takes the best floor any step reaches. `must_eq` serves both
ways. Asked only when the interval says negative, so no length that solved
before solves differently.

Sound because the bound is a check. `validate` refuses the message before the
length means anything, and an accessor asked without it clamps to the frame, as
for `[min = N]`. `a - 1` is compared signed in all four, so `packet_length`
zero is refused and does not wrap.

What it will not prove stays refused: no bound, a bound one too loose, a bound
in the wrong direction, a product of two fields, a bound on a field declared
later. A proved floor above zero raises the struct's minimum.

## The walkers

A bound over a field had no row in the image, so both walkers said `cannot-say`
for any struct holding one, since whenever such a bound was first allowed. It
has one now: check kinds 19 to 21, whose value is where the bound's program
starts. Format 7, because an older C walker declines a kind it does not know
and an older Python walker would skip it and answer OK. A bound over a field
on a variant's arm has no row yet and still declines.

## Rejected

- A checked subtraction, `u8 d[a -? b]`: a second arithmetic for one case, and
  the rule would live in the length rather than where the format states it.
- `max(a - b - 1, 0)`: reads a malformed length as an empty payload, which is
  the silent acceptance the check exists to prevent.
