# 26.853: a pad arm had an accessor that read one byte of it

Status: recorded -- the accessor is declined in all four and the differ
agrees; the run form of the CHECK is still 26.848's and is named below
Date: 2026-11-04
Source: 26.848, which recorded this as "an accessor shape with consumers
beyond this", and the measurement that found the consumer

## What it emitted

    struct arms { u8 kind;
                  variant body switch (kind) {
                      case 1:  pad_to(4);
                      default: u8 other; }
                  u8 tail; }

Python, before this:

    @property
    def body_pad(self) -> int:
        if self.kind != 1:
            raise VersionError(...)
        if self._len < 1 + 3:              # three bytes
            raise BoundsError(...)
        return self._read(1, 1, ...)       # one of them

The span is three bytes, the bounds test knows it, and the read takes one.
All four backends did the same thing in their own spelling.

**A pad MEMBER gets the honest form**, in all four:

    # arms.<pad> is reserved: no accessor, and
    # validate() holds it to the pattern the schema declares.

So the arm was the inconsistency rather than the question, and there was no
accessor to fix -- only one not to emit. A pad is a reserved RUN that
nothing is meant to read, and the extent arithmetic after the arm does not
need a value either: a pad's length comes from `pad_to`, not from the data.

## The consumer, which is what moved it

**`situc diff` PROBED it, in all four languages.** So the four-way
differential compared that accessor and the four AGREED -- on one byte of
three, which is agreement on a wrong answer and the one thing a
differential cannot report. `differ._arms` declines it now, which is
f2be5841's shape one construct over: the driver matching a decline the
backends make.

26.848 had the accessor recorded and not the probe. Finding the probe is
what turned "an accessor nobody should call" into "an accessor the
harness calls, and compares, and is satisfied by".

## The gate, and its detector was wrong first

**A list of definition spellings is the obvious detector and it inherits a
backend's habits.** Written out -- `def {name}`, `fn {name}`,
`{name}(view`, `std::uint8_t {name}` and three more -- it missed C++
entirely, whose accessor reads
`[[nodiscard]] ::situ::rt::err body_pad(std::uint8_t &out) const noexcept`
and matched none of the seven. That is the third phrasing-keyed detector of
the night.

So the gate strips comment lines and asserts the NAME appears nowhere a
compiler would read, which is the question as meant; and a second test
asserts the decline is NAMED in the generated text, because a missing
accessor nobody mentions reads as an emitter that forgot.

**Two controls**: the four declines, neutralised, fail the accessor tests;
the differ's, neutralised, fails the driver test alone -- the driver then
names a function nothing defines.

## Scope

The corpus has **no pad arm**, so this is output-neutral there by
construction, and measured as such: across 43 schemas in four languages
the only files differing from the capture taken before the night's emitter
work are `edges`' four, which are the reserved-arm and delimited
text-number checks. The 172 differ drivers are byte-identical.

## What is left, which is 26.848's

The run form of the reserved check for a pad arm: the packer's kind 13
scans the aligned span, and neither `report._arm_constraints` nor C's
`arm_constraints` renders a span kind for an arm. All six agree in saying
nothing about a pad arm's bytes meanwhile, which is why the accessor could
be declined without it.

**And the construct belongs in `edges.situ` when that lands, not before.**
A fragment in a unit test is what guards the decline today, and it is
enough for a decline: the test fails if any backend emits the accessor
again. What a corpus construct would add is the four-way differential and
both walkers asking about it on every commit -- which is worth having
exactly when there is an answer to compare, and is worth its cost then
(the image, the map, the wire signature, four backends' generated code and
the C checks suite all move for a new `edges` construct). Recorded here so
the order is deliberate rather than forgotten: the check first, the corpus
construct with it.
