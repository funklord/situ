# 26.709: the class moves and the reference did not

Status: recorded -- fixed; 26.705's second family closed, and its stated
cause was false
Date: 2026-10-28
Source: `project.md` section 26

26.705 recorded two name-collision families and parked both as design
questions. The holder settled the first (26.706). **The second was not a
design question at all**, and this entry is mostly about how it came to
look like one.

## What 26.705 said, and what is true

> A struct's name goes through `class_name`, which renames a class a
> member has taken and does not consult `KEYWORDS`.

**`class_name` has consulted `KEYWORDS` since it was written**, and its
own docstring says so in as many words -- *"A member's name is one way to
collide and a keyword is the other, and the second was missed for as long
as this file existed"*. So the premise the family was parked on is false,
and re-measuring was what found that rather than re-reading.

The class IS moved. What was not moved is every reference to it:

    struct int { u8 a; u16 b; }
    struct holder { int head; u16 tail; }

    class int_ : public ::situ::rt::view { ... };          // declared
    ...
    err head(::situ::int &out) const noexcept              // referenced

`::situ::int` is qualified and unsuffixed. **The suffix was applied where
the class is DECLARED and not where it is USED**, so a reader of either
half sees a correct name and only a compiler sees the pair. Ten sites
spelled a referenced struct with `c_name` where one spelled it with
`class_name`.

## The second mechanism is 26.695's, one level out

`offset` and `data` are not keywords and failed anyway:

    at(::situ::rt::message &owner, std::uint32_t offset, offset &out)
    required(const std::uint8_t *data, ...) { return data{ ... } ... }

The factories declare `offset` and `data` as their own parameters, so a
struct named either is hidden by them at a use site **in the same
function**. 26.695 qualified nine type positions for exactly this, where
the hider was a member; here it is the generator's own local, and the
error says nothing about a name -- `data` gives *cannot convert `const
uint8_t*` to `situ::rt::err` in return*.

## The population, and the control

Swept over `KEYWORDS` and the names the generator declares for itself --
`owner`, `offset`, `length`, `out`, `data`, `have`, `need`, `raw`, `view`,
`at`, `sink`, `no_check` and the rest -- **109 names as a struct name,
each held by a second struct**:

    HEAD    25 compile, 83 do not, 1 refused
    now    108 compile,  0 do not, 1 refused

The refusal is `bool` in both, for its own unrelated reason (*no bit
order in scope*), a situ type name rather than a C++ one. 26.705 listed
five names; it is 83.

**C, Rust and Python take all 109 on both trees.** Only `cpp/emit.py`
changed.

## What it cost

**43 of the 46 corpus C++ headers change, and every change is one of two
shapes**: `{name} &out` becoming `::situ::{name} &out` in the `at`
factory, and `return {name}{ ... }` becoming `return ::situ::{name}{ ...
}` in `required`. Both add a qualifier to a name already in that
namespace, so they are semantically identical -- proved by compiling all
46, which pass. No corpus struct is a keyword, so no reference moved.

The helper is deliberately **unqualified**: every caller already writes
its own `::{namespace}::`, and one carrying the qualifier too would double
it, which is 26.695's trap -- the pre-qualified string contains the bare
one, and a replace over both produced `::situ::::situ::adv_report`.

## The lesson is about the deferral, not the defect

`working-practice.md` says to check, before deferring something as a
design question, whether the project has already decided it somewhere else
under a different name -- and that **a wrongly-deferred question is caught
by nothing**, because it sits in the record looking exactly like
diligence. This is that, with the twist that the project had decided it in
the very function the entry named: `class_name` already implemented the
answer and the entry described it as not implementing it.

What would have caught it is the thing that did: **measuring before
choosing.** The question as posed -- suffix the schema's name or refuse
it -- had no answer because the suffix already existed. One sweep made the
design question evaporate and left two ordinary defects with established
remedies.
