# 26.1005: a builder writes an 8-bit tag

Status: recorded
Date: 2026-11-13
Source: the goal gap -- builder refusals over the example schemas

**FLAC's frame header could not be built**: its `crc` is a CRC-8, and
every builder's tag filler stored 16, 32 and 64 bits ("a 8-bit tag, and the
runtime stores 16, 32 and 64"). A byte has no order and the C runtime no
`put` for one, so C and C++ now store it directly; Rust's `to_*_bytes` and
Python's `to_bytes` already took a width of one.

**Measured against RFC 9639's first example frame header**,
`ff f8 69 18 00 00` and the CRC-8 `bf` (polynomial 0x07 from zero): Python
and C build those seven bytes from the six fields. The vector was recalled
rather than read, and corroborated independently -- a reference CRC-8 over
the six bytes gives `bf`. `test_the_four_builders_agree` now reaches
`frame_header` and the four agree.

USB's 5-bit token CRC stays refused: it is not whole bytes.
