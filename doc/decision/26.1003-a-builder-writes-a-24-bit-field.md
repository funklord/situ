# 26.1003: a builder writes a 24-bit field

Status: recorded
Date: 2026-11-13
Source: the goal gap -- every real-format struct with no builder, tallied
by reason over the 54 example schemas

**Every builder refused a `u24`**, as "whole bytes and not a width the
runtime stores -- 8, 16, 32 and 64 are". Four refusals in the tally, and
they are the length of a TLS handshake (RFC 8446 section 4, `uint24
length`) and of a FLAC metadata block, plus FLAC's `min_frame`: neither
format's framing structure could be built, though every reader read it.

**Written a byte at a time now**, for an unsigned field in a stated
order. C and C++ assemble it from shifts of the value; Rust's runtime
writer already took any width; Python's `to_bytes` already did. The
parameter is the next word up -- `uint32_t` for 24 bits -- so a value
wider than the field is refused as a constraint violation rather than
truncated to a message the caller did not ask for; Python's `to_bytes`
raises for it, as for any width.

**Still refused, and said so**: a signed field of such a width, whose sign
would have to be carried from a wider word, and a `native` one, whose order
is the host's and not knowable by situc running elsewhere. The refusal now
names which.

**Measured.** `test_the_four_builders_agree` reaches `tls` and `flac` and
the four write the same bytes. `test_a_builder_writes_a_24_bit_field` holds
them to the bytes: a TLS handshake's `01 00 00 len`, a `u24` in each order
and a `u40`, in Python and in C under the strict warnings, with a value
one past the field refused in C for both widths.
