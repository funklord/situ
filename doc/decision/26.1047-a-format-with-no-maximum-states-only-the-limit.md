# 26.1047: a format with no maximum states only the limit

Status: recorded
Date: 2026-11-17
Source: openmlx4's FS2 report (inbox 20261114T0041Z); the holder's word,
2026-11-17: "if there conceivably exists a protocol that needs a feature,
we do it, and we do it properly without regard for history and breakage
of old code"
Amends: 0054

**A legal image was called malformed.** FS2 ends its section list on a
sentinel, `next == 0xFF000000`, and states no maximum count; 64 is
`OMLX4_FS2_MAX_SECTS`, the size of fs2.c's arena. 0054 required `[depth]`
on every recursion and refused `[limit]` alone, so openmlx4 wrote
`[depth = 64]`, and every backend refused a 65-section image as
CONSTRAINT -- malformed -- where it is well formed and merely more than
this reader follows.

## The rule

A recursive struct states `[depth]`, `[limit]`, or both, and every struct
of a cycle states the same ones. With `[limit = N]` alone:

- past `N` the message is refused as `SITU_ERR_DEPTH` (`DepthError`,
  `Error::Depth`, `err::depth`), never CONSTRAINT, since no nesting of
  such a format is malformed;
- the extent and the depth probe follow one level past `N`, which is what
  seeing the limit crossed costs -- `declared_depth` answers `N + 1`, so
  every backend takes the branch it already had for a `[limit]` below a
  `[depth]`, and nothing new is generated;
- `size_max` is unbounded, as it already was for every recursion (the
  layout never derived it from `[depth]`).

A `[limit]` on a struct that does not contain itself is still refused:
there is nothing for it to cap. A cycle stating `[depth]` on some of its
structs and not the rest is refused like one doing so with `[limit]`,
since a walk entering at either end would follow a different bound.

## Measured

`test_a_located_chain.py`'s `limited` shape is FS2's sentinel chain under
`[limit = 8]`: the nine-section chain is OK with nesting 8, the ten-section
chain and the one looping to itself are DEPTH, in C, C++, Rust and Python,
and both walkers say what they say of the `[depth = 8]` chain. With
`declared_depth` answering `N` rather than `N + 1`, all four backends call
them CONSTRAINT and the four cases fail. The generated comment says "the
format sets no bound" rather than naming a depth nobody stated.
`test_recursion.py` holds the rules above.
