# 26.806: A member named `e` compiles in C++

Status: recorded -- fixed
Date: 2026-11-02
Source: found while probing 0068 step 2 with `entry(block = block) e;`

    struct pt { u8 x [max = 3]; }
    struct s  { u8 a; pt e; }

C++ `validate` checks a nested member through

    if (const ::situ::rt::err e = e(_held); e != ::situ::rt::err::ok)

The local `e` is in scope from its own initialiser, so `e(_held)` named
the local, and g++ refused it: *'e' cannot be used as a function*. A
delimited text number's check (`e(parsed)`) has the same shape. The
other three backends were unaffected.

## The change

Both calls go through `this->`. Every other call made in that position
names the member with a suffix (`_offset`, `_count`, `_whole`), so it
cannot be `e`.

## Tests

`test_a_member_named_e_compiles_in_cpp.py` compiles a nested member and a
text number both named `e`. With `situc/codegen/cpp/emit.py` reverted it
fails.
