# 26.831: the first three of `gen-checks`' nine kinds, in Python

Status: recorded -- three of nine ported, with the six named in the output
and the next step sized
Date: 2026-11-03
Source: 26.829; `situc/codegen/c/checks.py`; `project.md` sections 12.3, 18
and 22

26.829 measured which of section 1's four artifacts reach which of its four
languages and brought `gen-tests` to all four. `gen-checks` was the other
uneven one: C alone, and `situc/codegen/c/checks.py` is **3239 lines over 70
functions**, emitting **nine kinds** of check and asserting the `MUTATE`,
`OFFSET` and `SIZE` axes of the capability map.

A port rather than an increment, so this starts with one kind that stands
alone rather than deferring the whole thing.

## Which kind, and why that one

**A buffer one byte short of a struct's minimum must not yield a view.**

Section 12.3 calls that the single bounds check everything after it trusts,
and every generated accessor is written on the assumption that it passed. So
a backend that got it wrong would have every other guarantee resting on
nothing, which makes it the one to port first rather than the one to leave
until last. It is also one assertion per struct rather than per field, and
needs nothing but the acquiring call.

Python first for 26.829's reason: it has no compiler, so running the suite
is the only thing that executes the generated accessors at all.

## And the second kind: a field occupies its claimed bytes

The heart of the artifact. The capability map is a claim about **which
bytes a value comes from**, and this is the only check that reads that
claim back: flip each byte of the buffer in turn and ask whether the getter
noticed. Each claimed byte must be able to reach the value and **nothing
else may**.

Tested from outside, which is what makes it independent of how the
accessor was emitted. Over the corpus: **123 bounds checks and 359
claimed-byte checks across 42 schemas.**

**The control is decisive.** Changing `header.length`'s getter to read
bytes 5..6 where the map claims 3..4 fails exactly that field's check and
nothing else, with the message naming the field:

    AssertionError: False is not true : no claimed byte reaches length

`noticed` rather than "every claimed byte changes the value", which is the
C version's distinction and for its reason: a field narrower than its byte
legitimately does not notice a flip in a bit it does not use. The claim is
that the value comes from THESE bytes and from no others, not that it uses
all of them.

**And the fourth exclusion cost 22 of 42 schemas before it existed.** A
field whose extent is not fixed has no definite claimed range:
`udp_header.payload` is `[remaining]`, so at the struct's minimum it is
ZERO bytes long, and flipping its range changes nothing. The check
asserted that some claimed byte reaches the value and 22 schemas said
otherwise, every one of them correctly. **The map claims a byte range for a
field at a static offset with a fixed extent, and for no other** -- which
is the sort of thing that reads as obvious once written down and was not
obvious while writing the predicate.

## And the third: a writable field round-trips and moves nothing

The first kind here to assert **`MUTATE`**, where the two above assert
`OFFSET` and `SIZE` -- and the axis the advisor spends most of its rows on.
Write through the setter, read back, and require every byte outside the
field's claim unchanged. **267 of them, for 749 checks over 42 schemas in
all.**

**The map's own verdict is the gate, and it took two axes rather than one.**

`mutate = InPlaceFixed` says writing the field moves no bytes.
`auth = Covered` says writing it leaves an authentication tag stale, and
the backend withholds the plain setter for that reason (section 14.2). So a
field can be writable in place and have no setter at all --
`tcp_header.urgent` and `usb.token.address` are both, and both raised
`AttributeError: property 'urgent' of 'tcp_header' object has no setter`.
Five schemas before the second axis was in the gate. Writing one of those
is a different operation with a finalize after it, which is its own check
rather than this one.

**And the read-back goes through a FRESH view**, which is not caution.
`InPlaceFixed` says writing moves no bytes; it does not say a view taken
before the write survives it. `test/schema/shared`'s `len` drives another
member's extent, so writing it bumps the message generation and the old
view is correctly refused with `StaleViewError` -- section 12.3's typestate
working, not a field that failed to round-trip. 22 schemas said so before
this was understood. Whether bytes MOVED is asked of the buffer, which no
generation affects.

The control: a setter writing three bytes where the map claims two fails
exactly that field's check.

## The six it does not emit are named in the output

A
field decoding a known encoding; a nested member starting where the map
says; `must_eq` enforced; `reserved` being zero; an enum rejecting a value
no member names; a framing reader reassembling across every boundary.

Named in the generated module rather than left out, because **a suite that
checks three of nine things and does not say so reads as the whole map
having been checked** -- the same rule the vector targets carry, and the one
`gen-codec-tests` states for a signature that claims nothing.

The list is written out in the emitter rather than derived, because the C
emitter names its kinds only inside the test identifiers it builds and there
is no list to read. That is worth knowing for whoever ports the rest.

## Two exclusions, both of which cost a failing run first

Found by running the generated suites over the corpus, which is the whole
argument for that gate:

- **A register has no view.** It is a bus transaction rather than bytes off
  a wire, so its accessors take a device handle and there is no `at` to
  refuse anything. `example/register` raised `AttributeError: type object
  'dma_status' has no attribute 'at'`. `c/fuzz.py` excludes registers for
  the same reason and says so; `gen-dissector` has since it was written.
- **A zero-byte minimum has no short buffer.** `example/protobuf` is a bare
  `tlv` region whose minimum is zero, and `c/fuzz.py` carries a warning
  about this exact filter -- there `size_bytes > 0` dropped protobuf out of
  fuzzing entirely and left a harness that exercised nothing. Here the
  struct genuinely has nothing to check, so excluding it is right. **What
  was not right was the empty class body it left**, which is an
  `IndentationError`, and that is how protobuf failed. The module now says
  so with a skip: one that imports and defines nothing reads as a suite
  that passed.

## The control

**Neutralising the bounds condition in `runtime/python/situ_runtime.py`'s
`acquire` -- the function whose docstring is "The one bounds check" -- fails
both of `test/schema/header`'s checks.** A check nobody has watched fail is
not one, and this one is watching the exact line it exists to hold.

Over the corpus: 42 schemas generate and pass, one skipped where
`gen-checks` declines a schema taking a `parameter`, which is the
`refuse_parameters` family working.

## What remains, sized

The other six kinds, and C++ and Rust. **The pattern of what this cost is
worth carrying**: each of the three took one or two exclusions that only
running the generated suite over the corpus revealed, and in every case the
exclusion was the map being right and the check being wrong about what the
map claims. A register has no view; a variable extent has no byte range; a
covered field has no plain setter; a driving field invalidates the view it
was written through.

So the next kind -- **a field decodes a known encoding** -- should be
expected to cost the same kind of discovery rather than the writing, and the
corpus gate is what will supply it. Three axes are asserted now: `OFFSET`,
`SIZE` and `MUTATE`.
