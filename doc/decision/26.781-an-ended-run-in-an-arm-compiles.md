# 26.781: A run an arm ends by condition or delimiter compiles

Status: recorded -- fixed
Date: 2026-10-31
Source: `project.md` section 26 (the shapes 26.779 left unwalked)

    struct pt { u8 x; u8 y; }
    struct kv { u8 key[] until ":"; u8 value[] until ";"; }
    ... variant body switch (kind) { case 1: pt recs[] while (x != 0) max 6;
                                     default: u8 raw; }
    ... variant body switch (kind) { case 1: kv recs[] until "\n"; ... }

26.780 declined every run of structs in an arm and asked `array_count`
and `data_sized` which those were. A `while` run and a delimited run of
records set neither, so both still read as one struct. C++, Rust and
Python handed back the first record under the run's name, and so did C,
through `body_recs_view`.

It was worse than that. C did not compile for either shape:

- `frameable` asked only whether an arm held a counted run, while C's
  `_required` declines any run in an arm, so the frame layer and the
  differential driver called `arms_required` and nothing defined it.
- A delimited run in an arm had `check` ask `body_recs_terminated`, which
  only a delimited byte run has. Rust's `validate` asked the same.

And for a delimited run of records, C++ and Rust named `body_recs_span`
in the variant's length, and Python did the same for both shapes.

## The change

- `traverse.is_struct_run` covers a run that a `while` or a delimiter
  ends. The arm accessor in all four declines it with the sentence C
  uses, and C's struct-arm branch now asks it too.
- `traverse.is_unmeasured_run` is a counted run of variable records, or
  any run of records a condition or delimiter ends. `frameable` and the
  variant length in C++, Rust and Python ask it, so none names a span
  the arm family never emits. C's `_has_length` already declined these.
- C's, Rust's and Python's delimited-arm check skips a run of records.

No corpus schema has such an arm, and the corpus generates
byte-identically.

## What is still open

`validate` does not yet hold these runs to the frame. A `while` run of
`piece` whose second record overruns validates clean in all four and in
both walkers, as do `[remaining]` and recursive counted runs in an arm.
The walkers also disagree with each other on a delimited run of `kv`
cut short. Those are the walks 26.779 recorded as not done.

## Tests

`test_an_ended_run_in_an_arm.py`: for four shapes (a `while` and a
delimited run, each of fixed and of variable records), no backend emits
an accessor, `framed_structs` leaves `arms` out, and the four build and
agree on four messages. With `situc` reverted, all twelve fail.
`test_a_run_in_an_arm_is_walked.py` now also looks for a `_view`
definition.
