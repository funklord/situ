# 26.970: an array in an arm reads a handed order

Status: recorded
Date: 2026-11-12
Source: describing a TIFF entry's value as TIFF means it

A TIFF entry's value field is four bytes whose meaning `type` decides: a
SHORT sits left-justified in the first two, in the file's byte order, so

    variant value switch (type) { case 3: u16 shorts[2]; default: u32 long; }

and read as a `u32` a big-endian file's width of 3 is 196608. In
`ifd_entry`, which is handed its byte order (26.961), C's count and
getter for an array in an arm loaded through `arg_order` and took no
argument, so the header did not compile. They take the arguments their
text reaches now, as the located accessor does, and the getter hands the
count its share. The other three backends carry the argument on the view
and were right.

`example/tiff` describes the value that way, and
`test_a_located_member_takes_arguments.py` reads widths and lengths laid
out by hand in both orders as SHORTs, through all four backends.
