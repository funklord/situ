# 26.746: A versioned field the frame cut short validated

Status: recorded -- fixed
Date: 2026-10-29
Source: `project.md` section 26

Section 19.4: `validate` "reads the version first and skips a `[since]`
member the message does not carry". A message that DOES carry the member,
by its own version, and whose frame stops short of it is not an older
message -- it is a malformed one. Every backend's accessor already knew
the difference:

    if (situ_versioned_ver_get(view) < 3u) return SITU_ERR_VERSION;
    if (!situ_in_bounds(view, 7u, 2u))     return SITU_ERR_BOUNDS;

`check` did not. A `[since]` member sits at a STATIC offset past the
struct's minimum, so the acquiring check never answers for it, and the
version gate in `check` was emitted only where the member had a constraint
or a fit check to put behind it. A plain `u16 extra [since = 3]` had
neither, so got nothing:

    03 01 00 02 00 00 00 aa      version 3, one byte of `extra`
    extra ok=0                    in all four
    validate 0                    in all four, and in both walkers

The C walker's comment said it in as many words -- "the packer, the
Python walk and every backend leave that one unchecked, so a second
reader that flagged it would be the one out of six that disagreed". Six
readers agreed on the wrong answer and one of them explained why it kept
agreeing.

## How it was found

By `test_required_against_the_walker.py`'s instrument, built for 26.745:
`edges.versioned` validated on an eight-byte buffer whose `required` and
walker extent were both nine. Asking for more than a valid buffer holds
is allowed, so the test does not refuse it -- but `validate` passing a
buffer that both other measures say is short was worth reading.

## The fix

Every versioned member goes behind the version gate in `check`, whether
or not it has a constraint: the gate calls the accessor, passes VERSION,
and returns any other refusal, so the accessor is the frame check. In
Python a member with nothing else to check is read and dropped, since an
`if` with no body is not Python. Both walkers check that a `[since]`
member the version admits fits the frame, as they did only for a member
at a dynamic offset.

`[since]` is kept for single scalars only (`wellformed` refuses it on a
run), so the scalar path is the whole construct.

`test_a_versioned_field_must_fit.py` asserts five verdicts in all four
backends and both walkers; each half fails with its change removed.
