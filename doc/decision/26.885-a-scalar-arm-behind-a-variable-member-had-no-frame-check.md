# 26.885: A scalar arm behind a variable member had no frame check

Status: recorded
Date: 2026-11-05
Source: `example/pes`, under the random-bytes sweep

    000001cc 1452 24 fa 8a ...          28 bytes, every flag set but two

`pes.trick.trick_present` sits at byte 28 of that buffer. C and C++ answered
Bounds. Rust answered `Ok(0)` and Python answered 0. The value is a byte the
frame does not hold, and the Rust caller was handed a `Result` that said it was
there.

## Why

26.325 split the arm question from the frame question, and wrote the frame
question as a comparison with `byte_span`. `byte_span` is `None` at a dynamic
offset, so the bound came out empty and the read fell through to the lax
reader, which answers zero by design. C and C++ ask `situ_in_bounds` of the
offset expression, so they had no hole. Rust and Python had only the constant
form.

A struct arm in the same place was right all along: it compares the frame with
the arm's extent before it builds a view. Only the scalar branch had the hole,
so a schema met it only with an arm behind something variable and a frame that
ends before it. The random-bytes sweep had not drawn one over the other 34
scalar arms in the corpus.

## The fix

Both backends now bind `at` to the offset expression, compare it, and read at
`at`.

## Not a language change

No schema's meaning moves. An accessor that returned `Ok(0)` for a missing byte
now returns `Err(Bounds)`, as the other two did.

## Tests

`test_a_scalar_arm_past_the_frame_is_refused.py`: a u8 and a u16 arm behind a
run, each present and each one byte short, in all four. An enum arm is in the
schema, so Rust compiles it, and the probe does not ask it. Red with either
backend's emitter put back.
