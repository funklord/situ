# 26.860: The three builders drive from C's plan, and serve runs and size fields

Status: recorded -- 65 structs over 23 schemas of the 133 C serves. Bit
fields, delimited runs, varints, nested members and arms are what is left
Date: 2026-11-04
Source: measuring what kept C-served structs out of 26.858's class

26.858's class read placements. Measured over the corpus, the largest
exclusions were sized runs (22 structs for that alone), variants (19),
fixed arrays (9) and reserved bytes. Each is a role C's writer already has,
so this stops re-deriving and asks C's own `plan()`: `plain_build.parts`
answers with the plan where every part is one the three builders write.

| role | what the caller gives | what it does |
|---|---|---|
| `scalar` | an integer | store at the cursor |
| `run` | the bytes (`&[u8; N]` in Rust) | a fixed byte run |
| `span` | the bytes, and a length in C++ | a measured byte run |
| `size` | nothing | computed from the run it measures |
| `zero` | nothing | a reserved fill the schema states |
| `literal` | nothing | bytes the schema spells out |

A size field is never asked for, so a message cannot disagree with its own
schema. That includes one stated as arithmetic: `_invert`'s rule, run
backwards exactly or refused, is in all three.

The plan also settles what a parameter is called, so a schema's member
name that collides with a writer's local is handled once. And it took the
`[since]` structs in, which a placement-based rule had excluded for no
reason the writer shares: C writes them whole.

## What is declined, named on stderr

A part C writes and these do not: digits, a value another arm claims, a
run whose length a struct argument states, a marker-governed order, a count
of elements rather than bytes, and any other role.

## Tests

`test_the_four_builders_agree.py` feeds every role, with a span long enough
for an arithmetic size field to come out whole: 65 structs, 155 scalars, 23
spans, 20 size fields (4 solved), 14 runs, 5 reserved fills, 2 literals,
all four byte-identical.
