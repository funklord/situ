# 26.1012: an arm sized by its argument is written

Status: recorded
Date: 2026-11-13
Source: the goal gap -- the largest group of builder refusals over the
example schemas, "holds a `X`, whose own bytes do not state its extent"

**DNS resource records and wasm sections could not be built.** Their
bodies are arms like `case 1: a_data(size = rdlength) a;`, with
`a_data { parameter u16 size; u8 data[size] [holds = ipv4_address]; }`:
the arm's struct states no extent of its own, so situ emits no
`_required` for it, and the builder refused it because it could not tell
one from a longer blob.

It can. The struct's extent IS its argument, and the argument is a field
of this struct the caller passes -- `rdlength`, wasm's LEB128 `size` --
so the caller's bytes are one of it exactly when they are that long. The
writer checks that and copies them; the content is checked by the
builder's closing `validate`, which hands the arm the same argument a
reader does, so three bytes offered as an IPv4 address are refused there.
The shape is narrow on purpose: an arm struct of one parameter and one byte
run that long, handed a plain field.

**C only.** The other three builders do not yet build a member taking
arguments (`plain_build._serves`), so this is C reaching further, as it
has before.

**Measured** against RFC 1035 section 4.1.3, `example.com IN A
93.184.216.34` with TTL 300, byte for byte, an RDLENGTH that disagrees with
the bytes refused; and against the wasm core spec's custom section, id 0,
LEB128 size, a name. dnsname's six resource arms and wasm's six section
arms now build; mqtt's `publish_body`, sized by flag bits rather than a
length, is not this shape and stays refused.
