# 26.1101: the dissector counts a text number in digits

Status: recorded
Date: 2026-11-19
Source: `test_the_dissector_agrees_with_the_walker[edges]`, once 26.1099's
`classed` shifted the draws `counted_digits` receives

**`decimal u32 count[n]` was shown as `n * 4` bytes.** A text number's
count is its digits, one byte each, whatever width the scalar giving its
domain has -- the rule `layout` and every other reader already keep ("a text
number is not an array, however much its bracket looks like one"). The
dissector's counted-run path took the element width from the scalar, so a
counted text number covered four times its bytes and every member after it
was shown where none of the six other readers put it: `rest` 17 bytes on a
58-byte frame where the backends and both walkers read 47.

It had been there since counted text numbers reached the dissector. The
draws are made struct by struct in name order from one seed, so a struct
added before `counted_digits` in that order -- `classed` -- moved its draws
onto a frame with `n` above 4; the earlier draws had not reached one.

## The rule

A run's element is one byte where the run is a text number, as it is for
`opaque`.

## Measured

The edges comparison fails with the change reverted and passes with it;
`test_dissector.py` passes (455).
