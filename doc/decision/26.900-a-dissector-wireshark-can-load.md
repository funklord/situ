# 26.900: A dissector Wireshark can load

Status: recorded
Date: 2026-11-06
Source: loading `edges.lua` in tshark by hand, after 26.899

Six of the corpus's dissectors failed when Wireshark loaded them, and every test
passed. `luac` checks the syntax and the harness in `test_dissector.py` stands
in for Wireshark, so nothing had asked Wireshark.

- **A `Proto` name Wireshark holds.** `coap`, `radiotap`, `slip`, `frame`, `rtc`'s
  `calibration` and `sexpr`'s `list` each died at `Proto_new: there cannot be two
  protocols with the same name`. A dissector for a format Wireshark already
  dissects is the commonest case there is.
- **A `<` in an abbrev.** `_local` stripped the brackets of `<reserved0>` from the
  ends of the name, and a reserved member in an arm is `body.<reserved0>`.

`Proto` is now `situ_<schema>_<struct>`, and its description is
`<schema>.<struct> (situ)`, because two schemas may each have a `header` and
Wireshark holds both unique.

- **A field abbrev Wireshark holds.** `radiotap.vendor_namespace` exists as another
  type, and a `::` from a namespaced struct is no abbrev at all. A field is now
  `situ.<struct>.<member>`, so a display filter reads `situ.coap.code`. Two schemas
  with one struct name and a field of two types still cannot load together.

`test_wireshark_loads_every_dissector` loads each schema's in tshark, and
`test/lua/dissect.lua` drops the `situ.` when it reports a row.

## What running it showed

`test_wireshark_runs_a_dissector_down_through_what_it_holds` dissects a real
ClientHello in tshark, because a load does not say a dissector works. The first
rename left `Dissector.get("<struct>")` asking for a name nothing registered, and
the harness, which resolved either, passed.

- **A length field after a variable member could not be read.** No constant offset
  reaches it, so the member it sized and everything after went unshown as "the
  rest of the frame". That is most formats past their first variable member. The
  body now reads such a field at the cursor into a local, and the size uses it.
  An extent function has no cursor, so one measuring such a struct still declines.
- **A `[remaining]` run of records was one raw row.** It is walked now, each element
  dissected, as a counted run's are.
- **A `[holds]` run descends**, its row kept and the struct under it.
