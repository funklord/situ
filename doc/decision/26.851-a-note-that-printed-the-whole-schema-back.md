# 26.851: a note that printed the whole schema back at its author

Status: recorded -- fixed, with a gate over the class rather than the case
Date: 2026-11-04
Source: found while running 26.850's own lens on a NEW axis -- a generated
comment or a diagnostic that promises something, checked against what is
actually done -- on a fragment written to test something else

## What it printed

`case 1: scaled i64 code[5];` is refused, correctly: a scaled text number
cannot have a fixed width, because the width says how many characters there
are and not where the point goes, so `1.50` and `0.15` fit one field and
spell different values. The refusal's third note suggests the spelling that
would work, and said this:

    = a format whose point is always in the same place is a plain integer
      with a scale the reader applies: `decimal i64
      code[IntLiteral(span=Span(source=Source(path='/tmp/.../scaled.situ',
      text='target buffer;\nendian big;\n\nstruct arms {\n\tu8 kind;\n\t
      variant body switch (kind) {\n\t\tcase 1:  scaled i64 code[5];\n\t\t
      default: u8  other;\n\t}\n\tu8 tail;\n}\n'), start=109, end=110),
      value=5, text='5')]` reads the digits, and the schema says in a
      comment where the point is

One character of cause: `f"[{member.array.size}]"` over an AST node, where
an f-string gives the node's REPR. The node carries a `Span`, the span
carries its `Source`, and a `Source` carries the whole file -- so a
sentence written to help prints the author's entire schema back at them,
inside the suggestion.

`member.array.size.span.text()` is the fix, and it is the better answer for
a second reason: where the size is an expression, `[n + 1]` reads back as
written rather than as a tree.

Section 17 is what a diagnostic is for. This is the same class as 26.485 --
Python objects reaching shipped output -- arriving in a message rather than
in generated source.

## The gate is over the class, and the detector could not be static

A sweep of the source for an f-string over a node cannot tell
`{kind.value}` -- an enum's string, which is right, and there are a dozen
of them -- from `{member.array.size}`. Measured: the same pattern matches
eleven sites in `wellformed.py`, `layout.py`, `resolve.py` and
`propagate.py`, and ten of them are correct.

So `test_a_refusal_prints_no_python.py` renders REAL refusals, eleven
fragments over as many families, and reads what a person would see: no
`Span(`, no `Source(`, no `Literal(`, no `object at 0x`, no `<situc.`. Each
fragment is also asserted to REFUSE, so one that becomes legal fails the
file rather than quietly leaving the sweep a case shorter -- which is the
vacuous pass this shape is one language change away from.

**And a sweep that only forbids reprs passes against a note that dropped
its suggestion entirely**, so the case itself is asserted positively too:
the note has to contain `` `decimal i64 code[5]` reads the digits ``.

**The control**: with the fix reverted, three of the twelve fail -- the two
fragments that reach that note and the positive assertion -- and nine pass.

## Why the lens found it and nothing else had

The fragment was written to ask whether a SCALED text number could be a
variant arm, which mattered because 26.850's new arm clause parses with the
integer parser and 0056 records what happens when that runs over `12.5`.
The answer is that the compiler refuses the construct outright, so the
clause can never meet it -- no defect, and the refusal's own message was
the defect instead.

Worth keeping: **the check that came back clean still cost nothing and
still paid.** The question was "did I just introduce 0056's bug", the
answer was no, and the evidence was a diagnostic nobody had read closely.
