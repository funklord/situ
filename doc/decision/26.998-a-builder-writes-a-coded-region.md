# 26.998: a builder writes a coded region

Status: recorded
Date: 2026-11-13
Source: the goal gap after 26.996 -- readers decoded a stuffed region in
every language, and no writer could produce one

**Every builder refused every coded region**, C's included, because "the
bytes on the wire are the codec's output and not the ones a caller would
hand over". That is true and does not decide anything: the escaped-run
writer already takes CONTENT and writes the schema's wire form, and the
encoders exist natively in all four languages since 26.996. So a SLIP
frame or an SMTP DATA body had readers and no writer.

**The caller hands over the content, and the writer encodes it.** Where:

- the codec is bound `derived` and its code is in `WRITABLE_CODES` --
  `slip` and `ppp_async`, whose encoders write their own END, and
  `smtp_dot`, whose encoder leaves `CRLF . CRLF` to the framing;
- the region has one consumed delimiter, and it is the one the code
  protects (SLIP's 0xC0, PPP's 0x7E, SMTP's `CRLF . CRLF`) -- stuffing
  keeps only its own delimiter out of the body;
- the interior is one byte run to the region's end. Content with fields
  would be a struct to compose first, and is refused by name.

The plan reuses the ENDED role -- bytes and a length from the caller -- with
the code on the part, so every backend's signature, parameter naming and
measuring logic serves it unchanged and only the writing differs. Room is
the code's worst case, `ceil(len / per) * worst + overhead` (plus the
delimiter where the encoder does not write it), in 64 bits in C and C++:
a body that would fit after encoding can be refused, and none can overrun.
The builder's closing `validate` catches a framing the encoder got wrong.

- C and C++ call `situ_<codec>_encode`; C++'s header now declares the
  encoder beside the decoder, as C's does.
- Rust calls the native `<codec>_encode` from the module, no `unsafe`.
- Python calls `situ_schema.<codec>_encode` into a `memoryview` of the
  caller's buffer, so nothing allocates, as the module promises.

**Measured.** `test_the_four_builders_agree` reaches `slip.frame` and
`smtp.data_block` and the four write the same bytes.
`test_a_builder_writes_a_coded_region` holds them to the RFCs rather than to
each other: RFC 1055's END and ESC substitutions in Python and C, RFC 5321's
doubled leading periods, the worst-case room, and the refusal for an
interior with fields.

**Not reached.** COBS (its encoder's delimiter handling is not read here),
the bit-stuffing codes, `json_string`, a sized coded region, and a tier-1
`extern` codec, whose encoder is the caller's. Each is refused with the
list of codes that are written.
