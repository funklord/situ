# 26.973: a builder over a tail that ends the message

Status: recorded
Date: 2026-11-12
Source: fuzznet, inbox 20261112T1336Z (moving its call messages onto situ)

fuzznet's call messages are a variant whose `frame` arm ends in
`u8 media[remaining]`, one message a datagram:

    struct frame { u8 stream; u16 pieces [min = 1]; u8 media[remaining]; }
    struct message { u8 family [must_eq = 2]; kind kind;
        variant body switch (kind) { case kind.ring: nothing ring;
                                     case kind.frame: frame frame;
                                     default: error; } }

`situc build --layer edit` refuses the builder: "`body.frame` holds a
`frame`, whose own bytes do not state its extent -- situ emits no
`_required` for it -- so the writer cannot tell one from a longer blob".
The generated reader agrees field for field with fuzznet's hand-written
codec on all eight kinds; this is the one gap. Their alternative is a
16-bit length before `media` in their most frequent message, carried
only so a builder can be generated.

**The refusal is wider than its reason.** A builder takes an arm's value
as a blob and asks the arm struct's `_required` whether the blob is
exactly one. That question matters where something follows the arm: a
blob one byte too long would swallow it. Where the variant is the
message's last member and the message ends where its view does, the
blob's end is the message's end, so a blob of any length that validates
as a `frame` is exactly one -- the writer chooses the extent, as fuzznet
says. The builder can check it by acquiring the arm struct over the whole
blob and validating, without `_required`.

## Built

The shared plan (`c/build.py`) marks such an arm's part as a `tail`
where the arm's struct is sized by the data, has no `_required` only
because it ends where its view does, takes no argument, and the variant
is the struct's last member. A fixed-size arm struct keeps what it had:
mqtt's `connack_body` has no `_required` for a reason of its own, and
the first version of this took it in and called its fixed `_view` with a
length. Each writer then checks the caller's bytes by taking the arm
struct over all of them and validating -- C over a message it
initialises on those bytes, C++ over a raw view, Rust through `new`,
Python through `at` -- instead of asking `_required`. A struct with
anything after the variant is refused as before.

`test_a_builder_takes_a_tail_that_ends_the_message.py`: fuzznet's schema
builds a frame and the message around it to bytes laid out by hand, with
and without media; bytes that are no frame are refused; a trailing
member after the variant still refuses the builder; and the four writers
agree.
