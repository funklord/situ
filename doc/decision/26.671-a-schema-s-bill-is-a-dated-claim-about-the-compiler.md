# 26.671: A schema's bill is a dated claim about the compiler

Status: recorded
Date: 2026-10-22
Source: `project.md` section 26

Audited because the consumer queue produced the same shape four times in
two days, each time with the stale sentence doing the damage rather than
the gap it described.

## The four instances

- **`example/json`** said escapes were "a genuine gap rather than a
  language boundary: `[escape = "\\"]` exists for exactly this" -- a
  sentence naming the attribute that fixes it while calling itself a gap
  (26.299).
- **`test_examples.py`** called `situc map --check` "phase 9" for the 77
  days after it landed, in the stand-in test written *until* it existed
  (26.668).
- **`suggestion/netcfgd.md`** quoted `example/json`'s stale sentence back
  at situ as the reason its hottest member could not be described
  (26.670). The gap had been closed before they read it.
- **`example/sqlite`**, found by this audit and the worst of the four:
  a section titled "What this example asked for and did not get", false
  in every sentence, twenty-odd lines below the struct that does all of
  it.

## What `example/sqlite` claimed, and what the file beside it says

The bill gave two reasons a SQLite table leaf cell was inexpressible and
one consequence. Measured against the same file and its committed map:

| the bill | the file |
|---|---|
| "`varint_type` has one encoding and it is `leb128`" | declares `encoding = be128`, `max_bytes = 9`, twenty lines above |
| "nothing may be sized by [a varint]" | `u8 payload[payload_size]`, in `struct table_leaf_cell` |
| "The elements are `u8 cells[]` rather than a `cell` struct" | `table_leaf_cell cells[];` |
| "no backend can read one" | all four do; C emits `_get`, `_value` and `_len` |
| "`cells_at` is not [emitted]" | it is |

The schema was converted in pieces and the bill was never re-derived.
What is still honestly missing -- overflow pages -- was always stated
separately and stays.

## The audit, and why it cannot be a gate

63 comment lines in the corpus claim inexpressibility ("cannot", "no way
to", "not expressible"). **One was stale.** The rest are sound, and
several are deliberately historical: `example/sqlite`'s own header says
"until `[must_eq]` took a literal there was no way to say it", which is
past tense and correct.

Sampled and verified still true: `cpio`'s stopping rule (no comparison
against a byte string in a run condition -- re-measured, refused by
name), `id3`'s bit-stuffed checksum (with its own CRC measurement),
`ipv6ext`'s `while` versus `until`, `modbus`'s single-valued `[must_eq]`.

**So the detector is the problem, not the population.** A stale bill
reads exactly like a sound one: both are confident prose naming a
construct and a reason. What separates them is only whether the claim is
true today, which means the only detector is re-derivation -- and
nothing in the ordinary course of work brings a reader back to a comment
while the schema compiles.

What did find this one, every time, is a reader with a reason to care:
three of the four instances were found by a consumer quoting the sentence
or by somebody asking whether the gate existed. **That is the argument
for the suggestion queue being worth more than its content** -- a
consumer reads the bills, which nobody here does.

## The holder's question

**Should an inexpressibility claim in a schema carry a date?**
`evidence.md` already says a fact recorded without its method has a
shelf life, and that the countable present-tense claim about the tree's
own shape is the one that rots. A bill is exactly that claim, and
`// (2026-09-06) situ cannot ...` would make staleness visible without
anybody re-deriving: a reader seeing a date six months old knows to
check, where today's prose reads as current for ever.

It is a convention for schema comments across every example, so it is
raised rather than applied -- and the cost is real: 63 lines to date,
and a date is one more thing to get wrong in a file nobody runs.
