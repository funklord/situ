# 26.669: A refusal that named one of three spellings

Status: recorded
Date: 2026-10-21
Source: `project.md` section 26, from `suggestion/fuzznet.md`

`fuzznet` reported that `[max]` cannot bound a `remaining` field, twice
in one file: once for its tree node bodies and catalog content, and once
for its disclosure field, where it says in as many words **"we did not
write a schema"** because the schema would have stated less than its own
constant.

**The construct was built since and the refusal was still misdirecting
them.** 26.539 added `u8 content[remaining] max 470` -- a clause, not an
attribute, the same word in the same position as `until D max N`.
Measured on their shape: `struct node_body size=1..471` with `content
offset=AbsoluteStatic(0x01) size=Bounded(0, 470)`, which is exactly the
"worst case named without changing the offset" they asked for. Their
disclosure layout compiles too, `size=16..400` with `field Bounded(0,
384)`.

## The message named `until`, and `until` is a different run

    error: `[max]` means nothing here
      = belongs on a scalar field -- an array has no single value to
        bound, and a size cap is spelled `max N` after `until`

`until` is a DELIMITED run. `fuzznet`'s reach the end of the frame, so
the one spelling that would have worked for them was the one the message
did not mention -- and a reader who follows it, finds `until` is not
their shape, and concludes the cap is unsayable has read the message
correctly. That is 26.137's rule again: **a refusal that does not say
what WOULD have worked is read as "nothing works"**, and it had been
applied to `stuffing`'s catalogue and not here.

**It was one message for three audiences.** A frame-length run caps
itself after `[remaining]`; a counted run is bounded through its count,
which is `[max = N]` on the count's own field; a delimited run is the
`until` case the message named. The first two were both being sent to the
third. All three are named now, and the counted one names the field:
`put [max = N] on n`.

## The test asserted less than its docstring claimed

`test_the_attribute_form_is_still_refused` existed, with the docstring
*"The refusal fuzznet met, unchanged: it names the spelling instead."*
Its assertion was `"means nothing here" in str(raised.value)` -- which
says nothing about WHICH spelling is named, so the message could name
the wrong one forever and the test would hold. It checks the claim now,
including that a frame-length run is not sent to `until`.

Which is the shape worth keeping: **a docstring that states the property
and an assertion that checks a substring of the error are two different
tests**, and the gap between them is invisible while both pass. The
docstring was written by somebody who had read the message and knew what
it should say; the assertion was written to make the test green.

## What `fuzznet` still cannot write, and it is not this

**The blob leaf.** `commitment || ciphertext || tag` -- a fixed prefix, a
length-less variable region, and a trailing fixed tag -- is refused as it
was, and the cap does not reach it: `max N` bounds how large a run may be
and does not move where it ends. Re-measured rather than assumed.

Their two shapes for it are not equivalent and the choice is the
holder's: a run sized as remaining-minus-trailing-fixed is a layout form
every schema could use, where a `sealed{}` region reserving its declared
tag from the tail is a codec property the region already knows -- narrower,
and it states the thing once rather than at every call site.

**`sum` over a length table** is still refused and is still the same
question as their record-slot length tie: a field whose value must equal
a computed size of other fields. One language question with two
reporters, and situ's holder's.
