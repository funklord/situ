# 26.908: Names and shapes that broke one backend alone

Status: recorded
Date: 2026-11-06
Source: found building 26.904, each outside what that record is about

- `struct leaf` built in Python and raised a TypeError from inside a reader: the
  class replaced the runtime's `leaf`, which every size read calls. So does any
  name the module imports, `View` and `Message` among them. The import takes an
  alias, `leaf as _situ_leaf`, and the struct keeps its name: a schema's names
  are the protocol's, and `Message` is an ordinary one. A refusal was tried
  first and dropped, because it rejected schemas in the suite that the other
  three backends read. A word that means the struct is told apart by shape, as
  26.879 does for a builtin: a construction, an attribute, an annotation other
  than a `msg` parameter's. mypy found the attribute case.
- `struct tree` made a dissector that did not work, its proto hidden inside its
  own function by the parameter of that name. `tree`, `tvb`, `pinfo`, `subtree`
  and `at` are suffixed as a keyword is. The display filter keeps the schema's
  spelling, which it did not for a keyword either.
- A delimited member behind a member an argument sizes did not compile in C: its
  `_len`, `_span`, `_terminated`, `_ptr` and `_eq` took no tail, while their
  callers passed one.
