# 26.808: A dissector's extent counts a `parameter` as nothing

Status: recorded -- fixed
Date: 2026-11-02
Source: found while dissecting a run of argued elements (0068 step 6)

    struct entry { parameter u16 block [stream]; u8 tag; u8 data[block]; }
    struct vol   { u8 block [max = 6]; entry(block = block) ent; u8 after; }

The Lua dissector's extent function `_extent_steps` added `size_bits`
for every fixed member, so `entry_extent` was `3 + block` where an
`entry` is `1 + block` bytes. The parameter's two bytes of width are
not in the message. `traverse.fixed_span_bits` says so for every other
function that adds members up (0050, 0057), and its docstring names
this exact failure in generated Python. The dissector was a fourth
reader that kept its own sum.

Nothing measured an argued struct from outside before 0068, so the fault
was unreachable. With 26.804, `vol.after` was shown two bytes late.

## The change

`_extent_steps` asks `occupies_fixed_bytes` and `fixed_span_bits`, as
`traverse.extent_parts` does. That also covers a `peek` member, whose
span is nothing (0057).

## Tests

`test_a_dissector_extent_spans_no_parameter.py` holds the dissector to
the walker on `vol`. With `situc/dissector.py` reverted, `vol.after`
differs.
