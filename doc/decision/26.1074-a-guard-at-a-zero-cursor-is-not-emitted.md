# 26.1074: a framing guard at a zero cursor is not emitted, nor asked twice

Status: recorded
Date: 2026-11-18
Source: raidcfgd's cppcheck over its generated headers (inbox
20261118T0319Z)

**`required` asked `have < pos` where `pos` could only be zero.** Before
the first variable member, with no fixed bytes in front of it, the cursor
is still its starting value `gaps[0]`, and at zero the comparison is one no
unsigned `have` can make true. cppcheck names it `unsignedLessThanZero`:
six times in raidcfgd's three schemas.

**And every nested or variant framing asked the guard again.** The member's
own guard (`reading its length means reading bytes that have to be here
first`) is emitted a line above the nested struct's and the variant's, with
the same operand wherever no early length or discriminant literal stands in
for the cursor. The second asked nothing the first had not, and its `need`
could never be the one returned. cppcheck reported these as 61
`knownConditionTrueFalse` in raidcfgd's generated code.

Neither was wrong: the code was correct and the guards dead. What it cost
was a consumer's static analysis, where 67 findings in generated code sat
beside seven in its own.

## The rule

- At the first variable member, where `gaps[0]` is zero, the member's
  guard is not emitted. A nonzero start keeps the name `pos`, so the
  variable is still read where it is declared and no `variableScope` is
  traded in.
- A nested struct's or a variant's guard is emitted only where its operand
  differs from the member guard's: an early discriminant literal keeps its
  own check, the cursor does not repeat it.
- All four backends, in step. Rust and Python have no analyser asking, but
  the four emitters are kept the same shape so one can be read against
  another.

**And the dead guard was holding up a declaration.** C declares `pos` only
where a code line names it, and it told code from comment by the first
character: `*` read as a comment's continuation, so `*need = situ_need_u32(at,
(have > pos ? ...))` -- `_partial_need`, the varint and delimiter case --
did not count. With the guard gone, 15 corpus schemas failed to compile on
`pos` undeclared. A continuation is `*` followed by a space, a slash or the
end of the line now; `*need` is code.

The guards inside a run's walk are untouched: the cursor advances each
element, so they are live from the second one on.

## Measured

raidcfgd's three schemas, generated at the parent commit and with the
change, through raidcfgd's own cppcheck flags: 61 `knownConditionTrueFalse`
and 6 `unsignedLessThanZero` before, none after; the one note left is
`situ.h`'s own `variableScope`, there before. Replacing a nonzero start with
its literal as well was tried and dropped: it left `pos` read only inside one
block, and cppcheck traded the guards for `variableScope`.

The corpus, 63 schemas through the same flags, at the parent and here:
`unsignedLessThanZero` 224 to 119 and `knownConditionTrueFalse` 153 to
102. What remains is other shapes, not this one (`at >= view.limit` at a
zero `at`, `*need < at`, the arm-size ternary whose arms agree).

**And 18 `variableScope` were traded in** (77 to 95): where the first
variable member is a nested struct, the cursor is now read only inside that
member's block, and cppcheck suggests declaring it there. A style note in
place of a dead comparison, and left to the cppcheck lens that takes the
rest.

The framing suites (`test_required_*`, `test_four_backends_frame_alike`,
`test_the_differential_frames`, the frame tests) and the four codegen
suites pass, 2757 tests.
