# 26.1106: a registry's keyspace is part of the wire contract

Status: recorded
Date: 2026-11-19
Source: the goal gap walked at the end of run 6 -- 0070's registry is
generated by every backend and walked by both walkers, and `situc wire`
said nothing about it

**A registry is a contract between peers as a struct's layout is**: which
keys exist, what each cell is a message of, its bounds and sizes, the value
a peer assumes where a cell is absent, which way it is safe to move, and the
consumer's policy words. None of it was in the wire signature, so
`wire --check` passed a key removed, a cell's type changed or a bound
narrowed -- the changes a deployed peer is hurt by.

## The rule

The signature carries each registry after the structs, one line per key in
key order: `key="..."`, `cell=<type>`, `family` where it is one, then every
attribute but `unit`, sorted, with strings spelled without spaces so a fact
stays one token. The summary and a unit are how a client shows the cell,
not what may be sent, so rewording one is not a contract change.

The comparison classifies a key as a peer reads it: removed is breaking (an
old peer still writes that cell), added is forward, a changed cell type is
breaking (the same bytes are another message). Every other fact goes
through the member comparison, so a narrowed `max` is the tightening it is.

## Measured

`test_a_registry_is_in_the_wire_contract`: the keyspace is rendered without
its labels; a removed key, an added key, a changed cell and a narrowed
bound are each classified; a relabelled unit and summary are no finding.
With the comparison removed the four classification cases fail.
`edges.situ.wire` gains its registry block; the files touching the wire
signature pass.
