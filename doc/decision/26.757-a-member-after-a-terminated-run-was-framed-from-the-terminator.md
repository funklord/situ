# 26.757: A member after a terminated run was framed from the terminator

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26; reported in `suggestion/hull.md` section 21

`required` frames a run of records that ends at a terminator --
`form entries[] until ")"` -- one element at a time, through each
element's own `required`. When it meets the terminator it adds the
terminator's bytes to the running total `at` and breaks. It did not add
them to the cursor `pos`, and all four emitters said why: "the cursor is
never read after this break".

That is true where the run is the last variable member. Where another
follows, it reads the cursor to know where it starts:

    struct msg { u8 open; form entries[] until ")"; tail t; }

so `tail` was framed from the `)` itself, one byte early. Its atom's
length was then read from the wrong place and came out short, and all
four backends called `((1:a))(1:k5:alpha)` complete at 15 of its 19
bytes -- always short by the trailing atom's length less one, which is
what hull measured.

## How it was found

hull moving its pin from b186326 to 5ada3e8: two of its 46
`core/frontend.vectors` stopped conforming under `situc verify`, which
sizes a vector with the Python backend's `required`. hull bisected over
`git archive` copies to 1e81500, and so does a bisect here between
b186326 and HEAD (the write-up's "24084c6 before it" is a slip:
24084c6 descends from 1e81500). 1e81500 let a nested struct frame itself
through its own `required` -- the first thing after such a run to read
the cursor -- so the omission had been harmless until then.

The corpus differential could not see it, the four agreeing; nor could
`test_required_against_the_walker`, the corpus having no member after a
terminated run of records.

## The fix

Each backend's `_framing_walk` takes `ahead`, set where a later variable
member reads the cursor, and advances the cursor past the terminator
then. Only then: Rust's `-D warnings` refuses the store where nothing
reads it, which is what the original comment was protecting.

`test_a_member_after_a_terminated_run_is_framed.py` holds all four to the
whole length of hull's four messages and `situc verify` to accepting
them; both fail with the change removed.
