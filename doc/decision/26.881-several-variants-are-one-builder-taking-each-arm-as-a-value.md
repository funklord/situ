# 26.881: Several variants are one builder, taking each arm as a value

Status: recorded -- supersedes the product of 26.874; a single variant keeps
26.617's builder per arm
Date: 2026-11-05
Source: the holder, on 26.874's exponential count

26.874 gave a struct of several variants a builder per combination and said
the product had not mattered, `connect_body` being the only such struct in the
corpus. That was true of the corpus and said nothing about the language: a
member present behind a flag **is** a variant (`example/mqtt` says so), so a
format with k optional members is 2^k builders. Measured on k flags, each
guarding a `u32`, generating and compiling C with `-Os`:

    flags  builders  `_build.h`   gcc
        6        64     386 KB    2.9 s
        8       256     1.9 MB    9.4 s
       10      1024     9.0 MB   45.2 s
       12      4096      42 MB  234.5 s

Real formats sit there: MPEG PES has seven optional groups, an MP4 `tfhd` five,
and radiotap's present word more than twenty. The corpus holds none of them,
which is a sample and not a bound. Not one of those builders was doing
anything but repeating its siblings' common members.

## What is built

The variants of one struct choose independently, an arm is one member, and
`plan` depends on the arm in exactly two places: the discriminant and the
variant's own slot. The size passes read `own_members`, which holds no arm. So
nothing is lost by making the choice a value in that slot:

    situ_connect_body_build(out, cap, ..., client_id, client_id_len,
        situ_connect_body_will_arm_will_absent(),
        situ_connect_body_user_name_arm_user_present(name, name_len),
        situ_connect_body_password_arm_password_absent(), &wrote);

    build_connect_body(out, ..., client_id,
                       ConnectBodyWillArm::WillAbsent,
                       ConnectBodyUserNameArm::UserPresent(name),
                       ConnectBodyPasswordArm::PasswordAbsent)

C++ is `connect_body_will_arm::will_absent()` and Python the same spelling as
a static method. One builder and one constructor per arm, so what grows is the
**sum** of the arms.

**26.617's argument is kept, with a constructor in the place of a function.**
Which arm is said by the value, the value is made by that arm's constructor,
and the constructor fixes what the discriminant holds, so the discriminant
still comes from the body and cannot disagree with it. In Rust the enum says
it, and in C and C++ the field is the constructor's to set. Python has no type
to stop an arm of another variant, so the builder asks the class.

`plan` takes `EACH` for this. A variant becomes a `CHOSEN` part holding an
`ArmOf` per arm, and a discriminant gets `chooser`, which says whose value it
writes. Each backend writes an arm's part exactly as a builder of that arm
alone does, inside a `switch` or `match` that binds what it reads to the name
it expects, so no role grew a second writer.

**A default arm's tag is the caller's**, the constructor's first argument. It
is refused in the arm's branch if a named arm claims it, and a packed one is
refused if it does not fit its field, since masking it would write a valid
message saying something else. A peeked discriminant writes nothing and the
arm checks its first byte, as before.

**An arm holding a struct of no bytes takes nothing.** 26.874 had callers pass
an empty slice for `will_absent`, which is how a schema spells absent.

**An arm a backend cannot write is left out of the type**, and named on stderr
as `struct.arm`, as a builder of that arm was. `default: error` is no arm, and
`default: opaque` joins no value, as it joined no combination.

## Why a single variant stays as it is

It is no product: a builder per arm is linear, reads better at the call, and
26.617 and most of rung 2's 230 builders stand on it. Moving it would make one rule out of two
at the price of every caller, for no property a caller gains. The two forms
differ only in where the arm is said, and they are one rule: the arm says the
discriminant.

## Rejected

- **A cap, declining past N combinations.** Bounds the damage and refuses
  exactly the formats a schema compiler exists for. An honest refusal of a
  shape that needs no refusing.
- **A staged builder**, one call per variant in order, as protobuf's and
  Cap'n Proto's are stateful. It needs a state object in four languages, a
  typestate or a run-time order check, a back-patch of the discriminant bits
  written before the arm is known, and a half-built message on every failure.
  The value form is one call that validates as it always did.
- **An optional parameter per flag.** Serves present-or-absent and not
  variants of three arms, so it would be a second mechanism beside this one.
- **The caller stating the flags.** Two numbers for one fact, which is what
  computing a size field exists to refuse.
- **Telling authors to nest the arms.** A nested member is handed over built,
  so nesting does not multiply, but it moves the schema away from the format
  to suit a generator.
- **Allowing two variants on one discriminant**, which arm values open: the
  builder could check that the values agree. It stays refused. No consumer
  has the shape, and mqtt's schema says the idiom is one struct.

## What was measured after

The same schemas, the same flags, compiled the same way:

    flags  builders  `_build.h`   gcc     text
        6         1      10 KB    1.0 s    9.6 KB   (was 30 KB)
       10         1      16 KB    1.4 s     13 KB   (was 514 KB)
       12         1      18 KB    1.6 s     15 KB   (was 2.3 MB)
       24         1      34 KB    3.5 s     32 KB   (16.7 million builders)

Every other generator was then run at 8, 16 and 32 flags, as the same question
pointed at the rest of the compiler: all four backends at `edit`, C at `drive`,
`gen-checks`, `gen-fuzz`, `gen-dissector`, `gen-tamper`, `doc`, `advise`, `wire`,
`map` and `pack`. `product` had one caller. Output grows 2.1 to 2.4 times a
doubling, which is the reader's offset chain, each member's offset summing the
variable members before it; the slowest, Python at 32 flags, takes 6 seconds.
Nothing else is exponential. `gen-tests` is sized by the vectors its author gives
it and was not run.

## Tests

`test_a_builder_takes_each_arm_as_a_value.py`: the output grows with the sum at
6, 12 and 24 flags in all four; every combination of every kind of arm, behind
packed and whole discriminants, through all four and read back; the flags
stated as bytes; a default arm claiming a value; a packed default tag too wide,
and one that masks to a claimed value; a peeked arm beside another variant; and
Python refusing another variant's arm. The product lives on in
`test_the_four_builders_agree.py`, where it belongs: `_combinations` tries every
one, and nothing generated grows with them.

Fourteen sabotages each went red alone: the tag a constructor fixes, the claimed
check and the width check in each of the four languages, the peek's first-byte
check, and Python's class check.
