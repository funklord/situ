# 26.793: Both walkers hold a counted run of one-size records to the frame

Status: recorded -- fixed
Date: 2026-11-01
Source: found while testing 26.789

    struct pt { u8 x; u8 y; }
    struct s  { u8 n; pt r[n]; }

`02 01 02` declares two `pt` and holds one. All four backends refuse it
with "the length the message declares has to fit the frame". Both walkers
accepted it. `walk.counted_run_fits` and the C walker's `counted_run_fits`
answered True for any run whose element has one size, because the walk
they make is for elements that each carry their own length. Nothing asked
whether `count x size` fits. Where a member follows the run, that member's
own placement refused the message, so only a run that ends its struct
showed the gap.

## The change

For a counted run of one-size records, both walkers ask
`start + count x size <= limit`. Their element-wise walk is unchanged.

## Tests

`test_a_run_validates_its_elements.py`'s `s_fixed` gains `02 01 02` and
`03 01`, BOUNDS in all six. With `walker` reverted, the walkers' case
fails.
