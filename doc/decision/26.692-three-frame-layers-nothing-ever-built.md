# 26.692: Three frame layers nothing ever built

Status: recorded -- two built now, the gap they found is open
Date: 2026-10-26
Source: `project.md` section 26

`test_every_schema_frame_layer_compiles` has built the C frame layer over
every corpus schema since 26.260, when slip's reader called a
`situ_frame_required` the same header declined to define. **The other
three were generated and never built by anything.** 26.689's
`unwalkable_arm` put that same fault into all four at once and one
compiler found it; the other three would have shipped it.

Two of the three are built now, and both found the fault on their first
run.

## What they found

The C++ layer does not compile and the Python layer raises on first use,
for the same five structs in the same four schemas:

    coap.situ      coap
    protobuf.situ  proto_message
    edges.situ     tagged_options
    padded.situ    byte_run, pickle_string

    unit_frame.hpp:64: error: 'required' is not a member of
                              'situ::pickle_string'

The shared `frameable` says these structs are frameable, each layer emits
a Reader that calls the struct's `required`, **C defines one and the
other three decline it** -- `situ_pickle_string_required` is in C's
header for the same schema, and Python's module says "No `required`: one
of its members has no length this can compute" for the struct its own
frame layer calls.

So this is one gap in three backends rather than three faults, and it is
26.689's Python arm-run divergence one function over: the backend's own
`_has_length` is narrower than the shared predicate, and the frame layer
is guided by the predicate.

## Why it is not closed here

Two ways to close it and they are not equivalent:

- **three emitters gain what C has**, which is a feature-sized change in
  three backends and the one that keeps C's working `required`;
- **`frameable` narrows to what the narrowest backend can do**, which is
  one small change and takes a working operation away from C for four
  corpus schemas.

The first is right and is not a thing to start while recording the
second. Whoever picks it up should know that C's `required` for these
structs is not a lucky accident -- it is `_has_length` answering yes
where three backends answer no, which is the asymmetry 26.689 found
twice and fixed once.

## The two tests, and why they are shaped differently

**C++ asserts the failure rather than skipping it.** A skip hides a gap
and an `xfail` does not care why, where an asserted failure fails the day
somebody closes it -- which is when the entry should go -- and fails
differently if the layer breaks for a new reason. It matches on the name
and `error:` rather than on the compiler's wording, because gcc says "is
not a member of" for a class it can see and "has not been declared" for
one it cannot, and both appeared in these four.

**Python holds out the five structs rather than the four schemas**,
because the module imports cleanly: the fault is an attribute that is not
there, so it surfaces on use. The import is still worth asserting -- it
executes every class body -- and the stronger assertion, that each framed
struct has the `required` its Reader calls, is what found this.

**Rust's layer is still unbuilt.** It is the third of the three and
wants the module scaffolding the other Rust tests use -- `lib.rs`
declaring `situ_rt`, `unit` and `unit_frame`, compiled with
`-D warnings`. Expect it to find the same five, since the decline is in
the shared shape rather than in a language.

## What the class is worth

**A generated artifact nothing builds is a generated artifact nobody has
read.** Rung 4 has four implementations, one test, and the three without
one had carried a call to a missing function for as long as they have
existed. The cost of the test is a compile per schema; the cost of not
having it was that 26.260's fix was taken as a fix to the class.

The same question is worth asking of every rung above 4, which
`converse` and `drive` are -- and of every other file the generators
emit that no test feeds to a compiler.
