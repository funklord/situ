# 26.931: the dissector walks a run of records to its terminator

Status: recorded
Date: 2026-11-08
Source: the dissector's own "Not unrolled" note, last of the readers to walk 26.930's runs

**A run of records that a terminator ends is walked and each element dissected**, as
the four backends and both walkers walk it: where one of the terminators stands the
run ends, stepping past the longest only where the run owns it (`before` leaves it to
the next member), and elsewhere an element starts, is measured, and goes to its own
dissector. Until now the dissector wrote "Not unrolled" and stopped the cursor, so an
HTTP request showed its request line and nothing of its headers, and every member
after such a run went unshown.

**A delimited member now has a length here as well**, its content and the delimiter
it owns, through `situ_footprint` over the scan the member's own row makes. It had
none, so no struct holding a delimited member had an extent, and no such struct could
be an element of a run or nested in another: HTTP's `request_line` was not shown at
all. Both halves were needed for the headers, each `header_field` being two delimited
members.

The walk is bounded the two ways every generated walk is (invariant 24): an element
of no extent, or one the frame does not hold, ends it. Under `before` and `| end` each
terminator is asked only where it has room, so an element in the frame's last bytes,
shorter than a terminator, is still the run's (26.930).

Checked in real tshark rather than only in the Lua harness: a GET request with two
headers shows its method, target, both names and both values. The walker
differential compares 24 more member answers over the same random buffers, few
because random bytes rarely spell a terminator; the shaped cases are the unit tests.
