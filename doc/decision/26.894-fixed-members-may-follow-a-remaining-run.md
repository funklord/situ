# 26.894: Fixed members may follow a `[remaining]` run

Status: recorded
Date: 2026-11-06
Source: 26.669, from `suggestion/fuzznet.md`, and the holder's rule that a sane
protocol's need is ours

    struct leaf {
        u8 commitment[32];
        u8 ciphertext[remaining];
        u8 tag[16];
    }

Most AEAD frames are this shape, and one framed by its container carries no
length, on purpose. 26.669 offered two designs and left the choice open: a run
sized as the frame less what follows, or a `sealed` region reserving its tag.
The first is built, because any format can use it. A run of bytes followed by
members of a fixed size is the frame less those members, and `Placement.
tail_bytes` holds the number. The wire signature says `leaves=16`.

## The rule

The layout needs no lookahead. It places the run and goes on, and
`_leave_the_tail` judges what followed once the struct is placed. **What
follows must be a number**: a second run, a delimited member or a `while` run
is refused as before, since two members cannot both reach for the end. A frame
too short for the tail is an empty run, and the tail's own bounds check refuses
it.

Refused still, each with its reason:

- **A run of records or of wider elements.** It walks to the frame's end or
  divides by a stride, and has no length to take a tail from. 26.898 is the
  answer: a run of bytes that holds them takes the tail.
- **A run in an arm** (26.782). It is one arm's, and what follows the variant
  cannot be taken off the others.
Taking no tail, and accepted as they always were:

- **A run inside a region whose codec changes the length.** The run is counted
  in decoded bytes and the tail sits in wire bytes, so nothing can be taken off
  it. A first version refused this, and 26.440's control pins the shape as
  readable. The region stays unmeasured and what follows it has no accessor, so
  nothing is misread. Whether to refuse it is open.
- **A run inside a region that ends at a scan.** The run is the rest of the
  region, and what follows the region is not behind it (13.6).

`sealed(c) { u8 ciphertext[remaining]; } tag u8[16];` under a length-preserving
codec is the same rule, so fuzznet's second shape needed no second design: the
tail is what follows the region, and the region is as long as its run. Such a
run is the one `[remaining]` a region can be measured by, since the frame says
where it stops without a byte of the region being read, so `region_extent`
answers for it and the image carries the region's size.

## Why it touched so little

Nothing had ever followed such a run, so no offset chain had needed its length.
One branch per backend gives it one. Each walker reads a size program, so the
packer compiles `max(remaining, tail) - tail` and neither walker changed: `max`
first, so a short frame is empty rather than negative. The dissector is the one
other implementation of the fact.

`remaining` inside an expression of the schema's own is a different question
and stays refused or unsupported: `remaining - 2` may be negative, and only C
rendered the clamped form.

`edges.sealed_leaf` holds the shape, so every sweep meets it. It found the
walker and the dissector short of the tail before either was told.
