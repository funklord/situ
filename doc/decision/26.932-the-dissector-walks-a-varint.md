# 26.932: the dissector walks a varint, and a count of records

Status: recorded
Date: 2026-11-08
Source: a tally of what `gen-dissector` declines over the corpus, 51 of about 120 being varints

**Each varint type is read in Lua by the walker's rules** (`walk.decode_varint`), as
one function per declared type returning the number's width and its value. All fifteen
forms: leb128, be128 with SQLite's whole ninth byte, sleb128, quic, the four marked
forms, hpack and bertag, ebml and ebml_id, utf8, bijective128 and lebprefix. The
dissector said "a varint, whose width is in its own bytes and which this dissector does
not walk" and stopped the cursor, and every struct holding one had no extent, so CBOR,
WebAssembly, SQLite, Matroska, protobuf, HPACK and Bitcoin showed nothing past their
first number.

- **Arithmetic, not bit operators**, which decision 0021 does not let this file assume.
  The value accumulates as a float, so the 2^64 ceiling four forms check is a float
  compare, and it comes back as an integer saturated at 2^48: a length no frame holds,
  where a wrapped 64-bit value read negative and `tvb:len() >= at + n` let it through.
- **The value sizes what follows**: a varint at a fixed offset is read where it starts,
  one at an offset the walk decides is captured at the cursor as a fixed-width length
  already is, and a variant's discriminant is captured the same way, which Matroska's
  peeked width needed. A signed varint hands no value, its zigzag form not being the
  number; nor does a shared-first-byte form at an offset the walk decides.
- **Where the bytes are no number, the dissector returns there.** The walker refuses
  the message and its listing goes on placing members as though the number were zero
  bytes wide; drawing those is the confident wrong line `_uncomputable` exists for.
  Running to the frame's end instead still drew a zero-length row for a run it sized.

**A count of records each saying its own length is walked too**, each element to its
own dissector, as the extent's `_counted_span` already walked it. That is a Bitcoin
transaction's inputs and outputs, and `edges.segments`, which a test had held as the
example of a run nothing could place after.

**Found on the way:** a text number at an offset the walk decides, `decimal u32 n[4]`,
fell to the array branch and was sized as four u32s, sixteen bytes for four digits. A
varint in front of it is what made the offset dynamic, so nothing had reached it.

Held to the walker by one struct per form over 4800 packets biased to spell long numbers,
widths compared directly and the member after each; a sabotaged UTF-8 table fails it. In
real tshark the genesis coinbase reads version 1, an all-ones outpoint, 50 BTC out and
lock time 0. Declines over the corpus went from about 120 to 73; four left are runs of
varints.
