# 26.912: MQTT states its packet identifier

Status: recorded
Date: 2026-11-06
Source: walking the limits 26.907 listed

**`example/mqtt` read PUBLISH's packet identifier as payload, for a reason
that did not hold.** Its comment, and 26.907 after it, said `publish_body` could
take the QoS as a parameter but `gen-tests` hands no arguments. The vectors
name `packet`, which takes none: `packet` hands the argument, so nothing the
vectors reach needs one from outside. This file has now made 26.56's mistake
twice, recording a limit nobody tried.

    case control_kind.publish: publish_body(qos = (flags >> 1) & 3) publish;

A discriminant has to be a field, so `switch ((flags >> 1) & 3)` in the child
is refused; an argument may be an expression, so the parent does the arithmetic
and the child switches on a named `qos`. That reads better anyway.

**Measured on paho's own bytes.** The QoS 1 vector reads identifier 7 and
payload `21.5`, where the identifier used to be the payload's first two bytes.
3.3.1.2's forbidden QoS 3 has no arm, so `validate` refuses it, and a packet
promising an identifier its frame does not hold is refused as well.

**The same file's "real limit" was not one either.** It said the options byte
after a SUBSCRIBE filter could not hold bit fields, so bits 7-2 went unchecked.
A member behind a variable one has no bit position, true, but a nested struct
has: `filter_options` puts the bits at a known place inside itself, and
`subscription` holds it. 3.8.3.1's reserved bits are checked now.

The wire signature and the map change, since the format's description did. A
consumer reading `publish_body` directly now owes it a `qos`, and one that took
the identifier from the payload's front has to stop.

This supersedes the sentence about `example/mqtt` in 26.907.
