# 26.912: MQTT states its packet identifier

Status: recorded
Date: 2026-11-06
Source: walking the limits 26.907 listed

**`example/mqtt` read PUBLISH's packet identifier as payload, behind a refusal
wider than its reason.** Its comment, and 26.907 after it, said `publish_body`
could take the QoS as a parameter but `gen-tests` hands no arguments. That was
true: `refuse_parameters` declined the whole schema for a parameter anywhere in
it. It did not need to. The vectors name `packet`, which takes none and hands
the argument itself, so `gen-tests` now refuses only for a struct a vector names.

**This record first said that reason "did not hold"**, reasoned from the vectors
and not tried, which is the mistake it was accusing the file of. `make test-c`
refused the schema in the first gate over it.

**The same refusal cost more than vectors.** `gen-checks` and `gen-fuzz` declined
a schema with a parameter in C++, Rust and Python, so stating this identifier
would have dropped MQTT's checks and fuzzing in three languages, as a skip and
not a failure. C already skipped such a struct one at a time, and said why
(26.402); the others do now, and an emptied suite stays a refusal.

    case control_kind.publish: publish_body(qos = (flags >> 1) & 3) publish;

A discriminant has to be a field, so `switch ((flags >> 1) & 3)` in the child
is refused; an argument may be an expression, so the parent does the arithmetic
and the child switches on a named `qos`. That reads better anyway.

**Measured on paho's own bytes.** The QoS 1 vector reads identifier 7 and
payload `21.5`, where the identifier used to be the payload's first two bytes.
3.3.1.2's forbidden QoS 3 has no arm, so `validate` refuses it, and a packet
promising an identifier its frame does not hold is refused as well.

**The same file's "real limit" was not one either.** It said the options byte
after a SUBSCRIBE filter could not hold bit fields, so bits 7-2 went unchecked.
A member behind a variable one has no bit position, true, but a nested struct
has: `filter_options` puts the bits at a known place inside itself, and
`subscription` holds it. 3.8.3.1's reserved bits are checked now.

The wire signature and the map change, since the format's description did. A
consumer reading `publish_body` directly now owes it a `qos`, and one that took
the identifier from the payload's front has to stop.

This supersedes the sentence about `example/mqtt` in 26.907.

**This narrows 26.707**, which declined every schema holding a parameter so that
one message would serve, and said a refusal keyed on the vectors was a second
one to keep in step. That is still its cost. A vector naming an argued struct
stays refused, and a schema of nothing else does too.

**Three things this let through, which a skip had been hiding.**

- `situc verify` asked a corpus of `packet` for `--arg qos`, naming a parameter
  the parent hands over. It asks now only about the structs a vector names.
- `gen-checks` and `gen-fuzz` had never run over `test/schema/edges`, in C++,
  Rust or Python, because one parameter skipped them. They did not compile or
  did not pass: a namespaced struct and a keyword member in C++, a pinned run
  read as a number, and a nested start in a buffer its argument overran.
- Python's fuzz harness read 34 members with no property, runs of records and
  members nothing can place, in `example/dnsname`, `mqtt`, `tcp` and others. The
  read follows `validate`, so random bytes rarely reached it and an
  `AttributeError` waited for the first input that did. 0 of the 34 had one.
