# 26.695: every name the generator declares, swept

Status: recorded -- two causes fixed, two left to earlier decisions
Date: 2026-10-27
Source: `project.md` section 26

**26.694's lens, run as a population instead of a guess.** Three defects
in a row had one shape -- a schema name hiding something generated code
needs -- so the question is not "which names have we met" but "what does
the generator declare". That set is enumerable, and nobody had enumerated
it: 0062 lists `validate` and `size_bytes` for C++, from names people had
hit.

## Building the population, and the first attempt's error

**Extracting declared names from the 46 corpus headers gave 1,846 names
and was the wrong population.** Almost all are field names the corpus
already uses -- `ancount`, `dscp`, `ehlo` -- which are safe BY
CONSTRUCTION, since the corpus compiles. A list of names that cannot fail
is not a candidate list.

What works is six minimal schemas whose fields are named `zzqq`, `wwpp`,
`yyoo`, so that nearly every declared name is the generator's own:

    at bounds bytes check check_reserved0 const_bytes constraint data e
    have len n no_check ok pos raw required sink size_bytes size_min
    touch truncated version validate extent

plus `::situ::rt::view`'s own surface read from the runtime -- `raw`,
`base`, `limit`, `raw_`. **31 candidates**, swept against eleven
constructs: plain, arithmetic size, reserved run, bare size, delimited
run, variant, nested struct, counted run, `while` run, located, opaque.

**The construct population mattered as much as the name one.** Four
constructs found seven breaking names; the other seven constructs found an
eighth. A sweep over names alone would have under-reported.

## Four mechanisms, which the error text separates

    'sink' cannot be used as a function              a local captures it
    'foo' is not a type                              a member hides a type
    conflicts with a previous declaration            the class binds it twice
    invalid use of non-static member function        the BASE declares it

**1. A local in `check()` captures the getter -- `sink`. Fixed.**
`check()` declares `std::uint32_t sink;` as the fallback for a caller
passing `nullptr` for the identity, and `validate`'s constraint check
emitted a bare `sink()`. This is 26.501's mechanism, which fixed
`framed()`'s locals -- `at`, `n`, `have` -- and left this one. One `this->`
on the constraint read.

**2. A member hides a type the struct REFERENCES -- `foo`. Fixed.**

    struct foo { u8 q; }
    struct s { u8 foo [max = 4]; foo items[2]; u16 tail; }

`err items(std::uint32_t index, foo &out)` inside `class s`, where `foo()`
is the field's getter, so `'foo' is not a type`, and `foo::size_bytes`
goes the same way. The existing
`test_a_field_may_share_its_name_with_its_type` covers a field sharing its
OWN type's name and answers it by qualifying the return type; this is the
same hazard at the element out-parameter, and its docstring's words apply
unchanged -- *the hazard is not the author's to avoid*. Nine bare type
positions qualified.

**3. The class binds one name twice -- `validate`, `no_check`,
`size_bytes`, `size_min`, `check_reserved0`. Left to 0062.** That decision
refuses this in Python by parsing the emitted module, and says C++ and
Rust "keep their compile-time refusals for now". They do refuse, loudly,
naming the member. **What is new is the set: five names where 0062 lists
two**, and `check_reserved0` is the interesting one, being a name the
compiler synthesises for an unnamed reserved field -- so whether a schema
collides with it depends on how many reserved members precede.

**4. The base declares it -- `raw_`. Left open by 26.694**, which records
why: closing it qualifies every `raw_` reference rather than a list of call
sites.

**And three names are refused by the front end** in the bare-size
construct -- `limit`, `truncated`, `version`. A refusal is a different
outcome from a broken build and was not pursued.

## The trap in fixing mechanism 2, which only the compiler caught

**`inner` is bare at five assignment sites and pre-qualified at two**, and
the pre-qualified string *contains* the bare one. So a replace over
`{inner} &out) const noexcept` -- eight occurrences, seven bare -- double-
qualifies the eighth, and four schemas failed with

    error: expected identifier before '::' token
        ::situ::::situ::adv_report &out) const noexcept

A count assertion cannot see this, and neither can the only-the-qualifier
proof, because the malformed output never reaches it: the schema fails to
compile. **Compiling the corpus is what found it.** The fix is keyed on
each use's owning assignment rather than on the template text.

## Proofs

46 headers differ from the baseline only by the added `this->` and
`::situ::` -- compared after normalising both sides -- with 0 differing
otherwise, and **46 of 46 compile**. C, Rust and Python are byte-identical
across 184 files; both fixes are C++-only by construction.

Both controls were watched failing through the check under test: reverting
the constraint read gives *"'sink' cannot be used as a function"* at
unit.hpp:122, and reverting the nine type positions gives *"'foo' is not a
type"*.

**After both fixes the local-capture and type-hiding classes are empty
over the swept population**, which is a claim about 31 names and eleven
constructs rather than about the language -- and the population is written
down above so the next person can widen it rather than re-derive it.
