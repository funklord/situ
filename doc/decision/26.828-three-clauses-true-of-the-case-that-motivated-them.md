# 26.828: three clauses true of the case that motivated them

Status: recorded -- all three fixed, each with the test that would have
caught it
Date: 2026-11-03
Source: `situc/advise.py`; `project.md` sections 17 and 18.2; 26.824

26.824 added three rules to the advisor. Rendering their output across
several shapes and reading it -- rather than asserting anything about it --
found **three separate false or incomplete clauses, all of one shape**, and
not one of them was reachable by any gate that existed.

**The shape: a clause written while looking at the case that motivated it,
and asserted of the class.** Each was true of the instance in front of me
when I wrote it, which is exactly why it read as correct.

## The three

- **`crossing[0]`.** The bit-run suggestion's straddle clause named one
  field, so a run crossing a byte boundary twice left the other unmentioned.
  True and incomplete. No corpus schema has that shape, so every existing
  case rendered correctly -- `u4 a; u12 b; u12 c; u4 d` is the one that does
  not. The verb agreement went with the fix, which is what `_verb` exists
  for: "`b`, `c` crosses a byte boundary, so its write touches two" is the
  register that function was added to keep the advisor out of.
- **"a number no caller can allocate."** The unbounded branch of
  `pin-a-driven-length` said that of a worst case which, for a `u8` length,
  is 255 bytes. Written while looking at `sqlite`'s `payload_size` at 2^64-1
  and `ipv4`'s at 2^32-1, where it is obviously true, and 255 is the
  commonest of the three magnitudes in the corpus. What holds at every width
  is where the number came from, which is the argument anyway: the bound is
  the length field's type range rather than a decision anybody took.
- **"moves every member after this one."** Said unconditionally by the same
  rule, and false where the driven member is LAST -- which is the commonest
  place for a variable-length member to be, because getting it there is what
  `move-dynamic-to-tail` spends its whole row asking for. What a different
  length moves then is the struct's own extent.

The third carries a second lesson. The count has to be of members that
FOLLOW, not of `_behind`'s gainers: those stop at the next variable-length
member, and a different length moves everything after it whether or not a
pin would return it to an absolute offset. `struct s { u16 n [max = 8]; u8
body[n]; u8 t[n]; u32 a; }` is where the two numbers differ -- two follow,
one gains -- and a clause keyed on the convenient number would have said
one.

## Why no gate could see any of them

Each clause was asserted by a test that used the motivating case. The tests
were not weak about the thing they checked; they checked the instance the
clause was true of. A snapshot test on message text has the same property --
it pins the text for the schema it was written against and says nothing
about the schema nobody tried.

**Section 17 makes message quality the product**, and this is the argument
for reading the output rather than only asserting on it, met from the other
side: the fault is never in the sentence you are looking at. The pass that
found these was mechanical and cheap -- render the rule over four or five
shapes chosen to differ in the dimension the clause quantifies over (how
many straddle, how wide the driver, whether anything follows) and read what
comes out.

## The same wording is in the propagation table

`propagate.py`'s `bounded-size` row states its mutate effect as *"writing a
different length moves every member after this one"* -- the third clause
above, in the place the advisor's version was written from. It is wrong
there for the same reason and in the same case.

Not fixed here, and the reason is mechanical rather than cautious: a row's
`Effect` carries a fixed string, so conditioning it needs the per-placement
path `_bounded_effects` already has for the size axis, and that file is
imported by most of the suite. It is a small change in a sensitive place and
belongs to a pass that can run the suite behind it rather than to the tail
of this one.

**What makes it worth recording rather than merely noting**: the advisor's
clause was written by reading the row's. So the next rule that borrows a
sentence from the propagation table inherits whatever is wrong with it, and
the table is the copy that gets borrowed from.
