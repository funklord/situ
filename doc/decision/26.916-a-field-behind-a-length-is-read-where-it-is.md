# 26.916: a field behind a length is read where it is

Status: recorded
Date: 2026-11-06
Source: 26.915's first test, whose rule fired on a message it should have passed

    struct hdr { u8 kind; u16 len; }
    struct s   { u8 n; u8 d[n]; hdr h; u8 tail[h.len]; u8 last; }

**`tail` took its length from the wrong bytes, in all four backends, and they
agreed.** `s.h.len` read through its view gave 2; the size of `tail` read a
constant offset of 1 and got whatever `d` held. A variable member ahead of a
nested header whose field sizes something later is an ordinary protocol, and
this was the worst kind of fault: a plausible number, no diagnostic, and a
differential that compares four backends finding nothing, since all four
shared the mistake. No corpus schema has the shape. A `when` read the same way,
as did a discriminant, and the dissector.

**The layout was right.** A struct at a dynamic offset is frame-relative (section
12.2) and says so with `frame_relative` and `frame_base_dynamic`: `offset_bits`
counts from `h`. Every renderer read that number as a place in the message.

**Each backend now starts at the struct, and gates the read.** `behind_a_length`
names the struct and the depth, and each `_over_fields` loads there and answers
zero where the frame stops short. The gate is not optional: C++ recorded in
26.747 that an unchecked load at such an offset reads past the view. A bare
`[h.len]` takes a separate branch from `[h.len + 1]` in each backend, so those
delegate to `_over_fields`, which leaves one read per backend. The helper had to
look at every entry: the maps `_over_fields` builds hold readable members only,
`h` is not one, and looking there fell back to the old read without a word.

**A bit field is read there too**, in either bit order and across a byte, whose
read reaches one byte further than its width says. Python's bit read at a dynamic
offset had been a literal 0.

**Refused where no read is built.** A text number or a varint behind a length has
no plain load here. The text number was measured reading wrongly, a nested
`decimal u32 v[2]` holding `02` sizing a run of nothing; the varint's old answer
was not measured. A diagnostic replaces each. The dissector declines any such expression, since `_read` takes a frame
offset; a member past one is shown as the rest of the frame, as for any size it
cannot read. A walker says `cannot-say`, which it always did.

Over the corpus, old against new, 160 builds and 240 files: byte for byte the
same. `test_a_field_of_a_struct_behind_a_length.py` fixes the verdicts across
four backends, for a size, a sum of two such fields, a `when` and a discriminant.
