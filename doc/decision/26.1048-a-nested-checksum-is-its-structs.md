# 26.1048: a nested checksum is its own struct's

Status: recorded
Date: 2026-11-17
Source: compiling openmlx4's `fs2.situ` while landing 26.1046

**openmlx4's FS2 C header did not compile**, on master as it stood:

    fs2.h: In function 'situ_gph_chain_section_crc_check':
    error: implicit declaration of function
           'situ_gph_chain_section_crc_offset'

C gives a struct `covered`, `compute` and `check` for every tag in it,
a nested struct's included, so `gph_chain` carries `section.crc`'s. They
were derived in `gph_chain`'s terms, where the region the tag covers --
`gph_section`'s `body` -- is no member: `covered` answered bytes 0 to 0,
so `compute` summed nothing, and `check` named the stored sum's offset
through a `_section_crc_offset` emitted for no nested member. With the
CRC at a constant offset that compiled and answered wrongly; behind
FS2's variable-length payload it did not compile. C++, Rust and Python
emit no such copies, only the holder's dirty bit, and were unaffected.

## The rule

A nested struct's tag is that struct's. The holder's `covered`,
`compute` and `check` acquire the nested view through the plain nested
members leading to it and call the nested struct's own, `covered`
moving the offset into the holder's view; the dirty bit stays the
holder's. Where no single view reaches the tag -- through a run, an
`at`, an argument -- or the nested struct emits no such helper, the
holder emits none and says so.

## Measured

`test_a_nested_checksum_is_its_structs.py`: `outer { u8 tag; sec one; }`
with `sec`'s CRC behind `u8 data[n]` builds under `-Wall -Wextra
-Werror`; `situ_outer_one_crc_covered` answers byte 1, four bytes;
`compute` answers the section's CRC; `check` is OK, and CHECKSUM with
the stored byte flipped. With the change reverted the header does not
compile. `fs2.situ`'s C now compiles, `-Wunused-parameter` aside: two
`situ_fs2_header_undescribed*_len` take a view they do not read, which
is its own finding.
