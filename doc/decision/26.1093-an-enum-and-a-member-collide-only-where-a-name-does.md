# 26.1093: an enum and a member path collide only where a name does

Status: recorded
Date: 2026-11-18
Source: fuzznet (inbox 20261118T1654Z), from a benchmark's first C build

**`build --target c` refused an idiomatic schema, and `map` and `wire`
accepted it.** `fzn_message_call.outcome` of an enum `fzn_message_call_outcome`
flattens to the stem the enum has, and the stem check refused the pair --
four of fuzznet's contracts had the shape (`chain/revocation`,
`messages/line`, `roster/roster`, `state/setting`). But an enum derives
`_t`, `_is_known` and its arms' macros from its stem and a member `_get`,
`_set` and its own, so the stem is the wrong question for this pair: with
the check bypassed, all four compile cleanly under `-Wall -Wextra -Werror`.
And because only `build` asked, a contract was committed in a state its own
codegen refused.

## The rule

- An enum and a member path sharing a stem are set aside by the stem check
  and refused only where the emitted header defines a name twice -- a
  macro, a typedef, an enum constant, a function (a prototype does not
  count; a cycle's forward declarations repeat names legitimately). An arm
  `check` meets the member's check id `SITU_S_M_CHECK` and is refused. Read
  off the emitted text, as `check_runtime_collisions` reads it, so no list
  of suffixes has to be kept in step with the emitter.
- Any other pair sharing a stem -- two paths, a struct and a path -- derives
  the same names and is refused on the stem, as before.
- `map` and `wire` ask the same question, generating the header only to
  decide a set-aside pair; a schema the C backend declines for another
  reason is `build`'s to report.

## Measured

`test_an_enum_and_a_member_may_share_a_stem`: the idiom builds, compiles and
passes `map` and `wire`; an arm meeting the check id and a struct meeting a
path are refused by all three commands. With enum constants left out of
the scan, the clash goes unrefused and three cases fail. fuzznet's 59
contracts pass `map --check` and `wire --check`; its four now also build.

## Also found, not fixed here

Three fuzznet contracts (`log/gather`, `node/reconcile`, `spool/message`)
pass `map` and fail C generation: a bound naming an enum member bare --
`query` -- is "neither a constant nor a member". Recorded as its own item.
