# 26.779: `validate` walks a run in an arm

Status: recorded -- fixed; settles the open half of 26.689
Date: 2026-10-31
Source: `project.md` section 26 (26.689, left open)

    struct arms { u8 kind; u8 n;
                  variant body switch (kind) { case 1: piece recs[n];
                                               default: u8 raw; } }

No backend walks a counted run of records in a variant arm for an
accessor, so `_variant_length` has no expression for the variant and
26.777's `_variant_fits` asked nothing of it. `check` was the struct's
minimum and `return OK`: `01 02 | 01 05 | 01`, whose second record
declares a byte the message does not hold, validated clean in C, C++
and Rust. Python and both walkers took `piece recs[n]` for one `piece`,
so they checked the first record and no other and agreed with the
three -- and C++, Rust and Python each emitted an accessor reading that
one record under the run's name. C alone declined it. 26.689 offered two answers -- no `validate` for such a struct, or
a walk -- and the aims decide it: `validate` is what every framing
argument rests on, and dropping it costs every caller the operation
where a walk costs one loop.

## The change

- **All four backends, `_arms_fit`**: where `_variant_length` declines,
  each arm is asked on its own under its discriminant value. A counted
  run of a variable, non-recursive element with an extent is walked as a
  top-level run's `_fits` walks it; an arm with a length is held to the
  frame as 26.777 holds the whole variant; a zero-length arm is skipped.
  Where every member after the variant is fixed-size, each arm asks for
  its own length plus that tail (`traverse.fixed_tail_bytes`): no
  backend can place those members, so nothing else held them to the
  frame, and the corpus's `unwalkable_arm` with the default arm and one
  byte of `after` validated clean in all four where both walkers
  refused it.
  The refusal carries the variant's check id, which every backend
  already had, so no numbering moves.
- **C++, Rust and Python's arm accessors** decline a counted run with
  C's sentence, and Python's `validate` no longer delegates to it.
- **The Python walker** had three copies of "validate the selected arm".
  The matched-case path now calls `_arm_validates`, which the default
  path already did; `_arm_validates` walks a run of records through
  `counted_run_fits`, which takes the arm's start since an arm has no
  offset of its own; and the member loop no longer validates a run as
  one record -- it refused an empty run as shorter than one `piece`.
- **The C walker**: `counted_run_fits`' walk is `counted_run_walk`, and
  `arm_validates` calls it from the variant's offset.

Elements' own constraints are not validated, as they are not for a
top-level run in any backend.

- **The map**: an `unwalked-arm-predecessor` row gives a member placed
  after such a variant `mutate=Immutable` and `access=Sequential`, as
  `coded-predecessor` does for a codec. 26.689 left it out because the
  arm's element is another struct, not known when the variant is
  placed; `resolve` now re-applies the rows to those members once every
  struct is resolved, asking `traverse.offset_unresolvable`. The setter
  gate failed for `unwalkable_arm.after` until it did, as 26.689 said
  it would.

## What else it moved

`example/mqtt`'s `packet.body` has arms no backend measures (`publish`,
`subscribe`, `suback`, `unsubscribe`), so it was the same shape: no arm
was held to the frame. All four now check `connect`, `connack` and the
five `ident_body` arms, which the walkers already did through the
variant's size. No other corpus schema changes.

`unwalkable_arm` is back in `test/schema/edges.situ`, with a count of
its own rather than `kind`, so a run of more than one record is in the
corpus. Its map and wire signature are new rows, and the arm census
moves by one in two cells.

## Not done

A recursive element in an arm run, a `[remaining]`, delimited or `while`
run in an arm, and a fixed-size-element run of structs in an arm are not
walked; `check` says nothing about those arms, as before. The walkers
still record no check identity for most arm refusals on the Python side
(`failed_check` answers `cannot-say`), which the identity comparison
skips -- the class 26.689 lists as the walker identity divergences.

## Tests

`test_a_run_in_an_arm_is_walked.py`: the four agree on eight messages
for a variant that ends the struct and six for one with `u16 after`
behind it, both walkers agree on all fourteen, and no backend offers a
single-record accessor. With `situc` reverted the four-way and accessor
tests fail; with only C++ and Rust reverted the accessor test fails;
with `walker` reverted the walker test fails.
