# 26.962: a region whose codec adds a count has a length

Status: recorded
Date: 2026-11-12
Source: a sweep of coded regions over seven expansions, six readers

**Every `expansion = +N` region had no closed-form length, in every
reader.** `traverse.region_extent` read the codec's expansion as a string
and compared it with `"fixed_add"`; `ast.Expansion.FIXED_ADD` is spelt
`"add"`. So from d633a094 (2026-07-31), which wrote the comparison, the
`+N` branch was unreachable: no backend emitted an accessor for such a
region ("its encoded extent is c's to report"), the packer gave the
walkers no size program for it, and where the interior is sized by the
data -- `coded body(c) { u16 x; u8 data[n]; }` -- nothing after the
region could be placed either. The layout solver, which reads the enum,
knew the region was `2 + n + 4` bytes the whole time; `situc map` said
so beside a header that declined it.

The "add" branch each backend carries had never run. It is correct as
written: with the comparison fixed, the sweep's eight `+4` shapes agree
across the four backends and both walkers, and the unit test's lengths
and trailing member are the ones worked out by hand.

The four comparisons in that function test the enum now, not its
spelling.

## How it was found

A sweep of `coded` regions: seven expansions (preserving, `+4`, exact
2:1 and 5:4, padded 4:3, bounded, unbounded) by four interiors (fixed
scalars, a run sized outside, a run sized inside, a nested struct) by
two leads, a member after each region. Every `+4` shape failed to build
its differential -- the driver asked for the region's `_len` -- while
the preserving and ratio shapes agreed. Nothing in the corpus has a `+N`
codec whose region anything reads past, which is why no differential
had asked.

`test_an_added_expansion_has_a_length.py` fails with the fix reverted,
both halves: four backends and both walkers.
