# 26.1094: a bound may name an arm of the member's own enum, bare

Status: recorded
Date: 2026-11-18
Source: 26.1093's "also found" -- three fuzznet contracts `map` accepted
and no backend could build

**`fzn_gather_type type [must_eq = lines]` was refused by all four backends
and passed by `map` and `wire`.** The backends folded the bound as a
constant, found no `lines`, and said it was neither a constant nor a member;
the layout skipped a bound it could not fold, so the map passed; and the
wire signature published the bare word -- which, beside a run named
`lines`, reads as a reference to that run. fuzznet meant the arm, and the
contract it committed said something else.

## The rule

A bound -- `must_eq`, `min`, `max` -- whose value is a bare name that is an
arm of the member's own enum is that arm, `gather_kind.lines`, unless a
SCALAR member of the struct or a `const` has the name: a bound may read a
scalar sibling, so that reading keeps it, and a run of the same name is not
something a bound could read. Rewritten once after parsing, so every reader
-- the four backends, the packer, both walkers, the dissector, the map and
the wire signature -- sees the qualified arm it already understands.

The wire signature of such a bound changes, from the bare word to the arm's
value, as the qualified spelling already rendered: fuzznet's five such
contracts are to be regenerated.

## Measured

`test_a_bound_may_name_its_own_arm`: four backends validate a bare arm
beside a run of its name and a scalar sibling that shadows an arm; with the
rewrite off, the build is refused. `edges.bare_arm` and
`edges.shadowed_arm` carry both shapes; the edges sweeps across both walkers
and the dissector pass.
