# 26.1049: an opaque region has its size

Status: recorded
Date: 2026-11-17
Source: compiling openmlx4's `fs2.situ` under `-Wextra` while landing 26.1048

**A fixed-length `opaque` region was unreadable in every backend.**
openmlx4's FS2 header reserves two, `opaque undescribed0 [16]` and
`opaque undescribed1 [4]`, at static offsets. C emitted

    static inline uint32_t situ_fs2_header_undescribed0_len(situ_view_t view)
    {
        return (uint32_t)0u;
    }

-- a length of 0 for sixteen bytes, and `view` unused, which is what
`-Wextra` noticed -- and C++, Rust and Python emitted no accessor at all,
"this backend cannot resolve where the region is". All four asked the
region for a length expression, and a fixed region has none: nothing in
the message sizes it. A region the data sizes, `opaque q[n]`, was right
throughout.

## The rule

A fixed region's length is its size, a constant; only a region the data
sizes asks for an expression.

## Measured

`test_an_opaque_region_has_its_size.py`: `opaque o[4]`, `opaque p [3]`
and `opaque q[n]` read as 4, 3 and 2 bytes, each from its own first
byte, in C (under `-Wall -Wextra -Werror`), C++, Rust and Python. With
the constant taken away in all four emitters, all four cases fail.
