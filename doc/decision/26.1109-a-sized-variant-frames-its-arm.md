# 26.1109: a variant that states its size frames its arm, in all six readers

Status: recorded
Date: 2026-11-20
Source: openmlx4's inbox 20261119T1253Z, items 1 and 2 -- NVIDIA's MFA MAP
section, one record's `nimages` raised by one, accepted inside the section
and refused as a bare record

**A run of records in an arm of `variant body[len]` was walked to the end of
the frame, not of the variant**, and an element reaching past its end left
the walk rather than being refused. A top-level run is held to its frame by
its `_fits` accessor; an arm's run has no accessors, so nothing asked. All
four backends accepted `sized` over `03 05 aa bb` (a record wanting six
bytes in a three-byte body), and both walkers accepted `03 00 02 aa bb`,
whose second record read the byte after the variant as its own -- six
readers agreeing, some of them on each wrong answer, which is why the test
pins verdicts worked by hand.

**A variant whose only arm is `default`** -- `variant body[len] switch (len)
{ default: rec r; }`, the one way to frame a single struct by a length the
message carries, since `[size = expr]` is refused on a struct member -- got
no arm accessor in any backend while `validate` called one. The generated C
did not compile and `verify` died on an AttributeError. `_arm_guard` read
such an arm as "present always and never at once"; it is present always.

## The change

- Each backend's `_arm_run_elements` hands `_element_validation` the
  variant's end as the run's limit, and asks it to refuse an element past
  that limit as BOUNDS (a zero-size element still ends the walk, as before).
  The Python walker's `_arm_validates` and the C walker's `arm_validates`
  narrow the frame to the variant's end before walking the arm's run.
- `_arm_guard` answers an always-present `default` arm with a constant --
  never absent, always present -- in C, Rust and Python, and C++'s five
  sites likewise; each `_arm_member` drops the refusal block that constant
  would guard, so no consumer's analyser meets an `if (0)`.

## Not done here

`[remaining]` in a sized arm with a member after the variant is refused by
`wellformed` ("must be the last member of its frame") though 26.1040 says
the run ends where the variant does. Recorded as open in 0a.

Test: `test_a_run_in_a_sized_arm_ends_with_the_variant.py` -- `verify`, the
four backends and both walkers against hand-computed verdicts; each walker's
change and the Rust emitter's, reverted one at a time, turn it red.
