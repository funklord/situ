# 26.1010: an older contract compares by value

Status: recorded
Date: 2026-11-13
Source: openmlx4, situ inbox 20261113T1608Z

**`wire --check` called an unchanged schema breaking.** openmlx4's
committed `fs2.situ.wire` was rendered by signature format v1, which kept a
literal's spelling, `must_eq=0x4D544657`; today's renderer reduces literals
to their values, `must_eq=1297368663` (the defect 26.474 fixed in
rendering). The comparison read the two as different constraints: four
BREAKING findings, "no message satisfies both", over FS2 magics nobody had
touched -- and its own FORMAT note said a line may differ in how it is
written, then judged the spelling anyway. openmlx4's `make check` went red,
and its four other schemas asked for a regenerated contract for the same
reason.

**Facts are now compared by value**: `key=<integer literal>` is reduced to
its decimal value on both sides before anything is paired, so a contract of
any format compares by what it says. All five openmlx4 contracts, checked on
copies, read 0 breaking, 0 compatible; a value that really moved still
breaks.
