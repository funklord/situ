# 26.843: the ninth kind, and the guard that is its own backup

Status: recorded -- `gen-checks --target python` emits all nine kinds; the
control for the second arm took three attempts and the first two are the
finding
Date: 2026-11-03
Source: 26.838, 26.840, 26.842, which this completes

## What it asks

A framing reader reassembles a stream whatever the arrival boundaries are.
Two whole messages pushed one byte at a time -- which cuts the stream at
every boundary it has -- must yield exactly two; and one byte short of a
whole message must yield nothing.

**The pair is what discriminates.** A reader announcing a message on every
push satisfies the first and fails the second; one announcing nothing
passes the second and fails the first. Either alone is half a check.

The loop is bounded by the ANSWER rather than by the reader. A reader
announcing a message every time would otherwise spin for ever, and a test
that hangs is worse than one that fails -- the third message is impossible,
so seeing it is the failure.

## The control, and why the first two attempts measured nothing

Three sabotages, and the order they were tried in is the record worth
keeping:

| what was broken | what failed |
|---|---|
| `advance()` made a no-op | all 50 reassemble checks over 31 schemas; the partial arm stayed GREEN |
| the reader's `if need > len(self._buf)` | **nothing** |
| `required`'s `have < SIZE_BYTES` floor | **nothing** |
| both of those together | all 50 partial checks, and all 50 reassemble |

The first is the pair separating exactly as designed: a reader that never
consumes re-announces the same message, so the count climbs past two, while
a short stream is still refused.

**The two middle rows are the finding.** The reader's own truncation guard
and `required`'s floor refuse the same condition, so each is the other's
backup and **no single mutation can show that arm is alive**. Breaking
either leaves the suite green; breaking both fails all 50.

That matters beyond this check. A mutation score reads LOW for code
protected twice, and the natural reading of a surviving mutant -- "nothing
tests this" -- is wrong in exactly the places where something was tested
carefully enough to be guarded twice. The honest form of the measurement is
the one above: say which mutations the check survives and why, rather than
reporting a ratio.

It also says the reader's own guard is unreachable for a fixed-size struct,
`required` having raised already. Not a defect -- defence in depth at a
trust boundary is the right instinct -- but worth knowing before anybody
reads a coverage number off it.

## The import is conditional

The frame layer is a separate artifact (`build --layer frame`), so the
suite imports `<name>_frame` only where a framing check was emitted.
Importing it always would make every generated suite depend on a file the
caller may never have asked for, and the failure would land on IMPORT
rather than on a check -- the worst place for a suite to fail, because
nothing it was meant to assert gets asked at all. `--target c` appends its
header to the include list the same way and for the same reason.

The corpus gate builds that layer now for the same reason.
