# 26.680: A recursive variant under a depth cap counts differently

Status: recorded
Date: 2026-10-23
Source: `project.md` section 26

Found by the fixture added for 26.679, which is the fixture doing its job
twice: it was written to put an imported mutual cycle in front of the
compile gates, and the first random buffer the walker comparison fed it
produced a disagreement about something else.

    importer.situ: the walker and C disagree about ('twig', 'items'):
        walker: 'items count=112'
        C:      'items count=425'

The shape, which nothing in this corpus had:

    struct branch [depth = 8] {
    	peek u8  tag;
    	variant body switch (tag) {
    		case '[':  twig  as_twig;
    		default:   u8    as_byte;
    	}
    }

    struct twig [depth = 8] {
    	u8      open;
    	branch  items[]  until "]";
    }

425 against 112 is not a near miss, so the two are answering different
questions rather than rounding differently -- most likely about what a
depth cap does to a walk, since that is where the two readers' bounds are
written separately.

**It is NOT the delimited run, and this record said it was.** The pair was
narrowed to a COUNTED run to get the compile-order regression landed, and
the disagreement came back unchanged: the walker comparison and the
four-way differential both still refused, for `shared.situ` and
`importer.situ` alike. So the trigger is a recursive variant under a depth
cap, and `until` was a coincidence of the first reproduction -- which is
the shape of mistake this session has made four times, reading a cause off
one instance.

## Not fixed, and why the fixture does not carry it

26.679's fix was ready and hull is blocked on it: it cannot build its core
on any situ until the compile order is fixed, and it holds a workaround
file meanwhile. Holding that behind an unrelated divergence would be the
wrong trade.

So the pair is out of `test/schema/` altogether and the regression lives
in `test_imports.py`, which generates the two files and COMPILES the
result -- the right home anyway, since the fault is a compile-order one
and what a consumer meets is the compiler. It is verified against the
parent commit, where it fails with `implicit declaration of
q_twig_validate` and then `conflicting types`.

That test compiles a cycle of the schema's OWN beside the imported one,
because the first fix for this got the linkage backwards: it declared
`static` for a struct whose definition is external in the `.c`, and
`-Werror=unused-function` refused the header. One fixture, both
linkages.

The reproduction above is standalone and needs no import, and the
divergence appeared for `shared.situ` as well as `importer.situ`, so it
does not need one. Nothing about it is believed to be new: `until` on a
recursive variant is a shape the corpus never carried, so neither reader
has been held to the other on it.

**What this costs is a fixture.** A finding without one is a finding
nobody reaches, and this record is the only thing standing in for it. The
shape belongs in `edges.situ` once the two readers agree, and the next
session to touch delimited runs or depth caps should put it there first
and watch it fail.
