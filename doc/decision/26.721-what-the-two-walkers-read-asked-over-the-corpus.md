# 26.721: What the two walkers read, asked over the corpus

Status: recorded -- the fourth corpus sweep exists; three nested-struct
divergences are held out and raised rather than resolved
Date: 2026-10-28
Source: `project.md` section 26

Three questions were asked of the two walkers over the whole corpus:
whether a message is well formed (26.349), which check refused it (0051)
and where each member begins (26.538). None of them can see two walkers
that place a member identically, agree the message is fine, and read
different numbers out of it -- which is the question a caller actually
asks a member.

That question was asked on `example/udp` with one message, and on the
schemas `test_walker_c.py` writes inline. Nowhere else. `test_walker.py`
holds the **Python** walker to the four compiled backends on values over
the whole corpus, so what escaped was the C walker's half specifically: a
wrong value there had to be caught by a hand-written case naming the
construct, and 26.444 is the precedent for how that fails -- "a one-byte
span slip shows as a wrong value in a later member while every verdict
stays 0".

It was unaffordable until 26.720. Asked the way the three sweeps beside
it ask theirs, it would have cost fifteen minutes while every answer
carried a 2.61-second compile. It costs about seventy seconds now, and
compares **1145 values over 46 schemas, with 689 declined.**

## It disagreed on its first run, in three schemas

    http.request_head.start   C 2782332101   python 712277017891
    dnsname.question.qname    C 209          python 53679
    edges.kv_block.entries    C 13344        python 3416192

All three are a **nested struct whose extent the data decides**, and the
two numbers are not two guesses at one answer. They are two different
questions:

    http.request_head.start   row says 32 bits, measured 5 bytes
                              C   0xa5d704c5    -- the row's four
                              py  0xa5d704c523  -- the measured five

So C reads the `size_bits` the row states, which for a variable member is
its minimum, and the Python walk reads the extent it measured. **Both
walkers agree about the member's offset and about its width** -- measured
on all three -- which is exactly why the sweeps beside this one cannot
see it. Agreement about where a member is and how wide it is does not
imply agreement about what it holds.

The surface is larger than the three: 32 of the corpus's 1028 placements
are a nested struct with a variable extent. Two packets per struct
reached three of them, which is the same thing 26.689 says about its own
deal -- a seeded draw finds this class when the deal happens to reach it.

## What should happen is not mine to decide, and the reason is in the file

`situ_walk.h` states the contract and C does not keep it:

> A member's value, from a message. Fixed offsets and widths up to 64
> bits; anything else answers SITU_WALK_UNSUPPORTED rather than a number,
> because a wrong length is indistinguishable from a right one once it
> leaves.

A nested struct whose extent the data decides is the "anything else".

And the Python walk has refused four constructs for precisely that
reason, each recorded in `read_scalar` as it was settled: a run ("however
few bytes it happens to hold"), a delimited member, a variant, and a
varint settled the other way because it does have a value. The comments
there even count them -- "the third construct to reach here as bits",
"the fifth ... and the third settled by refusing". **A nested struct is
the next one to arrive there as bits and the only one still answering.**

So there are two available answers and both are a change to both
independent readers of the image: refuse in both, or define which bytes a
nested struct's value is. Which is right is the question 26.356 records
for `native` in the verdict sweep's own docstring -- "whether a walker
should answer for this at all is a question about what a walker IS, and
the two walkers currently answer it differently" -- and it is raised here
rather than taken.

Fixing only C would be worse than leaving it: C would decline, the
Python walk would go on answering a number nobody defined, and this
sweep's settled treatment of a refusal -- an answer about the walker
rather than a disagreement -- would turn a visible divergence into a
silent decline. That is the vacuity 26.718 cost eleven weeks.

## So the three are held out by name, with the measurement

`VALUES_APART` holds `(schema, struct)` pairs, like `IDENTITY_APART`, so
a fourth instance has to be added rather than the comparison loosened.
Holding the struct out costs the other members of those three --
`qtype`, `qclass`, `payload`, `fields` -- which is the price that set
already pays and is why it is keyed this way.

`test_the_value_comparison_asked_something` is the denominator, over the
corpus rather than per schema because `std/codecs.situ` and
`std/kernels.situ` declare no message struct. It names all three ways the
sweep could go vacuous, the third being `VALUES_APART` growing until it
covers the corpus.

## Proved by sabotage rather than by passing

A sweep that found three divergences has shown it can find something, and
that is not the same as showing it would catch a fault elsewhere. Byte
-swapping every 16-bit value in `situ_walk_read`, in a `git archive HEAD`
export with this sweep carried in, turns **27 of the 46 schemas red** --
including all five of `test/schema`, which is where a reader would look
first.
