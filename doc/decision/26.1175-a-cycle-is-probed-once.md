# 26.1175: a recursive struct's nesting is probed once, at the top

Status: recorded; built in the four backends.
Date: 2026-11-26
Source: the holder, 2026-11-26: fix performance where the structure is no
longer likely to change. Measured on example/json, whose `validate` path
has been stable since 26.904 and 26.1127.

## What was slow

`validate` on a recursive struct opens with `nesting`, a walk of the
whole subtree that answers how deep it goes, so that a message past
`[depth]` is refused before anything is read inside it (0054, 26.904).
Each level of the cycle validated its children through their public
`validate`, which opened with the same probe over their subtree. A JSON
document six brackets deep -- 24 struct levels -- was probed about two
dozen times, each probe a walk of everything under it.

C++ walked it twice per level besides: its `check` appended the depth
group to `checks`, which already held it as their first group.

Measured on 248 KB of JSON records nested six deep (`-O2`):

    validate        before       after
    C               0.40 MB/s    1.21 MB/s
    C++             0.15 MB/s    0.83 MB/s
    Rust            0.39 MB/s    1.13 MB/s
    Python          1.0 KB/s     2.1 KB/s     (24 KB of it)

and a flat array of 160000 numbers in C, 1.30 to 1.99 MB/s.

## The rule

A recursive struct whose cycle states one bound has a `_below` form of its
check -- C `situ_S_check_below` (static in the `.c`), C++ `check_below` /
`validate_below`, Rust `check_which_below` / `validate_below`, Python
`validate_below` -- which is everything its check does except the probe.
Its public check is the probe followed by a call to it. A check calls a
child's `_below` exactly where the child is a level of the same cycle
(`descends`, the rule `nesting` counts by): the probe at the top bounds
every level under it, since a level below nests one less than the level
above, so the child's own probe could not refuse.

"One bound" is the condition that makes the argument hold: with every
struct of the cycle at the same `[depth]` and `[limit]`, the top passing
implies each level passing. A cycle with mixed bounds keeps every probe.
So does a struct whose checks read members placed by `at` in Rust (its
check takes the message), and an imported struct's checks in C, which are
`static inline` in the header.

Verdicts do not change: the probe that is gone could only have answered
what the one above it already did.

## What is left

The rest is measuring. Each level measures its children's extents by
walking their subtrees, so validation is still O(n * d) in the depth
(d at most `[depth]`), and a validate that walked once and returned
where it ended would be O(n) -- a different shape for every reader, not
a hoisting. Python is slow for its own reasons as well: an arm chain
evaluates its discriminant once per comparison.

## How it is held

`test_a_cycle_is_probed_once.py`: in the generated C for json, sexpr and
cbor, each cycle struct's `check` probes and calls its `_check_below`,
which neither probes nor calls a cycle peer's probing entry; and json at
16 brackets validates and at 17 is refused from `value` and from `array`
alike. Turning the split off fails the structural tests.
