# 26.787: The C walker walks a run of records a terminator ends

Status: recorded -- fixed
Date: 2026-10-31
Source: left open by 26.785

    struct tpt { u8 k; pt recs[] until "\n"; u16 after; }

`walker/c/situ_walk.c` had no walk for `T x[] until "D"`. A record run
carries no count and no size program, so `size_bits_deep` fell through
to its nested-struct branch and measured the run as one record. A member
after the run was then placed at the wrong offset, and `00 0102 0a aa`,
whose `after` the frame cuts to one byte, validated clean in the C
walker alone. The same happened in an arm, through the variant's size,
which is why 26.785 left kinds 2 and 3 out of the C walker's tail cases.

## The change

`record_run_walk` follows `walk._record_run_walk` line for line, and so
the generated C. The terminator ends the run only where an element
would start. An element of zero extent, or one past the frame, ends it.
The terminator is counted where it stands. `size_bits_deep` asks it
beside `while_walk`, and an UNSUPPORTED from measuring a record travels
as it does there.

## Tests

`test_an_ended_run_in_an_arm.py`: the C walker now answers every tail
case 26.785 held the others to, and a new top-level case asks both
walkers about `tpt` and `tkv` over eight messages. With the C walker
reverted, three cases fail.
