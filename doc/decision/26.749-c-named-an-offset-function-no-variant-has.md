# 26.749: C named an offset function no variant has

Status: recorded -- fixed
Date: 2026-10-29
Source: `project.md` section 26

A variant whose arms are all one size is a fixed-size member. Behind a
variable-length member its offset is dynamic, so `validate` checks that
the frame holds it, and C wrote that check through the member's offset
function:

    if (!situ_in_bounds(view, situ_s_body_offset(view), 2u)) {

C emits offset functions for arm MEMBERS -- `situ_s_body_run_offset`,
`situ_s_body_other_offset` -- and not for the variant, so the call named
a function nothing defines and `unit.c` did not compile. C++, Rust and
Python inline the sum and were fine.

`_base_expression` already had this answer for an `authenticated`
region, which has no offset function either: it starts where its first
member does. A variant starts where its arms do, so it now takes its
first arm member's offset.

Found by the full composed sweep in every `nested-fixed-u8-*-in-arm`
cell. No corpus schema puts a uniform-width variant behind a variable
member. `test_a_variant_behind_a_variable_member.py` compiles the source
under `-Werror` and holds all four to two verdicts; both fail with the
change removed.
