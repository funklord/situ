# 26.848: the placeholder that reached three consumers

Status: recorded -- the name mismatch of 26.839 is fixed at its source; the
defect it was hiding is named below and NOT fixed
Date: 2026-11-03
Source: 26.839, which recorded this as a layout decision left unfixed, and
`test_a_refusal_says_what_the_member_is` on `edges.situ`

## What changed the calculus

26.839 found that the layout records an anonymous arm member as
`s.body.arm` while the placement it creates is `s.body.<reserved0>`, made
both `gen-checks` backends decline such a field rather than emit a check
about bytes nobody had selected, and left the mismatch alone: a
placement's name is a layout decision with consumers beyond `gen-checks`.

**The third consumer is what moved it.** With `arm_holder` in the corpus,
`test_a_refusal_says_what_the_member_is` fails:

    arm_holder.arm: the message names `arm_holder.body.arm`, which is
    not a member of `arm_holder`

A diagnostic citing a member the struct does not have, shown to the
author. `_arm_name`'s own docstring had already called the fallback "a
placeholder reaching a user-facing artifact, which invariant 16 is the
general form of: a label is not an identifier, and neither is a
fallback" -- and then returned `"arm"` for the one arm form it did not
know about.

So: three consumers, each wrong differently. `gen-checks` emitted a check
for bytes nobody had selected; the variant-arm census counted the arm
nowhere; a refusal named a non-member. **The third is the one a user
meets, and that is what makes it a layout fix rather than a guard.**

## The fix

The arm's member is read from the placement the layout creates, after
`arm_extent` has created it, rather than predicted:
`<reserved{n}>` is numbered as the layout walks, so guessing `n` at the
recording site would be a second answer to a question the layout already
answers.

All three consumers came right at once, which is what a root fix looks
like: the refusal names `arm_holder.body.<reserved0>`, `enclosing_arm`
finds the arm, the census gained the one scalar arm its annotation had
**predicted** it would gain, and `gen-checks` selects the arm and emits
the check it had been declining.

`traverse.inside_an_unresolved_arm` stays as the backstop it now is. Of
the corpus's placements it still answers true for six, and **every one is
an array element** -- the arm names `recs` and the placement is `recs[]`
-- which the emitters name more precisely, so the array branch is asked
first and the arm branch keeps no input of its own.

## The defect it was hiding

With the arm selectable, `gen-checks` emits the check -- and **the check
fails**:

    raw[0] = 0x01        # select the arm
    view.validate()      # passes
    raw[1] = 0xff        # break the reserved field
    view.validate()      # does NOT raise

**A reserved field inside a variant arm is not enforced by any of the four
backends.** `validate` carries the bounds check and nothing else: Python's
body is two lines, and C's `situ_s_check` likewise. Measured for all four.

**And by two different mechanisms, which the fix has to know.** C++, Rust
and Python drive their validate from `for entry in own_entries(struct)`,
which does not yield an arm's members at all -- the same exclusion that
made `gen-checks`' reserved kind blind to them until it was moved to
`struct.entries` (26.838). C already iterates `struct.entries`, so the
member reaches its `_check_groups`, and `_checks_for` returns nothing for
it anyway.

So three backends need the loop widened and the fourth needs its check
builder to stop declining -- and all four then need the check GUARDED by
the discriminant, since a constraint on bytes that are only in the message
when an arm is selected cannot be asserted unconditionally. That guard is
the real work, and `gen-checks`' `_select_arm` is the shape of the answer
one level out.

Section 8.8 says what that costs: reserved bits are malleability control,
not pedantry, and a receiver that ignores them lets a sender vary bytes
the format calls fixed -- a bypass primitive in anything authenticated.
Here the bytes are free in every language situ generates.

**Four steps were each necessary to see it**, and that is the entry's
lesson rather than the defect: a corpus construct nobody had written, a
name mismatch that made the arm unnameable, the fix that made it
nameable, and only then a check that could be built at all. Any one of
them missing and the gap stays invisible -- which is why the construct
went into the corpus in the first place, and why a decline is worth
writing down rather than leaving as silence.

Not fixed here. It is one change in four emitters, it is the first of the
nine kinds to find something the accessors get wrong rather than
something the checks got wrong, and it deserves its own pass with its own
sabotage.
