# 26.1174: `required` refuses a message nested past its bound

Status: recorded; built in the four backends.
Date: 2026-11-26
Source: fuzznet, inbox 20261126T1843Z, found under ASan after it moved its
JSON walks onto the run cursor (26.1172): `example/json`'s generated
`value_required` over 100000 `[` and as many `]` segfaulted at `-Os`.

## What was wrong

`required` frames a recursive struct by asking the nested struct's own
`required`, one call per level -- `value -> array -> elements -> element
-> value` for every bracket -- and never asked `[depth]`. Only `validate`
spent the depth (its `nesting` probe), and framing comes before
validation by design, so a reader framing a stream ran out of stack on
exactly the message the schema says it refuses. 20.1 promises generated
code a bounded stack; `extent` and `nesting` kept that promise (bounded at
`[depth] + 1`), `required` did not. C and C++ crashed, Rust aborted on
stack overflow, Python raised `RecursionError` -- a crash in its terms.

## The rule

A recursive struct's `required` carries the depth: `_required_at` in C,
`framed_at`/`required_at` in C++, `required_at` in Rust and Python, with
`required` itself starting at zero so no caller changes. A level is a
level exactly where `nesting` counts one -- the shared `descends` -- and
past `min([depth], [limit])` the answer is a refusal, the same two
`validate` gives:

- past the format's `[depth]`: CONSTRAINT -- malformed, as a thirteenth
  month is;
- past a smaller `[limit]`: DEPTH -- well formed, and more than this build
  follows (0054).

So `required` and `validate` refuse at the same level: json's 16 brackets
(64 struct levels) frame and validate, 17 are refused by both.

**A refusal is handed up, not read as short.** Every level turned any
answer from below into TRUNCATED with a need, which is right for a need
and wrong here: a framer told "send more" waits for bytes that cannot
help, since no byte to come makes a message shallower. Each call to a
struct that can reach a cycle (`traverse.reaches_a_cycle`) passes
CONSTRAINT and DEPTH up unchanged. Rust's `Framing` gains `Refused(Error)`
for it; Python's exception propagates as it always did; the frame layers
already return a non-TRUNCATED answer to their caller.

## Options weighed

- **The extent's rule, "at the cap, the rest of the view" (26.1127).**
  It keeps the two-answer contract, and it stalls a framer: the capped
  child claims every byte present, its parent still owes its closing
  bracket, and so asks for one more byte -- after which the child claims
  that one too. Refused.
- **Answering complete at the cap**, leaving the refusal to `validate`.
  The message is malformed whatever follows, so a framer would hand it on
  and `validate` would say so -- but `required` would have called bytes a
  whole message that are not one, and the length it gives a stream reader
  is where the next message starts. Refused.
- **A walk counting brackets first**, as fuzznet did by hand (its wire/
  json_walk.c refuses past sixteen levels). Correct for JSON, and a
  second statement of the schema's own bound outside it -- the shape
  26.1172 removed for the cursor. Refused.
- **Refusing at `[depth]` alone, ignoring `[limit]`.** A build declaring
  `[limit]` follows less than the format allows because it will not spend
  the stack; framing past it spends exactly that. Refused.

## How it is held

`test_required_holds_to_its_depth.py`, in each backend: json at its bound,
one past, a prefix of each and 100000 deep; `edges.unbounded_nest`
(`[limit = 2]`) the same for DEPTH; each beside the backend's own
`validate`. The C probe is built at `-Os`, as fuzznet built it. Two
sabotages: the C bound raised out of reach (the probe died on SIGSEGV),
and the refusal read as short again (the deep cases answered `need`).

## Not covered

The bound is the called struct's own `min([depth], [limit])` while the
depth counts from where the message entered the cycle. Where a cycle's
structs state different bounds the refusal can come at a different level
from `validate`'s, which judges each struct by its own nesting; every
corpus cycle states one bound for all its structs, as `json` does.
