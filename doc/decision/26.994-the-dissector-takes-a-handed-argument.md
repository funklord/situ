# 26.994: the dissector takes a handed argument

Status: recorded
Date: 2026-11-13
Source: the goal gap after 26.993 -- the schema that made hull's
"each frame lies inside the data" sayable had no dissector

`situc gen-dissector` refused any `parameter` without `[stream]` as "not
yet implemented", on 0050's reasoning that nothing in a capture carries a
per-message argument. That is true of a dissector at the top of a capture
and false of one called by its parent: since 0068 the parent reads the
argument out of the bytes it dissects and hands it, through the same
`handing` call a `[stream]` argument passed on uses (26.968, 26.978).

So the refusal is gone. A per-message parameter gets a preference like a
`[stream]` one -- zero by default, the existing refusal to guess -- read
only where the struct is dissected alone, by Decode As, and labelled so;
wherever a parent hands the value, `handing` sets it for the child's call.
A run whose elements are handed an argument reading `remaining` hands
`tvb:len() - at`, the bytes from the run's start, as every other reader
computes it (26.993); elsewhere such an argument declines as any unread
name does.

`test_an_argument_may_read_remaining` now asks the Lua harness over the
four packs: every byte dissected, and `entry.outside` exactly where the
other six readers refuse. It fails with the change reverted. Real tshark,
given the two packs in a user-DLT capture, shows both entries' offsets
and "a frame lies past the end of the data" on the one with a frame past
it. The corpus's 60 dissectors are unchanged.
