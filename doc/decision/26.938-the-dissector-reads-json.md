# 26.938: the dissector reads JSON

Status: recorded
Date: 2026-11-08
Source: the five JSON members still declined after 26.937

`example/json` had no extent anywhere in the dissector once recursion was followed
(26.936), for three reasons, each a general one:

- **A member's `skip` lead had no length.** `u8 open skip` is whitespace and then a
  quote, and `traverse.occupies_fixed_bytes` counts it as variable for that reason;
  `_length` answered nothing for it, so `member`, `object`, `array` and every `value`
  holding one had no extent. A lead is `situ_skip` over its byte set now, and the member
  measured from where it ends, by its span, so a peek that skips owns only its lead.
- **A `while` condition could not read a field behind a variable member.** An object's
  run ends on `sep`, the member's last byte, which stands behind a key and a value of
  any length. The condition is asked once the walk has passed the element, so `at` is
  its end, and a trailing field of fixed width -- a `skip` member's value included,
  though nothing before its lead -- is read that far back from it.
- **A captured field that skips was read before its lead.** The value's `kind` is
  captured for the variant at the cursor, which stood on the whitespace: in
  `{ "a" : [ 1 ] }` it read the space in front of `[` and chose the number arm. A
  member that skips is captured where its lead ends, in the body and in an extent.

Held to Python's `json.loads`, which nothing in situ wrote: four documents, with nesting
and whitespace between every token, give the same keys and numbers in the same order,
and the whitespace ones fail with the capture made at the cursor.
