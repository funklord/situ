# 26.1078: both walkers name the same check refusing a text number

Status: recorded
Date: 2026-11-18
Source: `test_the_two_walkers_agree_about_which_check_refused`, once
`edges.situ` held a variable-width `[minimal]` text number (0070's duration)

**The C walk named a different check from the Python walk, twice over.**
Both refused the same messages; 0051's comparison asks which check did it,
and nothing in the corpus could reach either difference before:

- **The spelling after the value.** The C walk parsed every text-number
  row's value before asking the row, so `[minimal]`'s spelling question
  failed on any byte that is not a digit: `a5` was `digits_minimal` there
  and `digits` in the Python walk -- whose order is the runtime's,
  `situ_digits_minimal` asking how the digits are written before anything
  asks what they are worth.
- **No fit check for digits the message counts.** `u8 n; decimal u32
  count[n]` with `n` past the frame: the packer writes no `fits_frame` row
  for a text number, its rows being its own, and the Python walk asks the
  fit from the placement (a radix, no fixed digit count, no delimiter).
  The C walk read the digits and named the spelling, or the read as
  `bounds`.

## The rule

- The spelling row reads no value; the value rows parse.
- Both walks ask a counted text number's fit before its digits, from the
  placement, and name `fits_frame`.

## Measured

`test_both_walkers_name_a_text_number_alike`, eight frames over a whole
and a counted member; each fix sabotaged alone fails it (`a5`, `\ta5`).
`edges.counted_digits` carries the shape for the corpus comparison.
