# 26.764: A versioned member inside a sealed region

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

    struct inside [version = ver] {
        u8 ver;
        tag u8 mac[16] covers(body);
        sealed body(sealing_aead) { u8 a; u8 b [since = 2]; }
    }

C's versioned getter took the gate, as every member inside a sealed
region does, and tested the version and the frame on `view`, which is
not in scope there: the generated C did not compile. That was so at
`6f807f0`, this session's starting commit. C++, Rust and Python read `b`
through the gate with no version test and no bounds check -- read from
the generated code: over an 18-byte version-1 message, which is whole,
each reads the byte after it, and Rust's indexes the slice.

## What changed

- C tests the version and the frame on the view its signature takes,
  `gate.view` for a gate. The version field is outside the region and
  plaintext, so it is read where it is.
- C++, Rust and Python give a versioned scalar in a gate the plain
  versioned member's accessor, from the same emitter as 26.760's gated
  arm: version first, then the frame, `version` and `bounds` as the
  refusals. An arm that is also versioned stays declined, as C declines
  it.
- The differ asks such a member as it asks a gated arm, `ok=` and the
  value, sealed and waived. It had asked a plain scalar, which no
  versioned getter is.

Found by the sealed-interior probe of 26.763.

## Still open

A covered setter ignores `[since]` in every backend, sealed or not: C's
`situ_plain_b_set` writes `b` with no version or bounds test, so a
versioned member after its tag is written past a version-1 message.
26.765.

## Tests

`test_a_versioned_member_inside_a_sealed_region.py`: sealed and waived,
all four agree and answer `b` exactly for a whole version-2 message, a
cut-short one and a version-1 one, and C++'s gated read stays inside an
18-byte frame under ASan. With C's view and C++'s guard reverted the
sealed form does not build and the C++ probe does not compile.
