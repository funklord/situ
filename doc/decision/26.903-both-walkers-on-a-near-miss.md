# 26.903: Both walkers, on a message nearly right

Status: recorded
Date: 2026-11-06
Source: the shape of 26.901, which random bytes and real vectors both missed

Random bytes stop at the first refusal and a committed vector reaches none. A
message nearly right lies between: a header that holds and a body cut short.
Mutating the committed vectors put 16650 such messages through both walkers,
and they disagreed in five ways. The generated code said which was wrong.

- `["` was ACCEPTED by the C walker. It framed an arm by the rest of the frame,
  so the arm's floor passed on bytes past the arm. `,` answered CONSTRAINT for
  the same reason. 503 of the messages.
- A Modbus write and an MQTT CONNECT cut inside an arm answered CONSTRAINT from
  the Python walker, which clamped the arm to the frame and read on. The four
  ask the arm's reach first. 22 of the messages.
- A BMP whose `image_size` passed 2^29 was BOUNDS in the C walker alone: its
  count of bits overflowed on a located run, which reaches past the frame by
  construction (9.8).

`test_both_walkers_agree_on_a_near_miss` keeps the sweep, 25 mutations of every
vector, and pins the five messages. Before the fixes it failed seven times:
those five and two of the sweeps.
