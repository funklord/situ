# 26.957: an arm behind a sized member, in the C walker

Status: recorded
Date: 2026-11-11
Source: a sweep of variant shapes through all six readers

**The C walker could not read an arm member placed behind a member the
data sizes.** An arm starts where its variant does and is no member of the
struct, so `chain_sum`, looking for it among the struct's members, ran off
the end and answered "not a member of this struct". Wherever an arm's
offset is written down, which is behind fixed members, the sum is never
asked; behind `u8 pre[m]` it is, and every arm read refused.

It showed only where a check reads the arm. A `u16` arm validated anyway,
having nothing to read it for; a text-number arm -- whose read IS its digit
check -- reported `digits` broken on a message the four backends and the
Python walker accepted:

    struct s { u8 m; u8 pre[m]; u8 t;
               variant v switch (t) { case 2: decimal u16 q[3]; ... } u8 k; }

    02 5f9d 02 "864" ff   four backends 0, Python walker 0, C walker 2

`walk.py` has stopped at the variant since 26.909; `chain_sum` does too
now, by the arm table's own rows.

## And the probe's count

With the arm reachable, the two walkers' arm probes still differed: the
Python side asked `walk._count`, which answers a text number's DIGITS --
what `sum` needs -- where `situ_walk_count` declines a text number's
bracket as no count of numbers. The probe mirrors the public call now.

## The sweep

Pairs of five arm kinds (scalar, nested struct, a run the data sizes, a
text number, four bytes), a `u8` or enum discriminant, first or behind a
sized member, a `pass` or `error` default: 80 shapes, 20 draws each. Every
other comparison agreed. `test_an_arm_behind_a_sized_member.py` holds a
scalar arm, a text-number arm and the default in both walkers, and fails
without the fix.
