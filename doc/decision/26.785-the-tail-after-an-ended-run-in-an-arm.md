# 26.785: The tail after an arm's `while` or delimited run

Status: recorded -- fixed in the four backends and the Python walker;
the C walker's half is open (its own fault, below)
Date: 2026-10-31
Source: the shapes 26.779 left unwalked, after 26.781 made them compile

    struct arms { u8 kind;
                  variant body switch (kind) {
                      case 1: piece recs[] while (len != 0) max 3;
                      case 2: pt    pts[] until "\n";
                      case 3: kv    kvs[] until "\n";
                      case 4: pt    rem[] while (remaining > 2);
                      default: u8 raw; }
                  u16 after; }

## What was wrong

- **C did not compile with a member after such a variant.** The
  differential driver called `arms_after_set`, which no backend emits.
  `traverse.offset_unresolvable` asked only whether an arm held a
  counted run, so the map and the driver took `after` as placeable.
- **Nothing in the four held `after` to the frame.** No backend has a
  length for these runs in an arm, so the variant had none, and `check`
  asked nothing about what follows. A message cutting `after` short
  validated clean in all four, and both walkers refused it.
- **Both walkers validated the run as its first record.** The Python
  walker did so in `_arm_validates` and in its member loop, and the C
  walker in `arm_validates`. A `kv` cut short became a missing
  delimiter (2) where the four answer on the frame. Without a tail, the
  walkers disagreed with each other on `01 00 3a`.

## What a run's reach means here

A `while` or delimited run in an arm means what it means at the top
level. A record the frame does not hold ends the run rather than
refusing it (26.680, and netlink's reason in `walk._while_walk`). The
terminator is counted where there is room for it. So the only new
refusal is the fixed tail after the variant. Without a tail there is
nothing to emit, and none is emitted.

## The change

- `offset_unresolvable` asks `is_unmeasured_run` of an arm.
- Each backend's `_arms_fit` calls a new `_arm_ended_walk`. It is the
  run's own span walk, which an arm does not emit, followed by a check
  that the tail fits.
- Both walkers return OK for such a run in `_arm_validates` /
  `arm_validates`, and the Python walker's member loop skips it.

The corpus has no such arm and generates byte-identically.

## Still open: the C walker measures a delimited run as one record

`walker/c/situ_walk.c` has no walk for `T x[] until "D"`.
`size_bits_deep` measures such a run as one `T`, at the top level as
well as in an arm. So a member after it is placed at the wrong offset,
and the C walker accepts `00 0102 0a aa` against `{ u8 k; pt recs[]
until "\n"; u16 after; }` where the other five refuse it. The tests
leave kinds 2 and 3 out of the C walker's tail cases for that reason.

## Tests

`test_an_ended_run_in_an_arm.py` gains the shape above. All four agree
on fourteen messages, the Python walker on all of them, and the C
walker on the `while` ones. Neither walker refuses a cut record where
no tail follows. With `situc` reverted the four-backend case fails;
with `walker` reverted the five walker cases fail.
