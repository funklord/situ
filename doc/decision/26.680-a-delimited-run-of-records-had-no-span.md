# 26.680: A delimited run of records had no span, so a nested one lost an element

Status: recorded
Date: 2026-10-23
Source: `project.md` section 26

Found by the fixture added for 26.679, on its first random buffer: the
walker said a run held 112 elements where C said 425. Fixed, and the route
to it is worth more than the fix, because three attributions were wrong
before an ablation was run.

## The fault

`content_bits` had **no branch for a delimited run of RECORDS**. The span
fell through to the single-element path, so a run measured one element wide
with no terminator: a nested `[A]` came back two bytes where it is three.
The enclosing walk then advanced onto the inner run's own terminator and
stopped there.

Minimal, after the random buffer was reduced:

    [[A]A]      C counts 2 elements, the walker counted 1

The outer run holds the inner group `[A]` (bytes 1..3) and then `A`
(byte 4), and `]` at byte 5 ends it. C is right.

**The count loop was correct the whole time and nothing else used it.**
`record_run_count` walked the run properly, checking for the terminator at
each element boundary; the span was computed somewhere else that had never
heard of a terminator. So the two answers about one rule were produced by
two pieces of code, which is the drift this walker's own notes warn about
for `while` runs and the counted run. One walk answers both questions now,
and `record_run_count` is a two-line wrapper over it.

The terminator is included where there is room for it and not otherwise,
which is C's rule in C's own words: "the terminator belongs to this
member, as a delimiter does. Where the run ran out of buffer instead there
is none to count."

## Three wrong attributions, each from one reproduction

This entry was written three times before the ablations ran, and each
version named a cause that the next measurement cleared:

| claimed | cleared by |
|---|---|
| the `until` delimiter | a counted run diverged too -- or so it seemed; see below |
| a `[depth]` cap | `depth = 8` and `depth = 40` give the same 112 against 425 |
| the import | the pair diverges standalone on `[[A]A]` |

The import claim is the instructive one. The pair alone **passed** the
walker comparison, and that was read as "it needs an import". It does not:
the random buffers that reach a standalone schema simply never contained a
nested group followed by another element. **Non-reproduction was taken for
evidence**, which `running-code.md` says in as many words is what
"intermittent" means -- and the ablation that settled it took one minute.

The counted-run claim was worse than wrong, it was never measured. After
narrowing the fixture, five tests failed and this record said "the
disagreement came back unchanged". Only the test NAMES had been read. An
ablation afterwards shows a counted run agrees, so those five failures were
something else -- most likely the census tests that a corpus change always
moves.

## The ablations, which are the method rather than the finding

Each row is one schema, one change, measured through the project's own
walker comparison:

| schema | result |
|---|---|
| delimited run of a recursive variant | diverges |
| the same, not imported | diverges on `[[A]A]`, agrees on the random set |
| counted run instead of delimited | agrees |
| delimited run, variant element, not recursive | agrees |
| delimited run, plain struct element | agrees |
| `depth = 40` instead of `8` | diverges identically |

And a positive control: restoring the recursive variant brings the
divergence back, so the negatives mean something. **A negative result
without that control is worth nothing**, and four of these are negatives.

## In the corpus now

`edges.situ` carries `nest_item`/`nest_group`, which is what this record
asked for while the readers disagreed. The shape it needs is a delimited
run of a recursive variant and nothing else -- no import, no cap, no
counted sibling -- and six hand-built buffers agree across both readers,
from `[AAAA]` to `[[[A]]B]`.
