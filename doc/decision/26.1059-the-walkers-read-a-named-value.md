# 26.1059: the walkers read a named value, and six readers compare it

Status: recorded
Date: 2026-11-17
Source: 26.1056's open half -- "the walkers do not show a named value";
the holder's word, 2026-11-17, to build what a protocol needs

**A `let` had four readers and no comparison.** Every backend got a getter
in 26.1056, and the image carried nothing, so the two walkers -- and the
listing and situ-edit built on them -- could not say what openmlx4's
48-bit `.mfa` offset is. The four getters were compared by one test with
one message.

## The rule

- The image carries each `let` as a row of `image_let` (section 31,
  ancillary: a walker that predates it reads every member as before) and
  a program in the code section.
- The program opens with a new opcode, `WRAP` (0x0C), which switches the
  rest of it to the backends' arithmetic (`traverse.LetSpelling`):
  modulo 2^64 on the bits, `/` `%` `>>` unsigned, and `/` and `%` by zero
  0. A length is never computed that way; its division by zero is still
  refused. One opcode rather than a flag on the row, so a program says
  how it computes and no evaluator signature changes.
- The Python walker's listing prints `name <value>`, held to the width
  and signed where the `let` is; the C walker has `situ_walk_let_count`
  and `situ_walk_let`, which also says whether to read the value signed.
  A field a value reads that is not in the message refuses in both.
- The differential asks each `let` of each struct through every
  backend's getter (`Probe.LET`).
- `edges` gains `assembled`: every operator a `let` takes, a signed read,
  a zero divisor, a shift of 70, a literal past 2^63 (packed as its two's
  complement, the same bits) and a value sizing a later member.

## Measured

`assembled` over one message gives 0x123489ABCDEF, -203, 0, 167, 0, 72,
168, 0xFFFF76543210, 3 and 0 -- each worked by hand -- in the four
backends and both walkers; the walkers agree over 40 random messages
with at least 100 values compared. With the C walker's wrapping division
answering 1 for a zero divisor, the worked values fail.

## Still open

The map and the dissector do not show a named value, and no setter splits
one back into its fields.
