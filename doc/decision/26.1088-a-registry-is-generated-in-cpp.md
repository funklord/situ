# 26.1088: a registry is generated in C++, and a u64 text number compiles

Status: recorded
Date: 2026-11-18
Source: 0070, step 6

**The C registry (26.1081) as a C++ class.** A nested `entry`, the table as
a C++17 inline static, and `find`, `check`, `value` and `safer` as static
member functions returning `::situ::rt::err`; header-only and `noexcept`,
as every other accessor of this backend is. Each policy word is an `inline
constexpr` bit beside the class (`scope_estate`). The struct classes are
named with their namespace inside it: the class's own `count` shadows a
cell type called `count`.

**And the backend's lax read of a `decimal u64` did not compile.** Its
`_value` accessor spelled the parse limit, 2^64 - 1, with no `u`, which no
signed type holds and `-pedantic-errors` refuses; the strict getter beside
it already wrote the suffix, and so did every other parse site. No corpus
schema carried an unbounded `u64` text number until a registry's count.
