# 26.452: The padded base codes, and two sabotages that proved nothing

Status: recorded
Date: 2026-09-20
Source: `project.md` section 26, where it was written

**`base32`, `base64` and `base64url` in Rust and Python**, which 26.451
left out because they are the shape symbol-at-a-time cannot express: a
group is the smallest run that is both a whole number of bytes and a
whole number of symbols -- five bytes and eight symbols for base32, three
and four for base64 -- so an input not ending on one has its last group
filled rather than truncated. Coverage is 25 of 42 kernels now.

Re-spelled from C's `_padded_table` with the same group arithmetic, the
same fill rule and the same reverse table, in which a byte outside the
alphabet is `0xFF` so a foreign byte refuses instead of decoding to zero.

**The oracle is Python's own `base64` module**, which is independent of
situ and is what C's arithmetic was written against. Every input length
from 0 to 39 is swept in both backends rather than a convenient case
picked, because C's own note says what the failure looks like: an encoder
wrong only for inputs of length 3n+1 looks right in casual testing. The
padding rule is the only thing that varies between one residue and the
next, so a sample is not a test here.

**Two sabotages proved nothing, in two different ways, and both are worth
keeping.**

The first APPLIED and the tests stayed green. Changing `(have * 8 +
inputs - 1)` to `(have * 8 + inputs)` is textually a change and
semantically inert: `full` is clamped by the symbol count anyway, so for
every length the arithmetic already agreed. A sabotage that lands and
does nothing is indistinguishable from a check that cannot fail, and the
only thing separating them is asking what the edit would change. The
replacement -- never pad, every symbol carries data -- fails both
backends.

The second applied, changed the output, and the tests still passed --
because they only ran PYTHON. Rust's padded path had been verified once,
by hand, and nothing in the tree would have noticed it breaking. The
sweep is compiled and run through `rustc` now, one process for all forty
lengths, and sabotaging Rust's padding fails it while leaving Python's
sweep green, which is the isolation a per-backend test is for.

**The bit helpers narrowed again.** 26.451 conditioned them on a TABLE
codec being bound; the padded path accumulates whole bytes and calls
neither, so a base64-only schema was carrying two dead functions. The
condition is an UNPADDED table codec now -- 0 helpers for a base64-only
module, 2 for a 4b5b one, checked in both directions. Same lesson as
26.451's 84 files, one tranche later: a generated file grows only for
what its schema uses.
