# 26.707: gen-tests was the fifth in the family and did not refuse

Status: recorded -- fixed; the family's own list corrected with it
Date: 2026-10-27
Source: `project.md` section 26

`situc gen-tests` emitted C that cannot be compiled for any schema with a
`parameter` in it. Found by an independent audit of 26.706 and reproduced
against `git archive HEAD` with byte-identical output, so it predates
that change and was not caused by it.

## The reproduction

    struct s { parameter u8 blk [stream]; u8 payload[blk]; u16 checksum; }
    s one 02 11 22 33 44

    assert_int_equal(situ_s_validate(view), SITU_OK);
    situ_s_blk_set(&msg, view, situ_s_blk_get(view));

    error: too few arguments to function 'situ_s_validate'
    error: implicit declaration of 'situ_s_blk_set'

`validate` takes the argument tail -- `situ_s_validate(situ_view_t,
uint8_t arg_blk)` -- and `situ_s_blk_get`/`_set` are accessors the C
backend deliberately does not emit for a parameter: it occupies no bytes,
so they would read the member after it.

## One function exists so there is one refusal, and this was the hole

`codegen.refuse_parameters` says what its population is: the generators
that emit a SECOND artifact over a schema and build calls of their own,
none of them on a `situc build` path, so what a parameter costs there is
the command declining rather than a broken build. `c/fuzz.py`,
`c/tamper.py` and `c/checks.py` call it. `c/vectors.py` did not, and was
named in neither the list nor the code.

Refused rather than taught to pass an argument, which is the whole
bargain the family already struck. The call goes FIRST, before the
vectors are checked against the schema, because the refusal is about the
schema and not about the vectors -- otherwise a stale-vector message
arrives for a schema this generator could never have served.

## And the family's own list was stale, which is why nobody looked

The docstring names seven generators and three call it. The differ
declines a parameterised struct by its own means and says so
(`codegen/differ.py:79`), and each of the three `derived` emitters states
that it reads no struct or member and so needs no refusal
(`c/derived.py`, `python/derived.py`, `rust/derived.py`). **A list that
over-claims is worse than none here**: the function exists to be the
single copy of this refusal, so its own list is where somebody checks
whether a generator is covered, and four of its seven entries were
pointing at code that does not call it while the fifth real member was
absent.

## The test named for this invariant does not check it

`test_every_generator_is_either_taking_an_argument_or_refusing_one` is
the guard, and **it passed with `c/vectors` in none of its three cells**.
What it actually asserts is that the set of `refuse_parameters` callers
equals a written list, which is a change detector: it catches a generator
that changes its mind and is silent about one that never had one. Its own
docstring names the lesson -- *"a partition asserted over a population
that had grown a cell nobody renamed"* -- so this is that failure a third
time, in the test written about it.

**A coverage assertion over "every generator" is not available, which is
worth saying rather than leaving as a to-do.** 46 modules under `situc`
define a top-level `generate`, and the cells name 11: the others are
layer emitters reached THROUGH the four backend packages, so a test
demanding all 46 be classified would demand 35 entries the architecture
does not have. The population that would have caught this is "the
generators a CLI subcommand reaches", and that is not enumerable from the
modules.

So the two outside the cells were measured by hand instead:

- **`c/codectests` is unreachable by a parameter.** It emits property
  tests from codec signatures and calls no `situ_` accessor at all --
  measured, zero occurrences in its output for a schema with both a codec
  and a parameter -- so it is in the same position as the three `derived`
  emitters.
- **The dissector has its own test**,
  `test_the_dissector_takes_a_stream_argument_rather_than_refusing`,
  because it takes the argument from a Wireshark preference.

That leaves the cells complete over the generators a subcommand reaches,
by measurement rather than by a sweep.

**`c/vectors` is the first inhabitant of `REFUSES`**, a cell kept empty
and asserted empty "so that a generator which genuinely should decline
outright has somewhere to go". The cell being there is what gave it one.
Its own test says why declining beats filtering here: the other two cells
filter and refuse only what the filter emptied, and that would work for a
vectors file naming only unargued structs -- but a vector naming the
argued one cannot be generated at all, so the choice is not "serve part of
this file" but "serve this file unless it mentions that struct", and a
refusal keyed on what a schema DECLARES is the family's one message where
a refusal keyed on which vectors happen to be present is a second one to
keep in step.

## Why it was invisible

**No `.vectors` file in the tree sits beside a schema that declares a
`parameter`.** `test/schema/edges.situ` carries the only one and has no
vectors file, so `make test-c` generates 46 vector suites and none of
them reaches this. The same hole 26.706 names from the other side: a
sweep over the subcommands could not reach `gen-tests` either, because it
needs a second argument.

## Proof

The refusal fires with the shared message and writes nothing, and the
control -- `test/schema/header.situ` and its four vectors -- still
generates. Both are asserted, the second because a refusal moved anywhere
earlier would pass the first just as happily. Against `git archive HEAD`
the refusal test fails with `situc: wrote takes_vectors.c (1 vectors)` on
stderr, which is the fault itself.
