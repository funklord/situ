# 26.1100: a bare `default: opaque` takes any discriminant

Status: recorded
Date: 2026-11-18
Source: the gate on 26.1096, whose `edges.opaque_arm_section` is the first
schema with the shape

**All six readers answered VERSION for the value an opaque default arm
exists to take, and agreed with each other.** Section 9.6 says an opaque
default arm swallows whatever is left. `traverse.unmatched_values_pass`
said so in its docstring and tested only for a default arm that SELECTS A
MEMBER; `default: opaque;` selects none, so it read as `default: error`.
The four backends' `classify_check` and the packer's `arm_selected` row
both asked it, so every reader refused the message the same way -- which
is the one disagreement a differential cannot see. It surfaced only because
the walkers then disagreed about the ORDER of two refusals on one frame.

## The rule

An arm with no case value accepts unmatched discriminants when it selects
a member or is `opaque`. The packer marks an opaque default DEFAULT and not
ERROR, the bit the C walk reads as "selects nothing". With no member to
measure, both walkers ask the variant's own length against the frame
there, as the backends' fit check does.

## Measured

`test_an_opaque_default_takes_any_value`: five frames through four
backends and both walkers; with traverse and the packer reverted, both its
tests fail.
