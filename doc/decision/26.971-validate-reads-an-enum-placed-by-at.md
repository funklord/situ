# 26.971: validate reads an enum placed by `at`

Status: recorded
Date: 2026-11-12
Source: the gap 26.967 left, measured

    enum kind : u8 { a = 1, b = 2 }
    struct t { u8 off; kind k at off; }

Both walkers refused `01 09` -- 9 is no `kind` -- and `09`, whose `k` the
message does not reach; all four backends validated both. 26.967 taught
`validate` to read a member placed by `at` through the `<name>_value`
getter, which 26.959 gives plain integers only: an enum is typed its own
way in each backend, so it has no such getter, and its check read
nothing.

`validate` does not need a public getter. `traverse.located_raw` is
`located_value`'s shape with an enum type allowed -- one plain integer of
its backing width in a stated order -- and each backend loads it from the
bytes its located accessor places: C through `_view` and the view's
owner, C++ from the accessor's bytes, Rust from the slice its accessor
returns (so a struct holding one takes `msg` in `validate_in`), Python
with `int.from_bytes`. The membership check is the one each backend
already makes for an enum member.

`test_a_located_member_is_validated.py` holds a little-endian sixteen-bit
enum at `off`: both members accepted, the big-endian reading of one
refused, and one past the end BOUNDS, in all four backends and both
walkers.
