# 26.917: a cpio entry adds up

Status: recorded
Date: 2026-11-06
Source: the lens 26.912 left, a limit written down and not tried

**`example/cpio` said its `newc_crc` check could not be stated**: it covers data
outside `cpio_header`, and the sum was not an algorithm situ could generate. Both
were true when written. `cpio_entry` holds header and data, a `when` reaches a
nested field now (26.915), and `sum` reads a run wherever it sits.

    when cpio_entry.header.check != 0
        && cpio_entry.header.check != (sum(cpio_entry.data) & 0xFFFFFFFF)
        refuse sum_mismatch "the file's bytes do not add up to `check`";

**Measured on what GNU cpio 2.15 wrote.** A `-H crc` entry and a `-H newc` entry
pass, and one bit flipped in the file is refused, in all four backends and both
walkers. The `-H crc` entry is a committed vector.

**A limit left in the rule.** It says `check != 0` where it means "this is
`newc_crc`", because `magic` is a byte enum and a `when` reads numbers. So a
`newc_crc` entry whose check was zeroed goes unnoticed. A byte enum in a `when`
was also an `UnknownName` traceback, and is a diagnostic now.
