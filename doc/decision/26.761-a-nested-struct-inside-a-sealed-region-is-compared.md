# 26.761: A nested struct inside a sealed region is compared

Status: recorded -- fixed; closes the item 26.759 left open
Date: 2026-10-30
Source: `project.md` section 26

    struct piece { u8 len; u8 body[len]; }
    struct inside { u8 kind; tag u8 mac[16] covers(body);
                    sealed body(sealing_aead) { piece p; } }

No schema with a nested struct inside a sealed region was compared by the
differential. There were two faults, and either was enough to keep it out:

- **Python named a gated member by the last component of its path.**
  `inside.body.p.len` was `len` on Python's gate, and `p_len` on C's,
  C++'s and Rust's -- Rust's `_gate_name` records the same fault fixed
  there. The driver asked `gate.p_len` and Python raised
  `AttributeError`, for every nested member, whatever its shape. Python
  now names a gated member by its path below the region, as the other
  three do. A member directly in the region is named as before.
- **The differ asked a run all four decline.** `_gated_bytes` holds out
  a run whose count names a field inside the region (26.752), and checked
  `<region>.<name>`. `p.body[len]` names `len` of the nested struct,
  `<region>.p.len`, so the check found nothing, the probe asked for
  `p_body`, and the C driver did not compile. The count is now resolved
  where the run is as well.

Over the 43 committed schemas the four backends' output and every packed
image are byte-identical before and after: none has a nested struct in a
sealed region.

## Tests

`test_a_nested_struct_inside_a_sealed_region_is_compared.py`: a nested
struct whose run is sized inside the region, one with a fixed run, and
one beside a plain member each build all four drivers, agree, and answer
the nested members exactly. With Python's naming reverted all three
fail; with the differ's check reverted the first fails.
