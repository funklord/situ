# 26.1056: a struct may name a value its fields assemble

Status: recorded
Date: 2026-11-17
Source: openmlx4's ask "one value assembled from two places" (inbox
20261114T0041Z, its project.md "Not adopted"), the `.mfa` 48-bit data
offset; the holder's word, 2026-11-17, to build what a protocol needs

**The `.mfa` table of contents keeps one offset in two fields.** The low
32 bits sit at byte 0 of the entry and the high 16 at byte 20, and
src/mfa.c assembles `(uint64_t)be16(te + 20) << 32 | be32(te)`. situ
could place a member by that sum (26.1037) but could not name it: every
caller did the shift, and a schema reading the value twice wrote the
assembly twice.

What the offset addresses is the archive's decompressed DATA section,
and that half needs nothing new: 13.6a's decode writes into the
caller's buffer, which the caller views at the offset.

## The rule

    let u64 data_offset = (data_offset_high << 32) | data_offset_low;

at a struct's top level, after the fields it reads. It occupies no
bytes. Every reader gets a getter -- C's `_get(view)`, C++'s and Rust's
method, Python's property -- and any expression after it in the struct
may name it, which reads as its definition: the parser substitutes it,
so nothing downstream of the parser meets the name. A use before the
`let`, or a `let` inside a block, is refused.

It reads integer fields declared before it (not an array, a field placed
by `at` or a parameter), constants and literals, through `+ - * / % << >>
& | ^` and unary `- ~`; it is 8, 16, 32 or 64 bits. Every reader computes
it alike: modulo 2^64 with each read widened first -- `data_offset_high <<
32` on a promoted `u16` is undefined in C -- `/` and `%` by zero are 0
and a shift by 64 or more is 0, where C would be undefined and Rust would
panic, and the result is held to the declared width.

## What is still open

The map, the wire signature, the walkers and the dissector do not show a
named value; it is not bytes. A setter that splits a value back into its
fields is not offered: `|` of shifted fields inverts and most arithmetic
does not.

## Measured

`test_a_named_value_is_read_alike.py`: one message read in C, C++, Rust
and Python -- the 48-bit offset `0x123489ABCDEF`, `a - b` as `i16` -197,
`low / 0` 0, `low << 70` 0, `3 * 200` as `u8` 88, and a `let` sizing a
later member -- the same in all four, C under `-Werror`, Rust under `-D
warnings`, Python under `mypy --strict`; and the refusals by name.
