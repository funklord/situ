# 26.983: a bound every command reads alike

Status: recorded
Date: 2026-11-13
Source: the words-by-contexts sweep 26.982 came from

A bound that is not a constant -- `[max = n]`, `[must_eq = size(s.v)]` --
is rendered by `invariant.bound` from a closed set of shapes: a sibling's
value, one element of a run, `size`, `offset` or `count` of a member, and
`+ - * / %` over those. The four backends refused anything else from
`_attr_checks`, in the emitters, so `map`, `wire`, `pack` and the
dissector published artifacts for `[max = remaining]`, `[max =
popcount(n)]`, `[max = lens[0]]`, `[max = n == 1]` and `[max = min(n,
3)]` where `build` exited 1. 26.233 closed that for a string and the `%`
in `invariant.OPERATORS` for one operator; the solver now refuses the
whole set, beside `check_bound_arithmetic`, naming the shapes a bound may
take and pointing a condition at `when`.

Two more found with it, the other way round:

- `[max = size(v)]`, the sibling named bare as every other bound names
  one, was refused by the four while `size(s.v)` built and both walkers
  and the dissector read it. `invariant.member` reads past the struct's
  name and found nothing in a bare one; `bound` qualifies it now.
- Rust did not compile a bound over a layout fact at all: `size`,
  `count` and `offset` answer `usize`, which an invariant stores, and a
  bound compares `i64`. The probe that showed `size(s.v)` "accepted" had
  generated it and never compiled it. Rust's bound path wraps the three.

`test_a_bound_every_command_reads_alike` holds the refused and the taken
shapes at `solve`, the bare `size(v)` across the four and both walkers,
and three layout-fact bounds through `rustc -D warnings`; 9 of its 16
fail with the change reverted.
