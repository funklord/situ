# 26.1013: an enum array is read element by element

Status: recorded
Date: 2026-11-13
Source: `situc verify`'s own qualifier, which after 26.1011 named one
thing still unread: "an enum array's membership"

**An enum that rejects unknown values was held to that for one value and
for no array of them**, in all six readers. Measuring it found two faults
worse than an unchecked rule:

- C checked a run the message counts as ONE scalar,
  `situ_kind_is_known(situ_m_kinds_get(view))`, through a getter no array
  has -- a schema with a counted enum array emitted C that did not compile.
  A fixed one was not checked at all.
- Rust's indexed getter for an enum array wider than a byte was declared
  `Result<u16>` and returned `Option<E>`, which `_load` produces for an
  enum -- a schema with one did not compile in Rust.

**Now every element is checked**: C walks the run's bytes or its indexed
getter; C++, Rust and Python walk their accessor; both walkers walk the
elements in the run's byte order, through a new image check kind,
`enum_each = 23`. A new kind rather than `enum_known` on an array row, so a
walker from before answers UNSUPPORTED for the struct (the C walker refuses
a kind it does not know) rather than reading the run as one scalar.
`std/image.situ`'s contract calls the new member breaking, and it is, in
that intended direction.

The differential's element probe excluded enums for a fixed count already
(four languages, four types) and not for a counted one, which reached
Rust's corrected getter as `held as i64` over an `Option`; it excludes both
now. `situc verify` names nothing for an enum array any more, and its test
that pinned "`07` as a `k` is not refused" now asserts that it is.

**Measured** by `test_an_enum_array_is_read_element_by_element`: an unknown
value in a counted byte run, a fixed one, a counted 16-bit one, and the
16-bit members in the other byte order, each refused by all four backends
and both walkers, a single member as the control.
