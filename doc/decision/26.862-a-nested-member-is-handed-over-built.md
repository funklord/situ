# 26.862: A nested member is handed over built, and a message reads back

Status: recorded -- 158 builders over 29 schemas, 72 of them an arm. Repeated
members are built since (26.865)
Date: 2026-11-05
Source: 26.861's measure, where `nested` held 59 of the units left

The caller builds the inner struct and passes its bytes, as in C: a pointer
and a length in C++, a slice in Rust, `bytes` in Python. A size field may
now measure one. The bytes state their own extent, so the writer asks the
inner struct's `required` and refuses anything but exactly one message. Too
many shift every member after it and too few leave the next member inside
it. Where the inner struct's first byte is the outer's peeked discriminant,
it has also to be this arm's, or the bytes are a valid message of another.

`plain_build.shape` builds the `Shape` from the real C header, which is what
says a struct frames itself. The three builders had been passing an empty
one. A nested member with arguments is declined.

Python reaches the inner class through `import <base> as situ_schema`,
because `header header;` makes the parameter shadow the class.

## Three faults a read-back found, all in C's plan

The differential compared four writers, which says nothing if all four are
wrong together. It now asks the reader what extent each built message
states, and that found three defects C had carried. Every target inherits
the plan, so they are fixed there.

- **Several variants.** `plan` wrote the requested arm for every variant in
  the struct: mqtt's CONNECT went out with `will_present` three times, in
  place of its user name and password. A builder writes one arm of one
  variant, so a struct with more is refused here. Each combination has its
  own builder since (26.874).
- **A packed discriminant.** A bit field took the caller's value, so the tag
  could say "absent" ahead of a body. 26.861's claim that the tag cannot
  disagree with the body held only for a whole scalar. Refused here, and
  written by the arm since (26.868).
- **`[since]`.** A message carrying `[since = 3]` members with `rev = 1`
  passed `validate`, since those members' rules are gated with them, and a
  reader stopped short of them. The version field now refuses the values
  below the newest member written, through the `others` list a default arm
  already uses. Both mean a value that makes the message read as something
  else.

## What the differential compares

It used to run one fixed set of values, and 64 of 152 units were compared
only on all four saying no. `_cases` now searches, through Python's builder,
for values a unit takes, and keeps the refused set as well. Inner messages
come from the same search. 36 of 158 units found no such values, 20 of them
in `edges`: their rules want more than small numbers and the other inner
messages can give, so those are still compared only on refusing.

## Tests

`test_a_nested_member_is_one_whole_message.py`: too many, too few and no
bytes, the wrong arm's bytes in a named and a default arm, and the three
plan faults. Removing the length check in C++, Rust and Python, and the arm
check in Python, each fails it. The read-back failed on `mqtt` and `edges`
before the plan was fixed. `test_what_it_does_not_build_is_named` moves from
modbus, which is now built whole, to mqtt.
