# 26.705: two name collisions whose fix is a decision

Status: recorded -- both families closed; the second one's stated cause
was false (26.709)
Date: 2026-10-27
Source: `project.md` section 26

Two families the name-collision arc did not reach, because it swept
MEMBER names and these are a `parameter`'s generated argument and a
STRUCT's own name. Both are reproduced, both are hard errors on legal
schemas, and both turn on the same question -- which name moves -- which
is why they were recorded rather than guessed at.

**The first was settled by the holder and the second turned out not to
be a question.** For the argument the holder chose *move the emitter's
name* -- the second of the two designs below -- and 26.706 is that
change, with what it cost. The populations here are what it was verified
against, so they stay.

**The second family is closed in 26.709, and this entry's account of it
was wrong.** It says below that `class_name` "does not consult
`KEYWORDS`". It does, and has since it was written; its own docstring
says so. The class IS moved to `int_` and every REFERENCE to it kept the
schema's spelling, so there was nothing to decide -- the suffix existed
and had to reach the use sites. The population is 83 names rather than
the five below, and `offset` and `data` are a second mechanism entirely:
the factories declare them as their own parameters, so they hide the bare
class name in the same function.

**So the deferral cost more than the fix.** The question as posed -- move
the schema's name or refuse it -- had no answer, because the move was
already there. One sweep dissolved it.

## A `parameter` collides with the emitter's own function arguments

    struct s { parameter u8 <name> [stream]; u8 payload[<name>];
               u16 checksum; }

    Python   data, msg, offset, cls      the module will not compile
    Rust     data, bytes                 E0415, bound more than once
    Rust     have                        E0308, mismatched types
    C        -- immune, the name is prefixed `arg_`
    C++      -- immune, the value is a data member on the view

The Python one is the worst: `def required(cls, data: bytes | bytearray |
memoryview, *, data: int) -> int:` is a `SyntaxError`, so the module
cannot be imported at all. Swept over 28 candidate names; `at`, `size`
and `limit` are refused by the front end (attribute names) and the
remaining 21 are clean, so these seven are the whole population for those
two backends.

**`argument_name`'s docstring says why C prefixes and the others do
not**: *"they put the value on the view object, where a schema's name
cannot collide with anything, while C has no such object"*. That is true
of the accessors and **false of `required`**, which has no view yet and
takes the value as a function parameter beside the emitter's own.

## A struct's own name is not keyword-suffixed the way a member's is

    struct <name> { u8 a; u16 b; }   struct s { <name> head; u16 tail; }

    int, float, new   error: expected identifier before 'int'
    offset            error: 'offset' is not a type
    data              error: cannot convert 'const uint8_t*' ...
    inner             clean

26.700 fixed this for MEMBER names -- `bare_name` suffixes a keyword and
every accessor now uses it at the declaration and the call alike. A
struct's name goes through `class_name`, which renames a class a member
has taken.

**~~and does not consult `KEYWORDS`.~~ It does.** That clause was wrong
when written and is what parked this family; 26.709 has the correction and
the real cause, which is that the rename reaches the declaration and not
the references.

## Why neither is fixed here

**Both have two viable designs and the choice is about generated API
shape, not about correctness.**

*Move the schema's name.* Detect the collision and suffix, which is this
tree's established answer -- `bare_name` for keywords, `class_name` for a
class a member has taken, 0062 for a Python class binding one name twice.
Corpus-neutral, because no committed schema carries any of these names.
The cost is a reserved set per backend and per position -- four names for
Python's `required`, three for Rust's, the C++ keyword set for struct
names -- each needing the derived test 26.700's set has, or it drifts.

*Move the emitter's name.* Prefix the schema's argument everywhere, as C
already does, so the three backends agree and no set is maintained. The
cost is that every parameterised struct's generated API changes, which in
this tree is `edges.situ`'s `negotiated` and nothing else -- so the
measurable cost is small and the precedent cost is not: it makes the
spelling of a generated argument a thing that moved once.

**The second is tidier and the first is this tree's habit**, and that
was the decision for the argument -- the second was taken, and 26.706
records that all 28 backend-and-name pairs build afterwards, that the
corpus cost was `negotiated` and nothing else, and that prefixing the four
obvious helpers left 205 bare spellings in places the premise above did
not suggest.

**For a struct's own name neither design was needed.** 26.709 found the
rename already implemented in `class_name` and missing from every
reference to it, which is a defect rather than a choice.
