# 26.982: a derived field the data places

Status: recorded
Date: 2026-11-13
Source: a lens from 26.979 to 26.981 -- an expression word valid in one
context reaching a generator in another -- swept as words by contexts

`invariant s.z == size(s.v)`, with `z` after `u8 v[n]`, raised `offset is
dynamic` out of all four generators. The recompute stores the derived
field at a static offset, and a field after a member the data sizes has
none. Every existing invariant maintained a field ahead of what it
derives from, which is the case that never asks.

Each backend now says in the generated code that it has no recompute for
such a field, as 16.1 already does for a right side it cannot evaluate:
the field stays unwritable and the implied refusal still holds a sender
to it in `validate`. `test_a_derived_field_the_data_places` builds the
four and has each refuse a contradicting `z`; it fails with the change
reverted. A recompute that stores through the field's dynamic offset is
the fuller answer and is not built: no schema in the tree or from a
consumer has asked for one.

The same sweep, 13 words by 8 contexts through the four backends, the
dissector, the packer and the map, found nothing else that crashes.
