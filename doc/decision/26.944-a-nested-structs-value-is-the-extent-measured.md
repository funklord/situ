# 26.944: a nested struct's value is the extent measured

Status: recorded
Date: 2026-11-09
Source: the copyright holder's answer to 26.721 -- "the C walker is right"

**A member whose type is a struct whose extent the data decides is read, by
both walkers, as the bits of the extent the walk measured, as an integer of
at most 64 bits; past 64 bits both refuse.** `02 aa bb` under
`struct inner { u8 n; u8 d[n]; }` reads 174779 (0x02aabb) in each, an
eight-byte payload (72 bits) is refused by each, and a seven-byte one reads
504686845217801735 in each.

## The answer arrived to a question that had changed

26.721 found the two walkers reading three nested structs differently: C
read the row's `size_bits`, which for such a member is its minimum, and the
Python walk the extent it measured. It held the three out in
`VALUES_APART` and asked which was right, and whether either should answer
at all.

Six days later a6313f02 (26.837) changed C's answer, for a reason of its own:
`situ_walk_read` ended in `read_at(..., held.size_bits, ...)`, and on
`edges.blocked_arg.one` the row's figure was the MAXIMUM, so C read a byte of
the member after it. It asks `content_bits_deep` now -- the measured extent,
Python's answer. Measured at b3dacbf1, where 26.721 was written, and at HEAD,
on the schema above:

    b3dacbf1   02aabb07   C 2        python 174779
    HEAD       02aabb07   C 174779   python 174779

So from 2026-11-03 the walkers agreed. Nothing emptied `VALUES_APART` and
nothing rewrote 26.721's open entry, which went on saying C read the row; the
holder answered the entry as written.

## Reading the answer

"The C walker is right" is taken in the present tense: C's answer is the
measured extent, and that is now the defined value. Two other readings were
possible and are recorded because they would change what gets built:

- **C as it was when 26.721 was written** -- the row's `size_bits`. Rejected:
  that read is what a6313f02 found taking another member's byte, and a value
  that disagrees with the width the same walker reports is the cheapest tell
  there is.
- **C's header contract** -- `situ_walk.h` said anything but a fixed offset
  and width "answers SITU_WALK_UNSUPPORTED". That was 26.721's own best guess
  ("refuse in both"). Not taken, because the holder named a walker rather
  than its comment, and the walker answers. Should the holder have meant
  this, it is a change to both readers: Python's `read_scalar` gains a sixth
  refusal beside the run, the delimited member and the variant, and C's
  `read_deep` gains the same.

## Consequences

- No reader changes. `situ_walk.h`'s comment now states the contract C
  keeps, where it stated one C did not.
- `VALUES_APART` is empty, and its guard is `not VALUES_APART` rather than
  `<= 3`: a divergence held out has to be argued in, and these three no
  longer diverge. The value sweep asks `http`, `dnsname` and `edges` whole
  again.
- 26.721's open entry in `project.md` is struck and points here, and the
  status block counts two holder questions, not three.
- 26.721 also held back dealing more packets per struct in the value sweep;
  that is free to do now.
