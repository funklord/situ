# 26.886: A lone value attribute is a size

Status: recorded
Date: 2026-11-06
Source: the holder, answering the question 26.877 left

    u32 size;
    u8  data[size];

This is the commonest shape in binary formats, and 0006 refused it: `size`
is an attribute name, so the bracket was an attribute list. 26.877 kept the
refusal and named `[(size)]`. The holder's answer is that the plain spelling
should work.

## The rule

A bracket holding one identifier is an attribute list when that identifier
**means something bare**. Otherwise it is an array spec.
`parser.VALUE_ATTRIBUTES` holds the 18 names that always take a value, and
`BARE_ATTRIBUTE_NAMES` is the rest of the vocabulary.

**0006's reason stands, and this narrows its rule rather than reversing it.**
0006 refused to resolve a bracket against the schema's names, because a
parse tree would then change when an unrelated member appeared. The decision
still reads the closed vocabulary and nothing else. 26.877 asked for each of
the 18 bare and each was refused, so no schema that compiled changes
meaning. Nothing in the corpus spells one: the only hits are in comments.

The set is the same for every struct, so `u8 k [secret]` beside `u8 secret`
stays the flag. `[secret]`, `[escape]`, `[rw]` and the others mean something
written alone, and a member of that name still needs `[(secret)]`.

## What moved with it

**A constant may have one of the 18 names.** 0006 refused the declaration
because `u8 buf[max]` could not be read as the constant. It can now, so the
refusal has no reason left for these names. It stands for the rest.

**A forgotten value keeps its message.** `u8 x [max];` with nothing called
`max` used to say the attribute needs a value, and after the parse changed
it would have said the name does not exist, which sends the author looking
for a member they never meant.
`wellformed.check_a_lone_value_name_is_declared` asks before the name check
and gives the attribute's refusal, naming both readings. 26.877's question
expected this to be the cost; it is not paid.

**A second bracket is still attributes.** `u8 x[max] [max];` is refused for
the value, since only the first group can be a size.

`[(size)]` still works and means the same, which the four-way test asserts
over both spellings.

## Rejected

**Reading the name against the struct's members.** That is 0006's rejected
alternative: `u8 x [max]` would change meaning when a member called `max` is
added elsewhere in the struct.

**Dropping names from the vocabulary.** Every one is a real attribute.
