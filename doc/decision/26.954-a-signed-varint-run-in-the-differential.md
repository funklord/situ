# 26.954: a signed varint run in the differential

Status: recorded
Date: 2026-11-10
Source: every varint encoding in every position, through all six readers

**The differential drivers read a varint run's first element as unsigned
whatever the run held.** For an `sleb128` run C++'s `_at` takes a
`std::int64_t &`, so its driver did not compile; C passed a `uint64_t *`
to an `int64_t *` parameter and printed -1 as 18446744073709551615 where
Python printed -1; Rust cast it to `u64`. The four agree now, declaring
and printing by `ask.signed`, which the single-varint probe has carried
since 26.687 and the run probe never read.

No corpus schema has a signed run -- wasm's `sleb128` values are single --
so the differential had never built one. The sweep that found it put
fifteen encodings in four positions: alone, sizing a run, as a counted
run, and as a variant arm. Every other accepted combination agreed in all
six readers. The refusals were what the language says: a prefix encoding
needs the bits above it stated, `quic` and `bertag` cannot be 32 bits, a
signed varint cannot size an array, and no varint can be a bare variant
arm -- 26.433's refusal, whose own note says to give the arm a struct
that holds it. That spelling was measured here for `leb128`, `der`,
`ebml` and `utf8` over 40 draws each: all six readers agree, so the "yet"
is a missing convenience with a working form rather than a gap.

`test_a_signed_varint_run_agrees.py` holds -1, -63 and -128 in all four
and both walkers, and fails without the fix.
