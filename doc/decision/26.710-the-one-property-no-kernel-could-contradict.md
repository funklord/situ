# 26.710: the one property no kernel could contradict

Status: recorded -- fixed; 26.491 closed, including its two smaller halves
Date: 2026-10-28
Source: `project.md` section 26

26.491 found that `authenticated` was declarable on a codec and derivable
from none of the seven kernel families, so nothing could contradict it. A
Manchester line code could declare it and be believed.

## The fix is two lines, because the machinery was already there

`authenticated` joins `DERIVED_PROPERTIES` and `Derived`, defaulting
`False`. Every family then implies `not authenticated` without any family
function changing, because all seven construct `Derived` by keyword and
take the default -- which is the fact 26.491 identified as the reason
this property was the real gap and `tag_bytes` was not: **all seven
families imply not authenticated**, so it is a sentence `Derived` can
carry, where a tag width has no left-hand side in any of them.

The existing comparison then does the rest, and its diagnostic needed no
wording:

    error: `manch` declares `authenticated` but its kernel implies
           `not authenticated`
      --> a.situ:6:11
       |
       |  kernel = table(input_bits = 1, output_bits = 2,
       |           ^^^^ the table kernel implies not authenticated
       |
       = a derived codec's properties are computed from its kernel, so a
         declaration that disagrees is one of the two being wrong

**Refused at the CODEC, not at a use.** Asserted with a schema that seals
nothing: the false claim is wrong where it is made, and the pre-existing
sealing gate at `wellformed.py:3542` is a separate and later refusal.

## What this does and does not fix

26.491 withdrew a third of its own claim and that withdrawal stands.
**Nothing was forged.** situ reads no tag for a real extern AEAD either --
`verified` is the caller's parameter -- and the generated `_open` is
byte-identical between a Manchester codec and an AEAD. What was missing is
the refusal protecting what `verified` MEANS, which `wellformed.py` states
in its own words: *the caller passes `verified`, nothing checked anything,
and the type system carries a promise the cryptography never made.*

`tag_bytes` and `nonce_bytes` stay outside `DERIVED_PROPERTIES`, with the
reason written beside the new field: no family could contradict them, so
that is a gap with nothing behind it where this was a gap with a fact
behind it.

## And the note that asserted two false clauses

`_authenticated_note` has one branch for *a tag width declared over a
length-preserving transform*, and `carries_tag` is false in **two**
situations -- that one, and no width declared at all. The second got the
first's sentences:

    sealing_aead     preserving, no tag_bytes   -> one clause false
    sealed_stuffing  expanding,  no tag_bytes   -> both clauses false

*"a length-preserving transform has nowhere in its own output to put a
tag"* over an expanding one, and *"`tag_bytes` is checked against that
field by the compiler"* where no width is declared to check. Both corpus
cases are in `edges.situ`, which is where a construct no worked example
carries goes.

**A note asserting a check nobody performs is worse than the silence it
was written to replace** -- the loop's own reason for having notes at all
is that *"silence would read as coverage"*, and a false note reads as more
than coverage.

**Split by CASE first, and that dropped a true sentence with the false
one.** A length-preserving codec with no width really does put its tag in
a schema field that 14.2 checks; only the compiler-checks-the-width clause
is wrong for it, and the case split removed both. `test_codecs.py`'s
existing `test_an_authenticated_claim_says_what_checks_it_instead` caught
it, its fixture being exactly that combination -- **the second time this
note has been corrected by a test rather than by anybody reading it.**

So the note is assembled from the clauses that hold rather than chosen
from a list of cases. There are two independent facts -- whether the
expansion preserves length, and whether a width is declared -- so four
combinations, and a case analysis gets one of them wrong. The new test
asserts each clause in both directions, because a note that says
everything is as useless as one that says nothing: the absences are what
make it a test.

    preserving, no width    14.2 clause, "no tag_bytes is declared"
    preserving, width       14.2 clause, "checked against that field"
    expanding,  no width    neither clause, "no tag_bytes is declared"
    expanding,  width       the `carries_tag` note: "must refuse"

## Proofs

The refusal fires for the Manchester case and the two legitimate shapes
are accepted: a kernel codec claiming nothing, and an `authenticated`
codec with **no** kernel, which is the normal case for a protocol under
design and what `std/codecs.situ` writes. The second control is asserted
as acceptance rather than through the new field, so it passes against
`git archive HEAD` too -- a control that fails on the old tree for want of
an attribute is testing the fix rather than guarding against the fix being
too broad, which is its whole job.

**Corpus-neutral.** All 46 schemas still map, and of 56 kernel-bearing
codecs none declares `authenticated` -- re-counted rather than taken from
26.491, which said 54 of 42 schemas. The only generated change is the two
notes above.

`no_kernel_family_authenticates` is asked of the CORPUS rather than of
declarations written in the test. Hand-written ones are a guess at each
family's arguments and **four of seven were wrong on the first attempt**,
which tests the author; and a fixture cannot say whether the claim covers
every family. Holding the corpus to `_FAMILIES` can, and does: all seven
are exercised, 56 codecs between them.

## The guard the omission needed

26.491 noted that `grep -rn DERIVED_PROPERTIES test/` returned nothing,
so no gate held the tuple to anything -- which is why an omission from it
was invisible. `DERIVED_PROPERTIES` and `Derived`'s field set are two
spellings of one list, kept in step by hand, and a test asserts they are
equal now.

**It would not have caught this one**, and says so: an omission from
*both* is still an omission. What it catches is the half-added case,
where a field arrives on the dataclass and the tuple never learns its
name, and the comparison then never asks about it.
