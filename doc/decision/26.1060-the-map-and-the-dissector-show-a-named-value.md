# 26.1060: the map and the dissector show a named value

Status: recorded
Date: 2026-11-17
Source: 26.1056's open half, after 26.1059 gave the walkers one

## The rule

**The map names every `let`**, after the struct's members, as it names
a parameter: `assembled.offset  let u64 = high << 32 | low`. No axes --
it occupies no bytes -- and its definition, so a reader of the committed
protocol description sees that every reader offers it and what it is.

**The wire signature does not.** It describes what is on the wire, and a
named value adds nothing there; two schemas differing only in a `let`
interoperate byte for byte.

**The dissector shows a `let` as a generated row where it can compute
it exactly, and declines it by comment elsewhere.** The backends compute
modulo 2^64 and hold the result to its width; the dissector's Lua
computes in numbers exact to 2^53 with no bit operators (0021). The two
agree where the value can set only bits its width holds, below 2^53 and
clear of a signed value's sign bit, which `_bit_range` proves from the
fields' widths: an `|` of shifted and masked unsigned fields -- the shape
of a value assembled from two places, `.mfa`'s 48-bit offset. A
subtraction, a variable shift or a wrapping product is declined rather
than shown wrong in some packets.

The Lua test stub learned the API's value-only `add`, which a generated
item uses: a row of no bytes.

## Measured

`edges`' `assembled` shows `offset` and `m` and declines the other
eight; `test_the_dissector_agrees_with_the_walker` compares both rows
with the walker's value on every draw, and both rows off by one fail it
on the first.
