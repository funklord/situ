# 26.1079: a named value may read a text number, compare, and test a token

Status: recorded
Date: 2026-11-18
Source: 0070's third measurement -- fuzznet bounds a duration in seconds

**`let` read integer fields alone** (26.1056), so a duration's seconds had
no spelling. fuzznet writes a duration as digits and a unit (`14d`) and
bounds it in seconds; the value is `count * <the unit's factor>`, and three
things stood in the way: a text number "is not one integer in the frame",
`==` was not arithmetic, and a token member was not a value.

## The rule

- A text number reads as its value, and as 0 wherever its checked getter
  refuses -- digits that are not one, a value past the member's own domain.
  A scaled number is a pair, and is refused by name.
- A comparison (`== != < <= > >=`) is 1 or 0.
- A token member is compared with `==` or `!=` against one of its own
  arms, and nothing else: its reading is which arm it spells, and the order
  the arms were declared in is not a number a schema means.

```situ
let u64 seconds = count * ((unit == time_unit.d) * 86400
                         + (unit == time_unit.h) * 3600
                         + (unit == time_unit.m) * 60
                         + (unit == time_unit.s));
```

C reads a text number through a `_let` helper over its `_get`, C++ through
its checked getter in a lambda, Rust through `map_or`, Python through
`_value`. Not C's and C++'s `_value`: those parse the clamped digits where
a count runs past the frame, which Python's does not.

**And both walkers held a text number's lax read to nothing.** They read
`4294967296` in a `decimal u32` as that number where every backend's
`_value` reads 0 -- the same read every size expression over a text number
takes, so it is fixed there rather than for named values alone: the digits
row's ceiling bounds it, and a signed member's floor is one below its
negation.

## Not yet

The walkers do not compute a token comparison: the image has no operation
for "this member spells that arm", so the packer records such a `let` as
one it cannot encode and both walkers answer nothing for it, which every
comparison reads as no line rather than a wrong one. The dissector declines
all of these, as it declines any value it cannot prove Lua computes
exactly (26.1060). And `when` cannot read a `let` yet, though the README
says a named value is usable by any expression after it; recorded on its
own.

## Measured

`test_a_named_value_reads_a_text_number`: thirteen frames through the four
backends' named-value lines, the text-number ones against both walkers;
four refusals. Sabotaged: a token index off by one in Python fails it on
`14d`; the walker ceiling removed fails it on `4294967296d`.
`edges.named_digits` carries the text-number shape for the corpus sweeps.
