# 26.990: a member called offsets

Status: recorded
Date: 2026-11-13
Source: the gate over `example/gitidx`

The materialized C++ view declares `struct offsets`, one field per member
the data places, and `resolve_offsets(offsets &out)`. git's pack index has
a member called `offsets`, so the struct held a field with its own name,
which C++ refuses: "`offsets` is not a type", and the header did not
compile.

The type yields where a placed member takes its name, as a keyword does in
`bare_name`: `offsets_` there, `offsets` everywhere else, so no other
schema's API moves. `test_codegen_cpp`'s corpus build over `gitidx` is the
test, and it failed before. C names the type with its prefix and Rust
`PascalCase`, so neither met it.
