# 26.925: a number can say its own form

Status: recorded
Date: 2026-11-07
Source: the holder's "anything that is theoretically a need for a (not insane)
protocol is ours", and what `situc` refused when asked for five real numbers

**Five numbers real formats use could not be stated.** Each is a new `encoding`:

| encoding | what it is | who uses it |
|---|---|---|
| `sleb128` | base-128, low group first, sign in bit six of the last group | DWARF, WebAssembly |
| `ebml` | the first set bit says the width and is dropped | Matroska, WebM |
| `ebml_id` | the same, and the bit is kept | their element IDs |
| `utf8` | a code point's shape, to seven bytes and thirty-six bits | FLAC's frame number |
| `bijective128` | high group first, a following group adds one | git's delta offset, Bitcoin Core's VARINT |
| `lebprefix` | base-128 whose first group is `prefix` bits of a shared byte | git's pack entry |

**A signed value goes the one way a signed value goes.** `sleb128`'s read hands back
the zigzag form, so the accessor, range check, walker flag and builder that a
`transform = zigzag` varint already has serve it unchanged, and nothing branches on a
second kind of signed. The parser sets the transform, and `unparse` and `wire` say
nothing of it. Writing `transform` on `sleb128` is refused.

**All ones in an `ebml` size reads as the number it spells.** RFC 8794 reserves it
for "unknown", which only the format can interpret: `example/matroska` says the
Segment then runs to the end. A value of all ones at a width takes the next width,
and 2^56 - 1 writes the eight-byte unknown a writer means. The one-byte unknown
cannot be written through `_put`, as 127 is a number that needs two.

**An `ebml_id` that is no ID has no length.** `_len` answers zero where the top byte's
marker does not stand where the value's width puts it, and `_put` refuses. `0x8100`
reads as nothing and so is written as nothing.

**`lebprefix`'s continuation is the top bit, and a field may name it.** Git's `more`
reads like any bit field and is the number's own: `_put` sets it and keeps only the
bits between. Rejected: leaving the top bit out of the struct, as the other forms'
top bits are stated fields and a gap there would be the one exception.

The image takes codes 205 to 209 and 220 + N, so it is format 9.

**Witnesses, none of them this project.** `example/wasm` is a module clang wrote, and
`i64.const -3000` is where llvm-objdump says, five-byte padded sizes and all.
`example/matroska` is what ffmpeg writes down a pipe, Segment of unknown size
included, and the track is the one ffprobe names. `example/flac`'s eight frames are
the numbers `flac -a` printed at the offsets it printed, from one byte to four, and
a CRC-8 written in the test agrees with each header. `example/git`'s entries are what
`git verify-pack -v` said, all eighteen objects compared by hand-run script, four
committed. Each form's writer is checked in three runtimes against an encoder written
in the test from the rule, over seeded values.

**Found on the way.** `[holds]` cannot stand in an arm, so an id, a size and a body
chosen by the id is one small struct per arm taking `size` as a `[stream]` parameter.
That states it, at a line an arm. CBOR's indefinite items needed nothing new but a
reader that looks for a terminator: 26.926.

**Not here.** A Cluster of unknown size, which ends at the next element of its own
level: that is a question about what an ID means. A block's opening type in
WebAssembly, a signed 33-bit number, as this subset is straight-line.
