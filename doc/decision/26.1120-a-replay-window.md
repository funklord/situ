# 26.1120: a replay window, stated in the schema

Status: recorded; built, in all four backends
Date: 2026-11-20
Source: fuzznet (inbox 20261120T1231Z, item 3; its sec 1311): "Which
nonces, times and message numbers a receiver accepts once: a window over a
counter or a time, per sender, with its size in the schema. 357 lines here."

## What fuzznet does by hand, measured

Two mechanisms, read from its tree:

- **A counter window per session** (`wire/session_frame.c`): a frame's
  counter is refused if heard before or older than the window --
  DTLS's and IPsec's sliding bitmap (RFC 6347 4.1.2.6, RFC 4303 3.4.3).
- **A nonce set with expiries** (`frame/freshness.h`): a fixed capacity
  the caller hands over, a horizon (`now < expires_at <= now + max_ahead`)
  so a frame cannot pin a slot for a century, the caller's clock, refusal
  rather than eviction when full, and nothing recorded for a refused
  frame -- so it runs after the tag verifies and a forgery spends no slot.

## Where it sits

Rung 5, `converse` (0032): the first rung that may hold state between
calls. Like a relation, it is a predicate over messages; unlike one, it
remembers. It is stated in the schema because both peers must agree on it
-- a window one side sizes at 64 and the other at 32 is a protocol
disagreement, and fuzznet's own note finds the expiry's UNIT stated
nowhere. The state is the caller's memory, handed over, as every rung
above `edit` takes its backing (26.99).

## The shape proposed

    replay session_counter(f: fzn_frame) [key = f.head.sender,
            counter = f.head.seq, window = 64];
    replay fresh(f: fzn_frame) [nonce = f.head.nonce,
            expires = f.head.expires, capacity = 4096, ahead = 30000];

Each generates a state type the caller allocates (one per key for a
counter window; one table for a nonce set) and `admit(state, view, now)`
answering OK, REPLAY, TOO_OLD, HORIZON or FULL -- recording only on OK.
`admit` takes a VERIFIED view where the fields it reads are behind a gate,
which is item (2)'s question and is answered with it: the window is asked
after the tag, never before.

## fuzznet's review (inbox 20261120T1610Z), which changes the shape

- **The counter window's key is the caller's state, not a field.** One
  sender holds several sessions, a rekeyed session starts a fresh window,
  and the counter is the AEAD nonce too: `key = f.head.sender` would merge
  sessions that must stay apart. So no key on the counter form -- the
  caller hands over the state instance it chose (the session's).
- **Two calls: `check` before the tag, `record` after.** A replayed or
  ancient counter should cost no AEAD work, and a forgery must record
  nothing; one `admit` after the tag keeps the second and loses the first.
  Generated: `check(state, view, now)`, pure, and `record(state, view,
  now)`, with `admit` as both for a caller with no tag.
- **Counter wrap is refused**, not read as ancient or new: the counter's
  width bounds it, and the declaration says so.
- **Zero expiry**: `expires == 0` means none stated, required or optional
  by frame kind in fuzznet (`fzn_expiry_rule_t`), and never recorded. The
  nonce form wants a rule for 0, per arm where it can be.
- **FULL refuses, never evicts** -- eviction re-admits the evicted nonce on
  retransmission -- stated as behaviour, not left to an implementation.
  `ahead = 0` is refused at compile time: forgetting the field must not be
  the unbounded case.
- One word, `replay`, with two forms; the clock's unit on the
  declaration (`[unit = ms]`) -- both answered yes.
- The generated header carries the sizing rule beside the capacity:
  `capacity >= peak admitted rate x ahead`, admitted meaning after the tag.

## Built

`replay NAME(m: T) [...]`, parsed and refused whole by
`wellformed.check_replays` (one form; window 1 to 64; `capacity` and
`ahead` from 1, so `ahead = 0` is an error; `unit` stated; paths rooted at
the parameter; `expiry` only on the nonce form). `--layer converse` writes
`<stem>_replay.{h,hpp,py,rs}`: a state type the caller owns, a pure
`check` and a `record` that checks and records only on OK, and one verdict
numbering -- OK, REPLAY, TOO_OLD, EXPIRED, HORIZON, FULL, NO_EXPIRY. The
counter form keeps one 64-bit bitmap below the highest counter; a wrapped
counter reads as older than the window and is refused. The nonce form's
slots are free when their expiry is at or before `now`, FULL refuses and
nothing is evicted, and a zero expiry is OK-and-unrecorded or NO_EXPIRY by
the `expiry` rule. Fields are read through `relation.path_bindings`, the
walk a relation's operands take. `test_a_replay_window.py` runs the same
cases through all four, held to verdicts worked by hand; moving the C
window's bound by one fails it. The walkers hold no state and answer
nothing here.
