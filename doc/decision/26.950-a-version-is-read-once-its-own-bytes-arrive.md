# 26.950: a version is read once its own bytes arrive

Status: recorded
Date: 2026-11-10
Source: 26.946's `READS_LATE`, the `[since]` members entry
Supersedes: 26.946's "`[since]` members (`edges.versioned`)" under *What is left*

**`required` reads a struct's `[version]` field as soon as the field's own
bytes have arrived.** Each backend framed a versioned struct behind a guard
on every member the versions share, so `edges.versioned` -- `u8 ver;
u16 length;` then `[since]` members -- was told 3 at two bytes with `ver`
in hand, and 9 at three bytes whatever the third byte was: a length
readable and unread, which 26.946 set out to end.

All four guard on `traverse.version_readable_from`, the end of the version
field, and still answer the shared members while it is short, so the
answer never falls. The read was already safe at that point: C loads the
field from `data`, and the three view-based readers read nothing but the
field.

`edges.versioned` is out of `READS_LATE`, eight entries left, and the
readability sweep is what holds it: the struct reading late again fails
it by name. The four backends frame alike prefix by prefix
(`test_four_backends_frame_alike`).
