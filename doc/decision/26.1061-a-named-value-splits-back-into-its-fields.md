# 26.1061: a named value splits back into its fields

Status: recorded
Date: 2026-11-17
Source: 26.1056's open half, "a setter that splits a value back into its
fields is not offered"; the holder's word, 2026-11-17, to build what a
protocol needs

**A writer of `.mfa` still did the shift by hand.** 26.1056 gave a `let`
a getter in every reader and a setter in none, because most arithmetic
does not invert. The shape that motivated the construct does.

## The rule

A `let` gets a setter -- C's `_set(view, value)` returning `situ_err_t`,
C++'s and Rust's `set_<name>` returning an error or a `Result`, a Python
property setter -- where `traverse.let_split` finds it to be an `|` of
unsigned fields, each alone or shifted left by a constant, whose bits are
disjoint and all inside the value's width, and the value unsigned. Then
splitting is the getter's exact inverse: setting `v` and reading it back
gives `v` for every `v` whose bits the fields hold.

**A value with any other bit set is refused, as a constraint, and nothing
is written.** Cutting it to fit would store a different value from the
one the caller named, with no sign that it had.

Declined: anything else (`a - b`, a mask, a field used twice, a signed
value), and a field whose own setter is not the plain one in all four --
one a checksum covers, whose C setter takes the message for its dirty
bit, or one a version gates, which can refuse. One predicate decides for
all four, so no backend offers a setter another lacks.

## Measured

`test_a_named_value_is_set`: `offset = (high << 32) | low` and `pair =
(nib << 8) | other` set and read back alike in C (under `-Wconversion`),
C++, Rust (`-D warnings`) and Python (`mypy --strict`); `1 << 48` is
refused in all four with the fields unchanged; `low - high` has no
setter. With the accepted mask widened by bit 48 in each backend, all
four fail.
