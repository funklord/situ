# 26.1051: a parameter's own bound is checked by no backend, again

Status: recorded
Date: 2026-11-17
Source: reading PCI VPD's RV through `rv_value(n = length)` (26.1050)

26.805 settled that a bound on a `parameter` itself -- `parameter u8 n
[min = 1]` -- is the solver's: it bounds the argument a caller supplies,
`validate` reads the message and not the argument, and no backend checks
it. C and C++ still emit nothing. **Python and Rust had gone back to
emitting a check, each wrong in its own way:**

- Rust compared the BYTE at the parameter's nominal offset -- the next
  member's, since a parameter occupies nothing -- so 26.805's own `struct
  t { parameter u8 b [max = 10]; u8 x; }` refused every `x` above 10.
- Python read `self.n`, which does not exist (the argument is
  `arg_n`), so `validate` over any such struct raised `AttributeError`.

Both gave the check id 0, where C's first real check holds it, so a
consumer keying on 0051's ids named a different member by language.
26.805's test only built the four, which is why neither was seen.

## Measured

`test_a_parameter_s_own_bound_builds.py` now runs `validate` over `t`
with `x = 200` in Python and Rust (OK in both) and compares the ids:
`u.x` is 0 in C, Python and Rust, and no `CHECK_B` is emitted. With
either skip removed it fails. The VPD reading in
`test_a_checksum_covers_the_message_before_it.py` is the case that
found it.
