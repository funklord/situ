# 26.733: C answered zero elements for a run it could not count

Status: recorded -- fixed; the construct is unimplemented in all four now
Date: 2026-10-29
Source: `project.md` section 26

26.691 closed with this, and it is half right:

> With the crash gone the construct builds, and the four backends split:
> **C emits `situ_r_v_count` and the other three decline** [...] Not
> implemented here, because three backends gaining a construct is a
> feature and this was a crash.

C emits the function. **It does not implement it.** Measured on
`r { u8 n; uvar v[remaining]; }`:

    static inline uint32_t situ_r_v_count(situ_view_t view)
    {
            return (uint32_t)0u;
    }

and on four bytes holding three one-byte varints:

    count=0
    situ_r_v_at(view, 0, &out)  ->  refused; the walk it drives never ran
    validate                   ->  SITU_OK

**The data was there and every accessor said the run was empty**, with a
clean verdict over it. So it was not three backends short of a construct;
it was four, with C the one that answered confidently -- which is the
arrangement 26.691's own closing paragraph warns about in the next
sentence: *"the three that decline fail loudly and the one that answers is
the one nobody checks."*

## The mechanism, for the fourth time this week

`uvar v[remaining]` is sized by the FRAME rather than by a field, so
`_count_read` looks for a field called `remaining`, finds none, and falls
through to `array_count or 0`. The count came out as the literal zero and
the emitter printed it.

That is 26.729's shape exactly: a quantity nothing can compute rendered as
a constant zero, and the backend answering rather than declining.
26.729 was a `tlv` region's extent in `required`; this is a varint run's
count in the accessors. **A length expression that cannot be computed must
make the emitter decline, not make it answer zero**, and a `0` is
indistinguishable from a real answer at every call site.

## The fix

C declines, in the same words the other three use -- "this backend cannot
resolve how many elements it holds". Declining takes nothing away, because
what it answered was wrong, and it leaves the construct **unimplemented in
all four rather than wrong in one**.

Walking varints to the end of the view is implementable and is the feature
26.691 asks for. None of the four does it, and this does not.

**Measured: the corpus C output is byte-identical**, all 46 schemas, by
sha256 over header and source before and after. No committed schema has
the construct, which is why it was latent -- and why 26.691 could record
the split without anything going red.

## What the fix broke, and the predicate that fixes both

`gen-checks` went on emitting

    assert_int_equal(situ_countless_varints_loose_at(view, 0u, &first), SITU_OK);

for an accessor no header now declares.
`test_generated_c_calls_only_accessors_the_headers_declare` caught it and
says what that is worth in its own message: *"a build failure `make test`
would find and this suite would not"*.

The cause is the one this week keeps producing: the checks generator asked
the PLACEMENT whether to call an accessor while the emitter decided
whether to emit one, and the two could disagree. So the question moves to
`traverse.elements_are_countable`, which both ask. It is false for exactly
one arrangement -- a run of varints the frame sizes -- and true for
everything else: a literal count answers itself, a field-driven count
answers from the field, `u8 data[remaining]` answers `limit - base`
because a fixed-size element divides what the frame leaves, and a
`[remaining]` run of RECORDS answers too, `mqtt_string
filters[remaining]` being one that C walks.

One predicate rather than three conditions is what 26.728 and 26.729 both
paid for, and this is the third time in two days that the fix was to make
two places ask one question.

## The construct

`test/schema/edges.situ` gains `countless_varints`, so
`test_the_backends_refuse_the_same_members` can see the four agree.
26.691 said in as many words that `edges.situ` had no such member and so
the split could not be seen -- and a split is what it was.

The packed image goes to 46,343 bytes against 26.722's 65,536 guard,
headroom 1.41.
