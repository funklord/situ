# 26.682: A delegated check was found only one component deep

Status: recorded
Date: 2026-10-23
Source: `project.md` section 26

Reported by bbq-predictor as item 5: a schema with a counted run inside a
variant arm generated C that does not compile.

## The fault

`_checked_by_its_own_type` asks whether some enclosing member already
delegates its checks to its own type, so the outer struct need not repeat
them. It read **the first path component only**:

	head, sep, _ = rest.partition(".")

A member inside a variant arm is two deep -- `s.x.c.count`, where `x` is
the variant and `c` the arm. The first component is the variant, which
nothing delegates to, so the answer was False and the check was emitted in
the outer struct as well: `situ_s_x_c_count_get`, a name nothing defines.
The accessor is `situ_col_count_get`, on the arm's own struct.

So the emitted check named a function that does not exist, and the
translation unit did not compile -- the one failure mode that cannot reach
production, which is why this is an inconvenience rather than a hazard and
is listed last of bbq's five.

## The fix

Every prefix rather than the first:

	for depth in range(1, len(parts)):
		owner = self.resolved.find(
			f"{struct.name}.{'.'.join(parts[:depth])}")
		if owner is not None and self._delegates(struct, owner.placement):
			return True
	return False

The arm IS delegated to, one component further in, and `situ_col_check`
already makes that very check. So the duplicate was redundant as well as
uncompilable, and finding it removes a check rather than adding one.
