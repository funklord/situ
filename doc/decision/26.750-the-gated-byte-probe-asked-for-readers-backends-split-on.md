# 26.750: The gated byte probe asked for readers the backends split on

Status: recorded -- the probe fixed; the split is open
Date: 2026-10-29
Source: `project.md` section 26

The differ's `SEALED` probe asks each byte run inside a gate for its
length and last byte, which is how 26.320 caught C++ handing out 60000
bytes where the other three said 33. `_gated_bytes` took every byte run
in the region that had a count, fixed or data-sized. The full composed
sweep found two shapes where a driver asked for a reader its backend does
not emit, and the driver did not compile:

- a FIXED run, `sealed body(seal) { u8 run[2]; }`: C emits `_ptr` and no
  `_len` (as it does for a fixed run outside a gate), and the C driver
  called `situ_s_body_run_len`;
- `u8 run[remaining]` inside the region: C++ declines it, and the C++
  driver called `gate.run()`.

Measured further, on one schema with all of them in one gate:

| run | C | C++ | Rust | Python |
|---|---|---|---|---|
| fixed `u8 x[2]` | `_ptr` only | none | `fn` | none |
| sized by a field outside | yes | yes | yes | yes |
| sized by a field inside | yes | yes | declined | yes |
| `u8 x[remaining]` | yes | declined | yes | yes |

## The fix to the probe

It asks only for runs sized by fields OUTSIDE the region -- by one field
or by an expression over them, `fragment[length - 24]` in dtls, which a
first version testing `sized_by` alone dropped from the corpus. Those are
the runs all four read, and they are all three of the corpus's gated
probes (`dtls.record`, `keystore`, `packet`), measured before and after.
No corpus schema has a run of any of the other three kinds, so nothing
compared before is lost.

## What is open

**The table is a backend inconsistency in its own right.** A fixed byte
run inside a sealed region is a plain thing to read, and two backends
give no reader for it; a run sized from inside the region and a
`[remaining]` run are each read by three and declined by one. Section 0
puts four backends that disagree on what a schema means at the top of
the list. `test_backends_refuse_the_same_members` cannot see it, because
it compares the corpus and no corpus schema has the shapes.

The work is in the emitters: C++ and Python gain a reader for a gated
fixed run (and C a `_len`, or the probe a constant), Rust learns a run
sized from inside the region, C++ a `[remaining]` one -- or each decline
is made unanimous with the reason stated. Recorded rather than started:
it is four emitters' worth of gate code.

**And one member over, the same fault.** With a run sized from inside the
region in the gate, C cannot place the `tag` after the region either and
declines `situ_g_mac_ptr`, while the driver's `TAG` probe asks the
placement and calls it. That is 26.733's shape -- the driver asking the
schema whether a reader exists, where the emitter is the one that knows --
and it is left with the split above rather than patched probe by probe.
