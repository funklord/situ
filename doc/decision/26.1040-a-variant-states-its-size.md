# 26.1040: a variant states its size

Status: recorded
Date: 2026-11-14
Source: the holder's answer to the run's first question, approving
`variant body[length] switch (kind)` for MQTT's remaining length

    struct packet {
        control_kind      kind;
        u4                flags;
        remaining_length  length;
        variant body[length] switch (kind) { ... }
    }

**MQTT could not be framed off a stream.** The Remaining Length is the
body's size (MQTT 3.1.1, 2.2.3), but nothing said so: a PUBLISH payload is
`u8 payload[remaining]`, which ran to the end of whatever buffer held the
packet, so no backend emitted `packet_required` and a broker reading a
socket had to frame packets by hand. The same shape is every
length-then-switch protocol whose arms end in "the rest".

## The rule

The brackets say what they say on an array: the bytes the member occupies.
The variant is that long whichever arm the discriminant selects, so the
members after it and the struct's `required` use the expression and never
ask an arm. Each arm is read within those bytes -- its view is cut there --
so a `remaining` inside it ends where the variant does.

An arm shorter than the size leaves the rest unread, as `[holds]` does for a
fixed struct shorter than its run (26.898): the arm's type decides what the
bytes are. An arm longer than the size is cut, and refused as BOUNDS where
its own minimum is not met. A size the frame does not hold is BOUNDS.

## What carries it

`Placement.size_expr` holds the expression's source for a variant even
where it is a bare path, since a variant has no count branch for `sized_by`
to drive. `traverse.frameable` and `ends_in_the_frame` skip the arms of a
sized variant, which is what lets the struct be framed. The four readers
take the size before the arm chain and cut each arm's view to it; the image
carries it as the variant's size program, which both walkers evaluate before
asking an arm and use as the arm's limit in `validate`; the dissector steps
over it and hands each arm a sub-buffer of that length.

## Builders and checks

**A builder computes the size from the arm it writes.** Each packet
builder is handed its arm as bytes, so the size field is that arm's `_len`
and stops being an argument: `situ_packet_build_publish` lost its `length`
parameter, which the caller could get wrong -- taking it from the caller
wrote packets whose length left the builder's own last bytes outside the
packet, which `test_the_four_builders_agree` caught. Declined, naming the
variant, where a builder chooses among arms or the size is arithmetic
rather than a field.

**The generated checks build no baseline for one**: a zeroed buffer states
a size of zero, and a CONNECT arm does not fit in it.

## Measured

`test/unit/test_a_variant_states_its_size.py`: a PUBLISH of topic "a/b" and
payload "hi" with two bytes of the next packet behind it frames at nine in
all four backends; both walkers refuse it one byte short and refuse a
SUBSCRIBE whose length cuts its filter's options byte; the dissector steps
over a PUBACK whose length is three. Before committing, 308 MQTT packets
gave one answer in the four readers, and 404 gave one verdict in the two
walkers and C's `validate`.

`example/mqtt`'s map now gives the packet a ceiling, 268435460 bytes, where
it said it had none; its wire signature gains `sized-by=length`, a breaking
change, since it decides where a packet ends.
