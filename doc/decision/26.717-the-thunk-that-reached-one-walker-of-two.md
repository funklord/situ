# 26.717: the thunk that reached one walker of two

Status: recorded -- `remaining` is asked for in the C walker too, and
`make fuzz` is green again
Date: 2026-10-28
Source: `project.md` section 26

`walk_keystore` died of a stack overflow on a **zero-byte input**, which is
as reachable as an input gets. Not a refusal: SIGSEGV, exit -11.

	chain_bits_deep(sealed.plaintext)   sums the PARENT's members
	  -> size_bits_deep(keystore.sealed)  reaches the region
	    -> content_bits_deep             the region's size program
	      -> offset_bits_deep            for `remaining`, EAGERLY
	        -> chain_bits_deep           and round again

48 frames to the period, repeating until the stack was gone, every one of
them at `depth` 0 -- so the depth ceiling could not see it. `depth` counts
hops into sub-structs, and this cycle never leaves the one struct.

## It is 26.585, in the other walker, three weeks later

That record fixed this exact cycle in `walk.py` on 2026-10-08, names
keystore's sealed `plaintext` as the case, and gives the remedy: `remaining`
becomes a thunk, called by the one op that wants it, because `plaintext`'s
size program never names the word and the offset was computed for nothing.

**The C walker never got the port.** So for three weeks situ's two
independent readers disagreed about whether a keystore can be read at all --
one answering, one dying -- and that is the expensive form of the
disagreement, because **a traceback is not a verdict anybody compares.**
Every differential check in this tree compares answers; none of them is
reached when a reader segfaults.

## What changed

`eval_tagged`'s body is `eval_lazy` now, taking `(walk_remaining_fn, void *)`
where it took an `int64_t`, and `OP_REMAINING` calls it. `situ_walk_eval`'s
public signature is untouched: callers that already hold the figure box it
in a constant thunk, which keeps ONE path through the op -- a second path is
a second place for the two walkers to disagree.

Two of the three sites that computed the offset eagerly pass a real thunk.
The third does not, and that is the finding inside the finding: it needs the
byte offset for the walk itself (`at = from`), so laziness buys it nothing.
Site A needs it too, but only on the branch for a counted run of
variable-length structs -- so there the offset is taken **inside that
branch**, where it is used, which is the same laziness by a different means.
The first attempt moved it out wholesale and would not compile, which is the
cheap version of that lesson.

## Why nothing caught it, and the answer is not "nobody ran it"

`make fuzz` ran it. `run-fuzz` does `|| exit 1`, so the walker half has been
failing the target -- the red was real and the target is manual, which is
the whole of how it stayed unseen. 26.585 says of its own case that the
planted draws cannot reach the cycle, because the drawn `length` fields are
3544 to 43311 against buffers of 40 to 1187 bytes, so the sealed region
never fits and the walk refuses first. The empty buffer reaches it because
there is nothing to refuse on the way.

## The proof

The regression test carries the construct rather than a number: keystore
over three frames -- empty, four bytes, and one whole -- asserted equal in
both walkers, plus the assertion that the whole one ANSWERS the region, so
the test is not two walkers agreeing on a refusal.

Taken from a `git archive HEAD` export with the new tests carried in, it
fails `assert -11 == 0` on the zero-byte frame and passes with the fix.

And the laziness is pinned from the other side, which the symptom test
cannot do: `body[remaining]` after a three-byte head over ten bytes must
measure **7**, from the member's own offset, where 10 is the frame-start
reading that sqlite and ipv6ext caught (44 against 37, 38 against 46). A
thunk nobody called would make every such run measure zero and the
agreement test would not notice, because the two walkers would agree on
nothing.

Green: 334 walker cases, 9,217 unit cases over six parts, `make test-c`,
`make cross-test`, style, typecheck.
