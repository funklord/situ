# 26.1080: a registry declares a keyspace of typed cells

Status: recorded
Date: 2026-11-18
Source: 0070, step 2 -- fuzznet's settings table, written as situ

**The declaration, before any reader generates from it.** A `registry`
names cells by key; each cell's bytes are a message of a struct the schema
declares, and each entry says what bounds it, what it defaults to, and what
a client shows for it:

```situ
policy scope   { estate, host }
policy display { restart, sensitive, advanced, verb, advertised }

registry node_settings {
	"revocation/k"  : count [min = 1, max = 255, scope = estate,
	                         safe = higher, unit = "root signatures"]
	                  "the estate's k";
	"stream/grant/" : count [max = 3, scope = estate, display = verb];
}
```

## The rule

- A key is segments of letters, digits and `._-` joined by `/`; one ending
  in `/` is a FAMILY, whose instances add one word. A key is declared once,
  and nothing sits inside a family declared beside it.
- A cell's type is a struct. Its VALUE is its `let value`, or its one
  member where it has one; a struct with neither is worth its bytes, and
  only `min_size` and `max_size` may bound it.
- situ's attributes: `min`, `max` (the value), `min_size`, `max_size`
  (the bytes), `default` and `unit` (strings, as stored), `safe = lower |
  higher`, `window` (milliseconds). Anything else is a word of a declared
  `policy`, one or several (`display = advanced | advertised`), checked
  against the policy and not interpreted.
- Registries and policies share the declaration namespace; dump and unparse
  carry both, and the unparse round-trips.
