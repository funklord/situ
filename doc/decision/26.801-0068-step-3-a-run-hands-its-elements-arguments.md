# 26.801: 0068 step 3 -- a run hands every element its arguments

Status: recorded
Date: 2026-11-02
Source: 0068, step 3

    struct entry { parameter u16 block [stream]; u8 tag [max = 5];
                   u8 data[block]; }
    struct vol   { u16 block; u8 n; entry(block = block) counted[n];
                   entry(block = 1) lit[2]; u8 after; }

Counted, literal, `[remaining]`, `while` and delimited runs of an argued
struct now build. 0068 rule 4 holds: the argument is evaluated once in
the parent and every element gets the same value. The four backends and
both walkers agree about where each run ends, how many elements it holds,
and what `validate` says about an element that breaks its own rule.

Still refused: a run inside a block, an arm (step 4), an `indexed`
region's element, a recursive element and a parent parameter handed on
(step 5).

## The backends

Every walk over a run constructs or measures its elements in several
places, and each now passes the arguments step 2's helpers render.

- **C**: `_element_extent_call` takes the arguments, so the span, index,
  `while` and fits walks get them through one path. `_record_run`,
  `_remaining_count`, both `_element_view` forms, the three `required`
  calls in `_framing_walk` and `_element_validation`'s `check` pass them
  at their own call sites.
- **C++**: each element construction (`{inner}(raw)`, `element(raw)`,
  `(found)`, `(narrowed)`, and the `(one)` validation builds) and the
  framing `required`.
- **Rust**: each struct literal, `::new` and the framing `required`.
- **Python**: an argued run gains `_make_<member>`, which builds one
  element with the run's arguments. Each walk calls it in place of the
  class, so the arguments are spelled once per run and not at a dozen
  constructor sites.

`_element_validation` in all four had skipped any element that takes
parameters (26.789: "takes arguments"). It now validates one when the run
hands it its arguments, and still skips one that has none to hand. The
four ask the same question, so the check ids agree.

## The walkers

Each run walk evaluates the ARGUMENTS rows once over the parent and
measures every element under them.

- **Python**: the counted, `[remaining]`, `while` and record walks in
  `walk.py`, and `report._run_elements` and `_elements_validate`.
  `_run_elements` declined any element taking parameters, and now does so
  only where the run hands it none.
- **C**: `child_binding` before the loop in `while_walk`,
  `record_run_walk`, `content_bits_deep`'s counted walk and
  `run_elements_validate`. `remaining_run_walk` and `counted_run_walk`
  take the element binding from their callers, and the arm callers (step
  4) pass the image unchanged. `element_validatable` is passed over where
  `argument_rows` says the run hands arguments.

## The corpus

`edges.situ` gains `hands_on_runs`, a counted run and a `[remaining]` run
of `negotiated`.
