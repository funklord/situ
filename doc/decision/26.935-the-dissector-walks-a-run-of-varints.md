# 26.935: the dissector walks a run of varints

Status: recorded
Date: 2026-11-08
Source: the four declines 26.932 left, wasm's type indices and QUIC's HTTP/3 settings among them

**A run of varints is walked element by element**, counted or to the end of the frame,
each a row, and a counted one has a span function so the struct holding it has an
extent. Where the bytes are no number the dissector returns there, as for one varint.

**The differential compares a run by its span.** The walker lists one line for a run,
`v count=3 span=4 [0]=129`, and the dissector one row per element, so the elements were
counted as shown and none compared, and the share of the dissector's rows compared fell
from 82% to 74%. The rows of one member that abut are summed and held to `span=`, and
count as one answer, as the walker's line is one. Rows of one member that do not abut
are two runs or one member shown twice, and are not compared.
