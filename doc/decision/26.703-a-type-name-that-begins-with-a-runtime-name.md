# 26.703: a type name that begins with a runtime name

Status: recorded -- fixed; the exact-name case stays 0062's
Date: 2026-10-27
Source: `project.md` section 26

**Rust's `use crate::situ_rt::{...}` list is decided by testing four
tokens against the rendered module, and three of them carry punctuation
no identifier can.** `situ_rt::`, `Error::`, `Result<` -- and `Dirty`
carried none:

    struct dirty_bits { u8 a; u16 b; }
    struct s { dirty_bits head; u16 tail; }

    error: unused import: `Dirty`
    use crate::situ_rt::{self, Dirty, Error, Result};

`DirtyBits` contains `Dirty`, so the import was added for a schema that
touches no dirty bit, and `-D warnings` refuses it. The control's import
line is `{self, Error, Result}` and compiles.

**A word boundary separates them, because the legitimate uses end at
one.** Measured across the corpus, every real use is `&Dirty` or
`&mut Dirty`; `DirtyBits` is `Dirty` followed by an identifier character.
So the tokens are regexes now and `Dirty` is `\bDirty\b`.

**A struct named `dirty` exactly is NOT covered, deliberately.** It emits
`pub struct Dirty`, which collides with the runtime's own name -- `the
name Dirty is defined multiple times`, E0255 -- and that is 0062's class
rather than a substring accident. It still fails, and should.

**Blast radius: the import lines are unchanged.** 46 generated Rust
modules, `edges.rs` differing only by the member 26.700 added to
`edges.situ`, every other file byte-identical, and all 46 compile under
`-D warnings`.
