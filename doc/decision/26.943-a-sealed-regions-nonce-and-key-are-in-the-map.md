# 26.943: a sealed region's nonce and key are in the capability map

Status: recorded
Date: 2026-11-09
Source: the copyright holder's answer to the question 26.117 left open and 0040 deferred to it

**The capability map names which field seeds a sealed region's nonce and
which selects its key**, on the region's own line, after the axes:

    record.sealed    offset=AbsoluteStatic(0x15) ... auth=Covered(tag) nonce=explicit key=epoch

Decided by the copyright holder: "yes, key and nonce go in the map". It
supersedes the one clause of 0041 that kept them out -- "They do not enter
the capability map, which prices API capability rather than stating
contract" -- and that record's rejected alternative, *Put the selector and
nonce in the capability map as well*. The wire signature half of 0041 is
unchanged: both have been on the signature's region line since it.

## Why the map as well

The map is committed beside its schema and is, in `capmap`'s own words,
the protocol documentation projects always want and never have. Before
this, the DTLS map said `stage=VerifyGated auth=Covered(tag)` over the
record body and nothing about the epoch, so a reader of the document the
project offers as its description could not learn that a flipped epoch
decrypts under a different key -- the one fact `example/dtls` exists to
show (0040).

0041's objection was that a fact in two artifacts is two chances to
disagree. Both read the same two fields of the same `Placement`
(`sealed_nonce`, `sealed_key`), so generated copies cannot disagree; a
hand-edited one is caught by `situc map --check` and the wire check, each
against its own committed file.

## Shape

They are not axes: neither weakens anything, and the map's rule that an
axis appears only below its strongest value has nothing to say about them.
So they follow the axes as names, the way a register's `access_width`
follows its size, and only where the schema names them -- a region without
`nonce =` or `key =` reads exactly as before. `FORMAT_VERSION` stays 1:
nothing reads the map back but `--check`, which compares it whole, and the
change adds tokens to existing lines only.

## What is still open

26.117 asked a second question, which this does not answer: whether an
attribute recorded on the wire signature but enforced by no generated code
(`[trim]` on a `u8`) is placed. 0041 answered it by placing the four
attributes; nothing here moves that.

## Consequences

- `capmap._sealed_by` renders the two names; the four committed maps with a
  sealed region regenerate (`dtls`, `keystore`, `packet`, `test/schema/edges`),
  each diff one line gaining tokens.
- `test_capmap.test_a_sealed_region_names_its_nonce_and_its_key` holds both
  the named and the silent case, and fails with `_sealed_by` stubbed out.
