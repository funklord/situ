# 26.1055: a driver takes an exchange by id

Status: recorded
Date: 2026-11-17
Source: fuzznet, inbox 20261117T1123Z (superseding its 1045Z), and its
project.md sec 1209 at 93a717d -- asks, at the holder's prompting, for
what would make the generated driver the cleaner road than node/asks.c

**fuzznet keeps its own resend schedule because the driver could not
hold four of its exchanges' facts.** Its asks table holds up to 64
exchanges; it seals every send under a fresh nonce and its own message
id; one exchange may wait for a fetch's tunable span deadline while
another waits 3 s and an awaited one is never resent; and it matches a
reply after opening it, and cancels every exchange on a socket before
closing it. Read against the drivers, in fuzznet's order of need:

1. **Expiry by id.** `step` counted expirations and named none, so a
   caller holding many could not say which to fail.
2. **The first send through the id-aware hook.** Retransmissions went
   through `on_resend`, told the id (26.1036); the first went through
   `submit`, told nothing, so it could not be sealed the way its resends
   were.
3. **A wait and resends per exchange.** Every exchange took the
   driver's numbers.
4. **An exchange ended by id.** Only `on_message`'s match by the
   relation ended one.

## The rule

In all four drivers, additively -- `send` and `step` keep their meaning:

- **`track`**: remember an exchange without sending it, for one the
  caller sent already or only awaits. `send` is `track` and then the
  first send, through the resend hook where one is set (C's
  `on_resend`, C++'s and Rust's `io` `resend`, Python's `resend=`), and
  through `submit` otherwise. Unless overridden, C++'s and Rust's
  `resend` is `submit`.
- **A policy per exchange**: C's `_send_with`/`_track_with` take a
  `_policy_t` (NULL takes the driver's), C++'s `send`/`track` an
  optional `policy*`, Rust's `send_with`/`track_with` an
  `Option<&Policy>`, Python's `send`/`track` keyword overrides. The slot
  holds its own numbers, so `step` and `part_held` read the exchange's.
- **`end(id)`**: ends an exchange without a reply to match; CONSTRAINT
  where none is pending.
- **An expiry hook**: C's `on_expire`, C++'s and Rust's `io` `expired`,
  Python's `expired=`, told each id as `step` drops it. The count stays.

The margin fuzznet's schedule keeps -- no resend within half the part
interval of the end -- is still not taken; nothing measured says it
matters, and fuzznet says it can wait.

## Measured

`test_a_driver_takes_an_exchange_by_id.py`: the same scenario in C, C++,
Rust and Python -- a send with a resend hook set reaches the hook as id 1
and `submit` not at all; a tracked exchange under 100 ms and no retries
sends nothing, expires at 150 and the hook is told 2; `end(1)` is OK and
again CONSTRAINT; at 200 nothing is outstanding. With C's first send put
back through `submit`, the C case fails. Every earlier driver test and the
Python driver's `mypy --strict` pass unchanged.
