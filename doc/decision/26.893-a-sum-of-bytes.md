# 26.893: A sum of bytes

Status: recorded
Date: 2026-11-06
Source: `suggestion/openmlx4.md`, and the holder's rule that a sane protocol's
need is ours

ACPI tables, the SMBIOS entry point, Intel HEX and openmlx4's FS2 all say the
same thing: the bytes, field included, add up to zero. situ had no spelling for
it. `require` is compile-time, and the workaround of writing the last byte as a
function of the others ran out at the first run of bytes.

    codec checksum8 { kernel = byte_sum(width = 8, negate); }
    checksum u8 sum[1] covers(body) is checksum8;

`byte_sum` is a family of its own, beside `ones_complement`, because it has no
end-around carry and no word order. `negate` is the two's complement. `width`
is 8, 16, 32 or 64, the sum being stored as a word. It takes the `_holed` and
`_spans` forms every digest has, so ACPI's checksum inside what it covers is
`[self_as = 0]`, and the Python walker computes it from a row of its own.

The published Intel HEX record is the check on the arithmetic: situ did not
write its last byte.

The four-way driver does not call a checksum's check, so the language
agreement here is each language's own function over the same bytes, and
Python's reader through `sum_check`. C++ takes C's.
