# 26.988: the walkers read the order

Status: recorded
Date: 2026-11-13
Source: writing hull a note about 26.985

26.985 had the walkers decline a struct holding an ordered run, as they
decline a `tlv` region's ordering: the image carried no way to compare
keys. So `situ-walk`, `situ-edit` and the embedded C walker -- the readers
a format needs no generated code for -- answered "cannot say" for every
struct holding one, and the six-way differential compared none of them.

**The reason first written here was wrong, and is kept so the next reader
does not repeat it.** Drafting a note to hull, this said hull's
`store_test`, which holds packs to `situc verify`, would verify every pack
as "cannot say". `situc verify` does not run the walker: it refuses
through the generated Python, and refused an out-of-order hull index
before this change as after it. Checked by running it, after the commit
had been written on the assumption; corrected before it was pushed.

The image carries the order now: section 30, `image_ordering`, one row per
ordered run -- its placement, stride, where the key sits and how wide it
is, and whether it compares as bytes, unsigned or signed, in which byte
order. The packer fills it from `traverse.run_ordering`, the answer the
four backends emit from, so all six compare the same bytes. Each walker
counts the run as its measured extent over the stride and compares after
the run's own checks; a refusal is CONSTRAINT and names the run, with a
check kind of its own (22, after the three bound kinds).

**What an older walker does with a newer image is the cost of the
format's growth rule, and it is a pass, not a refusal.** `std/image.situ`
grows by appending sections without a version bump, and a walker skips a
kind it does not know. Before this, the packer marked such a struct
unvalidatable, so an older walker said "cannot say"; now the struct is
validatable and an older walker, skipping section 30, passes an
out-of-order run as clean. `image_holds` (26.898) made the same trade.
Moving `FORMAT_VERSION` would make old walkers refuse every new image
instead; whether the growth rule should tell a section that carries a
check from one that only adds reach is not settled here.

`std/image.situ` describes the row. `test_a_run_holds_its_keys_in_order`
now requires both walkers to give the backends' verdict on all twelve of
its messages, where it had required them to abstain.
