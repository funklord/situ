# 26.747: A C++ arm accessor read its discriminant past the view

Status: recorded -- fixed
Date: 2026-10-29
Source: `project.md` section 26

An enum discriminant behind a variable-length member sits at a dynamic
offset. C++'s `_over_fields` rendered an enum field as a raw load of its
backing bytes, because the getter returns an `enum class` and nothing
compares one to a number. At a dynamic offset the load went through
`situ_advance_u32`, which clamps an offset to the frame's limit, and it
was not bounds-checked:

    if (static_cast<std::uint8_t>(*(situ_base(raw_)
            + situ_advance_u32(3, <head.n>, raw_.limit))) != 17u)

So a discriminant the frame does not reach was read at `base[limit]`,
**one byte past the view**, and the arm accessor answered `ok` or not off
whatever that byte held. The `which()` getter next to it checks
`situ_in_bounds` first. The arm test did not call it.

C++ is the one backend whose accessors are not lax, so this is a memory
fault rather than a wrong number. Under ASan, with the message in a heap
buffer of exactly its length:

    ERROR: AddressSanitizer: heap-buffer-overflow ... READ of size 1
      #0 situ::s::body_run(...) const  unit.hpp:268

## How it was found

By the full composed sweep (`tool/sweep.py --all`, four shards), whose
drivers ask `required` since 26.743: every cell with an arm behind a
nested-struct count disagreed, with C++ answering `body_run ok=1` where C,
Rust and Python answered `ok=0` -- 76 of them by the time the shards hit
their hour. The corpus differential and the C++ fuzz harness cannot reach
it, because no corpus schema has an enum discriminant at a dynamic offset
with an arm behind it.

## The fix

At a dynamic offset, `_over_fields` reads an enum field through its getter
and casts the value to the backing type. The getter answers zero where the
field does not fit, which is what the other three read there. A static
offset keeps the load, since the acquiring check covers it.

`test_an_arm_discriminant_past_the_frame.py` builds the reproduction
under ASan and UBSan and fails with the change removed.
