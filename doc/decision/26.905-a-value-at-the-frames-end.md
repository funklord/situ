# 26.905: A value at the frame's end

Status: recorded
Date: 2026-11-06
Source: the goal gap, by writing real protocols until one was refused

    peek u8 last at end;
    u8      payload[remaining];
    u8      padding[padded_flag * last];

RTP's padding count is the last octet of the packet and sizes the bytes before
it (RFC 3550 5.1); ESP's trailer is the same shape two bytes wide (RFC 4303 2).
A size names a field already read, so these had no spelling: the value comes
after what it sizes.

## Decision

Two pieces, neither new in kind.

`peek ... at end` is the read `peek` already makes, measured from the frame's
end. `at end - N` stops N bytes short of it, so ESP's two are `at end` and
`at end - 1`. It is the frame, not the message: `at expr` is measured from the
message (9.8) and its accessor takes the message, so a size could not read one.

A `[remaining]` run may leave a run of `u8` after it whose length was read
before the run began, as it already left fixed members (26.894). The rule is
unchanged: the frame less what follows, and a frame too short for that is an
empty run, with the member after it then past the frame and refused.

A frame shorter than the distance places the member past the frame, not at
zero, so the read refuses and no other byte is taken for it.

In the image, an unknown offset whose row still carries a number is measured
from the end, which needs no flag: `text_flags` has no bit left.

## Measured

`example/rtp` is the protocol. Its five vectors read as tshark's own RTP
dissector reads them, payload and padding count, and as the generated dissector
reads them inside tshark. That run found two faults of the dissector's own, in
code older than this:

- A `when` holding `&&` emitted `&&`, which Lua refuses, so the file did not
  load and no message of the protocol was shown. Every example's `when` had
  been a single comparison.
- An arm at a run-time offset was measured from byte zero, so whatever followed
  a variable arm sat on the wrong bytes.

## Not built

`[holds]` directly on an arm stays refused, and a struct that ends in its frame
still gets no view as an arm or a nested member, which is why `rtp` states the
P bit as arithmetic rather than as a variant of two bodies. That is the same gap
MQTT's PUBLISH body has.

## Rejected

- `u8 payload[remaining - count]`: no backend renders `remaining` inside an
  expression, and a negative result would need a meaning of its own. The run
  that leaves what follows already has one.
- Letting a size name a field declared after it: the offset of that field is a
  sum over the member being sized.
