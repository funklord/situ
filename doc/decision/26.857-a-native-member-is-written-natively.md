# 26.857: C's builder and owned form write `native` as the view reads it

Status: recorded -- fixed
Date: 2026-11-04
Source: 26.858's four-way byte comparison, on its first run

    endian native;
    struct native [allow_host_dependent] { u24 wide; u64 big; u16 small; u8 tail; }

`c/build.py` and `c/owned.py` picked a byte order with "little, or else
big", six sites in all. A `native` member went down and came up big-endian
on a little-endian host, while the view beside them reads `situ_get_ne`.
So netlink's header built in C read back byte-swapped through C's own
accessors, and the owned pair round-tripped happily, being wrong in both
directions. `u24` escaped, because it goes through `bit_extractor`, which
has always known `ne`.

`validate` could not see it, and neither could a round trip through one
form. It took a second language writing the same struct.

## The change

Every site asks `emit._order_suffix`, through `owned.order_suffix`, which
exists because `emit` imports `owned`. `tag_codec_endian` is left alone: a
codec's output order is stated or defaulted and has no `native`.

## Tests

`test_a_native_member_is_written_natively.py` builds and encodes one
struct and reads both through the view, and decodes what the builder wrote.
With `situc/codegen/c` reverted it fails.
