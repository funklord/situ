# 26.996: a derived region decodes natively

Status: recorded
Date: 2026-11-13
Source: the holder's "yes, we want codecs" (2026-11-13), on decision
0017's per-language implementations

**What was asked, and what it turned out to need first.** 0017's
amendment of 2026-09-04 made `derived` native in every backend, and the
2026-09-30 amendment measured it built: Rust and Python inline a native
`crc32` for a checksum. Measured today, that held for checksums and not
for a coded region. A region whose codec is derived still decoded in
Rust through `extern "C" situ_<codec>_decode` and `unsafe`, so a schema
using one linked the C runtime the amendment was written to keep out of
`#![no_std]` Rust; and Python emitted no decode at all, only a note to
load the C codec through ctypes. Three corpus schemas have such a
region: `example/slip`, `example/smtp` (dot-stuffing) and
`test/schema/edges` (an additive scrambler).

**Now both define the kernel in the module and call it.** The kernels
are the ones `gen-derived --target rust|python` already emits, through
the same `_for_kernel`, so each is a rendering of the one description
rather than a second implementation -- the distinction 0017's amendment
draws. A codec is native here when it is derived, `decodes_here`, has a
ratio, and its kernel is generated in that language; a tier-1 `extern`
codec is the caller's C and unchanged. The bit helpers a table code reads
through come along where one is used, as in `gen-derived`.

- Rust: `<name>_decode(&self, out)` calls `<codec>_decode(input,
  encoded, out)` with no `unsafe`, and clamps `encoded` to the bytes the
  region actually holds, since the native kernel indexes them where the
  C call was handed a pointer and a claimed length.
- Python: `<name>_decode()` returns the decoded bytes, empty where the
  codec refuses the encoded form, as C returns no bytes for it.

**Measured.** The corpus regenerated old against new in Rust and Python
changes those three schemas and nothing else. `test_codegen_rust` builds
a Manchester region with `-D warnings` and no link argument, encodes
with the module's own `halve_encode` and decodes through the accessor;
its lint sweep compiles slip, smtp and edges clean. Python decodes SLIP
per RFC 1055 (`ab ESC ESC_END ESC ESC_ESC c END` to `ab C0 DB c`, and an
undefined escape refused) and SMTP's dot-stuffing. `test_codecs`'s
control now asks that Rust DEFINES the derived decoder and declares no C
symbol, where it asked for the C declaration.

**Still open from 0017.** The `impl <codec> ... for <lang>` qualifier
the record specifies is still not parsed; with derived native everywhere
it is wanted only to bind a hand-written native implementation for one
language, and no consumer has asked for that yet.

**Found on the way, and not changed here.** `NAMED_CODES` in
`situc/codegen/c/derived.py` maps `manchester_802_3` to 1 -> `10`. IEEE
802.3 makes the first half of a bit cell the complement of the bit, so a
one is LO then HI, `01` -- which is the table situ calls
`manchester_thomas`. All four backends share the table, so the
differential cannot see it. It is the next item, because it changes what
the bytes mean.
