# 26.899: `popcount` counts a bitmap

Status: recorded
Date: 2026-11-06
Source: the goal gap, under the holder's rule that a sane protocol's need is ours

    u32 present;
    u32 values[popcount(present)];

A presence bitmap followed by one value per set bit could not be sized: no
expression counts bits. Section 10 keeps its rule, since this is total and has
no loop a message chooses.

**A read under `popcount` is not held to `LEAF_MAX`.** A leaf saturates at
2^31 - 1 so that four targets add up alike, and that is right for a length. A
bitmap is not one: bit 31 of a `u32` saturated away reads as thirty-one set
bits. `names._all_bits` respells each read whole in the argument, and nothing
sums it afterwards, because the count is what comes out. A first version kept
the leaf and would have miscounted exactly the top bit radiotap's `ext` uses.

**Unsigned only.** The set bits of a negative number depend on a width the
expression does not carry, so a signed argument is refused. The solver bounds
the count by the argument's bit length.

Rust refuses a literal past `i64` in any size expression, so a mask of
`0xFF00000000000000` does not compile there. That is older than this, and
`popcount(present)` of a whole `u64` is fine.

**The corpus struct found Lua's limit.** A chunk holds 200 locals, and `edges`
reached 201, so its dissector no longer parsed. A schema of that size would have
failed when Wireshark loaded it. Past the limit the top-level names go in a
table the chunk makes its `_ENV`, and every smaller dissector is unchanged.

Both walkers gain one opcode, `POPCOUNT` (0x33). The four backends and both
walkers agree over bit 31, bit 63 and all bits set.
