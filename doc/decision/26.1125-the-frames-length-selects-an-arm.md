# 26.1125: the frame's length selects an arm

Status: recorded; built 2026-11-21
Date: 2026-11-21
Source: fuzznet (inbox 20261120T2230Z): its setting record gained `rank`
(u8) before `signature[64]`, and records written earlier -- the same
layout one byte shorter -- sit in journals on disk and must stay readable.
Its codec tells them apart by the record's length; a schema could state
one of the two, so the codec stayed hand-written. "A member present when
the bytes allow ... decided by the length the frame gives."

## Decided

`variant NAME switch (remaining) { ... }`: the discriminant is the bytes
from the variant's start to the end of the frame, which is what
`remaining` already means in a size (26.986). Nothing new to learn: a
variant, a case per shape, and the word every size expression knows.

    struct setting {
        ...
        variant tail switch (remaining) {
            case 65: ranked   with_rank;      // u8 rank; u8 signature[64]
            default: unranked without_rank;   // u8 signature[64]
        }
    }

Three rules, each refused at layout, because each is a schema that cannot
mean what it says:

- **A `case N` arm is exactly N bytes.** It is read when N bytes remain; an
  arm of another size would never be read as itself.
- **A default arm is no case's size**, or a message of that length would
  be read as the case.
- **The variant ends the frame.** `remaining` counts everything after the
  variant, so a member following it would be counted as the arm's.

Builders write no discriminant: the arm written is its length, and the
builder's own closing validate reads it back through the same switch.

## Rejected

- **`[optional]` on a member, present when the bytes allow**, fuzznet's
  first spelling. It decides presence by arithmetic over what follows --
  `rank` is there when 65 bytes remain rather than 64 -- which the schema
  would have to derive from every later member's size, and it says one
  member where formats grow by several (NTP's authenticator is a key id and
  a digest of two sizes). The variant names each shape whole.
- **A `let` of `remaining` as the discriminant.** A `let` is arithmetic
  over fields with no position, and `remaining` is a position's.
- **`[remaining]` run with two arms by length** (fuzznet's second): the
  same variant under another name.

## What carries it

The four backends read `remaining` at the variant's offset in each
place a discriminant is read; both walkers take a new arm-row value,
`selects = 0xFFFFFFFE` beside `NONE`, and compute it the same way; the
dissector reads `tvb:len() - at` where the variant starts. A variant
switched on `remaining` inside a struct the dissector measures from its
parent is not measured there: its length is the frame's, which the parent
does not have.

NTP's example gained `ntp_datagram`, the packet and RFC 5905 7.3's
authenticator -- none at 48 bytes, MD5 at 68, SHA-1 at 72 -- so the whole
differential corpus exercises the construct.
