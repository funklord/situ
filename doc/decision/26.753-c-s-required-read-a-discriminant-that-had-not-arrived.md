# 26.753: C's `required` read a discriminant that had not arrived

Status: recorded -- fixed
Date: 2026-10-30
Source: `project.md` section 26

A getter at a static offset reads without a bounds check, because a view
acquired through `_view` has already been held to the struct's minimum
size. `required` builds its view from whatever has arrived, so that
promise does not hold there -- and C's variant framing read the
discriminant through the plain getter:

    struct kinded { peek u8 kind;
                    variant held switch (kind) { case 'a': kinded_a as_a;
                                                 default:  kinded_b as_b; } }

    if (situ_kinded_kind_get(view) == 97u)       /* have == 0: data[0] */

At `have = 0` that is a byte the caller never handed over. C chose the arm
off it, so its answer for an empty buffer depended on whatever followed
the buffer in memory: 2 where the slack held an `'a'`, 3 otherwise. C++,
Rust and Python read the discriminant bounds-checked, see zero, take the
default arm and answer 3.

## How it was found

By the corpus differential's `required()` probe (26.743), on a draw where
the byte after a zero-length allocation was not the one it usually is:
`edges.kinded` answered 2 in C and 3 in the other three. It had passed
every earlier run because the slack usually held something other than
`'a'`, which is what makes an uninitialised read look deterministic.

## The fix

C's variant framing reads a discriminant at a static offset as `(have >=
end ? value : 0u)`, which is what the other three read. The test plants
an `'a'` in the slack after an empty prefix and asserts 3; with the guard
removed C answers 2.

## A note, not a change

Three is the default arm's size, and the message could be the two-byte
`'a'` arm. All four agree on it because all four read an absent
discriminant as zero. It over-asks rather than under-asks, which is the
direction `required` allows, and it is recorded so that a later look at
discriminant-dependent framing starts from it.
