# 26.846: the fuzz harness was parked on a rule that does not apply

Status: recorded -- a parked question that did not need parking; the work
it blocks is named and not yet done
Date: 2026-11-03
Source: walking section 1's four deliverables against `situc <cmd> --help`
after `gen-checks` reached its fourth language

## The gap

Section 1 says `situc` generates, from a schema, four things. Asked of the
CLI rather than of the records:

| deliverable | languages reached |
|---|---|
| accessor code | c, cpp, python, rust |
| capability map | one, and language-independent |
| design advice | one, and language-independent |
| golden-vector tests (`gen-tests`) | c, cpp, python, rust |
| conformance checks (`gen-checks`) | c, cpp, python, rust |
| **fuzz harness (`gen-fuzz`)** | **c, cpp** |

So one half of "test scaffolding: golden-vector tests and a fuzz harness
per schema" reaches four languages and the other reaches two.

## Why it was parked, and why that reason is wrong

It was deferred earlier because `cargo-fuzz` is not installed here and
`atheris` -- libFuzzer for Python -- is third party, "which section 24
forbids".

**Section 24 forbids no such thing.** What decision 0001 says, at section
22, is that the implementation language for `situc` is "Python 3.11+,
standard library only", and "Do not add a dependency without recording a
decision". That constrains what **`situc` imports**. It says nothing about
what a file `situc` GENERATES expects of the consumer's toolchain.

And the existing targets prove the distinction, because `--target c`
already emits `LLVMFuzzerTestOneInput`, which needs clang's libFuzzer.
`situc` does not depend on libFuzzer; it emits a file that expects one.
A `cargo-fuzz` target or an `atheris` harness would be the same
arrangement in another language -- the consumer's dependency, not situ's.

So the question answers itself, and **the cost that was feared could not
occur.** That is `working-practice.md`'s rule exactly: a decision held
open because of what it might break is waiting on a measurement nobody
took, and the measurement is cheaper than the deliberation.

## Why this is the entry rather than the fix

The entry is the point. A wrong technical claim gets caught -- by a gate,
a test, a sabotage run. **A wrongly-deferred question is caught by
nothing**: it sits looking exactly like diligence, and every later reader
inherits the deferral together with the reasoning that justified it. This
one was inherited twice today before anybody read the rule it cited.

What makes it findable at all is the method, which is worth more than the
instance: **walk the aims against the CLI, not against the records.** The
records said test scaffolding was delivered. `--help` said one of its two
halves reaches half the languages. The same walk found the same shape at
26.829, when `gen-tests` took no `--target` at all.

## What the work is

`gen-fuzz --target rust` and `--target python`, emitting what each
ecosystem's fuzzer expects -- a `#[no_main]` `fuzz_target!` for cargo-fuzz
and an `atheris.Setup`/`Fuzz` harness -- and gated like the Rust and C++
suites are, with `skipif` on the tool's absence rather than a claim that
it is present. Neither is installed here, so the gate will skip and the
generated file will be held to its shape by a unit test, which is what
`test_cli.py` does for every other emitter.
