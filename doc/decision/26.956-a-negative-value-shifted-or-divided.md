# 26.956: a negative value shifted or divided, in the runtime, the walker and a `when`

Status: recorded
Date: 2026-11-11
Source: raidcfgd's cppcheck run over the vendored runtime (inbox 20261111T0055Z)

**raidcfgd reported one finding**: `situ_zigzag_encode` computed the
sign as `value >> 63`, a right shift of a negative signed value, which C99
6.5.7p5 makes implementation-defined. Every compiler here shifts
arithmetically, so nothing was wrong in practice, and the file around it
refuses to guess a byte order with an `#error` rather than lean on one.
It is `value < 0 ? ~(uint64_t)0 : 0` now.

## The same shape, three more times

cppcheck over the runtime and the C walker, with `-DSITU_HOST_BIG=0` --
without it the tool stops at the byte-order `#error` and reports a clean
pass over a file it never read, which the report says:

- the walker's parameter bound computed `(int64_t)1 << size_bits`, which
  is undefined for a 63-bit member. Unsigned arithmetic now.
- the walker's expression evaluator did `left >> right` on a signed
  value. `~(~left >> right)` for a negative one, arithmetic as Python's
  and Rust's.
- **and the generated code**: an expression's `>>` is copied into C and
  C++ as written, so a schema shifting a signed field right was at the
  compiler's discretion there and arithmetic in Rust and Python.

## And the arithmetic a `when` was never asked about

`interval_of` already refused `/` and `%` over a left operand that may
be negative, because C truncates and Python floors. It ran on layout
expressions only. A `when` rule reads the same fields and was asked
nothing, and that was a live disagreement, measured:

    struct s { i8 a; u8 k; }
    when (s.a / 2) == -1 refuse odd "x";

    a = -3:  C, C++, Rust refuse it   Python accepts it

Each struct's field ranges are kept once solved (`value_ranges`), and
`resolve` computes every `when` rule's range against them, so the same
refusals apply -- now including `>>` over a possibly negative left
operand, in both places. Nothing in the corpus is refused.
`test_a_when_is_held_to_a_sizes_arithmetic.py` holds all three operators,
and that an unsigned or `[min = 0]` field is accepted.
