# 26.986: a size reads remaining

Status: recorded
Date: 2026-11-13
Source: writing `example/gitidx`, whose `gen-tests` vector called a setter
for `large_offsets` that the header did not declare

`u64 large_offsets[max(remaining, 40) / 8 - 5]` was one `u64` in every
backend. The solver keeps a size written as arithmetic as `size_expr` and
drops one that is a constant, and its test for a constant, since
8f327801 (2026-08-03), was "names no field": `octets[4]` names none. So
does `remaining / 8`. Every backend then read a single element where the
schema states a run -- C declared `_get(view)` with no index, the vector
test round-tripped it through a setter that does not exist -- and nothing
was said. The walkers read `remaining` from the member's start, as
section 10 means it, and were right alone; `walk.py`'s `_sizes_in_bytes`
even documents the shape. Nothing in the tree had written it until git's
index did.

An expression reading `remaining` is not a constant now, and each backend
renders it in a member's size as the bytes from that member's start to
the view's end -- `situ_remaining_u32(view.limit, <start>)`,
`raw_.limit`, `situ_rt::remaining(...)`, `max(0, self._len - <start>)`.
Without that rendering C raised `UnknownName` and the other three
declined the member as unresolvable, which is honest and loses the run;
with it all four count what the walkers count.

`test_a_size_reads_remaining` asks the four over five frames, one of them
a trailer cut short, with the count pinned by hand and the walkers' verdicts
beside them; the four fail with the change reverted. The 52 example schemas
generate identically before and after.
