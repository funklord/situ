# 26.755: The C walker answers a relation

Status: recorded -- implemented; closes what 26.95 left outstanding
Date: 2026-10-30
Source: `project.md` section 26

26.95 built rung 3, `relate`, in the four compiled backends and named
four things outstanding: the walker, the map scalars, the dissector and
the fuzz harness. The Python walker, the dissector and the fuzz generator
took it up since (`c2969b6` and after); the C walker did not. Its
evaluator refused `arg_field` by name -- correctly, since a relation's
`must` reads a field of one of TWO messages and its callback held one --
so `relate` had five answers and a refusal, and `project.md` (932f996)
named that as what was left of the layer ladder.

## What it took

26.95's own sketch held: the VM needed nothing but the parameter.

- **The image's relation tables**, sections 18 and 19, which the C loader
  skipped as unknown: a row of `(name, request, response, first, count)`
  and a table of code offsets, one per `must`.
- **`arg_field` asks the callback by parameter.** The callback contract
  gains `SITU_WALK_ASK_ARG_REQUEST` and `SITU_WALK_ASK_ARG_RESPONSE`, and
  the evaluator reads the parameter byte and the placement index after the
  opcode. The ordinary walk's `ctx_load` refuses both asks rather than
  answering from the one message it holds, which would answer a question
  about another pair -- the property `test_arg_field_is_refused_outside_a_
  relation` holds in Python.
- **`situ_walk_relate`** holds both messages as the walk contexts
  `ctx_load` reads, so a relation compares exactly the values the rest of
  the walker reads. A plain field and the builtins read the request and
  `count` answers zero, as `walker.report.relate` does. The verdict is
  OK or CONSTRAINT, the four backends' answer and no richer.

## Verified

`test_the_c_walker_answers_a_relation.py` asks five pairs of
`test_relations.GOOD` -- both musts holding, each failing, and the order
reversed -- and holds every answer to the Python walk's, which
`test_relations.py` holds to the four backends; both verdicts occur. With
`arg_field` refused again the C walker answers `cannot-say` where the
walk answers OK.
