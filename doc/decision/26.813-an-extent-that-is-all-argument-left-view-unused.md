# 26.813: an extent that is all argument left `view` unused

Status: recorded -- fixed in C; the other three were already clean
Date: 2026-11-02
Source: `project.md` section 26

**A legal schema whose generated C does not compile under this project's
own flags.** Four lines:

    struct arg_only { parameter u8 width [stream]; u8 body[width]; }
    struct holder   { u8 lead; arg_only(width = 2) one; u8 trailer; }

C emits

    static inline uint32_t situ_arg_only_extent(situ_view_t view,
                                                uint8_t arg_width)
    {
            uint32_t extent = 0u;
            extent = extent + ((uint32_t)situ_nonneg_u32(
                                  situ_leaf_u64(arg_width)));
            return extent;
    }

whose body names `arg_width` and never `view`:

    error: unused parameter 'view' [-Werror=unused-parameter]

`make test-c` compiles the generated headers with
`-Wall -Wextra -Werror -Wconversion -Wsign-conversion`, so this is not a
style nit -- it is a schema the toolchain accepts and the build rejects.

## The condition asked the wrong question

`_extent_body` emitted `(void)view;` when `not terms and not ending` --
when the struct has no variable member at all. That is not the same
question as "does the body name `view`". A struct whose whole extent is
its ARGUMENT has a term, and that term reads the argument.

It is read off the body now, which is the rule `_argument_unused` beside
it already follows and says so in its own docstring: *"Read off the
signature rather than off the struct, because the opposite mistake is
silent in the other direction."* The same text now answers for `view`
and for the arguments, so the two cannot disagree about one body.

## Why it had not been seen

Three things hid it, and the third is the transferable one.

- **`edges.negotiated` cannot show it.** Its extent also reads a
  `[max]`-capped member, so `view` is named. The shape needs a child with
  nothing else to measure.
- **A fixed prefix hides it.** The bounds check above the terms names
  `view`, and it is emitted only `if constant and terms` -- so a child
  with any fixed member is clean whatever its terms read.
- **It needed a PARENT, and nothing could be one until recently.** A
  struct that takes a `parameter` was a top-level message, acquired by
  the caller, and its `_extent` is emitted only where something measures
  it. 0068 step 2 gave a parent a way to hand a constant down, which is
  when this became reachable -- so it is older than step 5 and was found
  while probing it, on a minimal schema written to isolate something
  else.

Measured on a `git archive HEAD` export to be certain it was not the
step-5 work: the same four lines fail there, through a constant argument
and step 2 alone.

**C only.** C++ and Rust were checked on the same schema and compile
clean, Rust under `-D warnings`, which is the flag that would have
caught the mirror of this. Python has no compiler and nothing to warn.

`edges.situ` carries `arg_only` and `holds_arg_only` so the corpus has a
child with nothing but its argument to measure.
