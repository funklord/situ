# 26.1015: a builder writes where an offset puts it

Status: recorded
Date: 2026-11-13
Source: the goal gap -- builder refusals over the example schemas

**A BMP file could not be built.** `bitmap_file` ends in `u8
pixels[info.image_size] at file.pixel_offset`, and 26.610 refused every
located member, 26.629 keeping the refusal for a reason stated as "a
POSITION the writer cannot know: ... the bytes in between are already
down". That is true of an offset into bytes not yet written -- a header
pointing past content that follows it. It is not true of the struct's LAST
member: when the writer reaches it every byte before it is down, the offset
among them, so the position is read rather than predicted.

**Narrowed, not reversed.** `late_position_refusals` lets through a located
member that is the struct's last and a byte run. C's builder asks the
reader's own accessor where the run lands, over the whole backing, so a run
past it is BOUNDS; refuses an offset behind its cursor, which would write
over what is down; zeroes any gap; and copies the caller's bytes, which
must be as long as the reader says. Every other located member keeps the
refusal, TIFF's `tiff_file.first` among them (a struct, not bytes). C only,
the other three not yet building this role.

**Measured against Pillow**: C builds a one-pixel 24-bit bitmap with the
pixels right after the headers and ten bytes further on, and Pillow decodes
both as (0x30, 0x20, 0x10) at 1x1, the gap zero; an offset into the headers
is refused.
