# 26.1052: a sized arm beside a framed one

Status: recorded
Date: 2026-11-17
Source: the four-way differential over PCI VPD's resource list, once it
compared structs that take arguments (26.1053)

**Python's `required` read half a length as the whole of it.** A VPD
resource is a large one -- `large_body`, framed by a little-endian `u16`
length -- or a small one, `u8 small_data[item_low]`, sized by bits of
its tag. Given `8a 2c`, a large resource and one byte of its length,
Python answered 47, reading that byte as the length; C, C++ and Rust
answered 3, the length not being there yet.

Python frames a variant through the chosen arm's own `required` (26.684)
only where every arm is a struct or fixed-size, and otherwise falls back
to the arms' EXTENT, which shrinks when the bytes run out -- the failure
26.684 was about, one arm shape over.

## The rule

An arm the data sizes, by fields ahead of the variant, is framed by its
length over the probe once the discriminant is in -- as the other three
read it -- so the variant still goes through each arm's own `required`.
A delimited arm or a run still sends the variant back to the extent.

A stricter guard, every byte up to the variant's start, was tried first
and the full gate caught it: netlink's `nl_message` at six bytes of 0xFF
answered 20, a lower bound, where all three read `nlmsg_len` and said
0x80000003.

## Measured

`test_a_sized_arm_beside_a_framed_one.py`: one byte of a large resource
needs 3, two bytes need 3, a whole one is its length, and a small one is
sized by its tag. With the new branch disabled the second answers 47. The
four-way over the VPD schema agrees on 40 random draws.
