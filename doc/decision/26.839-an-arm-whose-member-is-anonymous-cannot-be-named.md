# 26.839: an arm whose member is anonymous cannot be named

Status: recorded -- both backends decline it now and the construct is in
the corpus; the name mismatch underneath is a layout decision and is NOT
fixed here
Date: 2026-11-03
Source: found by a fixture written for 26.838, when widening the reserved
check to a struct's arm members

## The reproduction

    struct s {
        u8  kind;
        variant body switch (kind) {
            case 1:  reserved u8 [must_be_zero];
            default: u8  other;
        }
    }

`gen-checks` emitted, in `--target c` and `--target python` alike, a check
that breaks `s.body.<reserved0>` and asserts `validate` refuses it. The
check **fails**, correctly: the discriminant is zero in the baseline
buffer, zero selects the `default` arm, the reserved field is not in that
message at all, and `validate` accepts a nonzero byte where it sits.

So the generated suite asserted a refusal that should never come. C's own
`_prelude` docstring describes exactly this hazard and says the remedy is
to decline -- the remedy did not fire.

## Why it did not fire

`enclosing_arm` could not find the arm. Measured:

    placements:  s.kind, s.body, s.body.<reserved0>, s.body.other
    arm value=1  member='s.body.arm'
    arm value=None member='s.body.other'

**The arm names its member `s.body.arm` and the placement is
`s.body.<reserved0>`.** `arm_members` looks the first up among the
placements, finds nothing, and `enclosing_arm` reports no arm -- which is
the same answer it gives for a member in no arm at all.

That conflation is the defect's mechanism rather than its cause: two
different facts under one return value, and every caller that reads "no
arm" as "not in an arm" is wrong about exactly this construct.

## What is fixed, and what is not

**Fixed**: `traverse.inside_an_unresolved_arm` separates the two reasons,
and both backends consult it. Each declines with the reason stated -- in
the generated module for Python, through `suite.skip` for C -- rather than
emitting a check that cannot hold.

**Not fixed**: the name mismatch. A placement's name is a layout decision
and `s.body.arm` is written where `s.body.<reserved0>` is created; making
them agree is a change to the layout with consumers beyond `gen-checks`,
and it is recorded here rather than made in passing.

**And there is at least one other consumer already blind to it.**
`test_invariants`' variant-arm census counts `arm_holder`'s
`default: u8 other` and does not count the reserved arm, because it
resolves arms by the same lookup. That census is annotated to expect one
more in its first cell when this is fixed, which is the cheapest possible
reminder.

## Why the construct went into the corpus

The guard changed **nothing** in the corpus: generating `gen-checks
--target c` for all 43 schemas before and after it gave byte-identical
output, because no schema had an anonymous arm member. A branch no input
reaches is a branch a revert would not disturb, so `edges.arm_holder`
exists to reach it -- and `make test-c` compiles and runs the C side of it.

`--target python` declines `edges` for its `parameter`, so the Python side
is gated by a fixture in `test_cli.py` instead, with both arms asserted: a
nameable arm is selected and checked, an unnameable one is declined. A
backend that declined every arm would pass the first of those alone.
