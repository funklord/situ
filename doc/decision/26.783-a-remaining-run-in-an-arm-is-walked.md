# 26.783: A `[remaining]` run in an arm is walked

Status: recorded -- fixed
Date: 2026-10-31
Source: the shapes 26.779 left unwalked

    struct arms { u8 kind; u8 n;
                  variant body switch (kind) {
                      case 1:  piece recs[remaining];
                      default: u8 raw; } }

26.779 walked a counted run of records in an arm and declined a
`[remaining]` one. So `01 00 01 05 01`, whose second record declares a
byte the frame does not hold, validated clean in C, C++, Rust and
Python. Both walkers refused it. The C walker also refused `01 00 01
05`, which is one whole record. It evaluated `remaining` (two bytes) as
a record count and reached for a second record.

## The change

- Each backend's `_arm_run_walk` takes a `[remaining]` run and walks it
  to the end of the frame, as the top-level `_run_fits` does (26.736).
  It has no tail to check, since 26.782 refuses a member after one.
- The C walker splits `remaining_run_fits` so that its walk,
  `remaining_run_walk`, takes a start offset. `arm_validates` calls it
  for a run sized in bytes.

The corpus has no such arm and generates byte-identically.

## Tests

`test_a_run_in_an_arm_is_walked.py` gains the shape and seven messages.
With `situc` reverted the four-backend case fails; with `walker`
reverted the walkers' case fails.
