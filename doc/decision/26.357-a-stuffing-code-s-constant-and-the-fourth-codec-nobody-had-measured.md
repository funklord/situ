# 26.357: A stuffing code's constant, and the fourth codec nobody had measured

Status: recorded
Date: @ -28125,0 +28134,54 @@ walker promises rather than how it computes anything.
Source: `project.md` section 26, where it was written

**0048 built.** `ratio_bounded(a, b) + k` parses, the signature carries
both terms, and `kernels.STUFFING_BOUNDS` holds the constant per code. The
defect it repairs is 26.147's: COBS, SLIP and PPP each append a frame
delimiter after expanding, so a consumer sizing a buffer from the
published ratio overran by one on every encode.

**Most of it already existed and was unreachable.** `_expand` in
`layout.py` has applied an addend beside a ratio since 0016, for a
pipeline that appends parity before expanding -- so the arithmetic was
right and there was no way to SAY it. What the build lacked was a
spelling and a renderer, which is why the repair is small.

Spelled as the sum rather than as a third argument, because the sum is
what a consumer computes: `len * a / b + k`. A third term inside
something called a ratio would read as part of the ratio.

**The addend is the CODE's**, so it comes from the table rather than from
the schema -- the same rule the ratio already followed, and the reason
`worst_case` and `per` are refused when they disagree with the code named.

**And rendering both terms found a fourth codec under-reported.** `framed`
is `crc32 |> interleave_16 |> manchester_802_3`: four bytes of parity,
doubled, so its bound is `2n + 8`. The arithmetic has always known that
and the map printed `ratio_exact(2,1)`, because `_codec_properties`
rendered a ratio or an addend and never both -- which is 0048's own
diagnosis, met one construct away from the stuffing codes it was written
about. Nobody had measured `framed`; it fell out of fixing the renderer.

**Which then made a stale comment checkable.** `std/kernels.situ` said the
pipeline was "2:1 with 32 bytes of parity doubled to 64". Thirty-two is
reed-solomon's parity, not crc32's; the map now prints `+8` beside it, so
the sentence and the artifact disagreed in public. Corrected to four
doubled to eight, with a note saying what made it visible.

**Three controls, each through a different guard**, which is worth
recording because no one of them covers the construct:

    cobs      the derived-vs-hand-written library comparison
    slip      the encoder measured against the table, object file and all
    the map   the committed `.map` files going stale

`cobs` is declared in both libraries and `slip_framing` in only one, so
the first guard cannot see `slip` at all -- and the second is the only one
that reads what the encoder actually writes. Sabotaging the derived addend
catches `cobs`; sabotaging the table's `slip` row catches `slip`;
sabotaging the renderer catches all three schemas whose maps carry a
constant.

**No generated byte stream changes**, which is what made this the cheaper
of 0048's two forks: the alternative was three encoders dropping the
delimiter, and a COBS decoder finds a frame's end by that byte.
