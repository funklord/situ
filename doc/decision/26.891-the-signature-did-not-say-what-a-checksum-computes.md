# 26.891: The signature did not say what a checksum computes

Status: recorded
Date: 2026-11-06
Source: found writing 26.890

Changing a CRC's `init` changed no line of `situc wire`:

    codec check { kernel = polynomial(width = 16, poly = 0x100B, init = 0xFFFF); }

`init = 1`, `poly = 0x100D` or `augmented` left the signature byte for byte
the same, so `wire --check` passed a change after which every digest a peer
sends stops verifying. The signature exists to catch exactly that. The member
line named no codec for a tag, and the codec's parameters appeared nowhere.

## What it says now

A `kernel` line per codec a member names, in `varint`'s place and for its
reason: the parameters are the bytes.

    kernel crc32 : polynomial(width = 32, poly = 0x04C11DB7, init = 0xFFFFFFFF, xorout = 0xFFFFFFFF, reflect)

    ~  4  u8  crc  codec=crc32

A tag's line carries `codec=`, so a checksum moved to another codec is a
changed fact. A changed kernel is `breaking`. Only codecs a member names
appear: a schema importing `std/kernels.situ` is not bound by forty it never
calls.

A new kind of line, so the format is v3, for the reason v1 moved: an older
comparator would count it as a member. All 47 committed signatures were
regenerated, and besides the version line the diff is 14 `kernel` lines and
the `codec=` facts.

A tier-1 codec has no kernel, so its behaviour stays outside the contract, as
it is outside the schema.
