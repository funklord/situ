# 26.728: Rust's frame layer was the one nothing compiled

Status: recorded -- the Rust gate is in `test_codegen_rust.py`
Date: 2026-10-29
Source: `project.md` section 26

**This record's first version was titled "only C's frame layer was ever
compiled" and that was wrong.** It is kept at its filename because records
are cited by number, and the correction is the useful half.

What is true: rung 4 of decision 0032's ladder ships four ways, and on
2026-10-29 **three of the four had a gate and Rust had none**. C's
`test_every_schema_frame_layer_compiles` has existed since 26.260, and
C++'s and Python's siblings since 2026-10-26 -- the open register said so,
in the same entry that said *"Rust's is still unbuilt"*, and the register
was right.

## What the first version got wrong, and how

It read `test_relations.py`'s docstring -- *"C's is the only frame layer a
test compiles, and that is how it was found"* -- and took it as current.
That sentence was true when written and the two siblings landed after it,
so the file most likely to tell a reader about frame-layer compiling is
the one that had gone stale about it. **A docstring is a dated claim with
no date on it**, which is `evidence.md`'s shelf-life rule met in a comment
rather than a document.

The cost was a whole test file, `test_the_frame_layer_compiles.py`,
duplicating three existing gates with a fourth holdout list beside theirs.
It was committed as `0ddfd17` and removed again here. **Three overlapping
gates with three holdout lists is the drift this workspace fights**, and I
wrote it. What it genuinely added is one arm: Rust's, now in
`test_codegen_rust.py` beside its three siblings, in their idiom and with
their assert-to-fail discipline.

The check that would have caught it is one grep --
`grep -rn 'def test_every_schema_frame_layer' test/unit/` -- and it is the
same check *"before deferring something, look for where the project has
already decided it"* asks for, pointed at a test rather than a decision.

## What the gate found

Rust's frame layer failed on four schemas, five structs, exactly as 26.692
had already recorded: `coap`, `proto_message`, `tagged_options`,
`pickle_string` and `byte_run`. So the finding was not new either; what was
new is that Rust now fails about it rather than nobody asking.

**Three of those five turned out to be a different fault**, which is
26.729: each holds a `tlv` region, C framed it at the length of its fixed
members, and for `proto_message` that is zero and its Reader looped. No
backend frames those three now. What is left is `padded.situ`'s two, and
they are the real capability difference -- C has a pad branch in its
extent chain and the other three have none, which is 26.692's open item
unchanged.

## What is worth keeping

- **Rust's rung-4 output is compiled now**, over every schema
  `every_schema.py` lists, under `-D warnings`. The backend whose compiler
  refuses a dead store outright was the one whose frame layer nothing put
  a compiler near.
- **Look for the gate before writing it.** Three of the four existed.
- **A test file is a claim about coverage**, so adding one that overlaps an
  existing one costs more than it buys: the holdout lists drift, and the
  next reader cannot tell which is authoritative.
