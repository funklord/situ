# 26.728: only C's frame layer was ever compiled

Status: recorded -- the sweep is in the unit suite; the gap it documents is
26.692's open item and is not closed here
Date: 2026-10-29
Source: `project.md` section 26

Rung 4 of decision 0032's layer ladder ships four ways and was built one
way. `test_relations.py` says so in as many words, at
`test_no_reader_is_emitted_for_an_unframeable_struct`: *"C's is the only
frame layer a test compiles, and that is how it was found"*. The other
three were checked by reading their text for a struct's name.

So a consumer asking for `situc build --layer frame` gets
`<name>_frame.hpp`, `.rs` or `.py` beside the accessors, and for four
schemas the file does not build:

    error: 'required' is not a member of 'situ::pickle_string'
    error[E0599]: no function or associated item named `required` found
                  for struct `padded::PickleString`

## Measured, all four backends over all 42 schemas

**C is clean. C++, Rust and Python each fail on the same five structs** --
`coap`, `proto_message`, `tagged_options`, `pickle_string` and `byte_run`,
in `coap.situ`, `protobuf.situ`, `test/schema/edges.situ` and
`test/schema/padded.situ`. 152 (backend, schema) pairs have a frame layer;
140 build clean and 12 are held out.

**26.692's figure of five structs in four schemas is therefore right**, and
the first pass of this measurement wrongly said Python's was wider.

## The cause, which is one predicate against four

`frame.framed_structs` is shared -- C++'s, Rust's and Python's frame
modules all import C's -- and it asks `traverse.frameable`. Each emitter's
`_required` then applies its OWN narrower conditions and falls through to
`_unframeable`, which emits a comment and no function. **The predicate
deciding whether to emit a Reader and the predicate deciding whether to
emit what the Reader calls are different predicates**, and nothing made
them agree.

That is this week's shape for the fifth time, one level up: two decisions
taken in different places from different things, where neither constrains
the other. 26.693, 26.724 and 26.726 are three quantities inside
`required`; this is the question of whether `required` exists at all.

**C is clean because C is the widest.** It has a pad branch in its extent
chain -- `situ_align_up_u32(base, n, view.limit)` at the placement -- that
the other three have no branch for at all, so a `pad_to` struct reaches
their length expression, which answers None, and they decline. So
narrowing the shared predicate would take working Readers away from C: the
fix is three emitters gaining what C has, which is a feature rather than a
correction, and it is 26.692's open item unchanged.

## What this file does

It compiles all four, over every schema `every_schema.py` lists, and holds
the gap open with its measurement. The holdouts are **exact rather than a
ceiling**: a backend that starts compiling a held-out schema fails here
too, so closing the gap requires taking a name out of `FRAME_APART` and
cannot be done silently. Proved by sabotage both ways -- removing
`("rust", "coap.situ")` fails that case, and adding a fictitious
`("cpp", "udp.situ")` fails that one.

Python is checked by reading the call target rather than by compiling,
because Python has no compiler: a missing method is an `AttributeError` at
the call rather than at the build, which is this backend's whole
difference.

## Two detector faults, which are the transferable part

**Both of this sweep's first readings were wrong, in opposite directions,
and the project's own discipline caught both.**

- **g++ writes typographic quotes.** The pattern looking for `'required'
  is not a member of` found nothing in g++'s output, which reads as "no
  struct is missing one" and is the opposite of the truth. It matches both
  quotation styles now.
- **A split on `"class " + name` prefix-matches.** Asked about `image` it
  read `image_arm`'s body, found no `required` there, and reported
  `image`, `image_section`, `png.chunk` and `smtp.command` as missing when
  all four have one -- which is how the "Python's set is wider" claim was
  manufactured. A line-anchored class header says they do.

The first silently under-reports and the second silently over-reports, and
**neither is visible from the count.** That is why the holdouts are
compared as a SET: a count of twelve would have accepted the wrong twelve,
and the first version of this file did.

It is also the third instrument fault in one run -- after the probe that
returned on its first finding (26.726) and the three fills that could not
drive a run (26.727). The sweeps found four real faults this week and
produced three false readings, which is about the rate this tree's record
of them already suggests.
