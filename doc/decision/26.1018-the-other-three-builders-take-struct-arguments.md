# 26.1018: the other three builders take struct arguments

Status: recorded
Date: 2026-11-14
Source: the goal gap -- C-only builders in 26.1007 and 26.1017

**A struct that takes an argument was built by C alone.** TIFF's
`ifd_entry` and `ifd` take the header's byte order, pcap's `record` the
file's magic, and Python, C++ and Rust refused all three ("is a arg part,
which Python's builder does not write yet"), so the agreement test held C
to nobody for them.

**Now all four.** An argument is a parameter of the builder, in member
order and with the reader's own spelling (`arg_order`); where it is a byte
order, the fields in its scope are stored in the order it says, which is
the marker's mechanism of 26.1007 with the value handed over rather than
written. The closing view is taken with it, as the reader's is. And a run
of argued structs (26.1017) passes the caller's values to each element's
`required` and validation, by the reader's keywords in Python and
positionally in C++ and Rust.

What stays C's: an argument that sizes a run (`part.length`), an argued
nested member or arm (26.1012), and a span checked after (26.1016).

**Measured** by `test_the_four_builders_agree`, which now hands an argument
its little-endian literal where it is an order -- the value that tells a
writer ignoring it from one honouring it -- and gives the walker the same
arguments: `ifd_entry.long`, `ifd` (two entries, count `02 00`), `record`
and `pcap` (two records) are written byte for byte alike by all four and
read whole by the reader and the walker.
