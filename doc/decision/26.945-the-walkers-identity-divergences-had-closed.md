# 26.945: the walkers' identity divergences had closed

Status: recorded
Date: 2026-11-09
Source: 26.944, whose lens it is -- an open entry closed by later work that nobody connected to it

**The four structs `IDENTITY_APART` held out of the walkers' identity
comparison (26.689) had stopped diverging, and the set is empty.**

26.944 found 26.721's open question answered by a commit that never named
it. The shape of that finding is the lens: an entry recording a divergence
is a claim about the present, and nothing re-reads it when a fix lands
elsewhere. The other held-out set in `test_walker_c.py` was the obvious
place to point it.

## What the set held

`pickle_wstring`, `png.chunk`, `edges.oob_inner` and `edges.varint_driver`:
a run whose declared length is large enough to overflow the C walk's
`size_bits`. C refused there with no check named, which `c_why` renders as
`bounds`, and the Python walk, whose integers do not overflow, reached the
member's `fits_frame` row. Both refused, both said BOUNDS, and they
disagreed about which check. 26.689 left the reconciliation to the
copyright holder, because which walk is right is a question about both.

## What closed it

2441fe89 (2026-11-08), "name fits_frame where the C walk cannot count a
run's width", found the same shape on riff and made C name `fits_frame`
where the member is held to the frame. That is the Python walk's answer,
and it covers all four. Measured with 40 seeded packets per struct, the
refusals each walk names compared:

    2441fe89~1   pickle_wstring 33/40   png.chunk 27/40
                 oob_inner 38/40        varint_driver 1/29     differ
    2441fe89     0 of 149 differ

The probe is the identity sweep's own loop; at 601fa966, where the fourth
entry was added, it reports the same four as divergent, so it can see the
class. At HEAD, 300 packets per struct, 1136 refusals compared and none
differ.

## What stays

C's `size_bits` still refuses an overflowing count where the backends clamp,
as its own comment says ("recorded as the half still apart"). That
difference no longer reaches a caller, which gets `fits_frame` from both
walks. Whether `size_bits` should saturate is a question about one
function's internals, not about what either walker answers.

## Consequences

- `IDENTITY_APART` is empty and its guard is `not IDENTITY_APART`.
- 26.689's entry in the open register is struck and points here, and the
  status block names one holder question, 26.693.
