# 26.1068: std carries xz and zstd, and a flag may choose the compression

Status: recorded
Date: 2026-11-18
Source: openmlx4's report of 2026-11-14 (`suggestion/openmlx4.md`, "what
the five schemas still cannot say", item 5)

openmlx4 could not describe an MFA section whose payload is xz-compressed
when a flag bit says so: no `xz` codec, every conditional `coded` spelling
refused, and `verify` crashing on a nested struct handed the length as a
`[stream]` parameter.

**Two of the three were already answered, re-measured at a2b7af8a.** A
choice by flag is a sized variant (26.1040), and its arm may be a struct
holding the `coded` region:

    struct section {
        u8  compressed;
        u32 length;
        variant body[length] switch (compressed) {
            case 0: u8 raw[remaining];
            case 1: xz_payload packed;
            default: error;
        }
    }
    struct xz_payload { coded payload(xz) { u8 data[remaining]; } }

The variant is `length` bytes whichever arm is taken, and each arm's
`remaining` ends there. The `[stream]`-parameter shape is refused as a
member by name (0050), and `verify` on it as a top-level message runs,
with `--arg` and without.

**The third is std's:** `std/codecs.situ` gains `xz` and `zstd`, declared
as `deflate` is -- unbounded expansion, stream granularity, not seekable,
invertible, and not `deterministic`, since the bytes depend on the
encoder's preset or level. As with the other signatures, none is bound to
an implementation; the adopter's `impl ... extern` names one.
