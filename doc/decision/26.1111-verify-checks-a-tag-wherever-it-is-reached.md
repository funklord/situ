# 26.1111: `verify` checks a tag through nested structs, arms and chain links

Status: recorded
Date: 2026-11-20
Source: openmlx4's inbox 20261119T1237Z item 1 and 20261119T1253Z item 3

`verify` checked the tags of the struct a vector names and stopped:
a tag one struct down was reported "not checked (inside ..., which this
does not descend into)". Behind a variant it was worse, because the walk
over a struct's own members leaves a variant's arms out -- a checksum one
arm down was neither checked nor named, so a VPD keyword with its RV byte
flipped conformed in silence. And FS2's section chain, each link a
`gph_section` with its own CRC16, had every link's CRC unchecked: the CRC
openmlx4 most wanted run.

## The change

`_checked_tags` descends: a nested struct through its accessor, the arm
the discriminant selects through the arm's accessor (`VersionError` is the
generated code saying an arm is absent, and it is skipped), and a member
placed by `at` through its `_view`, which opens it over the same message,
so a tag covering `before` sums the message's bytes and not a copy's.
What it cannot open -- a run of structs, an accessor that returns no view
-- is named as before, now including tags behind arms. The depth guard is
256: 64 stopped one link short of openmlx4's own `sixty_five` chain, which
its `[limit = 64]` accepts.

## Measured

Against openmlx4's tree at the time: `fs2.vectors` 13 conform with no tag
left unchecked (two were noted before); `mfa` and `vpd` unchanged. The
test flips the third link's sum of a three-link chain, and a VPD keyword's
RV byte one arm down; both conformed before.
