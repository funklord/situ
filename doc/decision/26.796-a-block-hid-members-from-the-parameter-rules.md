# 26.796: A block hid its members from the parameter rules

Status: recorded -- fixed
Date: 2026-11-02
Source: found while building 0068

    struct e { parameter u8 b; u8 x; }
    struct s { u8 a; positional { e inner; } }

    struct t { parameter u8 n; u8 a;
               authenticated { u8 body[n]; u8 after; }
               tag u8[16] covers(authenticated); }

Both were accepted. `s` generated C calling `situ_e_validate(nested)`
without the argument it takes, which does not compile. `t` let a
parameter with no `[stream]` decide where `after` sits, which is the one
cell 0050 refuses.

`wellformed._members_and_arms` gave the parameter rules a struct's
members and each arm's member, and stopped there. 26.432 and 26.794 were
the same hole, an arm and then a struct naming itself. A container is
the third.

## The change

`_members_and_arms` returns `_walk_members(struct.members)`, which
descends every container through `nested`. That covers the nesting
refusal, the `[stream]` rule and the `arg_` name collision at once.

Every corpus schema still maps.

## Tests

`test_codegen_python.py::test_a_block_does_not_hide_a_member_from_the_parameter_rules`
refuses both schemas and accepts `t` with `[stream]`. With
`situc/wellformed.py` reverted it fails.
