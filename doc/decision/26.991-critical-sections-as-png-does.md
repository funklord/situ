# 26.991: critical sections, as PNG does

Status: recorded
Date: 2026-11-13
Source: the copyright holder's answer to 26.988's open question --
"critical sections, as PNG does"

The image directory had one rule for a kind a walker does not know: skip
it. That was the property the directory was built for, and it is right
for a section that adds reach or something to print. It is wrong for one
that carries a check: 26.988's `image_ordering` refuses a run out of
order, and a walker that predates it skipped the section and passed the
run as clean -- where before 26.988 it had said "cannot say".

PNG settled the same question for chunks: the chunk name says whether a
decoder that does not know it may ignore it (ancillary) or must refuse the
file (critical). A directory entry's kind is now a `u16` tag and a `u16`
of flags -- one little-endian `u32`, so a tag reads the same either way --
and bit 0 of the flags marks the section ancillary. A walker skips an
unknown ancillary tag and refuses an image holding an unknown critical
one: `ImageError` in `walker/image.py`, `SITU_WALK_UNSUPPORTED` from
`situ_walk_open`.

**Which are ancillary**: the names and the capability vectors, read only to
print, under `--metadata`. Everything else is critical, including every
future section unless it is marked otherwise -- the safe default is the one
that refuses.

**Unknown means unknown.** The C walker knows five kinds it does not read
-- strings, codecs, whitespace, tags and kernel tables -- and declines what
needs them where it is reached, as it always has. Those are known, listed
in its loader, and not refused: the flag governs only a tag a walker has
never heard of, which is PNG's rule too.

`FORMAT_VERSION` is 10, which is the version that says this: a version-9
walker would skip the flagged kinds as plain unknowns, so it refuses a
version-10 image instead. `std/image.situ` describes the split entry.

This settles 26.988's open question. `test_a_walker_refuses_an_unknown_critical_section`
rewrites one entry of a real image three ways -- an unknown ancillary tag,
the same tag marked critical, `image_ordering` renamed -- and has both
walkers skip the first and refuse the other two; four of its five fail
with the change reverted.
