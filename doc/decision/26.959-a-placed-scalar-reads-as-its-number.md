# 26.959: a placed scalar reads as its number

Status: recorded
Date: 2026-11-12
Source: a sweep of placed members through six readers; the open-register entry of 2026-11-11

**`u8 c at 3;` reads as a number now, in all four backends.** It was
accepted and exposed everywhere as one byte run of the message -- C
`situ_s_c_view`, C++ and Rust a byte slice, Python a `memoryview` -- and
never as the value its type declares. The four agreed, so no differential
saw it; the differential's C driver asked a setter and a getter nobody
emits, and did not compile.

## The shape

Each backend's placed byte accessor already takes the message, the offset
being the message's (9.8). The value getter is its sibling:

| backend | bytes | value |
|---|---|---|
| C | `situ_s_c_view(msg, view, &out)` | `situ_s_c_value(msg, view, &v)` |
| C++ | `c(msg, bytes &out)` | `c_value(msg, T &out)` |
| Rust | `c(&self, msg) -> Result<&[u8]>` | `c_value(&self, msg) -> Result<T>` |
| Python | property `c` | property `c_value` |

Each reads through the byte accessor, so the bounds check -- the offset is
the message's, so nothing about the frame says it is inside the buffer --
stays in one place. `traverse.located_value` decides which members get
one, once for all four: a plain 8, 16, 32 or 64-bit integer, big or little.
An enum-typed one (whose C out-parameter is its typedef), a native-order
one, a text number, a float and a bit field keep their bytes alone.

## Held

The differential asks `<name>_value` for every such member and no longer
asks a write for a placed one. `test_a_placed_scalar_has_a_value.py`
holds a `u8`, a big-endian `u16` at an offset field and a little-endian
`i16`, values worked out by hand, and a `u16` whose offset runs past the
message refused alike, in all four; it fails with Python's byte order
flipped.
