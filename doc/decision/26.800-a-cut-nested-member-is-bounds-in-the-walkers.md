# 26.800: A nested member the frame cuts short is BOUNDS in both walkers

Status: recorded -- fixed
Date: 2026-11-02
Source: found while testing 0068 step 2

    struct entry { u8 tag [max = 5]; u8 n; u8 data[n]; }
    struct vol   { entry ent; entry one; u8 after; }

In `0100bb05aaaa`, `one` declares five bytes of data and the frame holds
two, and its `tag` (0xbb) breaks `[max = 5]`. All four backends answer
BOUNDS. Each acquires `one` with `situ_view_sub(view, base, extent,
out)`, which refuses an extent past the limit, so the tag is never
asked. Both walkers answered CONSTRAINT:

- Python's `report._validate` made the inner frame `min(limit, at +
  extent)`, which clamps rather than refuses, and walked in.
- The C walker's `validate_deep` handed the nested walk the whole rest of
  the frame.

## The change

Both walkers refuse with BOUNDS where the member's measured extent passes
the frame, before validating inside it. Python's inner frame is then the
member's own extent, unclamped.

## Tests

`test_a_cut_nested_member_is_bounds.py` holds the four backends and both
walkers to one verdict on three messages: cut short with a broken rule,
whole with a broken rule, and whole. With `walker` reverted it fails.
